40.1 System Overview and Design Philosophy

Before writing a single line of code, the architecture must answer three questions: Where does state live? Where does intelligence live? Where does trust live?

In most AI-native applications, these answers get muddled. State is scattered across Redis, S3, Pinecone, and a relational database with no clear authority. Intelligence is a black box API call with no observability. Trust is an afterthought bolted on after launch.

The architecture in this chapter answers them cleanly:

  • → **State lives in PostgreSQL.** Conversations, embeddings, documents, tool results, audit logs, user permissions — all of it. PostgreSQL becomes the single source of truth.
  • → **Intelligence lives at the boundary.** LLM APIs (Claude, OpenAI) are called from application code and agent workers. Their inputs and outputs are always recorded in PostgreSQL before any side effect is applied.
  • → **Trust lives in the database.** Row-level security, role separation, and cryptographic audit trails enforce access control at the data layer, not just the API layer.

    • The application we are building is an enterprise knowledge assistant: users ask questions, the system retrieves relevant documents via RAG, optionally invokes tools (database lookups, web search, code execution), maintains multi-turn conversation history, and generates responses with full citation. Everything is observable, auditable, and recoverable.

    Component inventory:

    | Layer | Technology | Role |

    |---|---|---|

    | API | FastAPI | HTTP endpoints, streaming responses |

    | Database | PostgreSQL 16 + pgvector | All persistent state |

    | Connection pool | PgBouncer | Connection management |

    | Cache | Redis | Embedding cache, session tokens |

    | Async workers | Celery + Redis | Document ingestion, re-embedding |

    | LLM | Claude 3.5 Sonnet / GPT-4o | Generation and reasoning |

    | Embeddings | OpenAI text-embedding-3-small | Vector representations |

    | Orchestration | LangChain / LlamaIndex | RAG pipelines, agent loops |

    | Protocol | MCP (Model Context Protocol) | Tool exposure to agents |

    | Replication | Logical replication | Read replicas for embedding queries |

    graph TD
    Client[Client] --> API[FastAPI Layer]
    API --> PgBouncer[PgBouncer Pool]
    PgBouncer --> Primary[(PostgreSQL Primary\nai.* / audit.* / ops.*)]
    Primary -.logical replication.-> Replica[(Read Replica\nHNSW vector search)]
    API --> Redis[(Redis\nembedding + session cache)]
    API --> LLM[Claude / GPT-4o]
    API --> MCP[MCP Tool Server]
    MCP --> Primary
    Ingest[Document Ingest Endpoint] --> Primary
    Primary --> Celery[Celery Workers]
    Celery --> Embeddings[OpenAI Embeddings API]
    Celery --> Primary
    Primary --> Prometheus[Metrics Exporter / Grafana]

    *The request path (client through FastAPI, PgBouncer, and the primary) stays on the write path only long enough to persist state; vector search and analytics are pushed to the read replica, while document ingestion runs asynchronously through Celery — PostgreSQL anchors every branch.*

-- Trigger to auto-increment sequence_num within a conversation
CREATE OR REPLACE FUNCTION ai.next_message_sequence()
RETURNS TRIGGER AS $$
BEGIN
    SELECT COALESCE(MAX(sequence_num), 0) + 1
    INTO NEW.sequence_num
    FROM ai.messages
    WHERE conversation_id = NEW.conversation_id;

    -- Update conversation counters
    UPDATE ai.conversations
    SET message_count = message_count + 1,
        updated_at = now(),
        token_usage = token_usage || jsonb_build_object(
            'input',  (token_usage->>'input')::int + COALESCE((NEW.usage->>'input_tokens')::int, 0),
            'output', (token_usage->>'output')::int + COALESCE((NEW.usage->>'output_tokens')::int, 0)
        )
    WHERE conversation_id = NEW.conversation_id;

    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_message_sequence
    BEFORE INSERT ON ai.messages
    FOR EACH ROW EXECUTE FUNCTION ai.next_message_sequence();

async def get_current_user(
    authorization: str = Header(...),
    db: AsyncSession = Depends(get_db_session),
):
    """Validate JWT, resolve user + tenant, set RLS context."""
    # In production: verify JWT signature, check expiry
    token = authorization.removeprefix("Bearer ")

    cached = await redis_client.get(f"session:{token}")
    if not cached:
        raise HTTPException(status_code=401, detail="Invalid or expired token")

    session_data = json.loads(cached)

    # Set RLS session variables — every query in this session respects tenant isolation
    await db.execute(
        "SELECT set_config('app.tenant_id', :tid, true), set_config('app.user_id', :uid, true)",
        {"tid": session_data["tenant_id"], "uid": session_data["user_id"]},
    )

    return session_data

    40.4 The Chat Service: RAG + Agent Loop

    The ChatService is where the real work happens. It orchestrates retrieval, history loading, tool dispatch, LLM calls, and persistence in a single request lifecycle.

    # app/services/chat_service.py

import hashlib
import json
import time
import uuid
from typing import AsyncIterator, Optional

import numpy as np
from anthropic import AsyncAnthropic
from openai import AsyncOpenAI
from sqlalchemy import text
from sqlalchemy.ext.asyncio import AsyncSession


class ChatService:
    def __init__(
        self,
        db: AsyncSession,
        redis,
        anthropic: AsyncAnthropic,
        openai: AsyncOpenAI,
    ):
        self.db = db
        self.redis = redis
        self.anthropic = anthropic
        self.openai = openai

    # ------------------------------------------------------------------
    # Embedding with cache
    # ------------------------------------------------------------------
    async def embed(self, text: str) -> list[float]:
        cache_key = f"emb:{hashlib.sha256(text.encode()).hexdigest()[:16]}"
        cached = await self.redis.get(cache_key)
        if cached:
            return json.loads(cached)

        response = await self.openai.embeddings.create(
            model="text-embedding-3-small",
            input=text,
        )
        vector = response.data[0].embedding
        # Cache for 24 hours — embeddings are deterministic
        await self.redis.setex(cache_key, 86400, json.dumps(vector))
        return vector

    # ------------------------------------------------------------------
    # RAG retrieval
    # ------------------------------------------------------------------
    async def retrieve_chunks(
        self,
        query: str,
        collection_id: uuid.UUID,
        tenant_id: uuid.UUID,
        top_k: int = 8,
        score_threshold: float = 0.35,
    ) -> list[dict]:
        query_vector = await self.embed(query)
        vector_literal = "[" + ",".join(str(v) for v in query_vector) + "]"

        result = await self.db.execute(
            text("""
                SELECT
                    c.chunk_id,
                    c.document_id,
                    c.content,
                    c.metadata,
                    d.title AS document_title,
                    d.source_uri,
                    1 - (c.embedding <=> :query_vec::vector) AS cosine_score
                FROM ai.document_chunks c
                JOIN ai.documents d ON d.document_id = c.document_id
                WHERE c.collection_id = :collection_id
                  AND c.tenant_id = :tenant_id
                  AND c.embedding IS NOT NULL
                  AND 1 - (c.embedding <=> :query_vec::vector) >= :threshold
                ORDER BY c.embedding <=> :query_vec::vector
                LIMIT :top_k
            """),
            {
                "query_vec": vector_literal,
                "collection_id": str(collection_id),
                "tenant_id": str(tenant_id),
                "threshold": score_threshold,
                "top_k": top_k,
            },
        )

        rows = result.mappings().all()
        return [dict(row) for row in rows]

    # ------------------------------------------------------------------
    # Conversation history
    # ------------------------------------------------------------------
    async def load_history(
        self,
        conversation_id: uuid.UUID,
        max_messages: int = 20,
    ) -> tuple[list[dict], Optional[str]]:
        """Returns (recent messages, rolling summary if exists)."""

        conv_result = await self.db.execute(
            text("""
                SELECT summary, summary_at, message_count
                FROM ai.conversations
                WHERE conversation_id = :cid
            """),
            {"cid": str(conversation_id)},
        )
        conv = conv_result.mappings().first()
        summary = conv["summary"] if conv else None

        msg_result = await self.db.execute(
            text("""
                SELECT role, content, tool_name, tool_input, tool_output, sequence_num
                FROM ai.messages
                WHERE conversation_id = :cid
                  AND role IN ('user', 'assistant', 'tool')
                ORDER BY sequence_num DESC
                LIMIT :limit
            """),
            {"cid": str(conversation_id), "limit": max_messages},
        )
        messages = list(reversed(msg_result.mappings().all()))
        return [dict(m) for m in messages], summary

    # Create or load conversation

    async def ensure_conversation(

        user_id: uuid.UUID,
        tenant_id: uuid.UUID,
        collection_id: Optional[uuid.UUID],

    # ------------------------------------------------------------------
    # Build the context prompt
    # ------------------------------------------------------------------
    def build_system_prompt(
        self,
        chunks: list[dict],
        summary: Optional[str],
    ) -> str:
        lines = [
            "You are an enterprise knowledge assistant. Answer questions accurately "
            "using the provided context. Cite your sources by referencing document "
            "titles. If the context does not contain enough information to answer "
            "confidently, say so rather than speculating."
        ]

        if summary:
            lines.append(f"\n## Conversation Summary\n{summary}")

        if chunks:
            lines.append("\n## Retrieved Context\n")
            for i, chunk in enumerate(chunks, 1):
                title = chunk.get("document_title", "Unknown")
                score = chunk.get("cosine_score", 0)
                lines.append(
                    f"[{i}] {title} (relevance: {score:.2f})\n{chunk['content']}\n"
                )

        return "\n".join(lines)

    # ------------------------------------------------------------------
    # Main generate (non-streaming)
    # ------------------------------------------------------------------
    async def generate_response(self, request, current_user: dict) -> dict:
        tenant_id = uuid.UUID(current_user["tenant_id"])
        user_id = uuid.UUID(current_user["user_id"])

        conversation_id = await self.ensure_conversation(
            request.conversation_id, user_id, tenant_id, request.collection_id
        )

        # Save user message
        await self.save_message(
            conversation_id, tenant_id, "user", request.message
        )

        # Retrieve context
        chunks = []
        if request.collection_id:
            chunks = await self.retrieve_chunks(
                request.message, request.collection_id, tenant_id
            )

        history, summary = await self.load_history(conversation_id)
        system_prompt = self.build_system_prompt(chunks, summary)

        # Build messages for Claude
        messages = []
        for msg in history[:-1]:  # exclude the message we just inserted
            messages.append({"role": msg["role"], "content": msg["content"]})
        messages.append({"role": "user", "content": request.message})

        t0 = time.monotonic()
        response = await self.anthropic.messages.create(
            model="claude-3-5-sonnet-20241022",
            max_tokens=4096,
            system=system_prompt,
            messages=messages,
        )
        latency_ms = int((time.monotonic() - t0) * 1000)

        content = response.content[0].text
        usage = {
            "input_tokens": response.usage.input_tokens,
            "output_tokens": response.usage.output_tokens,
        }
        citations = [
            {
                "chunk_id": str(c["chunk_id"]),
                "document_title": c["document_title"],
                "score": round(float(c["cosine_score"]), 4),
                "excerpt": c["content"][:200],
            }
            for c in chunks
        ]

        message_id = await self.save_message(
            conversation_id,
            tenant_id,
            role="assistant",
            content=content,
            model="claude-3-5-sonnet-20241022",
            usage=usage,
            citations=citations,
            latency_ms=latency_ms,
            finish_reason=response.stop_reason,
        )

        return {
            "conversation_id": conversation_id,
            "message_id": message_id,
            "content": content,
            "citations": citations,
            "usage": usage,
        }

    # ------------------------------------------------------------------
    # Streaming variant
    # ------------------------------------------------------------------
    async def stream_response(
        self, request, current_user: dict
    ) -> AsyncIterator[str]:
        tenant_id = uuid.UUID(current_user["tenant_id"])
        user_id = uuid.UUID(current_user["user_id"])

        conversation_id = await self.ensure_conversation(
            request.conversation_id, user_id, tenant_id, request.collection_id
        )

        await self.save_message(conversation_id, tenant_id, "user", request.message)

        chunks = []
        if request.collection_id:
            chunks = await self.retrieve_chunks(
                request.message, request.collection_id, tenant_id
            )

        history, summary = await self.load_history(conversation_id)
        system_prompt = self.build_system_prompt(chunks, summary)

        messages = []
        for msg in history[:-1]:
            messages.append({"role": msg["role"], "content": msg["content"]})
        messages.append({"role": "user", "content": request.message})

        # Emit citations metadata before the text stream begins
        citations = [
            {
                "chunk_id": str(c["chunk_id"]),
                "document_title": c["document_title"],
                "score": round(float(c["cosine_score"]), 4),
                "excerpt": c["content"][:200],
            }
            for c in chunks
        ]
        yield f"data: {json.dumps({'type': 'citations', 'citations': citations})}\n\n"

        full_content = []
        t0 = time.monotonic()
        usage = {}
        finish_reason = None

        async with self.anthropic.messages.stream(
            model="claude-3-5-sonnet-20241022",
            max_tokens=4096,
            system=system_prompt,
            messages=messages,
        ) as stream:
            async for text_delta in stream.text_stream:
                full_content.append(text_delta)
                yield f"data: {json.dumps({'type': 'delta', 'text': text_delta})}\n\n"

            final = await stream.get_final_message()
            usage = {
                "input_tokens": final.usage.input_tokens,
                "output_tokens": final.usage.output_tokens,
            }
            finish_reason = final.stop_reason

        latency_ms = int((time.monotonic() - t0) * 1000)
        content = "".join(full_content)

        message_id = await self.save_message(
            conversation_id,
            tenant_id,
            role="assistant",
            content=content,
            model="claude-3-5-sonnet-20241022",
            usage=usage,
            citations=citations,
            latency_ms=latency_ms,
            finish_reason=finish_reason,
        )

        yield f"data: {json.dumps({'type': 'done', 'message_id': str(message_id), 'usage': usage})}\n\n"

    The ingestion pipeline runs outside the request/response cycle. A Celery worker picks up jobs from the ops.ingestion_jobs table (or from a Redis queue), processes documents, and writes chunks with embeddings back to PostgreSQL.

def chunk_text(text: str, chunk_size: int = 512, overlap: int = 64) -> list[str]:
    """Recursive character splitter — identical logic to LangChain's default."""
    words = text.split()
    chunks = []
    start = 0
    while start < len(words):
        end = min(start + chunk_size, len(words))
        chunks.append(" ".join(words[start:end]))
        if end == len(words):
            break
        start += chunk_size - overlap
    return chunks


def embed_batch(texts: list[str], model: str = "text-embedding-3-small") -> list[list[float]]:
    """Embed up to 2048 texts in a single API call."""
    response = openai_client.embeddings.create(model=model, input=texts)
    return [item.embedding for item in sorted(response.data, key=lambda x: x.index)]


@celery_app.task(bind=True, max_retries=3, default_retry_delay=30)
def ingest_document(self, job_id: str, document_id: str, tenant_id: str):
    conn = get_connection()
    cur = conn.cursor(cursor_factory=psycopg2.extras.RealDictCursor)

    try:
        # Mark job as running
        cur.execute(
            """
            UPDATE ops.ingestion_jobs
            SET status = 'running', started_at = NOW(), attempts = attempts + 1
            WHERE job_id = %s
            """,
            (job_id,),
        )
        conn.commit()

        # Load document
        cur.execute(
            """
            SELECT d.document_id, d.raw_content, d.collection_id,
                   dc.chunk_strategy, dc.embedding_model
            FROM ai.documents d
            JOIN ai.document_collections dc ON dc.collection_id = d.collection_id
            WHERE d.document_id = %s AND d.tenant_id = %s
            """,
            (document_id, tenant_id),
        )
        doc = cur.fetchone()
        if not doc or not doc["raw_content"]:
            raise ValueError(f"Document {document_id} not found or has no content")

        strategy = doc["chunk_strategy"]
        chunk_size = strategy.get("chunk_size", 512)
        overlap = strategy.get("overlap", 64)
        model = doc["embedding_model"]

        # Chunk
        text_chunks = chunk_text(doc["raw_content"], chunk_size, overlap)
        total = len(text_chunks)

        # Update progress
        cur.execute(
            "UPDATE ops.ingestion_jobs SET progress = %s WHERE job_id = %s",
            (json.dumps({"current": 0, "total": total}), job_id),
        )
        conn.commit()

        # Delete existing chunks (idempotent re-ingestion)
        cur.execute(
            "DELETE FROM ai.document_chunks WHERE document_id = %s",
            (document_id,),
        )

        # Embed in batches of 100
        batch_size = 100
        for batch_start in range(0, total, batch_size):
            batch_texts = text_chunks[batch_start : batch_start + batch_size]
            embeddings = embed_batch(batch_texts, model)

            insert_data = [
                (
                    str(uuid.uuid4()),
                    document_id,
                    str(doc["collection_id"]),
                    tenant_id,
                    batch_start + i,
                    text,
                    len(text.split()),
                    "[" + ",".join(str(v) for v in emb) + "]",
                    model,
                    datetime.utcnow(),
                )
                for i, (text, emb) in enumerate(zip(batch_texts, embeddings))
            ]

            psycopg2.extras.execute_values(
                cur,
                """
                INSERT INTO ai.document_chunks
                    (chunk_id, document_id, collection_id, tenant_id,
                     chunk_index, content, token_count, embedding,
                     embedding_model, embedding_at)
                VALUES %s
                """,
                insert_data,
                template="(%s, %s, %s, %s, %s, %s, %s, %s::vector, %s, %s)",
            )
            conn.commit()

            processed = min(batch_start + batch_size, total)
            cur.execute(
                "UPDATE ops.ingestion_jobs SET progress = %s WHERE job_id = %s",
                (json.dumps({"current": processed, "total": total}), job_id),
            )
            conn.commit()

        # Mark document as ready
        cur.execute(
            """
            UPDATE ai.documents
            SET status = 'ready', updated_at = NOW()
            WHERE document_id = %s
            """,
            (document_id,),
        )

        # Mark job as done
        cur.execute(
            """
            UPDATE ops.ingestion_jobs
            SET status = 'done', completed_at = NOW()
            WHERE job_id = %s
            """,
            (job_id,),
        )
        conn.commit()

    except Exception as exc:
        conn.rollback()
        cur.execute(
            """
            UPDATE ops.ingestion_jobs
            SET status = 'failed', error = %s
            WHERE job_id = %s
            """,
            (str(exc), job_id),
        )
        conn.commit()
        raise self.retry(exc=exc)

    finally:
        cur.close()
        conn.close()

    40.7 Observability: Metrics and Query Health

    A production AI application needs to know when things go wrong before users do. These SQL views and a lightweight metrics exporter give you visibility into retrieval quality, LLM latency, token spend, and ingestion pipeline health — all from the data already in PostgreSQL.

    -- ============================================================
-- OPERATIONAL VIEWS
-- ============================================================

-- Message latency and token usage by model, last 24 hours
CREATE OR REPLACE VIEW ops.message_stats_24h AS
SELECT
    model,
    COUNT(*)                                         AS message_count,
    ROUND(AVG(latency_ms))                           AS avg_latency_ms,
    PERCENTILE_CONT(0.50) WITHIN GROUP (ORDER BY latency_ms) AS p50_ms,
    PERCENTILE_CONT(0.95) WITHIN GROUP (ORDER BY latency_ms) AS p95_ms,
    PERCENTILE_CONT(0.99) WITHIN GROUP (ORDER BY latency_ms) AS p99_ms,
    SUM((usage->>'input_tokens')::int)               AS total_input_tokens,
    SUM((usage->>'output_tokens')::int)              AS total_output_tokens,
    COUNT(*) FILTER (WHERE finish_reason = 'error')  AS error_count
FROM ai.messages
WHERE role = 'assistant'
  AND created_at >= NOW() - INTERVAL '24 hours'
GROUP BY model;

-- RAG retrieval quality — average top-1 cosine score per conversation
-- (low scores suggest queries that don't match the corpus well)
CREATE OR REPLACE VIEW ops.retrieval_quality_daily AS
SELECT
    DATE_TRUNC('hour', m.created_at)                  AS hour,
    COUNT(*)                                           AS messages_with_citations,
    ROUND(
        AVG((c_entry->>'score')::float)::numeric, 4
    )                                                  AS avg_top1_score,
    COUNT(*) FILTER (
        WHERE (
            SELECT MAX((x->>'score')::float)
            FROM jsonb_array_elements(m.citations) x
        ) < 0.4
    )                                                  AS low_confidence_count
FROM ai.messages m,
     LATERAL jsonb_array_elements(m.citations) AS c_entry
WHERE m.role = 'assistant'
  AND m.citations IS NOT NULL
  AND jsonb_array_length(m.citations) > 0
  AND m.created_at >= NOW() - INTERVAL '7 days'
GROUP BY DATE_TRUNC('hour', m.created_at)
ORDER BY hour DESC;

-- Ingestion pipeline health
CREATE OR REPLACE VIEW ops.ingestion_pipeline_health AS
SELECT
    j.job_type,
    j.status,
    COUNT(*)                                           AS job_count,
    ROUND(AVG(
        EXTRACT(EPOCH FROM (j.completed_at - j.started_at))
    ))                                                 AS avg_duration_seconds,
    MAX(j.attempts)                                    AS max_attempts,
    COUNT(*) FILTER (WHERE j.attempts > 1)             AS retried_count
FROM ops.ingestion_jobs j
WHERE j.enqueued_at >= NOW() - INTERVAL '24 hours'
GROUP BY j.job_type, j.status
ORDER BY j.job_type, j.status;

-- Tenant token consumption summary (for billing / quota enforcement)
CREATE OR REPLACE VIEW ops.tenant_token_usage AS
SELECT
    t.tenant_id,
    t.name                                             AS tenant_name,
    t.plan,
    SUM((c.token_usage->>'input')::bigint)             AS total_input_tokens,
    SUM((c.token_usage->>'output')::bigint)            AS total_output_tokens,
    COUNT(DISTINCT c.conversation_id)                  AS total_conversations,
    COUNT(DISTINCT c.user_id)                          AS active_users,
    MAX(c.updated_at)                                  AS last_activity
FROM ai.tenants t
LEFT JOIN ai.conversations c ON c.tenant_id = t.tenant_id
WHERE t.is_active = true
GROUP BY t.tenant_id, t.name, t.plan
ORDER BY total_output_tokens DESC;

-- Slow query diagnostic — top 10 most expensive statement patterns
-- (requires pg_stat_statements)
CREATE OR REPLACE VIEW ops.slow_queries AS
SELECT
    LEFT(query, 120)                                   AS query_prefix,
    calls,
    ROUND((total_exec_time / calls)::numeric, 2)       AS avg_ms,
    ROUND(total_exec_time::numeric, 0)                 AS total_ms,
    ROUND((rows / calls)::numeric, 1)                  AS avg_rows,
    shared_blks_hit + shared_blks_read                 AS total_blks
FROM pg_stat_statements
WHERE calls > 10
ORDER BY total_exec_time DESC
LIMIT 10;

    40.9 Failure Modes and Recovery Playbook

    Every production system fails. This section catalogs the failure modes specific to AI applications on PostgreSQL and gives you concrete recovery procedures for each.

    Failure 1: HNSW index becomes stale after bulk ingestion

    Symptom: Retrieval quality drops after a large batch of documents is ingested. The HNSW graph has not reorganized around the new vectors.

    Diagnosis:

    -- Check index bloat and last vacuum on the chunks table
SELECT
    relname,
    n_dead_tup,
    n_live_tup,
    last_vacuum,
    last_autovacuum,
    last_analyze
FROM pg_stat_user_tables
WHERE relname = 'document_chunks';

    Recovery:

    -- REINDEX CONCURRENTLY rebuilds the HNSW index without locking reads
REINDEX INDEX CONCURRENTLY idx_chunks_embedding;

-- Afterward, increase ef_search for higher recall at query time
-- (session-level, no restart required)
SET hnsw.ef_search = 100;

    ---

    Failure 2: PgBouncer connection exhaustion

    Symptom: API returns 500 errors with no more connections allowed from PgBouncer. This happens when long-running queries hold server connections in transaction mode.

    Diagnosis:

    -- From a direct connection to PostgreSQL (bypassing PgBouncer)
SELECT count(*), state, wait_event_type, wait_event
FROM pg_stat_activity
WHERE datname = 'aiapp'
GROUP BY state, wait_event_type, wait_event
ORDER BY count DESC;

    Recovery:

    1. Identify and cancel the blocking queries:

    SELECT pg_cancel_backend(pid)
FROM pg_stat_activity
WHERE datname = 'aiapp'
  AND state = 'idle in transaction'
  AND query_start < NOW() - INTERVAL '30 seconds';

    2. Increase DEFAULT_POOL_SIZE in PgBouncer and restart.

    3. Add statement_timeout = '30s' to the PostgreSQL role to prevent future runaway queries.

    ---

    Failure 3: Embedding model version mismatch

    Symptom: After switching embedding models (e.g., from text-embedding-ada-002 to text-embedding-3-small), similarity scores collapse across the board. New queries embed with the new model but the corpus still has old embeddings.

    Diagnosis:

    SELECT embedding_model, COUNT(*), MAX(embedding_at)
FROM ai.document_chunks
GROUP BY embedding_model
ORDER BY COUNT DESC;

    Recovery: Queue re-embedding jobs for the entire affected collection via the ingestion worker. Do not mix embeddings from different models in the same HNSW index — they live in incompatible vector spaces.

    -- Identify collections with mixed models
SELECT dc.collection_id, dc.name, ch.embedding_model, COUNT(*) AS chunk_count
FROM ai.document_chunks ch
JOIN ai.document_collections dc ON dc.collection_id = ch.collection_id
GROUP BY dc.collection_id, dc.name, ch.embedding_model
ORDER BY dc.collection_id, ch.embedding_model;

    Then submit re-embed jobs for each affected collection:

    from app.workers.ingestion_worker import ingest_document

# For each document in the affected collection:
ingest_document.delay(job_id=str(job_id), document_id=str(doc_id), tenant_id=str(tenant_id))

    ---

    Failure 4: Audit partition missing

    Symptom: Inserts into audit.events fail with no partition of relation "events" found for row.

    Recovery:

    -- Create the missing partition immediately
CREATE TABLE audit.events_2025_03 PARTITION OF audit.events
    FOR VALUES FROM ('2025-03-01') TO ('2025-04-01');

    Prevention: Use pg_partman to auto-create partitions four weeks ahead:

    SELECT partman.create_parent(
    p_parent_table => 'audit.events',
    p_control => 'created_at',
    p_type => 'range',
    p_interval => '1 month',
    p_premake => 4
);

    ---

    Failure 5: LLM API timeout during streaming

    Symptom: The client receives partial SSE output; the assistant message is never saved to the database because the exception fires mid-stream.

    Recovery pattern — write the partial content with finish_reason = 'interrupted':

    # In stream_response, wrap the stream block:
full_content = []
finish_reason = "interrupted"

try:
    async with self.anthropic.messages.stream(...) as stream:
        async for text_delta in stream.text_stream:
            full_content.append(text_delta)
            yield f"data: {json.dumps({'type': 'delta', 'text': text_delta})}\n\n"

        final = await stream.get_final_message()
        finish_reason = final.stop_reason
        usage = {
            "input_tokens": final.usage.input_tokens,
            "output_tokens": final.usage.output_tokens,
        }
finally:
    # Always persist what we have, even if partial
    if full_content:
        content = "".join(full_content)
        await self.save_message(
            conversation_id, tenant_id,
            role="assistant",
            content=content,
            finish_reason=finish_reason,
            usage=usage if finish_reason != "interrupted" else {},
        )
    yield f"data: {json.dumps({'type': 'error', 'finish_reason': finish_reason})}\n\n"

    40.10 Scaling Beyond a Single Node

    When a single PostgreSQL instance is no longer enough, these strategies extend the architecture without changing the application's data model.

    Read replicas for embedding search

    The HNSW vector search is the most CPU-intensive read workload. Route all SELECT queries against ai.document_chunks to a streaming replica:

    # In ChatService, use a separate read-only engine for retrieval
read_engine = create_async_engine(
    "postgresql+asyncpg://app_user:secret@postgres-replica:5432/aiapp",
    pool_size=10,
)

async def retrieve_chunks(self, query, collection_id, tenant_id, top_k=8):
    async with AsyncSession(read_engine) as read_session:
        # Set RLS context on the replica session too
        await read_session.execute(
            "SELECT set_config('app.tenant_id', :tid, true)",
            {"tid": str(tenant_id)},
        )
        # ... rest of retrieval query unchanged

    Partitioning document chunks by tenant

    For multi-tenant deployments with large tenants dominating a shared table, partition ai.document_chunks by tenant_id using list partitioning. Each large tenant gets its own partition with its own HNSW index:

    -- Convert to partitioned table (requires pg_partman or manual migration)
-- Each tenant partition gets a dedicated HNSW index tuned to its size
CREATE TABLE ai.document_chunks_tenant_abc
    PARTITION OF ai.document_chunks
    FOR VALUES IN ('tenant-uuid-abc');

CREATE INDEX idx_chunks_embedding_abc ON ai.document_chunks_tenant_abc
    USING hnsw (embedding vector_cosine_ops)
    WITH (m = 32, ef_construction = 128);  -- higher quality for large corpus

    Citus for horizontal sharding

    When the document corpus grows beyond what a single node can serve at acceptable latency, the Citus extension distributes the document_chunks table across worker nodes using tenant_id as the distribution key. All queries that filter by tenant_id are pushed down to a single shard and never require cross-shard joins:

    -- After installing Citus extension:
SELECT create_distributed_table('ai.document_chunks', 'tenant_id');
SELECT create_distributed_table('ai.documents', 'tenant_id');
SELECT create_distributed_table('ai.conversations', 'tenant_id');

-- Co-locate tables on the same shard so joins stay local
SELECT create_distributed_table('ai.messages', 'tenant_id',
    colocate_with => 'ai.conversations');

    Token budget enforcement at the database layer

    Rather than enforcing token quotas only in application code (which can be bypassed or crash), enforce them with a PostgreSQL function that checks accumulated usage before each message is saved:

    CREATE OR REPLACE FUNCTION ai.check_token_budget()
RETURNS TRIGGER AS $$
DECLARE
    v_plan TEXT;
    v_used BIGINT;
    v_limit BIGINT;
BEGIN
    -- Only check on assistant messages (they consume output tokens)
    IF NEW.role != 'assistant' THEN
        RETURN NEW;
    END IF;

    SELECT t.plan,
           (t.settings->>'monthly_output_token_limit')::bigint
    INTO v_plan, v_limit
    FROM ai.tenants t
    JOIN ai.conversations c ON c.tenant_id = t.tenant_id
    WHERE c.conversation_id = NEW.conversation_id;

    IF v_limit IS NULL THEN
        RETURN NEW;  -- no limit configured
    END IF;

    SELECT SUM((usage->>'output_tokens')::int)
    INTO v_used
    FROM ai.messages m
    JOIN ai.conversations c ON c.conversation_id = m.conversation_id
    WHERE c.tenant_id = (
        SELECT tenant_id FROM ai.conversations WHERE conversation_id = NEW.conversation_id
    )
    AND m.created_at >= DATE_TRUNC('month', NOW())
    AND m.role = 'assistant';

    IF COALESCE(v_used, 0) + COALESCE((NEW.usage->>'output_tokens')::int, 0) > v_limit THEN
        RAISE EXCEPTION 'monthly_token_budget_exceeded'
            USING DETAIL = format('Tenant has used %s of %s output tokens this month', v_used, v_limit);
    END IF;

    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_token_budget
    BEFORE INSERT ON ai.messages
    FOR EACH ROW EXECUTE FUNCTION ai.check_token_budget();

    The exception propagates back through SQLAlchemy as an IntegrityError, which the API layer catches and converts to an HTTP 402 response.

    40.11 The Complete Picture

    Step back and look at the data flows in this architecture:

    1. A user sends a message. The API authenticates the token from Redis, sets the RLS context in PostgreSQL, and calls ChatService.

    2. The user message is persisted first. Before any LLM call, the message is in the database. If the API crashes here, nothing is lost except the response.

    3. Context is assembled. The query is embedded (with Redis caching), vector search runs against the HNSW index on the read replica, and the last N messages are fetched from the conversation history.

    4. The LLM is called. System prompt includes retrieved chunks and a rolling summary. The call streams tokens back to the client via SSE.

    5. The assistant message is persisted. Chunk citations, token usage, latency, and finish reason are all written atomically. The conversation's token counter is updated by a trigger.

    6. The audit event is written. An asynchronous task (or a trigger on ai.messages) writes to audit.events, which lands in the correct monthly partition.

    7. Metrics are scraped. The Prometheus exporter reads the operational views every 60 seconds. Grafana dashboards show retrieval quality trends, error rates, and per-tenant token spend.

    Documents travel a parallel path:

    1. A document arrives at the ingest endpoint. A row is inserted into ai.documents with status = 'pending', and a job is created in ops.ingestion_jobs.

    2. The Celery worker picks up the job. It reads the raw content, chunks it, calls the OpenAI embeddings API in batches, and bulk-inserts chunks with their vectors.

    3. The document transitions to ready. Retrieval queries immediately see the new chunks via the HNSW index.

    PostgreSQL is present at every step — not as a passive store, but as an active participant: enforcing tenant isolation through RLS, enforcing token budgets through triggers, routing queries through the right partitions, and serving as the single authoritative record of everything that happened.

    That is the payoff of treating your database as the central nervous system rather than a peripheral.

    Key Takeaways

  • → **PostgreSQL can serve as the complete state layer for a production AI application** — conversations, embeddings, tool registry, audit logs, and operational metrics all coexist in a single schema with enforced relationships and access control, eliminating the coordination overhead of a distributed polyglot architecture.
  • → **Row-level security combined with session-scoped configuration variables is the correct mechanism for tenant isolation** — it enforces access control at the query executor rather than at the application boundary, so a bug in the API layer cannot leak cross-tenant data.
  • → **Every LLM call should be bookended by database writes** — persisting the user message before the LLM call and the assistant message immediately after the stream completes ensures that no interaction is lost to crashes, and creates a complete, queryable record of all AI-generated content in the system.
  • → **The HNSW index on `document_chunks` is the performance-critical path** — it should be sized with `m` and `ef_construction` appropriate to the corpus, rebuilt with `REINDEX CONCURRENTLY` after bulk ingestion, and served from a read replica to keep vector search latency off the write primary.
  • → **Failure recovery must be designed in, not retrofitted** — the most common failure modes in AI applications (stream interruption, embedding model drift, partition gaps, and connection pool exhaustion) each have specific PostgreSQL-level diagnostics and recovery procedures that can be codified into runbooks before the first production incident.
