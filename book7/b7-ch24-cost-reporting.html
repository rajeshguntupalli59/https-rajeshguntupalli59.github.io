Chapter 24: Per-Team, Per-App, Per-Feature Cost Reporting

Organizations that implement granular cost reporting—breaking cloud database spend down to the team, application, and feature level—consistently identify 20–35% in previously invisible waste within the first 90 days. The mechanism is straightforward: when a team can see that their recommendation engine's nightly batch job costs $4,200/month while the feature drives less than $800/month in attributed revenue, the conversation about optimization practically has itself. This chapter covers how to build that attribution layer from scratch across AWS RDS, Azure SQL, and Google Cloud SQL, including the tagging taxonomy, the cost allocation queries, the dashboard pipelines, and the automated weekly reports that land in engineering leads' inboxes without anyone having to run a manual export.

---

24.1 Building a Tagging Taxonomy That Actually Works

The failure mode for most tagging initiatives is starting with too many tags and enforcing none of them. Production environments end up with 40% of resources untagged, and the cost attribution reports are immediately discredited because the numbers don't add up.

A workable minimum taxonomy for database cost attribution uses exactly five tags:

| Tag Key | Example Values | Purpose |

|---|---|---|

| team | payments, ml-platform, core-api | Charge back to engineering team |

| app | checkout-service, fraud-detector | Charge back to application |

| environment | prod, staging, dev | Separate production from non-production spend |

| feature | recommendations, search, auth | Feature-level attribution |

| cost-center | cc-1042, cc-2017 | Finance system integration |

The feature tag is optional for initial rollout. Add it when teams are ready to instrument individual workloads. Forcing feature-level tagging prematurely creates inconsistent data that undermines trust in the entire system.

Enforcing tags at resource creation is non-negotiable. Resources that exist without tags accumulate cost in an unattributed bucket that grows until someone gets angry about it in a budget review.

# AWS: Enforce required tags using an SCP at the organization level
# Save as enforce-db-tags-scp.json and attach to target OUs

cat > enforce-db-tags-scp.json << 'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyRDSWithoutRequiredTags",
      "Effect": "Deny",
      "Action": [
        "rds:CreateDBInstance",
        "rds:CreateDBCluster",
        "rds:CreateDBInstanceReadReplica"
      ],
      "Resource": "*",
      "Condition": {
        "Null": {
          "aws:RequestTag/team": "true"
        }
      }
    },
    {
      "Sid": "DenyRDSWithoutAppTag",
      "Effect": "Deny",
      "Action": [
        "rds:CreateDBInstance",
        "rds:CreateDBCluster"
      ],
      "Resource": "*",
      "Condition": {
        "Null": {
          "aws:RequestTag/app": "true"
        }
      }
    }
  ]
}
EOF

# Apply the SCP to an OU (requires AWS Organizations admin)
aws organizations create-policy \
  --name "RequireDBTags" \
  --description "Deny RDS creation without required cost tags" \
  --content file://enforce-db-tags-scp.json \
  --type SERVICE_CONTROL_POLICY

# Tag an existing RDS instance that is missing tags
aws rds add-tags-to-resource \
  --resource-name arn:aws:rds:us-east-1:123456789012:db:prod-payments-pg \
  --tags \
    Key=team,Value=payments \
    Key=app,Value=checkout-service \
    Key=environment,Value=prod \
    Key=cost-center,Value=cc-1042

# Audit: find all RDS instances missing the 'team' tag
aws resourcegroupstaggingapi get-resources \
  --resource-type-filters rds:db \
  --tag-filters Key=team \
  --query 'ResourceTagMappingList[?Tags[?Key==`team`] == `[]`].ResourceARN' \
  --output text

For Azure, Policy definitions enforce tags at the resource group or subscription level:

# Azure: Create a policy that requires the 'team' tag on SQL databases
az policy definition create \
  --name "require-team-tag-sql" \
  --display-name "Require team tag on Azure SQL databases" \
  --description "Denies creation of Azure SQL resources without a team tag" \
  --rules '{
    "if": {
      "allOf": [
        {
          "field": "type",
          "equals": "Microsoft.Sql/servers/databases"
        },
        {
          "field": "tags[team]",
          "exists": "false"
        }
      ]
    },
    "then": {
      "effect": "deny"
    }
  }' \
  --mode All

# Assign the policy to a subscription
az policy assignment create \
  --name "require-team-tag-sql-assignment" \
  --policy "require-team-tag-sql" \
  --scope "/subscriptions/YOUR_SUBSCRIPTION_ID"

# Tag an existing Azure SQL database
az sql db update \
  --resource-group prod-rg \
  --server prod-sql-server \
  --name payments-db \
  --set tags.team=payments tags.app=checkout-service tags.environment=prod

For GCP, labels on Cloud SQL instances serve the same function, and Organization Policy can enforce label requirements:

# GCP: Add labels to an existing Cloud SQL instance
gcloud sql instances patch prod-payments-pg \
  --update-labels=team=payments,app=checkout-service,environment=prod,cost-center=cc-1042

# List Cloud SQL instances missing the 'team' label
gcloud sql instances list \
  --filter="NOT labels.team:*" \
  --format="table(name,region,databaseVersion,settings.tier)"

Handling the untagged backlog is a common stumbling block. The pragmatic approach is to run a quarterly tagging sprint. Pull all untagged resources, assign them to account owners based on VPC or subnet membership, and have those owners tag within 30 days or face a chargeback to a shared pool. The shared pool penalty is the behavioral incentive that makes the tagging sprint work.

24.2 Extracting Per-Team Cost Data from Each Cloud Provider

Once tags are in place, the next step is extracting cost data in a form that can be joined, aggregated, and reported. Each cloud provider exposes this differently, and the approach that works across all three is to land the data in a common schema in your data warehouse or an S3/GCS/Azure Blob bucket.

AWS Cost Explorer with Tag Filtering

#!/usr/bin/env python3
"""
Pull per-team RDS costs from AWS Cost Explorer and write to a PostgreSQL
reporting database. Designed to run on a weekly schedule via Lambda or cron.

Requirements: boto3, psycopg2-binary, python-dateutil
"""

import boto3
import psycopg2
import json
from datetime import datetime, timedelta
from dateutil.relativedelta import relativedelta
import logging

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

# Configuration
REPORTING_DB_CONN = "host=reporting-db.internal dbname=finops user=finops_writer password=REPLACE"
AWS_ACCOUNT_ID = "123456789012"
REGION = "us-east-1"

def get_rds_costs_by_team(start_date: str, end_date: str) -> list[dict]:
    """
    Query Cost Explorer for RDS costs grouped by team tag.
    Returns list of dicts with team, service, cost, and usage_type.
    """
    client = boto3.client("ce", region_name="us-east-1")
    
    response = client.get_cost_and_usage(
        TimePeriod={
            "Start": start_date,
            "End": end_date
        },
        Granularity="MONTHLY",
        Filter={
            "And": [
                {
                    "Dimensions": {
                        "Key": "SERVICE",
                        "Values": [
                            "Amazon Relational Database Service",
                            "Amazon Aurora"
                        ]
                    }
                },
                {
                    "Not": {
                        "Dimensions": {
                            "Key": "RECORD_TYPE",
                            "Values": ["Credit", "Refund"]
                        }
                    }
                }
            ]
        },
        GroupBy=[
            {"Type": "TAG", "Key": "team"},
            {"Type": "TAG", "Key": "app"},
            {"Type": "DIMENSION", "Key": "USAGE_TYPE"}
        ],
        Metrics=["UnblendedCost", "UsageQuantity"]
    )
    
    results = []
    for time_period in response["ResultsByTime"]:
        period_start = time_period["TimePeriod"]["Start"]
        for group in time_period["Groups"]:
            keys = group["Keys"]
            # Keys order: team tag, app tag, usage_type
            team_raw = keys[0] if len(keys) > 0 else ""
            app_raw = keys[1] if len(keys) > 1 else ""
            usage_type = keys[2] if len(keys) > 2 else ""
            
            # Strip the tag key prefix that Cost Explorer adds
            team = team_raw.replace("team$", "") or "untagged"
            app = app_raw.replace("app$", "") or "untagged"
            
            cost = float(group["Metrics"]["UnblendedCost"]["Amount"])
            usage = float(group["Metrics"]["UsageQuantity"]["Amount"])
            unit = group["Metrics"]["UsageQuantity"]["Unit"]
            
            if cost > 0:
                results.append({
                    "period_start": period_start,
                    "team": team,
                    "app": app,
                    "usage_type": usage_type,
                    "cost_usd": round(cost, 4),
                    "usage_quantity": round(usage, 4),
                    "usage_unit": unit,
                    "account_id": AWS_ACCOUNT_ID,
                    "extracted_at": datetime.utcnow().isoformat()
                })
    
    logger.info(f"Extracted {len(results)} cost records for period {start_date} to {end_date}")
    return results


def get_rds_costs_by_feature(start_date: str, end_date: str) -> list[dict]:
    """
    Query Cost Explorer for RDS costs grouped by feature tag.
    Use this for feature-level attribution where teams have instrumented
    their workloads with the 'feature' tag.
    """
    client = boto3.client("ce", region_name="us-east-1")
    
    response = client.get_cost_and_usage(
        TimePeriod={"Start": start_date, "End": end_date},
        Granularity="MONTHLY",
        Filter={
            "Dimensions": {
                "Key": "SERVICE",
                "Values": ["Amazon Relational Database Service", "Amazon Aurora"]
            }
        },
        GroupBy=[
            {"Type": "TAG", "Key": "team"},
            {"Type": "TAG", "Key": "feature"},
        ],
        Metrics=["UnblendedCost"]
    )
    
    results = []
    for time_period in response["ResultsByTime"]:
        period_start = time_period["TimePeriod"]["Start"]
        for group in time_period["Groups"]:
            keys = group["Keys"]
            team = keys[0].replace("team$", "") or "untagged"
            feature = keys[1].replace("feature$", "") or "untagged"
            cost = float(group["Metrics"]["UnblendedCost"]["Amount"])
            
            if cost > 0:
                results.append({
                    "period_start": period_start,
                    "team": team,
                    "feature": feature,
                    "cost_usd": round(cost, 4),
                    "account_id": AWS_ACCOUNT_ID
                })
    
    return results


def upsert_team_costs(records: list[dict]) -> None:
    """Write team cost records to the reporting database."""
    if not records:
        logger.warning("No records to write")
        return
    
    conn = psycopg2.connect(REPORTING_DB_CONN)
    cur = conn.cursor()
    
    # Ensure the table exists
    cur.execute("""
        CREATE TABLE IF NOT EXISTS db_team_costs (
            id SERIAL PRIMARY KEY,
            period_start DATE NOT NULL,
            team TEXT NOT NULL,
            app TEXT NOT NULL,
            usage_type TEXT NOT NULL,
            cost_usd NUMERIC(12,4) NOT NULL,
            usage_quantity NUMERIC(16,4),
            usage_unit TEXT,
            account_id TEXT,
            extracted_at TIMESTAMPTZ DEFAULT NOW(),
            UNIQUE (period_start, team, app, usage_type, account_id)
        )
    """)
    
    upsert_sql = """
        INSERT INTO db_team_costs 
            (period_start, team, app, usage_type, cost_usd, usage_quantity, usage_unit, account_id, extracted_at)
        VALUES 
            (%(period_start)s, %(team)s, %(app)s, %(usage_type)s, %(cost_usd)s,
             %(usage_quantity)s, %(usage_unit)s, %(account_id)s, %(extracted_at)s)
        ON CONFLICT (period_start, team, app, usage_type, account_id)
        DO UPDATE SET
            cost_usd = EXCLUDED.cost_usd,
            usage_quantity = EXCLUDED.usage_quantity,
            extracted_at = EXCLUDED.extracted_at
    """
    
    cur.executemany(upsert_sql, records)
    conn.commit()
    cur.close()
    conn.close()
    logger.info(f"Upserted {len(records)} records into db_team_costs")


if __name__ == "__main__":
    # Pull the previous full month
    today = datetime.today()
    first_of_this_month = today.replace(day=1)
    first_of_last_month = first_of_this_month - relativedelta(months=1)
    
    start = first_of_last_month.strftime("%Y-%m-%d")
    end = first_of_this_month.strftime("%Y-%m-%d")
    
    logger.info(f"Pulling RDS costs from {start} to {end}")
    
    team_records = get_rds_costs_by_team(start, end)
    upsert_team_costs(team_records)
    
    feature_records = get_rds_costs_by_feature(start, end)
    # Feature costs go into a separate table with the same pattern
    logger.info(f"Feature-level records: {len(feature_records)}")

Azure Cost Management per-team extraction:

# Pull Azure SQL costs grouped by team tag for the previous month
# Requires az billing or az costmanagement access

START_DATE=$(date -d "$(date +%Y-%m-01) -1 month" +%Y-%m-01)
END_DATE=$(date +%Y-%m-01)

az costmanagement query \
  --scope "/subscriptions/YOUR_SUBSCRIPTION_ID" \
  --type Usage \
  --timeframe Custom \
  --time-period start="$START_DATE" end="$END_DATE" \
  --dataset-configuration columns='["Cost","UsageQuantity","ResourceType","Tags"]' \
  --dataset-filter '{
    "and": [
      {
        "dimensions": {
          "name": "ResourceType",
          "operator": "In",
          "values": [
            "microsoft.sql/servers/databases",
            "microsoft.sql/managedinstances",
            "microsoft.dbforpostgresql/flexibleservers"
          ]
        }
      }
    ]
  }' \
  --dataset-grouping \
    name=team type=TagKey \
    name=app type=TagKey \
    name=ResourceType type=Dimension \
  --output json > azure_sql_costs_by_team.json

# Parse and summarize by team
cat azure_sql_costs_by_team.json | python3 -c "
import json, sys
data = json.load(sys.stdin)
rows = data.get('properties', {}).get('rows', [])
cols = data.get('properties', {}).get('columns', [])
col_names = [c['name'] for c in cols]
print(','.join(col_names))
for row in rows:
    print(','.join(str(x) for x in row))
" | sort -t',' -k1,1 -k3,3n -r | head -50

# GCP: Pull Cloud SQL costs from the billing export in BigQuery
# (Assumes billing export is configured to a BigQuery dataset)
bq query --use_legacy_sql=false --format=csv '
SELECT
  SUBSTR(usage_start_time, 1, 7) AS month,
  labels.value AS team,
  SUM(cost) AS total_cost_usd,
  SUM(usage.amount) AS total_usage,
  usage.unit
FROM `YOUR_PROJECT.billing_export.gcp_billing_export_v1_XXXXXX`
  , UNNEST(labels) AS labels
WHERE
  service.description LIKE "%Cloud SQL%"
  AND labels.key = "team"
  AND usage_start_time >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 90 DAY)
GROUP BY 1, 2, 4, 5
ORDER BY 1 DESC, 3 DESC
' > gcp_cloudsql_by_team.csv

echo "GCP Cloud SQL costs exported to gcp_cloudsql_by_team.csv"

24.3 Database-Level Attribution with pg_stat_statements

Tags cover the infrastructure cost—instance hours, storage, I/O. But they cannot tell you which feature's queries are consuming 60% of your Aurora cluster's CPU. For that, you need query-level attribution using pg_stat_statements on PostgreSQL, or sys.dm_exec_query_stats on SQL Server. This is the layer that connects infrastructure cost to application behavior.

The pattern is to add a comment to every query at the application layer that embeds team and feature metadata. Query planners ignore SQL comments, but pg_stat_statements captures them, so they appear in the query column and can be parsed out.

Application code wraps queries like this:

-- Pattern: prefix queries with a structured comment
-- /* app:checkout-service team:payments feature:cart-totals */
SELECT p.product_id, p.price, i.quantity
FROM products p
JOIN inventory i ON p.product_id = i.product_id
/* app:checkout-service team:payments feature:cart-totals */
WHERE p.product_id = ANY($1);
