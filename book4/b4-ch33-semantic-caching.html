Chapter 33: Semantic Caching for LLM Applications

LLM API calls are expensive, slow, and deterministic enough that many questions asked of a system are semantically equivalent even when worded differently. A user asking "What's the refund policy?" and another asking "How do I get my money back?" want the same answer. Conventional caching based on exact string matching would treat these as cache misses. Semantic caching uses vector similarity to recognize that two queries mean roughly the same thing and return a cached response—cutting latency from seconds to milliseconds and reducing token costs by 40–80% in production workloads with high query repetition. This chapter covers how semantic caches work, how to build one with pgvector and Redis, how to integrate caching into LangChain and LlamaIndex pipelines, and how to operate a semantic cache in production without sacrificing answer quality.

---

33.1 How Semantic Caching Differs from Conventional Caching

Traditional application caches operate on exact key matching. You hash the input, look up the hash, return the value if it exists. This works well when inputs are programmatically generated and predictable—SQL query strings, API endpoint parameters, serialized data structures. It fails completely for natural language, where the same information need generates an infinite variety of phrasings.

Semantic caching replaces the hash lookup with a vector similarity search. The cache stores (embedding, response) pairs. When a new query arrives, you embed it, search the cache for the nearest stored embedding, and if the similarity exceeds a threshold, return the cached response rather than hitting the LLM. The similarity threshold is the most operationally significant parameter in the entire system.

*The similarity threshold at the decision point is the single most consequential tuning parameter — too low and wrong answers get served with confidence, too high and the cache never fires.*

The threshold problem in database terms

Think of the similarity threshold like a fuzzy match tolerance in a string similarity join. Set similarity_threshold = 1.0 and you effectively get exact matching—nothing hits the cache. Set it to 0.7 and you start returning cached responses to queries that are topically related but semantically distinct. A question about "returning a defective product" and "canceling a subscription" might both score 0.75 cosine similarity against a cached refund policy answer, but they need different responses.

In production systems, threshold tuning requires:

  • → A labeled evaluation set of query pairs tagged as "same intent" or "different intent"
  • → Precision/recall measurement against that set at multiple thresholds
  • → Separate thresholds per query domain (customer support vs. code generation vs. data lookup)

    • Typical production thresholds by domain:

    | Domain | Threshold (cosine) | Rationale |

    |---|---|---|

    | FAQ / support | 0.92–0.95 | High repetition, controlled vocabulary |

    | Code generation | 0.97–0.99 | Small semantic changes produce different code |

    | Document Q&A | 0.93–0.96 | User intent more variable |

    | Data lookup / SQL gen | 0.96–0.99 | Precision required |

    Cache invalidation

    Semantic caches share the same invalidation challenges as conventional caches, plus a new one: a cached response may become stale not because the query changed but because the underlying data or policy changed. A refund policy answer cached in January may be wrong after a February policy update. You need TTL-based expiration and event-driven invalidation tied to source document updates, just as you would in any read-through cache architecture.

    33.2 Building a Semantic Cache with pgvector

    PostgreSQL with pgvector is a natural fit for a semantic cache if your application is already running on Postgres. You avoid introducing a new infrastructure component, benefit from transactional consistency, and can use standard SQL for cache management queries.

    Schema design

    -- PostgreSQL / pgvector

CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE semantic_cache (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    query_text      TEXT NOT NULL,
    query_embedding VECTOR(1536) NOT NULL,
    response_text   TEXT NOT NULL,
    model           TEXT NOT NULL DEFAULT 'gpt-4o',
    namespace       TEXT NOT NULL DEFAULT 'default',
    hit_count       INTEGER NOT NULL DEFAULT 0,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_accessed   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at      TIMESTAMPTZ,
    metadata        JSONB
);

-- HNSW index for fast ANN lookup
-- ef_construction=128, m=16 are reasonable defaults for a cache
-- that may grow to millions of entries
CREATE INDEX idx_semantic_cache_embedding
    ON semantic_cache
    USING hnsw (query_embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 128);

-- Namespace + expiry index for cache management
CREATE INDEX idx_semantic_cache_namespace_expires
    ON semantic_cache (namespace, expires_at)
    WHERE expires_at IS NOT NULL;

-- Function to look up cache and update hit count atomically
CREATE OR REPLACE FUNCTION semantic_cache_lookup(
    p_embedding     VECTOR(1536),
    p_namespace     TEXT,
    p_threshold     FLOAT DEFAULT 0.93,
    p_limit         INT DEFAULT 1
)
RETURNS TABLE (
    id              UUID,
    query_text      TEXT,
    response_text   TEXT,
    similarity      FLOAT
)
LANGUAGE SQL
AS $$
    UPDATE semantic_cache sc
    SET
        hit_count    = hit_count + 1,
        last_accessed = NOW()
    FROM (
        SELECT
            c.id,
            c.query_text,
            c.response_text,
            1 - (c.query_embedding <=> p_embedding) AS similarity
        FROM semantic_cache c
        WHERE
            c.namespace = p_namespace
            AND (c.expires_at IS NULL OR c.expires_at > NOW())
            AND 1 - (c.query_embedding <=> p_embedding) >= p_threshold
        ORDER BY c.query_embedding <=> p_embedding
        LIMIT p_limit
    ) ranked
    WHERE sc.id = ranked.id
    RETURNING sc.id, sc.query_text, sc.response_text, ranked.similarity;
$$;

-- Purge expired entries (run on a schedule)
CREATE OR REPLACE FUNCTION purge_expired_cache(p_namespace TEXT DEFAULT NULL)
RETURNS INTEGER
LANGUAGE plpgsql
AS $$
DECLARE
    v_deleted INTEGER;
BEGIN
    DELETE FROM semantic_cache
    WHERE expires_at < NOW()
      AND (p_namespace IS NULL OR namespace = p_namespace);
    GET DIAGNOSTICS v_deleted = ROW_COUNT;
    RETURN v_deleted;
END;
$$;

    Python client wrapping the pgvector cache

    # Python
import hashlib
import asyncio
import psycopg
import numpy as np
from openai import AsyncOpenAI
from datetime import datetime, timedelta, timezone
from typing import Optional

# pip install openai psycopg[binary] numpy

class PgvectorSemanticCache:
    """
    Semantic cache backed by pgvector.
    Drop-in wrapper around any LLM call function.
    """

    def __init__(
        self,
        dsn: str,
        openai_client: AsyncOpenAI,
        namespace: str = "default",
        threshold: float = 0.93,
        ttl_seconds: int = 86400,  # 24 hours
        embedding_model: str = "text-embedding-3-small",
    ):
        self.dsn = dsn
        self.oai = openai_client
        self.namespace = namespace
        self.threshold = threshold
        self.ttl_seconds = ttl_seconds
        self.embedding_model = embedding_model
        self._pool: Optional[psycopg.AsyncConnection] = None

    async def _get_conn(self) -> psycopg.AsyncConnection:
        if self._pool is None:
            self._pool = await psycopg.AsyncConnection.connect(self.dsn)
        return self._pool

    async def embed(self, text: str) -> list[float]:
        response = await self.oai.embeddings.create(
            model=self.embedding_model,
            input=text,
        )
        return response.data[0].embedding

    async def get(self, query: str) -> Optional[dict]:
        embedding = await self.embed(query)
        embedding_str = "[" + ",".join(str(x) for x in embedding) + "]"

        conn = await self._get_conn()
        async with conn.cursor() as cur:
            await cur.execute(
                """
                SELECT id, query_text, response_text, similarity
                FROM semantic_cache_lookup(
                    %s::vector,
                    %s,
                    %s,
                    1
                )
                """,
                (embedding_str, self.namespace, self.threshold),
            )
            row = await cur.fetchone()
            if row:
                return {
                    "id": str(row[0]),
                    "cached_query": row[1],
                    "response": row[2],
                    "similarity": float(row[3]),
                    "cache_hit": True,
                }
        return None

    async def set(
        self,
        query: str,
        response: str,
        model: str = "gpt-4o",
        metadata: Optional[dict] = None,
    ) -> str:
        embedding = await self.embed(query)
        embedding_str = "[" + ",".join(str(x) for x in embedding) + "]"
        expires_at = datetime.now(timezone.utc) + timedelta(seconds=self.ttl_seconds)

        conn = await self._get_conn()
        async with conn.cursor() as cur:
            await cur.execute(
                """
                INSERT INTO semantic_cache
                    (query_text, query_embedding, response_text,
                     model, namespace, expires_at, metadata)
                VALUES (%s, %s::vector, %s, %s, %s, %s, %s)
                RETURNING id
                """,
                (
                    query,
                    embedding_str,
                    response,
                    model,
                    self.namespace,
                    expires_at,
                    metadata,
                ),
            )
            result = await cur.fetchone()
            await conn.commit()
            return str(result[0])

    async def get_or_generate(
        self,
        query: str,
        llm_call_fn,
        model: str = "gpt-4o",
    ) -> dict:
        """
        Cache-aside pattern: check cache first, generate and store on miss.
        llm_call_fn: async callable(query) -> str
        """
        cached = await self.get(query)
        if cached:
            return cached

        # Cache miss — call the LLM
        response_text = await llm_call_fn(query)
        entry_id = await self.set(query, response_text, model=model)

        return {
            "id": entry_id,
            "response": response_text,
            "similarity": 1.0,
            "cache_hit": False,
        }


# Usage example
async def main():
    oai = AsyncOpenAI()
    cache = PgvectorSemanticCache(
        dsn="postgresql://app:secret@localhost:5432/llmcache",
        openai_client=oai,
        namespace="customer_support",
        threshold=0.93,
        ttl_seconds=3600 * 24 * 7,  # 7 days
    )

    async def call_llm(query: str) -> str:
        response = await oai.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": query}],
        )
        return response.choices[0].message.content

    # First call — cache miss, LLM invoked
    result1 = await cache.get_or_generate(
        "What is your return policy for electronics?",
        call_llm,
    )
    print(f"Cache hit: {result1['cache_hit']}, similarity: {result1['similarity']:.4f}")

    # Semantically similar — should hit the cache
    result2 = await cache.get_or_generate(
        "Can I return a laptop I bought last week?",
        call_llm,
    )
    print(f"Cache hit: {result2['cache_hit']}, similarity: {result2['similarity']:.4f}")


asyncio.run(main())

    33.3 Semantic Caching with Redis and a Dedicated Vector Store

    For applications that need sub-5ms cache lookups and cannot afford a full Postgres query round-trip, Redis with the RediSearch module (or Redis Stack) provides an in-memory vector cache. The tradeoff is that Redis is bounded by available memory; entries must be kept small or the cache must be tiered.

    An alternative pattern uses a dedicated fast vector store—Qdrant or Chroma—as the semantic index while storing full response text in Redis by ID. The vector store answers "does a similar query exist?" (returning an ID), and Redis retrieves the response body by that ID in a second sub-millisecond lookup.

    # Python
# Tiered semantic cache: Qdrant for similarity search, Redis for response storage
# pip install qdrant-client redis openai sentence-transformers

import json
import uuid
import hashlib
import redis.asyncio as aioredis
from qdrant_client import AsyncQdrantClient
from qdrant_client.models import (
    Distance,
    VectorParams,
    PointStruct,
    Filter,
    FieldCondition,
    MatchValue,
    SearchRequest,
)
from sentence_transformers import SentenceTransformer
from typing import Optional
import asyncio

COLLECTION_NAME = "semantic_cache_index"
EMBEDDING_DIM = 384  # all-MiniLM-L6-v2
CACHE_TTL_SECONDS = 86400


class TieredSemanticCache:
    """
    Qdrant holds the embedding index.
    Redis holds response payloads keyed by cache entry ID.
    Embedding is done locally with sentence-transformers to avoid
    external API latency on cache reads.
    """

    def __init__(
        self,
        qdrant_url: str = "http://localhost:6333",
        redis_url: str = "redis://localhost:6379",
        threshold: float = 0.92,
        namespace: str = "default",
    ):
        self.qdrant = AsyncQdrantClient(url=qdrant_url)
        self.redis_url = redis_url
        self.threshold = threshold
        self.namespace = namespace
        self.encoder = SentenceTransformer("all-MiniLM-L6-v2")
        self._redis: Optional[aioredis.Redis] = None

    async def _get_redis(self) -> aioredis.Redis:
        if self._redis is None:
            self._redis = await aioredis.from_url(self.redis_url, decode_responses=True)
        return self._redis

    async def initialize(self):
        """Create Qdrant collection if it doesn't exist."""
        collections = await self.qdrant.get_collections()
        existing = [c.name for c in collections.collections]
        if COLLECTION_NAME not in existing:
            await self.qdrant.create_collection(
                collection_name=COLLECTION_NAME,
                vectors_config=VectorParams(
                    size=EMBEDDING_DIM,
                    distance=Distance.COSINE,
                ),
            )
            print(f"Created collection: {COLLECTION_NAME}")

    def embed(self, text: str) -> list[float]:
        # SentenceTransformer is synchronous; wrap in thread pool for async use
        vec = self.encoder.encode(text, normalize_embeddings=True)
        return vec.tolist()

    async def get(self, query: str) -> Optional[dict]:
        embedding = self.embed(query)

        results = await self.qdrant.search(
            collection_name=COLLECTION_NAME,
            query_vector=embedding,
            query_filter=Filter(
                must=[
                    FieldCondition(
                        key="namespace",
                        match=MatchValue(value=self.namespace),
                    )
                ]
            ),
            limit=1,
            score_threshold=self.threshold,
        )

        if not results:
            return None

        hit = results[0]
        entry_id = hit.payload["entry_id"]
        similarity = hit.score

        # Fetch response from Redis
        redis = await self._get_redis()
        payload_json = await redis.get(f"scache:{entry_id}")
        if payload_json is None:
            # Redis entry expired but Qdrant entry still exists — treat as miss
            return None

        payload = json.loads(payload_json)
        return {
            "entry_id": entry_id,
            "cached_query": payload["query"],
            "response": payload["response"],
            "model": payload.get("model"),
            "similarity": similarity,
            "cache_hit": True,
        }

    async def set(
        self,
        query: str,
        response: str,
        model: str = "gpt-4o",
        metadata: Optional[dict] = None,
    ) -> str:
        entry_id = str(uuid.uuid4())
        embedding = self.embed(query)

        # Write to Qdrant
        await self.qdrant.upsert(
            collection_name=COLLECTION_NAME,
            points=[
                PointStruct(
                    id=entry_id,
                    vector=embedding,
                    payload={
                        "namespace": self.namespace,
                        "entry_id": entry_id,
                        "query_preview": query[:100],
                    },
                )
            ],
        )

        # Write response to Redis with TTL
        payload = {
            "query": query,
            "response": response,
            "model": model,
            "metadata": metadata or {},
        }
        redis = await self._get_redis()
        await redis.setex(
            f"scache:{entry_id}",
            CACHE_TTL_SECONDS,
            json.dumps(payload),
        )

        return entry_id

    async def invalidate_namespace(self, namespace: str):
        """Delete all cache entries for a namespace from Qdrant."""
        await self.qdrant.delete(
            collection_name=COLLECTION_NAME,
            points_selector=Filter(
                must=[
                    FieldCondition(
                        key="namespace",
                        match=MatchValue(value=namespace),
                    )
                ]
            ),
        )


# Benchmark: measure cache hit latency vs LLM latency
async def benchmark():
    import time

    cache = TieredSemanticCache(threshold=0.90, namespace="demo")
    await cache.initialize()

    test_query = "Explain the difference between OLTP and OLAP databases."

    # Warm the cache with a synthetic response
    await cache.set(
        query=test_query,
        response="OLTP systems handle high-volume transactional workloads...",
        model="gpt-4o",
    )

    # Measure lookup latency
    queries = [
        "What is the difference between OLTP and OLAP?",
        "OLAP vs OLTP — what should I know?",
        "How are transactional and analytical databases different?",
    ]

    for q in queries:
        t0 = time.perf_counter()
        result = await cache.get(q)
        elapsed_ms = (time.perf_counter() - t0) * 1000
        hit = result is not None
        sim = result["similarity"] if result else 0.0
        print(f"[{elapsed_ms:5.1f}ms] hit={hit} sim={sim:.4f} | {q[:60]}")


asyncio.run(benchmark())

    Typical latency profile for this tiered design on local hardware:

  • → Embedding (MiniLM, CPU): 3–8ms
  • → Qdrant ANN search (in-memory, 100K entries): 0.5–2ms
  • → Redis GET: 0.2–0.5ms
  • → **Total cache hit latency: 4–12ms**
  • → GPT-4o API call: 800ms–4000ms

    • The 100x latency reduction justifies the operational complexity for high-traffic applications.

    LlamaIndex with a custom semantic cache node postprocessor

    # Python
# LlamaIndex: semantic cache as a query-level postprocessor
# This pattern caches full RAG query results, not just LLM calls
# pip install llama-index llama-index-vector-stores-qdrant openai

import time
import hashlib
from typing import Optional, List
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader, Settings
from llama_index.core.schema import NodeWithScore, QueryBundle
from llama_index.core.postprocessor.types import BaseNodePostprocessor
from llama_index.embeddings.openai import OpenAIEmbedding
from llama_index.llms.openai import OpenAI

# --- Simple in-process semantic cache for RAG responses ---
# In production, replace the dict store with pgvector or Qdrant

class RAGSemanticCache:
    """
    Caches full (query -> RAG response) pairs using embedding similarity.
    Stored in-memory here; swap _store for a persistent backend.
    """

    def __init__(
        self,
        embedding_model: OpenAIEmbedding,
        threshold: float = 0.94,
    ):
        self.embedder = embedding_model
        self.threshold = threshold
        # List of (embedding: list[float], response: str)
        self._store: list[tuple[list[float], str, str]] = []  # (embedding, query, response)

    def _cosine_similarity(self, a: list[float], b: list[float]) -> float:
        import math
        dot = sum(x * y for x, y in zip(a, b))
        norm_a = math.sqrt(sum(x * x for x in a))
        norm_b = math.sqrt(sum(x * x for x in b))
        if norm_a == 0 or norm_b == 0:
            return 0.0
        return dot / (norm_a * norm_b)

    async def get(self, query: str) -> Optional[dict]:
        embedding = await self.embedder.aget_text_embedding(query)
        best_sim = 0.0
        best_entry = None
        for stored_emb, stored_query, stored_response in self._store:
            sim = self._cosine_similarity(embedding, stored_emb)
            if sim > best_sim:
                best_sim = sim
                best_entry = (stored_query, stored_response)
        if best_entry and best_sim >= self.threshold:
            return {
                "cached_query": best_entry[0],
                "response": best_entry[1],
                "similarity": best_sim,
                "cache_hit": True,
            }
        return None

    async def set(self, query: str, response: str) -> None:
        embedding = await self.embedder.aget_text_embedding(query)
        self._store.append((embedding, query, response))


class SemanticCachedQueryEngine:
    """
    Wraps a LlamaIndex query engine with a semantic response cache.
    On cache hit, returns the cached response without touching the index.
    """

    def __init__(self, query_engine, cache: RAGSemanticCache):
        self.engine = query_engine
        self.cache = cache
        self.stats = {"hits": 0, "misses": 0}

    async def aquery(self, query_str: str) -> dict:
        # Check cache
        cached = await self.cache.get(query_str)
        if cached:
            self.stats["hits"] += 1
            return {
                "response": cached["response"],
                "cache_hit": True,
                "similarity": cached["similarity"],
                "cached_query": cached["cached_query"],
            }

        # Cache miss — run the full RAG pipeline
        self.stats["misses"] += 1
        t0 = time.perf_counter()
        rag_response = await self.engine.aquery(query_str)
        elapsed_ms = (time.perf_counter() - t0) * 1000
        response_text = str(rag_response)

        # Store in cache
        await self.cache.set(query_str, response_text)

        return {
            "response": response_text,
            "cache_hit": False,
            "rag_latency_ms": elapsed_ms,
        }

    def query(self, query_str: str) -> dict:
        import asyncio
        return asyncio.get_event_loop().run_until_complete(self.aquery(query_str))


# Wire it together
async def build_cached_rag_engine(docs_path: str):
    embed_model = OpenAIEmbedding(model="text-embedding-3-small")
    llm = OpenAI(model="gpt-4o", temperature=0)

    Settings.embed_model = embed_model
    Settings.llm = llm

    documents = SimpleDirectoryReader(docs_path).load_data()
    index = VectorStoreIndex.from_documents(documents)
    base_engine = index.as_query_engine(similarity_top_k=4)

    cache = RAGSemanticCache(embedding_model=embed_model, threshold=0.94)
    cached_engine = SemanticCachedQueryEngine(base_engine, cache)
    return cached_engine

    The right level to cache in a RAG pipeline

    A common design question: should the semantic cache sit in front of the LLM call, or in front of the entire RAG pipeline (retrieval + LLM)?

    | Cache placement | What is cached | When to use |

    |---|---|---|

    | LLM-only | LLM response for a given prompt (including retrieved context) | High prompt repetition, stable retrieval |

    | Full RAG (query → response) | Complete answer for a user query | When retrieval is also expensive (large corpus, many chunks) |

    | Retrieval-only | Retrieved document chunks for a query | Stable corpora, expensive vector search at scale |

    For most production systems, caching at the full RAG level (query → final answer) offers the best latency savings, since retrieval and LLM inference are both bypassed. The tradeoff is that the cached answer reflects the document state at the time of the original query—if documents are updated frequently, TTLs must be set accordingly.

    33.5 Cache Hit Rate Optimization

    A semantic cache delivering a 20% hit rate is nearly useless. To reach the 50–80% hit rates that justify the infrastructure, you need deliberate optimization across four levers: query normalization, namespace segmentation, embedding model selection, and threshold tuning.

    Query normalization before embedding

    Small textual differences that don't affect meaning can scatter embeddings unnecessarily. Normalizing queries before embedding pushes semantically equivalent questions closer together in embedding space.

    # Python
import re
import unicodedata

def normalize_query(text: str) -> str:
    """
    Normalize a user query before embedding for cache lookup.
    Reduces unnecessary cache misses from surface-form variation.
    """
    # Unicode normalize (handles fancy quotes, diacritics in English queries)
    text = unicodedata.normalize("NFKC", text)

    # Lowercase
    text = text.lower()

    # Collapse whitespace (tabs, newlines, multiple spaces)
    text = re.sub(r"\s+", " ", text).strip()

    # Remove trailing punctuation that doesn't affect meaning
    text = re.sub(r"[?.!,;:]+$", "", text).strip()

    # Expand common contractions
    contractions = {
        "what's": "what is",
        "i'm": "i am",
        "can't": "cannot",
        "don't": "do not",
        "won't": "will not",
        "how's": "how is",
        "it's": "it is",
        "that's": "that is",
        "there's": "there is",
        "i've": "i have",
        "you've": "you have",
        "we've": "we have",
        "i'd": "i would",
        "you'd": "you would",
        "he'd": "he would",
        "she'd": "she would",
    }
    for contraction, expansion in contractions.items():
        text = re.sub(r"\b" + re.escape(contraction) + r"\b", expansion, text)

    return text

    Namespace segmentation

    A single cache namespace mixing product questions, support queries, and code generation requests will produce false positive hits—code generation questions semantically overlapping with English descriptions. Segmenting by namespace (which maps to a Qdrant collection filter or a Postgres WHERE namespace = ... predicate) keeps the search space focused and reduces false positives.

    Threshold sensitivity analysis

    Before deploying to production, run an offline analysis on a sample of logged queries to find the threshold that maximizes F1 score across your labeled evaluation set.

    # Python
# Offline threshold analysis
# Requires: a list of (query_a, query_b, is_same_intent: bool) pairs

import numpy as np
from openai import OpenAI

oai = OpenAI()

def get_embedding(text: str) -> np.ndarray:
    response = oai.embeddings.create(
        model="text-embedding-3-small",
        input=text,
    )
    return np.array(response.data[0].embedding)

def cosine_similarity(a: np.ndarray, b: np.ndarray) -> float:
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b) + 1e-10))

def analyze_thresholds(
    eval_pairs: list[tuple[str, str, bool]],
    thresholds: list[float] = None,
) -> list[dict]:
    if thresholds is None:
        thresholds = [round(t, 2) for t in np.arange(0.80, 1.00, 0.01)]

    # Precompute similarities
    similarities = []
    labels = []
    for q_a, q_b, same_intent in eval_pairs:
        emb_a = get_embedding(q_a)
        emb_b = get_embedding(q_b)
        sim = cosine_similarity(emb_a, emb_b)
        similarities.append(sim)
        labels.append(same_intent)

    similarities = np.array(similarities)
    labels = np.array(labels)

    results = []
    for thresh in thresholds:
        predictions = similarities >= thresh
        tp = int(np.sum(predictions & labels))
        fp = int(np.sum(predictions & ~labels))
        fn = int(np.sum(~predictions & labels))
        tn = int(np.sum(~predictions & ~labels))

        precision = tp / (tp + fp) if (tp + fp) > 0 else 0.0
        recall    = tp / (tp + fn) if (tp + fn) > 0 else 0.0
        f1        = (2 * precision * recall / (precision + recall)
                     if (precision + recall) > 0 else 0.0)

        results.append({
            "threshold": thresh,
            "precision": round(precision, 4),
            "recall":    round(recall, 4),
            "f1":        round(f1, 4),
            "tp": tp, "fp": fp, "fn": fn, "tn": tn,
        })

    # Sort by F1 descending
    results.sort(key=lambda r: r["f1"], reverse=True)
    return results


# Example eval set (in production, source this from human-labeled query logs)
eval_pairs = [

    33.6 Production Operations: Monitoring, Eviction, and Invalidation

    A semantic cache that nobody monitors slowly drifts into a state where stale responses are served confidently. Production operation requires three ongoing concerns: monitoring cache quality, evicting dead weight, and invalidating entries when source data changes.

    Monitoring key metrics

    The following metrics should feed into your observability stack (Prometheus, Datadog, or equivalent):

    | Metric | Description | Alert threshold |

    |---|---|---|

    | cache_hit_rate | Fraction of queries answered from cache | Alert if drops below baseline by >10pp |

    | cache_miss_latency_p99 | P99 latency of LLM calls on cache miss | Baseline × 2 |

    | cache_hit_latency_p99 | P99 latency of cache lookups | >50ms warrants investigation |

    | stale_entry_fraction | Entries past TTL still in index | >5% suggests purge job is lagging |

    | false_positive_rate | Cached responses rated incorrect by users | >2% warrants threshold increase |

    | embedding_error_rate | Embedding API failures | Any sustained failure |

    Tracking false positives with user feedback

    The most dangerous failure mode of a semantic cache is serving a cached answer that is wrong for the new query. Track this with a lightweight thumbs-down signal:

    # Python
# FastAPI endpoint pattern for collecting cache quality feedback
from fastapi import FastAPI, HTTPException

                        COALESCE(metadata, '{}'),

    Event-driven invalidation

    When a source document changes—a policy page is updated, a product spec is revised—cached responses derived from that document should be invalidated. The pattern mirrors how CDN edge caches are purged: a content update event triggers a cache invalidation call.

    # Python
# Cache invalidation triggered by document update events
# Integrates with any event bus (Kafka, SQS, Redis Streams, etc.)

import asyncio
import json
from datetime import timezone, datetime

async def handle_document_updated_event(event: dict, cache: PgvectorSemanticCache):
    """
    Called when a source document is updated.
    Invalidates cached entries that reference that document.
    event = {
        "document_id": "doc_123",
        "namespace": "support",
        "updated_at": "2024-06-01T12:00:00Z",
    }
    """
    doc_id = event["document_id"]
    namespace = event.get("namespace", "default")

    conn = await cache._get_conn()
    async with conn.cursor() as cur:
        # Delete entries in this namespace that reference the document
        # (requires storing document_id in metadata at cache-write time)
        await cur.execute(
            """
            DELETE FROM semantic_cache
            WHERE namespace = %s
              AND metadata->>'source_document_id' = %s
            RETURNING id
            """,
            (namespace, doc_id),
        )
        deleted_ids = await cur.fetchall()
        await conn.commit()

    print(
        f"Invalidated {len(deleted_ids)} cache entries "
        f"for document {doc_id} in namespace {namespace}"
    )
    return [str(row[0]) for row in deleted_ids]


async def handle_namespace_flush_event(event: dict, cache: PgvectorSemanticCache):
    """
    Full namespace flush — used when a large batch of documents is updated,
    making entry-level invalidation impractical.
    """
    namespace = event["namespace"]
    conn = await cache._get_conn()
    async with conn.cursor() as cur:
        await cur.execute(
            "DELETE FROM semantic_cache WHERE namespace = %s RETURNING id",
            (namespace,),
        )
        count = len(await cur.fetchall())
        await conn.commit()
    print(f"Flushed {count} entries from namespace {namespace}")

    Eviction strategies

    Unlike memory-bounded caches like Redis, a Postgres-backed semantic cache grows without bound unless you actively evict entries. Three practical eviction strategies:

    1. TTL-based expiry: Set expires_at at write time and run purge_expired_cache() as a scheduled job (pg_cron or an external scheduler). This is the minimum viable eviction strategy.

    2. LFU eviction on index size: When the table exceeds a row count threshold, delete the N entries with the lowest hit_count that are also older than a minimum age. This keeps high-value entries and removes long-tail entries that never proved useful.

    3. Namespace-scoped budgets: Assign a maximum row count per namespace. When a namespace exceeds its budget, evict the least recently used entries first.

    -- PostgreSQL
-- LFU eviction: remove the bottom 10% of entries by hit count
-- when the table exceeds 500,000 rows

DO $$
DECLARE
    v_total BIGINT;
    v_evict_target BIGINT;
BEGIN
    SELECT COUNT(*) INTO v_total FROM semantic_cache;

    IF v_total > 500000 THEN
        v_evict_target := v_total / 10;  -- evict 10%

        DELETE FROM semantic_cache
        WHERE id IN (
            SELECT id FROM semantic_cache
            WHERE created_at < NOW() - INTERVAL '1 hour'  -- protect very new entries
            ORDER BY hit_count ASC, last_accessed ASC
            LIMIT v_evict_target
        );

        RAISE NOTICE 'Evicted % entries (total was %)', v_evict_target, v_total;
    END IF;
END;
$$;

    33.7 Semantic Caching for Agentic and Multi-Turn Workloads

    Single-turn Q&A is the simplest semantic caching case. Agentic workloads—where an LLM reasons across multiple steps, invokes tools, and maintains conversation state—present two harder problems: what to cache and at what granularity.

    Caching at the tool-call level

    In a ReAct-style agent, the expensive operations are typically not the reasoning steps themselves but tool calls: web searches, database queries, API calls, sub-agent invocations. Caching at the individual tool-call level rather than the full agent trajectory captures most of the value without the staleness risk of caching an entire multi-step reasoning chain.

    # Python
# Tool call semantic cache — wraps any tool function
# Works with LangChain tools, LlamaIndex tools, or custom tool implementations

import functools
import asyncio
from typing import Callable, Any

def semantic_cache_tool(
    cache: PgvectorSemanticCache,
    namespace_prefix: str = "tool",
):
    """
    Decorator that adds semantic caching to any async tool function.
    The tool's input is serialized to a string for embedding.
    """
    def decorator(tool_fn: Callable) -> Callable:
        tool_namespace = f"{namespace_prefix}:{tool_fn.__name__}"

        @functools.wraps(tool_fn)
        async def wrapper(*args, **kwargs) -> Any:
            # Serialize inputs to a canonical query string
            input_repr = f"{tool_fn.__name__}({args!r}, {kwargs!r})"
            # Use a copy of the cache pointed at the tool's namespace
            tool_cache = PgvectorSemanticCache(
                dsn=cache.dsn,
                openai_client=cache.oai,
                namespace=tool_namespace,
                threshold=cache.threshold,
                ttl_seconds=cache.ttl_seconds,
                embedding_model=cache.embedding_model,
            )

            cached = await tool_cache.get(input_repr)
            if cached:
                return cached["response"]

            result = await tool_fn(*args, **kwargs)
            await tool_cache.set(input_repr, str(result))
            return result

        return wrapper
    return decorator


# Usage with a database lookup tool
@semantic_cache_tool(cache=some_cache, namespace_prefix="tool")
async def lookup_customer_account(customer_id: str, fields: list[str]) -> dict:
    """Fetches customer account data from CRM API."""
    # ... actual CRM API call ...
    return {"customer_id": customer_id, "status": "active"}

    Multi-turn conversation caching

    In multi-turn conversations, the relevant semantic unit is not a single utterance but the current question in context. A user asking "What about the return window?" as their third message has a different intent from the same string asked cold. Two strategies handle this:

    1. Context-conditioned embedding: Concatenate the last N turns of conversation history with the current query before embedding. This captures context but reduces cache hit rate (each conversation history is unique).

    2. Semantic intent extraction: Use a fast, cheap LLM call to extract the standalone question from the conversation context ("User is asking: what is the return window for electronics?"), then cache on the extracted standalone question. The extraction step costs a small-model token call but dramatically improves cache reuse.

    # Python
async def extract_standalone_question(
    conversation_history: list[dict],
    current_query: str,
    oai_client,
) -> str:
    """
    Condenses a multi-turn conversation into a standalone question
    suitable for embedding and cache lookup.
    Uses a cheap, fast model for this step.
    """
    if not conversation_history:
        return current_query

    history_text = "\n".join(
        f"{m['role'].capitalize()}: {m['content']}"
        for m in conversation_history[-4:]  # last 4 turns
    )

    prompt = f"""Given the following conversation, rewrite the final user question
as a complete, standalone question that can be understood without the conversation context.
Return only the rewritten question, nothing else.

Conversation:
{history_text}
User: {current_query}

Standalone question:"""

    response = await oai_client.chat.completions.create(
        model="gpt-4o-mini",  # fast, cheap model for extraction
        messages=[{"role": "user", "content": prompt}],
        max_tokens=100,
        temperature=0,
    )
    return response.choices[0].message.content.strip()


async def multi_turn_cached_response(
    conversation_history: list[dict],
    current_query: str,
    cache: PgvectorSemanticCache,
    llm_call_fn,
    oai_client,
) -> dict:
    standalone = await extract_standalone_question(
        conversation_history, current_query, oai_client
    )
    result = await cache.get_or_generate(standalone, llm_call_fn)
    result["standalone_query"] = standalone
    return result

    33.8 Failure Modes and Mitigations

    A semantic cache introduces failure modes that conventional caches do not have. Understanding them prevents subtle production bugs.

    Embedding model version drift

    If the embedding model used to populate the cache differs from the model used at query time—because the model was upgraded—all existing cache entries become unsearchable. Cosine distances computed across model versions are meaningless. Always store the embedding model name with each cache entry and route lookups to only compare against entries produced by the same model. During a model migration, run both models in parallel, rebuild the cache with the new model under a new namespace, and cut over atomically.

    Threshold creep

    Under pressure to improve hit rates, teams lower the threshold incrementally ("0.93 → 0.92 → 0.91…") without re-running precision/recall analysis. By the time false positives appear in user feedback, the threshold has drifted far from the safe operating range. Treat threshold changes as configuration changes requiring offline evaluation before deployment.

    Cold start

    A freshly deployed semantic cache has no entries. Under production traffic, the first N queries are all cache misses, and the cache fills gradually as the LLM handles them. For applications with predictable query distributions, pre-warm the cache at deployment time with the top-K queries from historical logs.

    # Python — cache pre-warming from historical query log
async def prewarm_cache(
    cache: PgvectorSemanticCache,
    historical_queries: list[tuple[str, str]],  # (query, response) pairs
    model: str = "gpt-4o",
    batch_size: int = 50,
) -> int:
    """
    Pre-warm a semantic cache from a list of (query, response) pairs.
    Returns the number of entries written.
    """
    written = 0
    for i in range(0, len(historical_queries), batch_size):
        batch = historical_queries[i : i + batch_size]
        tasks = [
            cache.set(query, response, model=model)
            for query, response in batch
        ]
        await asyncio.gather(*tasks)
        written += len(batch)
        print(f"Pre-warmed {written}/{len(historical_queries)} entries")
    return written

    Cascade failure: embedding API unavailability

    When the embedding API is down, your semantic cache cannot compute embeddings and every request falls through to the LLM. Design the cache as a best-effort layer with a circuit breaker: if embedding calls fail consecutively, bypass the cache entirely rather than letting latency stack up.

    # Python
import time

class CircuitBreaker:
    """
    Simple circuit breaker for embedding API calls.
    Opens after consecutive_failures failures,
    retries after reset_timeout_seconds.
    """
    def __init__(self, consecutive_failures: int = 5, reset_timeout_seconds: float = 60.0):
        self.threshold = consecutive_failures
        self.reset_timeout = reset_timeout_seconds
        self._failures = 0
        self._opened_at: Optional[float] = None

    @property
    def is_open(self) -> bool:
        if self._opened_at is None:
            return False
        if time.monotonic() - self._opened_at > self.reset_timeout:
            # Half-open: allow one probe
            return False
        return True

    def record_success(self):
        self._failures = 0
        self._opened_at = None

    def record_failure(self):
        self._failures += 1
        if self._failures >= self.threshold:
            self._opened_at = time.monotonic()

    async def call(self, fn, *args, **kwargs):
        if self.is_open:
            raise RuntimeError("Circuit breaker open — embedding API unavailable")
        try:
            result = await fn(*args, **kwargs)
            self.record_success()
            return result
        except Exception as exc:
            self.record_failure()
            raise

    Key Takeaways

  • → **Semantic caching replaces exact-match hash lookups with vector similarity search**, allowing applications to serve cached LLM responses to queries that are phrased differently but mean the same thing—achieving latency reductions of two orders of magnitude on cache hits.
  • → **The similarity threshold is the single most operationally significant parameter**: too low and you serve wrong answers with confidence; too high and the cache never hits. Calibrate it with a labeled evaluation set and precision/recall analysis per query domain before deploying.
  • → **Tiered architectures—a fast vector index for similarity lookup combined with a key-value store for response bodies—deliver the best latency profile**, with total cache hit latency typically under 15ms compared to multi-second LLM API calls.
  • → **Production semantic caches require active lifecycle management**: TTL-based expiry, LFU eviction when index size grows, event-driven invalidation when source documents change, and monitoring of false positive rates through user feedback signals.
  • → **Agentic and multi-turn workloads require adapted caching strategies**: cache at the tool-call level rather than the full agent trajectory, and use standalone-question extraction to normalize multi-turn context into cache-friendly canonical query forms before embedding.
