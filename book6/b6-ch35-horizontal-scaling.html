Chapter 35: Horizontal Scaling for AI-Heavy Read Workloads

AI applications have a fundamentally different read profile than traditional web apps. A single RAG query might touch a vector similarity search, a full-text search, several JOIN operations across conversation history, a user preference lookup, and a metadata filter — all before handing results to an LLM that takes 800ms to 3 seconds to respond. Multiply that by hundreds of concurrent users, and your PostgreSQL primary becomes the bottleneck not because it can't store the data, but because it's saturated with expensive read operations that could be offloaded. This chapter covers the full architecture for horizontally scaling AI-heavy read workloads: streaming replicas for read distribution, connection pooling with PgBouncer, replica-aware application patterns, caching layers with Redis, and async workload separation with Celery — all designed around the specific query shapes that LLM-powered applications produce.

---

Understanding the AI Read Workload Profile

Before building a scaling architecture, you need to understand what makes AI application reads different from CRUD application reads.

A typical e-commerce read is fast and selective: SELECT * FROM products WHERE id = $1. A typical RAG read is expensive and broad:

-- A realistic RAG retrieval query — expensive, broad, and run on every user message
WITH candidate_chunks AS (
    SELECT
        dc.id,
        dc.document_id,
        dc.chunk_text,
        dc.chunk_index,
        dc.embedding <=> $1::vector AS semantic_distance,
        ts_rank_cd(dc.search_vector, websearch_to_tsquery('english', $2)) AS text_rank
    FROM document_chunks dc
    INNER JOIN documents d ON dc.document_id = d.id
    WHERE
        d.tenant_id = $3
        AND d.status = 'active'
        AND d.collection_id = ANY($4::uuid[])
        -- Pre-filter to a semantic neighborhood before ranking
        AND dc.embedding <=> $1::vector < 0.45
    ORDER BY dc.embedding <=> $1::vector
    LIMIT 150
),
reranked AS (
    SELECT
        cc.*,
        -- Reciprocal rank fusion of semantic + text signals
        (1.0 / (60 + ROW_NUMBER() OVER (ORDER BY semantic_distance))) +
        (1.0 / (60 + ROW_NUMBER() OVER (ORDER BY text_rank DESC))) AS rrf_score
    FROM candidate_chunks cc
    WHERE text_rank > 0.01 OR semantic_distance < 0.35
),
enriched AS (
    SELECT
        r.*,
        d.title AS document_title,
        d.source_url,
        d.metadata,
        ch.content AS conversation_context
    FROM reranked r
    INNER JOIN documents d ON r.document_id = d.id
    LEFT JOIN (
        SELECT DISTINCT ON (session_id)
            session_id,
            content
        FROM conversation_history
        WHERE session_id = $5
        ORDER BY session_id, created_at DESC
    ) ch ON true
    WHERE d.tenant_id = $3
)
SELECT
    id,
    document_id,
    chunk_text,
    document_title,
    source_url,
    metadata,
    conversation_context,
    rrf_score,
    semantic_distance
FROM enriched
ORDER BY rrf_score DESC
LIMIT $6;

This query:

  • → Performs an IVFFlat or HNSW vector scan across potentially millions of embeddings
  • → Executes a GIN-indexed full-text search
  • → Joins three tables
  • → Uses window functions for reciprocal rank fusion
  • → Runs for every single user message, hundreds of times per minute at moderate scale

    • The right response to this profile is not vertical scaling alone — it's distributing these expensive reads across multiple PostgreSQL instances while keeping writes on the primary.

    Streaming Replication and Replica Topology for AI Workloads

    PostgreSQL streaming replication is the foundation of horizontal read scaling. For AI workloads, you want a topology that separates concerns: different replicas can be tuned for different query types.

    graph TD
    P[(Primary: all writes)] -->|streaming replication| R1[RAG replica: vector-heavy, more RAM for caching]
    P -->|streaming replication| R2[Analytics replica: reporting, dashboards]
    P -->|streaming replication| R3[Standby: failover target]
    App[Application] -->|writes, fresh reads| P
    App -->|cache-miss RAG reads| R1
    App -->|reporting queries| R2

    *Replicas are tuned per workload, not just duplicated for capacity — the RAG replica trades write capability for more RAM headroom on vector index caching.*

    Monitoring replication lag — critical for AI systems:

    -- Run on primary — monitor replica lag
-- Excessive lag means replicas return stale embeddings or miss recent document ingestion
CREATE OR REPLACE VIEW replication_status AS
SELECT
    client_addr,
    application_name,
    state,
    sent_lsn,
    write_lsn,
    flush_lsn,
    replay_lsn,
    write_lag,
    flush_lag,
    replay_lag,
    -- Convert lag to human-readable bytes behind
    pg_wal_lsn_diff(sent_lsn, replay_lsn) AS bytes_behind,
    pg_size_pretty(pg_wal_lsn_diff(sent_lsn, replay_lsn)) AS size_behind
FROM pg_stat_replication
ORDER BY replay_lag DESC NULLS LAST;

-- Alert if any replica is more than 60 seconds behind
-- This means newly ingested documents won't be searchable on that replica
SELECT
    application_name,
    replay_lag,
    pg_size_pretty(pg_wal_lsn_diff(sent_lsn, replay_lsn)) AS bytes_behind
FROM pg_stat_replication
WHERE replay_lag > interval '60 seconds'
   OR pg_wal_lsn_diff(sent_lsn, replay_lsn) > 500 * 1024 * 1024; -- 500MB behind

    PgBouncer Configuration for AI Connection Patterns

    AI applications have a connection pattern that differs from web apps: fewer, longer-lived connections that hold transactions open during LLM inference. PgBouncer requires specific configuration to handle this without starving replicas.

    # connection_router.py — intelligent routing between primary and replicas
# Routes AI reads to replicas, writes to primary, with replica health checking

import asyncio
import asyncpg
import redis.asyncio as redis
from contextlib import asynccontextmanager
from dataclasses import dataclass
from typing import Optional, AsyncGenerator
import logging
import time

logger = logging.getLogger(__name__)

@dataclass
class ReplicaHealth:
    host: str
    port: int
    lag_seconds: float
    is_healthy: bool
    last_checked: float
    connection_count: int

class AIWorkloadRouter:
    """
    Routes database connections intelligently for AI workloads.
    
    Strategy:
    - Writes → primary always
    - RAG queries → replicas with acceptable lag
    - Conversation history writes → primary
    - Conversation history reads → replica (slight staleness OK)
    - Fresh document searches (< 30s after ingest) → primary
    """

    PRIMARY_DSN = "postgresql://ai_app:secret@pgbouncer:6432/ai_app_primary"
    REPLICA_DSNS = [
        "postgresql://ai_app:secret@pgbouncer:6432/ai_app_replica1",
        "postgresql://ai_app:secret@pgbouncer:6432/ai_app_replica2",
    ]
    RAG_POOL_DSN = "postgresql://ai_app:secret@pgbouncer:6432/ai_app_rag"

    # Maximum acceptable replication lag for RAG queries (seconds)
    MAX_ACCEPTABLE_LAG = 30.0

    def __init__(self, redis_client: redis.Redis):
        self.redis = redis_client
        self._primary_pool: Optional[asyncpg.Pool] = None
        self._rag_pool: Optional[asyncpg.Pool] = None
        self._replica_health: dict[str, ReplicaHealth] = {}
        self._health_check_task: Optional[asyncio.Task] = None

    async def initialize(self):
        """Create connection pools and start health monitoring."""
        self._primary_pool = await asyncpg.create_pool(
            self.PRIMARY_DSN,
            min_size=5,
            max_size=25,
            max_inactive_connection_lifetime=300,
            command_timeout=30,
        )

        self._rag_pool = await asyncpg.create_pool(
            self.RAG_POOL_DSN,
            min_size=10,
            max_size=50,
            max_inactive_connection_lifetime=300,
            # Longer timeout for vector searches
            command_timeout=90,
            # Set HNSW ef_search for quality RAG results
            init=self._configure_rag_session,
        )

        self._health_check_task = asyncio.create_task(
            self._replica_health_monitor()
        )
        logger.info("AIWorkloadRouter initialized")

    async def _configure_rag_session(self, conn: asyncpg.Connection):
        """Configure each RAG pool connection for optimal vector search."""
        await conn.execute("SET hnsw.ef_search = 100")
        await conn.execute("SET enable_seqscan = off")
        await conn.execute("SET max_parallel_workers_per_gather = 4")

    async def _replica_health_monitor(self):
        """Background task that monitors replica lag every 15 seconds."""
        while True:
            try:
                async with self._primary_pool.acquire() as conn:
                    rows = await conn.fetch("""
                        SELECT
                            client_addr::text AS host,
                            application_name,
                            EXTRACT(EPOCH FROM replay_lag) AS lag_seconds,
                            EXTRACT(EPOCH FROM write_lag) AS write_lag_seconds
                        FROM pg_stat_replication
                        WHERE state = 'streaming'
                    """)

                    for row in rows:
                        host = row['application_name']
                        lag = row['lag_seconds'] or 0.0
                        self._replica_health[host] = ReplicaHealth(
                            host=row['host'],
                            port=5432,
                            lag_seconds=lag,
                            is_healthy=lag < self.MAX_ACCEPTABLE_LAG,
                            last_checked=time.time(),
                            connection_count=0,
                        )

                        # Publish health to Redis for other app instances
                        await self.redis.setex(
                            f"replica_health:{host}",
                            60,
                            f"{lag:.2f}",
                        )

            except Exception as e:
                logger.error(f"Health monitor error: {e}")

            await asyncio.sleep(15)

    def _replicas_healthy(self) -> bool:
        """Returns True if at least one replica is within acceptable lag."""
        if not self._replica_health:
            return False
        return any(h.is_healthy for h in self._replica_health.values())

    @asynccontextmanager
    async def read_connection(
        self,
        require_fresh: bool = False,
        workload: str = "general",
    ) -> AsyncGenerator[asyncpg.Connection, None]:
        """
        Get a connection for read operations.
        
        Args:
            require_fresh: If True, always use primary (for post-ingest queries)
            workload: 'rag' routes to dedicated RAG pool, 'general' to any replica
        """
        if require_fresh or not self._replicas_healthy():
            pool = self._primary_pool
            logger.debug(f"Read routing to primary (fresh={require_fresh})")
        elif workload == "rag":
            pool = self._rag_pool
            logger.debug("Read routing to RAG pool")
        else:
            pool = self._rag_pool  # Could load-balance across replica pools
            logger.debug("Read routing to replica pool")

        async with pool.acquire() as conn:
            yield conn

    @asynccontextmanager
    async def write_connection(self) -> AsyncGenerator[asyncpg.Connection, None]:
        """Always routes to primary for writes."""
        async with self._primary_pool.acquire() as conn:
            yield conn

    @asynccontextmanager
    async def transaction(self) -> AsyncGenerator[asyncpg.Connection, None]:
        """Transactions always go to primary."""
        async with self._primary_pool.acquire() as conn:
            async with conn.transaction():
                yield conn

    async def close(self):
        if self._health_check_task:
            self._health_check_task.cancel()
        if self._primary_pool:
            await self._primary_pool.close()
        if self._rag_pool:
            await self._rag_pool.close()

    Redis Caching Layer for Embedding and RAG Results

    The most expensive part of a RAG query is often not the PostgreSQL vector search — it's the OpenAI embedding call that precedes it. Caching at multiple layers dramatically reduces latency and cost.

    # cache_layer.py — multi-tier caching for AI workloads
# Tier 1: Redis (embedding cache, query result cache)
# Tier 2: PostgreSQL query_cache table (durable, cross-instance)
# Tier 3: In-process LRU cache (hot embeddings)

import hashlib
import json
import time
import asyncio
from typing import Optional, Any
from functools import lru_cache
import numpy as np
import redis.asyncio as redis
from openai import AsyncOpenAI
import asyncpg
import logging

logger = logging.getLogger(__name__)

openai_client = AsyncOpenAI()

class EmbeddingCache:
    """
    Caches OpenAI embeddings to avoid redundant API calls.
    At $0.02/1M tokens for text-embedding-3-small, caching saves real money at scale.
    
    Cache key: SHA-256 of (model + normalized_text)
    TTL: 7 days (embeddings don't change unless model changes)
    """

    EMBEDDING_TTL = 7 * 24 * 3600  # 7 days
    EMBEDDING_MODEL = "text-embedding-3-small"

    def __init__(self, redis_client: redis.Redis):
        self.redis = redis_client
        self._local_cache: dict[str, list[float]] = {}
        self._local_cache_max = 500  # Keep 500 embeddings in process memory

    def _cache_key(self, text: str) -> str:
        normalized = " ".join(text.lower().split())
        content = f"{self.EMBEDDING_MODEL}:{normalized}"
        return f"emb:{hashlib.sha256(content.encode()).hexdigest()}"

    async def get_embedding(self, text: str) -> list[float]:
        """Get embedding with cache-aside pattern."""
        cache_key = self._cache_key(text)

        # Tier 1: in-process cache
        if cache_key in self._local_cache:
            return self._local_cache[cache_key]

        # Tier 2: Redis cache
        cached = await self.redis.get(cache_key)
        if cached:
            embedding = json.loads(cached)
            self._update_local_cache(cache_key, embedding)
            return embedding

        # Tier 3: Call OpenAI API
        start = time.monotonic()
        response = await openai_client.embeddings.create(
            model=self.EMBEDDING_MODEL,
            input=text,
        )
        elapsed = time.monotonic() - start
        logger.debug(f"OpenAI embedding call took {elapsed:.3f}s")

        embedding = response.data[0].embedding

        # Populate both cache tiers
        await self.redis.setex(
            cache_key,
            self.EMBEDDING_TTL,
            json.dumps(embedding),
        )
        self._update_local_cache(cache_key, embedding)

        return embedding

    def _update_local_cache(self, key: str, embedding: list[float]):
        """Simple LRU eviction: drop oldest entry when full."""
        if len(self._local_cache) >= self._local_cache_max:
            # Remove first (oldest) key
            oldest = next(iter(self._local_cache))
            del self._local_cache[oldest]
        self._local_cache[key] = embedding

    async def get_embeddings_batch(self, texts: list[str]) -> list[list[float]]:
        """
        Batch embedding with partial cache hits.
        Only calls API for texts not already cached.
        """
        cache_keys = [self._cache_key(t) for t in texts]
        results: list[Optional[list[float]]] = [None] * len(texts)
        uncached_indices: list[int] = []

        # Check local cache first
        for i, key in enumerate(cache_keys):
            if key in self._local_cache:
                results[i] = self._local_cache[key]

        # Check Redis for remaining
        uncached_after_local = [i for i, r in enumerate(results) if r is None]
        if uncached_after_local:
            redis_keys = [cache_keys[i] for i in uncached_after_local]
            cached_values = await self.redis.mget(redis_keys)
            for idx, (i, val) in enumerate(zip(uncached_after_local, cached_values)):
                if val:
                    embedding = json.loads(val)
                    results[i] = embedding
                    self._update_local_cache(cache_keys[i], embedding)
                else:
                    uncached_indices.append(i)

        # Call API for truly uncached texts
        if uncached_indices:
            uncached_texts = [texts[i] for i in uncached_indices]
            response = await openai_client.embeddings.create(
                model=self.EMBEDDING_MODEL,
                input=uncached_texts,
            )
            pipe = self.redis.pipeline()
            for api_idx, i in enumerate(uncached_indices):
                embedding = response.data[api_idx].embedding
                results[i] = embedding
                pipe.setex(cache_keys[i], self.EMBEDDING_TTL, json.dumps(embedding))
                self._update_local_cache(cache_keys[i], embedding)
            await pipe.execute()

        return results  # type: ignore[return-value]


class RAGResultCache:
    """
    Caches full RAG retrieval results by (tenant_id, query_embedding_hash).
    
    Cache invalidation strategy:
    - TTL-based: 10 minutes for active tenants, 1 hour for inactive
    - Tag-based: when a document is ingested for tenant X, invalidate tenant X's cache
    - Redis SCAN-based invalidation (avoids KEYS command in production)
    """

    SHORT_TTL = 600      # 10 minutes — hot queries
    LONG_TTL = 3600      # 1 hour — cold queries

    def __init__(self, redis_client: redis.Redis, db_pool: asyncpg.Pool):
        self.redis = redis_client
        self.db_pool = db_pool

    def _result_cache_key(self, tenant_id: str, embedding_hash: str, filters: dict) -> str:
        filter_str = json.dumps(filters, sort_keys=True)
        content = f"{tenant_id}:{embedding_hash}:{filter_str}"
        return f"rag_result:{hashlib.sha256(content.encode()).hexdigest()}"

    def _tenant_tag_key(self, tenant_id: str) -> str:
        return f"rag_tenant_tag:{tenant_id}"

    async def get(
        self,
        tenant_id: str,
        embedding: list[float],
        filters: dict,
    ) -> Optional[list[dict]]:
        """Retrieve cached RAG results if available and not invalidated."""
        emb_hash = hashlib.sha256(
            json.dumps(embedding[:8]).encode()  # Use first 8 dims as fingerprint
        ).hexdigest()[:16]

        cache_key = self._result_cache_key(tenant_id, emb_hash, filters)
        tag_key = self._tenant_tag_key(tenant_id)

        # Check if cache entry and tenant tag both exist (both must be present)
        pipe = self.redis.pipeline()
        pipe.get(cache_key)
        pipe.exists(tag_key)
        results = await pipe.execute()

        cached_data, tag_exists = results

        if cached_data and tag_exists:
            try:
                return json.loads(cached_data)
            except json.JSONDecodeError:
                return None

        return None

    async def set(
        self,
        tenant_id: str,
        embedding: list[float],
        filters: dict,
        chunks: list[dict],
        ttl: int = SHORT_TTL,
    ) -> None:
        """Store RAG results in cache."""
        emb_hash = hashlib.sha256(
            json.dumps(embedding[:8]).encode()
        ).hexdigest()[:16]

        cache_key = self._result_cache_key(tenant_id, emb_hash, filters)
        tag_key = self._tenant_tag_key(tenant_id)

        pipe = self.redis.pipeline()
        pipe.setex(cache_key, ttl, json.dumps(chunks))
        # Ensure tenant tag exists; refresh its TTL to be >= the cache entry TTL
        pipe.setex(tag_key, ttl + 60, "1")
        await pipe.execute()

    async def invalidate_tenant(self, tenant_id: str) -> int:
        """
        Invalidate all cached RAG results for a tenant.
        Called when a document is ingested or deleted.
        
        Strategy: delete the tenant tag key. Cache entries that check
        tag existence will treat themselves as invalid on next access.
        Old cache entries will expire naturally via their own TTL.
        """
        tag_key = self._tenant_tag_key(tenant_id)
        deleted = await self.redis.delete(tag_key)
        logger.info(f"Invalidated RAG cache for tenant {tenant_id}")
        return deleted

    async def invalidate_tenant_and_persist(
        self,
        tenant_id: str,
        db_conn: asyncpg.Connection,
    ) -> None:
        """
        Invalidate Redis cache AND mark PostgreSQL query_cache entries as expired.
        Used for strict cache coherence after document operations.
        """
        await self.invalidate_tenant(tenant_id)

        # Also expire rows in the durable PostgreSQL cache table
        await db_conn.execute("""
            UPDATE query_cache
            SET expires_at = NOW() - INTERVAL '1 second'
            WHERE tenant_id = $1
              AND expires_at > NOW()
        """, uuid.UUID(tenant_id))

    Replica-Aware Application Patterns

    Directing reads to replicas requires patterns that tolerate replication lag. The key is identifying which reads are lag-tolerant and which are not.

    # rag_service.py — full RAG query service using the router and cache layers

import uuid
import time
import logging
from typing import Optional
import asyncpg

from connection_router import AIWorkloadRouter
from cache_layer import EmbeddingCache, RAGResultCache

logger = logging.getLogger(__name__)


class RAGService:
    """
    Orchestrates the full RAG retrieval pipeline with:
    - Embedding cache (avoid redundant OpenAI calls)
    - RAG result cache (avoid redundant vector searches)
    - Replica routing (heavy reads go to replicas)
    - Post-ingest freshness (new documents route to primary)
    """

    def __init__(
        self,
        router: AIWorkloadRouter,
        embedding_cache: EmbeddingCache,
        result_cache: RAGResultCache,
    ):
        self.router = router
        self.embedding_cache = embedding_cache
        self.result_cache = result_cache

    async def retrieve_chunks(
        self,
        query: str,
        tenant_id: str,
        collection_ids: list[str],
        session_id: Optional[str] = None,
        top_k: int = 10,
        require_fresh: bool = False,
    ) -> list[dict]:
        """
        Full RAG retrieval with caching and replica routing.
        
        require_fresh=True bypasses cache and replica, used when:
        - A document was just ingested (< 60s ago)
        - The user explicitly asked to search their latest upload
        """
        start = time.monotonic()

        # Step 1: Get embedding (cached)
        embedding = await self.embedding_cache.get_embedding(query)

        filters = {
            "collection_ids": sorted(collection_ids),
            "top_k": top_k,
        }

        # Step 2: Check RAG result cache (skip if require_fresh)
        if not require_fresh:
            cached = await self.result_cache.get(tenant_id, embedding, filters)
            if cached:
                logger.info(
                    f"RAG cache hit for tenant={tenant_id} "
                    f"in {time.monotonic() - start:.3f}s"
                )
                return cached

        # Step 3: Execute vector search on replica (or primary if fresh required)
        async with self.router.read_connection(
            require_fresh=require_fresh,
            workload="rag",
        ) as conn:
            chunks = await self._execute_rag_query(
                conn=conn,
                embedding=embedding,
                query=query,
                tenant_id=tenant_id,
                collection_ids=collection_ids,
                session_id=session_id,
                top_k=top_k,
            )

        elapsed = time.monotonic() - start
        logger.info(
            f"RAG retrieval for tenant={tenant_id}: "
            f"{len(chunks)} chunks in {elapsed:.3f}s "
            f"(fresh={require_fresh})"
        )

        # Step 4: Cache result (skip if require_fresh — result may not be stable yet)
        if not require_fresh and chunks:
            await self.result_cache.set(tenant_id, embedding, filters, chunks)

        return chunks

    async def _execute_rag_query(
        self,
        conn: asyncpg.Connection,
        embedding: list[float],
        query: str,
        tenant_id: str,
        collection_ids: list[str],
        session_id: Optional[str],
        top_k: int,
    ) -> list[dict]:
        """Execute the hybrid RAG query against PostgreSQL."""
        embedding_str = f"[{','.join(str(x) for x in embedding)}]"

        rows = await conn.fetch("""
            WITH candidate_chunks AS (
                SELECT
                    dc.id,
                    dc.document_id,
                    dc.chunk_text,
                    dc.chunk_index,
                    dc.embedding <=> $1::vector AS semantic_distance,
                    ts_rank_cd(
                        dc.search_vector,
                        websearch_to_tsquery('english', $2)
                    ) AS text_rank
                FROM document_chunks dc
                INNER JOIN documents d ON dc.document_id = d.id
                WHERE
                    d.tenant_id = $3::uuid
                    AND d.status = 'active'
                    AND d.collection_id = ANY($4::uuid[])
                    AND dc.embedding <=> $1::vector < 0.45
                ORDER BY dc.embedding <=> $1::vector
                LIMIT 150
            ),
            reranked AS (
                SELECT
                    cc.*,
                    (1.0 / (60 + ROW_NUMBER() OVER (ORDER BY semantic_distance))) +
                    (1.0 / (60 + ROW_NUMBER() OVER (ORDER BY text_rank DESC))) AS rrf_score
                FROM candidate_chunks cc
                WHERE text_rank > 0.01 OR semantic_distance < 0.35
            ),
            enriched AS (
                SELECT
                    r.*,
                    d.title AS document_title,
                    d.source_url,
                    d.metadata,
                    ch.content AS conversation_context
                FROM reranked r
                INNER JOIN documents d ON r.document_id = d.id
                LEFT JOIN (
                    SELECT DISTINCT ON (session_id)
                        session_id,
                        content
                    FROM conversation_history
                    WHERE session_id = $5::uuid
                    ORDER BY session_id, created_at DESC
                ) ch ON true
                WHERE d.tenant_id = $3::uuid
            )
            SELECT
                id::text,
                document_id::text,
                chunk_text,
                document_title,
                source_url,
                metadata::text,
                conversation_context,
                rrf_score,
                semantic_distance
            FROM enriched
            ORDER BY rrf_score DESC
            LIMIT $6
        """,
            embedding_str,
            query,
            uuid.UUID(tenant_id),
            [uuid.UUID(c) for c in collection_ids],
            uuid.UUID(session_id) if session_id else None,
            top_k,
        )

        return [dict(r) for r in rows]

    async def record_conversation_turn(
        self,
        session_id: str,
        tenant_id: str,
        role: str,
        content: str,
        tokens_used: int,
        model: str,
    ) -> None:
        """
        Write conversation history to primary.
        Reads of recent conversation history use primary too (require_fresh=True pattern).
        """
        async with self.router.write_connection() as conn:
            await conn.execute("""
                INSERT INTO conversation_history
                    (session_id, tenant_id, role, content, tokens_used, model)
                VALUES ($1::uuid, $2::uuid, $3, $4, $5, $6)
            """,
                uuid.UUID(session_id),
                uuid.UUID(tenant_id),
                role,
                content,
                tokens_used,
                model,
            )

    async def get_conversation_history(
        self,
        session_id: str,
        last_n: int = 10,
    ) -> list[dict]:
        """
        Conversation history reads go to primary — replication lag here causes
        the LLM to lose context of the most recent exchange, which is unacceptable.
        """
        async with self.router.read_connection(require_fresh=True) as conn:
            rows = await conn.fetch("""
                SELECT role, content, tokens_used, model, created_at
                FROM conversation_history
                WHERE session_id = $1::uuid
                ORDER BY created_at DESC
                LIMIT $2
            """, uuid.UUID(session_id), last_n)

        return [dict(r) for r in reversed(rows)]

    The lag-tolerance classification table:

    | Operation | Lag Tolerance | Routing |

    |---|---|---|

    | Vector similarity search | High (30s+ OK) | RAG replica pool |

    | Document metadata lookup | High | Any replica |

    | Conversation history read | None | Primary |

    | Recent ingest search (< 60s) | None | Primary |

    | User preferences | Low (5s OK) | Any replica |

    | Tenant plan/limits check | None | Primary |

    | Analytics aggregations | Very high (minutes OK) | Analytics replica |

    | Cache invalidation queries | None | Primary |

@celery_app.task(
    bind=True,
    name="tasks.ingest_document",
    max_retries=3,
    default_retry_delay=60,
    queue="ingestion",
)
def ingest_document(
    self,
    document_id: str,
    tenant_id: str,
    content: str,
    chunk_size: int = 512,
    chunk_overlap: int = 64,
) -> dict:
    """
    Background document ingestion pipeline:
    1. Split content into overlapping chunks
    2. Generate embeddings in batches (respect OpenAI rate limits)
    3. Insert chunks into PostgreSQL
    4. Invalidate tenant RAG cache
    5. Signal freshness window to application layer
    """
    task_logger.info(f"Starting ingestion for document {document_id}")
    start = time.monotonic()

    try:
        # Step 1: Chunk the document
        chunks = _chunk_text(content, chunk_size, chunk_overlap)
        task_logger.info(f"Document {document_id}: {len(chunks)} chunks")

        # Step 2: Generate embeddings in batches of 100 (OpenAI limit)
        embeddings = []
        batch_size = 100
        for batch_start in range(0, len(chunks), batch_size):
            batch = chunks[batch_start: batch_start + batch_size]
            response = openai_client_sync.embeddings.create(
                model="text-embedding-3-small",
                input=batch,
            )
            embeddings.extend([d.embedding for d in response.data])
            # Rate limit: ~3000 RPM for text-embedding-3-small on tier 2
            if batch_start + batch_size < len(chunks):
                time.sleep(0.05)

        # Step 3: Insert chunks into PostgreSQL
        conn = get_sync_db()
        try:
            with conn.cursor() as cur:
                # Use COPY for bulk insert performance
                records = []
                for i, (chunk_text, embedding) in enumerate(zip(chunks, embeddings)):
                    records.append((
                        str(uuid.uuid4()),
                        document_id,
                        i,
                        chunk_text,
                        f"[{','.join(str(x) for x in embedding)}]",
                        len(chunk_text.split()),
                    ))

                psycopg2.extras.execute_values(
                    cur,
                    """
                    INSERT INTO document_chunks
                        (id, document_id, chunk_index, chunk_text, embedding, token_count)
                    VALUES %s
                    ON CONFLICT (document_id, chunk_index) DO UPDATE SET
                        chunk_text = EXCLUDED.chunk_text,
                        embedding = EXCLUDED.embedding,
                        token_count = EXCLUDED.token_count
                    """,
                    records,
                    template="(%s, %s::uuid, %s, %s, %s::vector, %s)",
                    page_size=50,
                )

                # Update document status
                cur.execute("""
                    UPDATE documents
                    SET status = 'active',
                        metadata = metadata || '{"chunk_count": %s, "ingested_at": %s}'::jsonb
                    WHERE id = %s::uuid
                """, (len(chunks), time.time(), document_id))

                conn.commit()

        finally:
            conn.close()

        # Step 4: Invalidate RAG cache for this tenant
        tag_key = f"rag_tenant_tag:{tenant_id}"
        redis_client_sync.delete(tag_key)

        # Step 5: Set freshness window — routes next N queries to primary
        freshness_key = f"doc_fresh:{document_id}"
        redis_client_sync.setex(freshness_key, 120, "1")  # 2-minute freshness window

        elapsed = time.monotonic() - start
        task_logger.info(
            f"Document {document_id} ingested: {len(chunks)} chunks in {elapsed:.2f}s"
        )

        return {
            "document_id": document_id,
            "chunk_count": len(chunks),
            "elapsed_seconds": elapsed,
            "status": "success",
        }

    except openai.RateLimitError as exc:
        task_logger.warning(f"OpenAI rate limit hit for doc {document_id}, retrying")
        raise self.retry(exc=exc, countdown=60)

    except Exception as exc:
        task_logger.error(f"Ingestion failed for doc {document_id}: {exc}")
        # Mark document as failed in DB
        try:
            conn = get_sync_db()
            with conn.cursor() as cur:
                cur.execute("""
                    UPDATE documents SET status = 'failed'
                    WHERE id = %s::uuid
                """, (document_id,))
                conn.commit()
            conn.close()
        except Exception:
            pass
        raise self.retry(exc=exc, countdown=30)


@celery_app.task(
    bind=True,
    name="tasks.warm_query_cache",
    queue="cache_warming",
)
def warm_query_cache(self, tenant_id: str, top_queries: list[str]) -> dict:
    """
    Pre-warm the RAG result cache with a tenant's most frequent queries.
    Run nightly via Celery Beat to reduce cold-start latency.
    """
    task_logger.info(f"Warming cache for tenant {tenant_id}, {len(top_queries)} queries")
    warmed = 0
    failed = 0

    for query in top_queries:
        try:
            # Generate embedding
            response = openai_client_sync.embeddings.create(
                model="text-embedding-3-small",
                input=query,
            )
            embedding = response.data[0].embedding

            # Cache the embedding itself
            emb_key = f"emb:{_embedding_hash(query)}"
            redis_client_sync.setex(emb_key, 7 * 24 * 3600, json.dumps(embedding))

            warmed += 1
            time.sleep(0.02)  # Rate limit buffer

        except Exception as e:
            task_logger.warning(f"Cache warm failed for query '{query[:50]}': {e}")
            failed += 1

    return {"warmed": warmed, "failed": failed, "tenant_id": tenant_id}

def _chunk_text(text: str, chunk_size: int, overlap: int) -> list[str]:
    """Simple word-boundary chunker with overlap."""
    words = text.split()
    chunks = []
    step = chunk_size - overlap
    for i in range(0, len(words), step):
        chunk = " ".join(words[i: i + chunk_size])
        if chunk:
            chunks.append(chunk)
    return chunks


def _embedding_hash(text: str) -> str:
    import hashlib
    normalized = " ".join(text.lower().split())
    return hashlib.sha256(f"text-embedding-3-small:{normalized}".encode()).hexdigest()

    Observability: Monitoring the Scaled Read Tier

    Horizontal scaling introduces new failure modes. You need metrics that tell you whether replicas are actually being used, whether lag is impacting user experience, and whether the cache is earning its keep.

    -- Observability queries — run these on primary to monitor the scaled read tier

-- 1. Cache hit rate from PostgreSQL query_cache table
SELECT
    t.name AS tenant_name,
    COUNT(*) AS cache_entries,
    SUM(qc.hit_count) AS total_cache_hits,
    AVG(qc.hit_count) AS avg_hits_per_entry,
    SUM(CASE WHEN qc.expires_at > NOW() THEN 1 ELSE 0 END) AS live_entries,
    MIN(qc.created_at) AS oldest_entry,
    MAX(qc.created_at) AS newest_entry
FROM query_cache qc
JOIN tenants t ON qc.tenant_id = t.id
GROUP BY t.id, t.name
ORDER BY total_cache_hits DESC;

-- 2. Replica lag impact — identify sessions that may have seen stale data
-- (Useful for post-incident analysis)
SELECT
    application_name,
    replay_lag,
    EXTRACT(EPOCH FROM replay_lag) AS lag_seconds,
    CASE
        WHEN replay_lag < interval '5 seconds' THEN 'healthy'
        WHEN replay_lag < interval '30 seconds' THEN 'acceptable'
        WHEN replay_lag < interval '60 seconds' THEN 'degraded'
        ELSE 'critical'
    END AS lag_status,
    pg_size_pretty(pg_wal_lsn_diff(sent_lsn, replay_lsn)) AS bytes_behind
FROM pg_stat_replication
ORDER BY replay_lag DESC NULLS LAST;

-- 3. Most expensive queries hitting the primary (should be writes + fresh reads only)
-- Run on primary; if you see vector searches here, routing is broken
SELECT
    LEFT(query, 120) AS query_preview,
    calls,
    round(mean_exec_time::numeric, 2) AS mean_ms,
    round(total_exec_time::numeric, 2) AS total_ms,
    round((total_exec_time / SUM(total_exec_time) OVER ()) * 100, 2) AS pct_total_time
FROM pg_stat_statements
WHERE query ILIKE '%embedding%'
   OR query ILIKE '%<=>%'
   OR query ILIKE '%websearch_to_tsquery%'
ORDER BY total_exec_time DESC
LIMIT 20;

-- 4. Connection pool utilization (run on each PgBouncer node via admin console)
-- Exposed via pgbouncer SHOW POOLS;
-- Translated to SQL for monitoring dashboards:
-- SELECT * FROM pgbouncer.pools;  -- requires pgbouncer_fdw extension

-- 5. Conversation write throughput — should remain on primary
SELECT
    date_trunc('minute', created_at) AS minute,
    role,
    COUNT(*) AS messages,
    SUM(tokens_used) AS tokens
FROM conversation_history
WHERE created_at > NOW() - INTERVAL '1 hour'
GROUP BY date_trunc('minute', created_at), role
ORDER BY minute DESC
LIMIT 60;

def track_rag_query(func):
    """Decorator that records routing decisions and query latency."""
    @functools.wraps(func)
    async def wrapper(self, *args, **kwargs):
        start = time.monotonic()
        require_fresh = kwargs.get("require_fresh", False)
        destination = "primary" if require_fresh else "replica"
        has_cache_hit = False

        try:
            result = await func(self, *args, **kwargs)
            # Detect cache hit by checking if result arrived unusually fast
            elapsed = time.monotonic() - start
            has_cache_hit = elapsed < 0.020  # Sub-20ms is almost certainly a cache hit
            return result
        finally:
            elapsed = time.monotonic() - start
            DB_ROUTE_COUNTER.labels(
                destination=destination,
                workload="rag",
                reason="fresh" if require_fresh else "replica",
            ).inc()
            QUERY_LATENCY.labels(
                destination=destination,
                has_cache_hit=str(has_cache_hit),
            ).observe(elapsed)

    return wrapper

    SQL Server Equivalent: Always On Availability Groups for AI Read Scale-Out

    For teams running SQL Server, the equivalent of PostgreSQL streaming replication is Always On Availability Groups (AG) with readable secondaries. The configuration philosophy mirrors what we've built, with different syntax.

    -- SQL Server: Configure AG read routing for AI workloads

-- 1. Create the availability group with read-scale secondaries
-- (Run on primary replica)
CREATE AVAILABILITY GROUP [AI_App_AG]
WITH (
    AUTOMATED_BACKUP_PREFERENCE = SECONDARY,
    DB_FAILOVER = ON,
    DTC_SUPPORT = NONE
)
FOR DATABASE [ai_app]
REPLICA ON
    N'sql-primary' WITH (
        ENDPOINT_URL = N'TCP://sql-primary:5022',
        AVAILABILITY_MODE = SYNCHRONOUS_COMMIT,
        FAILOVER_MODE = AUTOMATIC,
        SEEDING_MODE = AUTOMATIC,
        SECONDARY_ROLE (ALLOW_CONNECTIONS = NO)
    ),
    N'sql-rag-replica-01' WITH (
        ENDPOINT_URL = N'TCP://sql-rag-replica-01:5022',
        AVAILABILITY_MODE = ASYNCHRONOUS_COMMIT,
        FAILOVER_MODE = MANUAL,
        SEEDING_MODE = AUTOMATIC,
        SECONDARY_ROLE (
            ALLOW_CONNECTIONS = READ_ONLY,
            READ_ONLY_ROUTING_URL = N'TCP://sql-rag-replica-01:1433'
        )
    ),
    N'sql-rag-replica-02' WITH (
        ENDPOINT_URL = N'TCP://sql-rag-replica-02:5022',
        AVAILABILITY_MODE = ASYNCHRONOUS_COMMIT,
        FAILOVER_MODE = MANUAL,
        SEEDING_MODE = AUTOMATIC,
        SECONDARY_ROLE (
            ALLOW_CONNECTIONS = READ_ONLY,
            READ_ONLY_ROUTING_URL = N'TCP://sql-rag-replica-02:1433'
        )
    );

-- 2. Configure read-only routing list on the primary
-- SQL Server routes ApplicationIntent=ReadOnly connections to these replicas
ALTER AVAILABILITY GROUP [AI_App_AG]
MODIFY REPLICA ON N'sql-primary'
WITH (PRIMARY_ROLE (
    READ_ONLY_ROUTING_LIST = (
        ('sql-rag-replica-01', 'sql-rag-replica-02'),  -- Round-robin between these two
        'sql-primary'   -- Fallback to primary if both replicas unavailable
    )
));

-- 3. Check replica synchronization status
SELECT
    ar.replica_server_name,
    ars.role_desc,
    ars.synchronization_health_desc,
    ars.connected_state_desc,
    ars.last_connect_error_description,
    drs.synchronization_state_desc,
    drs.log_send_queue_size / 1024.0 AS log_send_queue_kb,
    drs.log_send_rate / 1024.0 AS log_send_rate_kb_per_sec,
    drs.redo_queue_size / 1024.0 AS redo_queue_kb,  -- Equivalent to PG replay lag
    drs.redo_rate / 1024.0 AS redo_rate_kb_per_sec,
    drs.last_redone_time,
    DATEDIFF(SECOND, drs.last_redone_time, GETUTCDATE()) AS approx_lag_seconds
FROM sys.availability_replicas ar
JOIN sys.dm_hadr_availability_replica_states ars ON ar.replica_id = ars.replica_id
JOIN sys.dm_hadr_database_replica_states drs ON ar.replica_id = drs.replica_id
WHERE ar.group_id = (
    SELECT group_id FROM sys.availability_groups WHERE name = 'AI_App_AG'
)
ORDER BY ars.role_desc, ar.replica_server_name;

-- Check if a read is hitting secondary (useful for verifying routing)
SELECT
    SERVERPROPERTY('ServerName') AS server_name,
    sys.fn_hadr_is_primary_replica('ai_app') AS is_primary,
    DATABASEPROPERTYEX('ai_app', 'Updateability') AS updateability;

-- SQL Server read workload — monitor expensive queries on secondaries
-- Run on each readable secondary
SELECT TOP 20
    LEFT(qt.text, 120) AS query_preview,
    qs.execution_count,
    qs.total_elapsed_time / qs.execution_count / 1000.0 AS avg_ms,
    qs.total_elapsed_time / 1000.0 AS total_ms,
    qs.total_logical_reads / qs.execution_count AS avg_logical_reads
FROM sys.dm_exec_query_stats qs
CROSS APPLY sys.dm_exec_sql_text(qs.sql_handle) qt
WHERE qt.text LIKE '%document_chunks%'
   OR qt.text LIKE '%conversation_history%'
ORDER BY qs.total_elapsed_time DESC;

import pyodbc
from contextlib import contextmanager
from typing import Literal

AG_LISTENER = "sql-ag-listener,1433"
DATABASE = "ai_app"
AUTH = "Trusted_Connection=yes"  # or use SQL auth

PRIMARY_CONN_STR = (
    f"DRIVER={{ODBC Driver 18 for SQL Server}};"
    f"SERVER={AG_LISTENER};"
    f"DATABASE={DATABASE};"
    f"ApplicationIntent=ReadWrite;"
    f"{AUTH}"
)

REPLICA_CONN_STR = (
    f"DRIVER={{ODBC Driver 18 for SQL Server}};"
    f"SERVER={AG_LISTENER};"
    f"DATABASE={DATABASE};"
    f"ApplicationIntent=ReadOnly;"
    f"MultiSubnetFailover=yes;"  # Required for AG listener
    f"{AUTH}"
)


@contextmanager
def get_read_connection(require_fresh: bool = False):
    """
    Route SQL Server reads via ApplicationIntent.
    require_fresh=True forces ReadWrite (primary) intent.
    """
    conn_str = PRIMARY_CONN_STR if require_fresh else REPLICA_CONN_STR
    conn = pyodbc.connect(conn_str, autocommit=True)
    try:
        yield conn
    finally:
        conn.close()


@contextmanager
def get_write_connection():
    conn = pyodbc.connect(PRIMARY_CONN_STR, autocommit=False)
    try:
        yield conn
    finally:
        conn.close()

    Putting It All Together: The Request Lifecycle

    A fully scaled RAG request flows through every layer we've built. Here's the complete request lifecycle as a sequence that ties the chapter together:

    User message arrives at FastAPI endpoint
    │
    ▼
Check Redis: is there a freshness flag for this tenant's recent ingest?
    │ YES → set require_fresh=True
    │ NO  → require_fresh=False
    ▼
EmbeddingCache.get_embedding(query)
    ├── L1 hit: return from process memory (~0.01ms)
    ├── L2 hit: return from Redis (~0.5ms)
    └── L3 miss: call OpenAI API (~100-300ms), populate L1+L2
    ▼
RAGResultCache.get(tenant_id, embedding, filters)
    ├── Cache hit: return chunks (~1ms total so far)
    └── Cache miss: continue to database
    ▼
AIWorkloadRouter.read_connection(require_fresh, workload="rag")
    ├── require_fresh=True → primary pool
    └── require_fresh=False + replicas healthy → RAG replica pool
    ▼
Execute hybrid RAG SQL query
    (vector HNSW scan + full-text + joins + RRF reranking)
    ~50-500ms depending on collection size
    ▼
RAGResultCache.set(result) → populate Redis cache
    ▼
Return chunks to LLM pipeline
    ▼
LLM generates response (~800ms-3s)
    ▼
RAGService.record_conversation_turn() → primary (write)
    ▼
Response delivered to user

    Under this architecture, the second and subsequent identical or near-identical queries from the same tenant return in milliseconds. The expensive vector search only runs on cache misses, and it runs on replicas rather than your primary. Writes remain on the primary, which handles only a fraction of the total query volume.

    Key Takeaways

  • → **AI reads have a different profile than CRUD reads.** A single RAG query combines vector search, full-text search, multi-table joins, and window functions. Treating this like a simple primary-only workload saturates your database quickly at moderate scale.
  • → **Replica topology should match workload type.** Separate RAG replicas (high `work_mem`, parallel workers) from analytics replicas (large `maintenance_work_mem`) and primary (writes + fresh reads). Each tier can be independently tuned for its specific query shape.
  • → **Lag tolerance is the key routing decision.** Conversation history has zero lag tolerance (the LLM loses context). Recent-ingest vector searches have zero lag tolerance (user expects to search what they just uploaded). Background analytics have high lag tolerance. Explicit `require_fresh` flags in your routing layer make these decisions explicit and testable.
  • → **Cache at multiple tiers for AI workloads.** Embedding caching (7-day TTL, three-tier: process memory → Redis → OpenAI API) eliminates redundant API calls. RAG result caching (10-minute TTL with tag-based invalidation on ingest) eliminates redundant vector searches. Together they dramatically reduce both latency and cost at scale.
  • → **Async workload separation keeps the request path fast.** Document ingestion, bulk embedding generation, cache warming, and analytics aggregations belong in Celery task queues, not in the synchronous request path. This keeps p99 latency predictable even as ingestion workloads grow.
