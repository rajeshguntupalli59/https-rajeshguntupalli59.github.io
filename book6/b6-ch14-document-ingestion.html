Chapter 14: Document Ingestion: Chunking, Embedding, Storing

The pipeline that transforms raw documents into searchable, queryable vector knowledge is where most RAG systems either succeed or quietly fall apart. Getting a proof of concept working is straightforward — point a library at some PDFs, generate embeddings, and call it done. Running that same process reliably across millions of documents, with incremental updates, deduplication, failure recovery, and observable progress, is an entirely different problem. This chapter covers the complete ingestion pipeline: how to chunk documents intelligently so that embeddings carry meaningful semantic signal, how to store those chunks and their embeddings in PostgreSQL with a schema that supports real production operations, and how to orchestrate the process asynchronously so that your application stays responsive while large corpora process in the background. PostgreSQL is not just the destination here — its features actively enable a more robust pipeline than any vector-only store can offer.

graph LR
    A[Document submitted] --> B{content_hash changed?}
    B -->|no| C[Skip: unchanged]
    B -->|yes/new| D["ingest_document task: mark 'chunking'"]
    D --> E["chunk_document: select_chunker by source_type"]
    E --> F["embed_chunks: batched OpenAI calls, SKIP LOCKED"]
    F --> G["finalize_document: mark 'complete'"]
    G --> H[(document_chunks + chunk_embeddings)]

*A Celery chain — chunk, embed, finalize — with the document's ingestion_status column as the durable record of where it is in the pipeline at any moment.*

14.1 Schema Design: Documents, Chunks, and Embeddings

Before writing a single line of Python, the schema deserves real thought. Many teams reach for a single flat table — one row per chunk, embedding included — and discover months later that they cannot answer basic operational questions: Which documents have been processed? Which chunks belong to a document that was updated last Tuesday? Which embeddings were generated with an older model that needs reprocessing?

A normalized schema separates concerns cleanly and gives you the relational power that makes PostgreSQL worth choosing over a dedicated vector store.

-- Enable required extensions
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS pgcrypto;

-- Collections: logical groupings of documents (a tenant's knowledge base, a project, etc.)
-- Created before `documents` since documents.collection_id references it
CREATE TABLE document_collections (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        TEXT NOT NULL,
    description TEXT,
    owner_id    UUID,                        -- foreign key to your users table
    settings    JSONB DEFAULT '{}',          -- e.g., {"chunk_size": 512, "overlap": 64}
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Source documents: one row per ingested file or URL
CREATE TABLE documents (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    source_uri      TEXT NOT NULL,
    source_type     TEXT NOT NULL CHECK (source_type IN ('pdf', 'html', 'markdown', 'txt', 'docx', 'confluence', 'notion')),
    title           TEXT,
    author          TEXT,
    language        TEXT DEFAULT 'en',
    content_hash    TEXT NOT NULL,           -- SHA-256 of raw content; detect changes
    byte_size       BIGINT,
    page_count      INT,
    metadata        JSONB DEFAULT '{}',      -- arbitrary source-specific fields
    ingestion_status TEXT NOT NULL DEFAULT 'pending'
                    CHECK (ingestion_status IN ('pending', 'chunking', 'embedding', 'complete', 'failed')),
    error_message   TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    last_ingested_at TIMESTAMPTZ,
    collection_id   UUID REFERENCES document_collections(id) ON DELETE SET NULL
);

CREATE UNIQUE INDEX idx_documents_source_uri ON documents(source_uri);
CREATE INDEX idx_documents_status ON documents(ingestion_status);
CREATE INDEX idx_documents_collection ON documents(collection_id);
CREATE INDEX idx_documents_metadata ON documents USING GIN(metadata);
CREATE INDEX idx_documents_content_hash ON documents(content_hash);

-- Chunks: the actual text segments that get embedded
CREATE TABLE document_chunks (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id     UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    chunk_index     INT NOT NULL,            -- ordinal position within document
    chunk_text      TEXT NOT NULL,
    token_count     INT,                     -- actual token count for the chunk
    char_count      INT GENERATED ALWAYS AS (char_length(chunk_text)) STORED,
    start_char      INT,                     -- character offset in original document
    end_char        INT,
    page_number     INT,                     -- for PDFs and paginated sources
    section_title   TEXT,                    -- heading or section this chunk falls under
    chunk_type      TEXT DEFAULT 'text'
                    CHECK (chunk_type IN ('text', 'table', 'code', 'header', 'caption')),
    metadata        JSONB DEFAULT '{}',
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (document_id, chunk_index)
);

CREATE INDEX idx_chunks_document ON document_chunks(document_id);
CREATE INDEX idx_chunks_page ON document_chunks(document_id, page_number);
CREATE INDEX idx_chunks_metadata ON document_chunks USING GIN(metadata);
-- Trigram index for keyword fallback search
CREATE INDEX idx_chunks_text_trgm ON document_chunks USING GIN(chunk_text gin_trgm_ops);

-- Embeddings: separate table so you can re-embed without losing chunks
-- Also supports multiple embedding models simultaneously
CREATE TABLE chunk_embeddings (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    chunk_id        UUID NOT NULL REFERENCES document_chunks(id) ON DELETE CASCADE,
    embedding_model TEXT NOT NULL,           -- e.g., 'text-embedding-3-small', 'text-embedding-3-large'
    embedding_dim   INT NOT NULL,
    embedding       vector(1536),            -- adjust per model; use CHECK or partitioning for multi-dim
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (chunk_id, embedding_model)
);

-- Partial indexes for each model improve query speed significantly
CREATE INDEX idx_embeddings_small ON chunk_embeddings USING hnsw (embedding vector_cosine_ops)
    WHERE embedding_model = 'text-embedding-3-small';

CREATE INDEX idx_embeddings_large ON chunk_embeddings USING hnsw (embedding vector_cosine_ops)
    WHERE embedding_model = 'text-embedding-3-large';

-- Ingestion job log: full audit trail
CREATE TABLE ingestion_jobs (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id     UUID REFERENCES documents(id) ON DELETE CASCADE,
    job_type        TEXT NOT NULL CHECK (job_type IN ('ingest', 'reprocess', 'reembed', 'delete')),
    status          TEXT NOT NULL DEFAULT 'queued'
                    CHECK (status IN ('queued', 'running', 'complete', 'failed', 'retrying')),
    celery_task_id  TEXT,
    chunks_created  INT DEFAULT 0,
    embeddings_created INT DEFAULT 0,
    started_at      TIMESTAMPTZ,
    completed_at    TIMESTAMPTZ,
    error_message   TEXT,
    retry_count     INT DEFAULT 0,
    worker_id       TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_jobs_document ON ingestion_jobs(document_id);
CREATE INDEX idx_jobs_status ON ingestion_jobs(status);
CREATE INDEX idx_jobs_celery ON ingestion_jobs(celery_task_id);

-- Trigger to keep updated_at current on documents
CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
    NEW.updated_at = now();
    RETURN NEW;
END;
$$;

CREATE TRIGGER trg_documents_updated_at
    BEFORE UPDATE ON documents
    FOR EACH ROW EXECUTE FUNCTION set_updated_at();

The separation between document_chunks and chunk_embeddings deserves emphasis. When OpenAI releases a new embedding model, you can generate new embeddings for all existing chunks without re-parsing or re-chunking the source documents. When you need to compare retrieval quality between text-embedding-3-small and text-embedding-3-large, both sets of embeddings coexist and you can run A/B queries against them. The content_hash column on documents lets you skip re-ingestion for files that have not changed — a detail that pays dividends when your nightly sync touches ten thousand documents but only twenty have actually been modified.

14.2 Chunking Strategies That Preserve Semantic Meaning

Chunking is the step that most introductory RAG tutorials get wrong by treating it as a simple split_every_N_characters problem. The text you retrieve during query time needs to be semantically coherent — a chunk that contains half a sentence from one paragraph and the beginning of the next paragraph will embed into a muddled vector that retrieves poorly.

The right chunking strategy depends on document structure. Markdown files have clear heading boundaries. PDFs may have paragraph structure detectable through newlines and indentation. Code documentation often has function signatures and their docstrings as natural units. A production pipeline handles all of these.

# chunkers.py — semantic chunking with multiple strategies
import hashlib
import re
from dataclasses import dataclass, field
from typing import Generator
import tiktoken
from langchain.text_splitter import RecursiveCharacterTextSplitter, MarkdownHeaderTextSplitter
from llama_index.core.node_parser import SentenceSplitter, SemanticSplitterNodeParser
from llama_index.embeddings.openai import OpenAIEmbedding
import fitz  # PyMuPDF
from docx import Document as DocxDocument


@dataclass
class ChunkResult:
    text: str
    chunk_index: int
    token_count: int
    char_start: int
    char_end: int
    page_number: int | None = None
    section_title: str | None = None
    chunk_type: str = "text"
    metadata: dict = field(default_factory=dict)


def count_tokens(text: str, model: str = "text-embedding-3-small") -> int:
    """Accurate token counting using tiktoken."""
    # text-embedding-3-* uses cl100k_base
    enc = tiktoken.get_encoding("cl100k_base")
    return len(enc.encode(text))


class FixedSizeChunker:
    """
    Baseline chunker: fixed token windows with overlap.
    Good for homogeneous plain text with no meaningful structure.
    """

    def __init__(self, chunk_tokens: int = 512, overlap_tokens: int = 64):
        self.chunk_tokens = chunk_tokens
        self.overlap_tokens = overlap_tokens
        self.splitter = RecursiveCharacterTextSplitter.from_tiktoken_encoder(
            model_name="text-embedding-3-small",
            chunk_size=chunk_tokens,
            chunk_overlap=overlap_tokens,
            separators=["\n\n", "\n", ". ", " ", ""],
        )

    def chunk(self, text: str) -> Generator[ChunkResult, None, None]:
        splits = self.splitter.split_text(text)
        char_offset = 0
        for idx, split_text in enumerate(splits):
            # Locate the chunk position in the original text
            char_start = text.find(split_text, max(0, char_offset - 20))
            if char_start == -1:
                char_start = char_offset
            char_end = char_start + len(split_text)
            char_offset = char_end

            yield ChunkResult(
                text=split_text,
                chunk_index=idx,
                token_count=count_tokens(split_text),
                char_start=char_start,
                char_end=char_end,
            )


class MarkdownChunker:
    """
    Structure-aware chunking for Markdown.
    Splits on headers first, then further chunks large sections by size.
    Preserves the heading context in each chunk's metadata.
    """

    def __init__(self, max_chunk_tokens: int = 512, overlap_tokens: int = 64):
        self.max_chunk_tokens = max_chunk_tokens
        self.overlap_tokens = overlap_tokens
        self.header_splitter = MarkdownHeaderTextSplitter(
            headers_to_split_on=[
                ("#", "h1"),
                ("##", "h2"),
                ("###", "h3"),
                ("####", "h4"),
            ],
            strip_headers=False,
        )
        self.size_splitter = RecursiveCharacterTextSplitter.from_tiktoken_encoder(
            model_name="text-embedding-3-small",
            chunk_size=max_chunk_tokens,
            chunk_overlap=overlap_tokens,
        )

    def chunk(self, text: str) -> Generator[ChunkResult, None, None]:
        header_docs = self.header_splitter.split_text(text)
        global_idx = 0

        for doc in header_docs:
            section_heading = " > ".join(
                v for k, v in doc.metadata.items() if k in ("h1", "h2", "h3", "h4") and v
            ) or None

            section_text = doc.page_content.strip()
            if not section_text:
                continue

            # If the section fits within token budget, keep it whole
            if count_tokens(section_text) <= self.max_chunk_tokens:
                yield ChunkResult(
                    text=section_text,
                    chunk_index=global_idx,
                    token_count=count_tokens(section_text),
                    char_start=text.find(section_text),
                    char_end=text.find(section_text) + len(section_text),
                    section_title=section_heading,
                    metadata={"headers": doc.metadata},
                )
                global_idx += 1
            else:
                # Split large sections further
                sub_chunks = self.size_splitter.split_text(section_text)
                for sub_text in sub_chunks:
                    yield ChunkResult(
                        text=sub_text,
                        chunk_index=global_idx,
                        token_count=count_tokens(sub_text),
                        char_start=text.find(sub_text),
                        char_end=text.find(sub_text) + len(sub_text),
                        section_title=section_heading,
                        metadata={"headers": doc.metadata},
                    )
                    global_idx += 1


class PDFChunker:
    """
    PDF-aware chunker using PyMuPDF.
    Extracts text per page, detects paragraph boundaries via blank lines,
    then assembles chunks that respect page and paragraph structure.
    """

    def __init__(self, max_chunk_tokens: int = 512, overlap_tokens: int = 64):
        self.max_chunk_tokens = max_chunk_tokens
        self.overlap_tokens = overlap_tokens

    def chunk(self, pdf_bytes: bytes) -> Generator[ChunkResult, None, None]:
        doc = fitz.open(stream=pdf_bytes, filetype="pdf")
        global_idx = 0
        buffer_text = ""
        buffer_page = 1
        buffer_chars = 0

        for page_num in range(len(doc)):
            page = doc[page_num]
            page_text = page.get_text("text")

            # Split page into paragraphs on double newlines
            paragraphs = re.split(r"\n{2,}", page_text.strip())

            for para in paragraphs:
                para = para.strip()
                if not para or len(para) < 20:  # skip headers/noise lines
                    continue

                para_tokens = count_tokens(para)

                # Would adding this paragraph exceed our budget?
                if buffer_text and count_tokens(buffer_text + "\n\n" + para) > self.max_chunk_tokens:
                    # Emit current buffer as a chunk
                    yield ChunkResult(
                        text=buffer_text,
                        chunk_index=global_idx,
                        token_count=count_tokens(buffer_text),
                        char_start=buffer_chars,
                        char_end=buffer_chars + len(buffer_text),
                        page_number=buffer_page,
                    )
                    global_idx += 1
                    # Start new buffer with overlap: keep last sentence of previous chunk
                    sentences = buffer_text.split(". ")
                    overlap_text = ". ".join(sentences[-2:]) if len(sentences) > 1 else ""
                    buffer_text = (overlap_text + "\n\n" + para).strip() if overlap_text else para
                    buffer_chars += len(buffer_text)
                    buffer_page = page_num + 1
                else:
                    buffer_text = (buffer_text + "\n\n" + para).strip() if buffer_text else para
                    if buffer_page is None:
                        buffer_page = page_num + 1

        # Emit any remaining buffer
        if buffer_text:
            yield ChunkResult(
                text=buffer_text,
                chunk_index=global_idx,
                token_count=count_tokens(buffer_text),
                char_start=buffer_chars,
                char_end=buffer_chars + len(buffer_text),
                page_number=buffer_page,
            )


class SemanticChunker:
    """
    Embedding-based semantic chunking via LlamaIndex.
    Groups sentences that belong together semantically rather than by size.
    More expensive but produces higher quality chunks for dense technical content.
    """

    def __init__(self, openai_api_key: str, breakpoint_percentile: int = 95):
        embed_model = OpenAIEmbedding(
            model="text-embedding-3-small",
            api_key=openai_api_key,
        )
        self.splitter = SemanticSplitterNodeParser(
            buffer_size=1,
            breakpoint_percentile_threshold=breakpoint_percentile,
            embed_model=embed_model,
        )

    def chunk(self, text: str) -> Generator[ChunkResult, None, None]:
        from llama_index.core import Document as LIDocument
        doc = LIDocument(text=text)
        nodes = self.splitter.get_nodes_from_documents([doc])

        for idx, node in enumerate(nodes):
            chunk_text = node.get_content()
            yield ChunkResult(
                text=chunk_text,
                chunk_index=idx,
                token_count=count_tokens(chunk_text),
                char_start=node.start_char_idx or 0,
                char_end=node.end_char_idx or len(chunk_text),
            )


def select_chunker(source_type: str, settings: dict):
    """Factory that picks the right chunker based on document type and collection settings."""
    chunk_tokens = settings.get("chunk_size", 512)
    overlap_tokens = settings.get("overlap", 64)

    if source_type == "markdown":
        return MarkdownChunker(max_chunk_tokens=chunk_tokens, overlap_tokens=overlap_tokens)
    elif source_type == "pdf":
        return PDFChunker(max_chunk_tokens=chunk_tokens, overlap_tokens=overlap_tokens)
    else:
        return FixedSizeChunker(chunk_tokens=chunk_tokens, overlap_tokens=overlap_tokens)

The semantic chunker via LlamaIndex uses actual embedding similarity to find breakpoints — sentences whose embeddings diverge sharply from what came before represent natural topical boundaries. This approach works well for long-form technical documentation where paragraphs shift between related but distinct concepts. The cost is additional embedding API calls during ingestion, so reserve it for corpora where retrieval quality justifies the extra latency.

14.3 Generating and Storing Embeddings at Scale

With chunks in hand, the embedding step has two distinct challenges: rate limits from embedding APIs and the need to batch efficiently. Sending one API call per chunk will hit rate limits on any non-trivial corpus and waste significant time on network round trips. Batching chunks into groups of 100–500 tokens saturates throughput while staying within API constraints.

# embedder.py — batched embedding generation with retry logic
import asyncio
import time
import logging
from typing import Sequence
import numpy as np
import openai
from openai import AsyncOpenAI
import anthropic  # Claude does not yet expose a public embeddings API; pattern shown for completeness
import psycopg
from psycopg.rows import dict_row
import redis
import json
import hashlib

logger = logging.getLogger(__name__)


class EmbeddingCache:
    """
    Redis cache for embeddings keyed by (text_hash, model).
    Avoids re-embedding identical chunks across document versions.
    """

    def __init__(self, redis_url: str, ttl_seconds: int = 86400 * 30):
        self.client = redis.from_url(redis_url, decode_responses=False)
        self.ttl = ttl_seconds

    def _key(self, text: str, model: str) -> str:
        text_hash = hashlib.sha256(text.encode()).hexdigest()
        return f"emb:{model}:{text_hash}"

    def get(self, text: str, model: str) -> list[float] | None:
        raw = self.client.get(self._key(text, model))
        if raw:
            return json.loads(raw)
        return None

    def set(self, text: str, model: str, embedding: list[float]) -> None:
        key = self._key(text, model)
        self.client.setex(key, self.ttl, json.dumps(embedding))


class OpenAIEmbedder:
    """
    Async batched embedder using OpenAI's text-embedding-3-* models.
    Handles rate limits with exponential backoff and respects token budgets per batch.
    """

    # Model specs: (max_tokens_per_batch, dimensions, max_texts_per_batch)
    MODEL_SPECS = {
        "text-embedding-3-small": {"dims": 1536, "max_batch_tokens": 8191 * 16, "max_per_batch": 2048},
        "text-embedding-3-large": {"dims": 3072, "max_batch_tokens": 8191 * 16, "max_per_batch": 2048},
        "text-embedding-ada-002": {"dims": 1536, "max_batch_tokens": 8191 * 8, "max_per_batch": 2048},
    }

    def __init__(
        self,
        api_key: str,
        model: str = "text-embedding-3-small",
        redis_url: str | None = None,
        max_retries: int = 5,
    ):
        self.client = AsyncOpenAI(api_key=api_key)
        self.model = model
        self.spec = self.MODEL_SPECS[model]
        self.max_retries = max_retries
        self.cache = EmbeddingCache(redis_url) if redis_url else None

    def _build_batches(self, texts: list[str]) -> list[list[str]]:
        """Group texts into batches respecting both count and token limits."""
        import tiktoken
        enc = tiktoken.get_encoding("cl100k_base")

        batches = []
        current_batch = []
        current_tokens = 0

        for text in texts:
            tokens = len(enc.encode(text))
            if (current_tokens + tokens > self.spec["max_batch_tokens"] or
                    len(current_batch) >= self.spec["max_per_batch"]):
                if current_batch:
                    batches.append(current_batch)
                current_batch = [text]
                current_tokens = tokens
            else:
                current_batch.append(text)
                current_tokens += tokens

        if current_batch:
            batches.append(current_batch)

        return batches

    async def _embed_batch_with_retry(self, texts: list[str]) -> list[list[float]]:
        """Single batch with exponential backoff on rate limit errors."""
        wait = 1.0
        for attempt in range(self.max_retries):
            try:
                response = await self.client.embeddings.create(
                    model=self.model,
                    input=texts,
                    encoding_format="float",
                )
                # OpenAI returns results in the same order as input
                return [item.embedding for item in sorted(response.data, key=lambda x: x.index)]
            except openai.RateLimitError:
                if attempt == self.max_retries - 1:
                    raise
                logger.warning(f"Rate limit hit, waiting {wait:.1f}s (attempt {attempt + 1})")
                await asyncio.sleep(wait)
                wait = min(wait * 2, 60.0)
            except openai.APIError as e:
                if attempt == self.max_retries - 1:
                    raise
                logger.warning(f"API error {e}, retrying in {wait:.1f}s")
                await asyncio.sleep(wait)
                wait = min(wait * 2, 60.0)

    async def embed_texts(self, texts: list[str]) -> list[list[float]]:
        """
        Embed a list of texts, using cache where available.
        Returns embeddings in the same order as input.
        """
        results: list[list[float] | None] = [None] * len(texts)
        uncached_indices: list[int] = []
        uncached_texts: list[str] = []

        # Check cache for each text
        if self.cache:
            for i, text in enumerate(texts):
                cached = self.cache.get(text, self.model)
                if cached is not None:
                    results[i] = cached
                else:
                    uncached_indices.append(i)
                    uncached_texts.append(text)
        else:
            uncached_indices = list(range(len(texts)))
            uncached_texts = texts

        if uncached_texts:
            batches = self._build_batches(uncached_texts)
            batch_results: list[list[float]] = []

            for batch in batches:
                embeddings = await self._embed_batch_with_retry(batch)
                batch_results.extend(embeddings)
                # Brief yield to avoid blocking the event loop
                await asyncio.sleep(0)

            # Place results back in original positions and populate cache
            for original_idx, embedding in zip(uncached_indices, batch_results):
                results[original_idx] = embedding
                if self.cache:
                    self.cache.set(texts[original_idx], self.model, embedding)

        return results  # type: ignore[return-value]


async def store_embeddings(
    conn: psycopg.AsyncConnection,
    chunk_ids: list[str],
    embeddings: list[list[float]],
    model: str,
) -> int:
    """
    Bulk-insert embeddings using unnest for maximum throughput.
    Returns the number of rows upserted.
    """
    dims = len(embeddings[0])

    # Convert to pgvector-compatible strings
    embedding_strs = [f"[{','.join(str(v) for v in emb)}]" for emb in embeddings]

    async with conn.cursor() as cur:
        await cur.execute(
            """
            INSERT INTO chunk_embeddings (chunk_id, embedding_model, embedding_dim, embedding)
            SELECT
                unnest(%s::uuid[]),
                %s,
                %s,
                unnest(%s::vector[])
            ON CONFLICT (chunk_id, embedding_model)
            DO UPDATE SET
                embedding = EXCLUDED.embedding,
                created_at = now()
            """,
            (chunk_ids, model, dims, embedding_strs),
        )
        return cur.rowcount


async def embed_pending_chunks(
    db_url: str,
    openai_api_key: str,
    model: str = "text-embedding-3-small",
    batch_size: int = 256,
    redis_url: str | None = None,
) -> dict:
    """
    Find all chunks without embeddings for the given model and generate them.
    Designed to run as a recurring Celery task or a standalone script.
    """
    embedder = OpenAIEmbedder(api_key=openai_api_key, model=model, redis_url=redis_url)
    stats = {"processed": 0, "errors": 0, "cached": 0}

    async with await psycopg.AsyncConnection.connect(db_url, row_factory=dict_row) as conn:
        while True:
            # Fetch next batch of chunks lacking embeddings for this model
            async with conn.cursor() as cur:
                await cur.execute(
                    """
                    SELECT dc.id, dc.chunk_text
                    FROM document_chunks dc
                    LEFT JOIN chunk_embeddings ce
                        ON ce.chunk_id = dc.id AND ce.embedding_model = %s
                    WHERE ce.id IS NULL
                      AND EXISTS (
                          SELECT 1 FROM documents d
                          WHERE d.id = dc.document_id
                            AND d.ingestion_status = 'complete'
                      )
                    ORDER BY dc.created_at
                    LIMIT %s
                    FOR UPDATE OF dc SKIP LOCKED
                    """,
                    (model, batch_size),
                )
                rows = await cur.fetchall()

            if not rows:
                break

            chunk_ids = [r["id"] for r in rows]
            chunk_texts = [r["chunk_text"] for r in rows]

            try:
                embeddings = await embedder.embed_texts(chunk_texts)
                await store_embeddings(conn, chunk_ids, embeddings, model)
                await conn.commit()
                stats["processed"] += len(chunk_ids)
                logger.info(f"Embedded {len(chunk_ids)} chunks with {model}")
            except Exception as e:
                await conn.rollback()
                stats["errors"] += len(chunk_ids)
                logger.error(f"Embedding batch failed: {e}")
                # Continue to next batch rather than aborting the whole job
                continue

    return stats

The FOR UPDATE ... SKIP LOCKED pattern in embed_pending_chunks allows multiple worker processes to pull from the same queue concurrently without double-processing any chunk. Each worker locks its batch, embeds, writes, and commits; other workers skip those rows and take the next available ones. This is PostgreSQL as a work queue — no Redis job broker needed for this particular coordination problem.

14.4 Asynchronous Ingestion with Celery and PostgreSQL

The embedding step above can run standalone, but a full ingestion pipeline needs orchestration: document submission triggers chunking, chunking completion triggers embedding, and all of this must be observable and recoverable. Celery with PostgreSQL as the result backend is a robust foundation for this.

# tasks.py — Celery task definitions for the ingestion pipeline

import logging
import os

import celery
from celery import Celery, chord, chain
from celery.utils.log import get_task_logger
import psycopg
from psycopg.rows import dict_row
import httpx

from embedder import OpenAIEmbedder, store_embeddings
import asyncio

    "ingestion",

)

app.conf.update(

    result_serializer="json",
    accept_content=["json"],
    timezone="UTC",
    enable_utc=True,
    task_acks_late=True,            # Acknowledge only after task completes
    task_reject_on_worker_lost=True,  # Re-queue if worker dies mid-task
    worker_prefetch_multiplier=1,    # One task at a time per worker for memory control
    task_routes={
        "tasks.chunk_document": {"queue": "chunking"},
        "tasks.embed_chunks": {"queue": "embedding"},
        "tasks.finalize_document": {"queue": "default"},
    },

DB_URL = os.environ["DATABASE_URL"]
OPENAI_API_KEY = os.environ["OPENAI_API_KEY"]
REDIS_URL = os.environ.get("REDIS_URL")


def get_sync_conn():
    """Synchronous connection for use inside Celery tasks."""
    return psycopg.connect(DB_URL, row_factory=dict_row)


@app.task(
    bind=True,
    max_retries=3,
    default_retry_delay=30,
    name="tasks.ingest_document",
)
def ingest_document(self, document_id: str) -> dict:
    """
    Entry point: fetch raw content, compute hash, detect if changed.
    If the document is new or modified, kick off the chunking task.
    """
    try:
        with get_sync_conn() as conn:
            with conn.cursor() as cur:
                cur.execute(
                    "SELECT * FROM documents WHERE id = %s FOR UPDATE",
                    (document_id,),
                )
                doc = cur.fetchone()
                if not doc:
                    return {"status": "not_found", "document_id": document_id}

                # Mark as in-progress
                cur.execute(
                    """
                    UPDATE documents
                    SET ingestion_status = 'chunking', updated_at = now()
                    WHERE id = %s
                    """,
                    (document_id,),
                )

                # Log the job start
                cur.execute(
                    """
                    INSERT INTO ingestion_jobs
                        (document_id, job_type, status, celery_task_id, started_at, worker_id)
                    VALUES (%s, 'ingest', 'running', %s, now(), %s)
                    RETURNING id
                    """,
                    (document_id, self.request.id, self.request.hostname),
                )
                job_id = cur.fetchone()["id"]
            conn.commit()

        # Chain: chunk → embed → finalize
        task_chain = chain(
            chunk_document.s(document_id, str(job_id)),
            embed_chunks.s(document_id, str(job_id)),
            finalize_document.s(document_id, str(job_id)),
        )
        task_chain.apply_async()

        return {"status": "pipeline_started", "document_id": document_id, "job_id": str(job_id)}

    except Exception as exc:
        logger.error(f"ingest_document failed for {document_id}: {exc}")
        raise self.retry(exc=exc)


@app.task(
    bind=True,
    max_retries=3,
    default_retry_delay=60,
    name="tasks.chunk_document",
    time_limit=600,         # 10 minutes max for chunking
    soft_time_limit=540,
)
def chunk_document(self, document_id: str, job_id: str) -> dict:
    """
    Parse and chunk the document. Stores chunks in document_chunks.
    Returns chunk count for the next task in the chain.
    """
    try:
        with get_sync_conn() as conn:
            with conn.cursor() as cur:
                cur.execute(
                    """
                    SELECT d.*, dc.settings
                    FROM documents d
                    LEFT JOIN document_collections dc ON dc.id = d.collection_id
                    WHERE d.id = %s
                    """,
                    (document_id,),
                )
                doc = cur.fetchone()

            # Fetch content from source
            content = _fetch_content(doc)

            # Select chunker based on source type and collection settings
            settings = doc.get("settings") or {}
            chunker = select_chunker(doc["source_type"], settings)

            # Delete existing chunks for this document (re-ingestion scenario)
            with conn.cursor() as cur:
                cur.execute(
                    "DELETE FROM document_chunks WHERE document_id = %s",
                    (document_id,),
                )

            # Chunk and insert
            # (_fetch_content returns raw bytes for PDFs and decoded text otherwise;
            # the chunker returned by select_chunker() already matches the source type)
            chunks: list[ChunkResult] = list(chunker.chunk(content))

            if chunks:
                chunk_records = [
                    (
                        document_id,
                        c.chunk_index,
                        c.text,
                        c.token_count,
                        c.char_start,
                        c.char_end,
                        c.page_number,
                        c.section_title,
                        c.chunk_type,
                        psycopg.types.json.Jsonb(c.metadata),
                    )
                    for c in chunks
                ]

                with conn.cursor() as cur:
                    cur.executemany(
                        """
                        INSERT INTO document_chunks
                            (document_id, chunk_index, chunk_text, token_count,
                             start_char, end_char, page_number, section_title,
                             chunk_type, metadata)
                        VALUES (%s, %s, %s, %s, %s, %s, %s, %s, %s, %s)
                        """,
                        chunk_records,
                    )

            # Update document status and job stats
            with conn.cursor() as cur:
                cur.execute(
                    """
                    UPDATE documents
                    SET ingestion_status = 'embedding', updated_at = now()
                    WHERE id = %s
                    """,
                    (document_id,),
                )
                cur.execute(
                    """
                    UPDATE ingestion_jobs
                    SET chunks_created = %s
                    WHERE id = %s
                    """,
                    (len(chunks), job_id),
                )
            conn.commit()

        logger.info(f"Chunked document {document_id} into {len(chunks)} chunks")
        return {"chunk_count": len(chunks), "document_id": document_id}

    except Exception as exc:
        _mark_document_failed(document_id, job_id, str(exc))
        logger.error(f"chunk_document failed for {document_id}: {exc}")
        raise self.retry(exc=exc)


@app.task(
    bind=True,
    max_retries=3,
    default_retry_delay=120,
    name="tasks.embed_chunks",
    time_limit=3600,        # 1 hour max for large documents
    soft_time_limit=3540,
)
def embed_chunks(self, prev_result: dict, document_id: str, job_id: str) -> dict:
    """
    Generate embeddings for all chunks belonging to this document.
    Runs the async embedder inside the synchronous Celery task.
    """
    try:
        async def _run():
            embedder = OpenAIEmbedder(
                api_key=OPENAI_API_KEY,
                model="text-embedding-3-small",
                redis_url=REDIS_URL,
            )

            async with await psycopg.AsyncConnection.connect(DB_URL, row_factory=dict_row) as conn:
                async with conn.cursor() as cur:
                    await cur.execute(
                        """
                        SELECT id, chunk_text
                        FROM document_chunks
                        WHERE document_id = %s
                        ORDER BY chunk_index
                        """,
                        (document_id,),
                    )
                    rows = await cur.fetchall()

                if not rows:
                    return 0

                # Embed in batches of 256
                batch_size = 256
                total_embedded = 0
                for i in range(0, len(rows), batch_size):
                    batch = rows[i:i + batch_size]
                    ids = [r["id"] for r in batch]
                    texts = [r["chunk_text"] for r in batch]
                    embeddings = await embedder.embed_texts(texts)
                    count = await store_embeddings(conn, ids, embeddings, "text-embedding-3-small")
                    await conn.commit()
                    total_embedded += count

                return total_embedded

        total = asyncio.run(_run())

        with get_sync_conn() as conn:
            with conn.cursor() as cur:
                cur.execute(
                    """
                    UPDATE documents
                    SET ingestion_status = 'complete',
                        last_ingested_at = now(),
                        updated_at = now()
                    WHERE id = %s
                    """,
                    (document_id,),
                )
                cur.execute(
                    """
                    UPDATE ingestion_jobs
                    SET embeddings_created = %s
                    WHERE id = %s
                    """,
                    (total, job_id),
                )
            conn.commit()

        return {"embeddings_created": total, "document_id": document_id}

    except Exception as exc:
        _mark_document_failed(document_id, job_id, str(exc))
        logger.error(f"embed_chunks failed for {document_id}: {exc}")
        raise self.retry(exc=exc)


@app.task(name="tasks.finalize_document")
def finalize_document(prev_result: dict, document_id: str, job_id: str) -> dict:
    """
    Mark the ingestion job complete and emit any post-processing hooks.
    """
    with get_sync_conn() as conn:
        with conn.cursor() as cur:
            cur.execute(
                """
                UPDATE ingestion_jobs
                SET status = 'complete', completed_at = now()
                WHERE id = %s
                """,
                (job_id,),
            )
        conn.commit()

    logger.info(f"Document {document_id} ingestion complete. Job {job_id} finalized.")
    return {"status": "complete", "document_id": document_id, "job_id": job_id}


def _mark_document_failed(document_id: str, job_id: str, error: str) -> None:
    """Helper: update document and job status to failed."""
    try:
        with get_sync_conn() as conn:
            with conn.cursor() as cur:
                cur.execute(
                    """
                    UPDATE documents
                    SET ingestion_status = 'failed', error_message = %s, updated_at = now()
                    WHERE id = %s
                    """,
                    (error[:2000], document_id),
                )
                cur.execute(
                    """
                    UPDATE ingestion_jobs
                    SET status = 'failed', error_message = %s, completed_at = now()
                    WHERE id = %s
                    """,
                    (error[:2000], job_id),
                )
            conn.commit()
    except Exception as e:
        logger.error(f"Failed to mark document {document_id} as failed: {e}")


def _fetch_content(doc: dict) -> bytes | str:
    """
    Retrieve raw document content from its source URI.
    Returns bytes for PDFs, str for text-based formats.
    """
    uri = doc["source_uri"]
    source_type = doc["source_type"]

    if uri.startswith("s3://"):
        import boto3
        s3 = boto3.client("s3")
        bucket, key = uri[5:].split("/", 1)
        response = s3.get_object(Bucket=bucket, Key=key)
        content = response["Body"].read()
        return content if source_type == "pdf" else content.decode("utf-8")
    elif uri.startswith("http"):
        response = httpx.get(uri, timeout=30)
        response.raise_for_status()
        return response.content if source_type == "pdf" else response.text
    else:
        # Local file path
        mode = "rb" if source_type == "pdf" else "r"
        with open(uri, mode) as f:
            return f.read()

The Celery chain — chunk_document → embed_chunks → finalize_document — models the ingestion pipeline as a series of dependent tasks. If embedding fails, the document stays in embedding status and the retry logic re-runs only the embedding step, not re-chunking. The task_acks_late=True setting ensures a task is acknowledged only after it completes, so a worker crash mid-task puts the message back in the queue for another worker to pick up.

14.5 Incremental Updates and Deduplication

Documents change. New versions of product documentation are published, wiki pages are edited, and crawled web content is refreshed nightly. A robust ingestion pipeline must handle updates without duplicating content or leaving stale embeddings behind.

The content_hash column in documents drives this logic. When a document is submitted for ingestion, compute the SHA-256 of its raw bytes before doing anything else. If the hash matches the stored value, skip the document entirely — it has not changed. If the hash differs, the document has been modified and needs re-ingestion.

# ingestion_api.py — FastAPI endpoint for submitting documents
import hashlib
from fastapi import FastAPI, HTTPException, BackgroundTasks
from pydantic import BaseModel, AnyHttpUrl
import psycopg
from psycopg.rows import dict_row
import httpx
from tasks import ingest_document

app = FastAPI()


class DocumentSubmission(BaseModel):
    source_uri: str
    source_type: str
    title: str | None = None
    collection_id: str | None = None
    metadata: dict = {}
    force_reprocess: bool = False


@app.post("/documents/submit")
async def submit_document(submission: DocumentSubmission):
    """
    Submit a document for ingestion. Idempotent: if the document
    exists and has not changed, returns the existing record immediately.
    """
    # Fetch content to compute hash
    try:
        if submission.source_uri.startswith("http"):
            async with httpx.AsyncClient() as client:
                response = await client.get(submission.source_uri, timeout=30)
                response.raise_for_status()
                raw_bytes = response.content
        else:
            with open(submission.source_uri, "rb") as f:
                raw_bytes = f.read()
    except Exception as e:
        raise HTTPException(status_code=422, detail=f"Could not fetch document: {e}")

    content_hash = hashlib.sha256(raw_bytes).hexdigest()

    async with await psycopg.AsyncConnection.connect(
        os.environ["DATABASE_URL"], row_factory=dict_row
    ) as conn:
        async with conn.cursor() as cur:
            # Check for existing document with same URI
            await cur.execute(
                "SELECT id, content_hash, ingestion_status FROM documents WHERE source_uri = %s",
                (submission.source_uri,),
            )
            existing = await cur.fetchone()

        if existing and not submission.force_reprocess:
            if existing["content_hash"] == content_hash:
                # Nothing changed — return immediately
                return {
                    "document_id": existing["id"],
                    "status": "unchanged",
                    "message": "Document content unchanged; no reprocessing needed.",
                }
            else:
                # Content changed — update hash and re-ingest
                async with conn.cursor() as cur:
                    await cur.execute(
                        """
                        UPDATE documents
                        SET content_hash = %s,
                            ingestion_status = 'pending',
                            error_message = NULL,
                            updated_at = now()
                        WHERE id = %s
                        """,
                        (content_hash, existing["id"]),
                    )
                await conn.commit()
                document_id = existing["id"]
        else:
            # New document — insert it
            async with conn.cursor() as cur:
                await cur.execute(
                    """
                    INSERT INTO documents
                        (source_uri, source_type, title, content_hash,
                         byte_size, metadata, collection_id, ingestion_status)
                    VALUES (%s, %s, %s, %s, %s, %s::jsonb, %s, 'pending')
                    RETURNING id
                    """,
                    (
                        submission.source_uri,
                        submission.source_type,
                        submission.title,
                        content_hash,
                        len(raw_bytes),
                        psycopg.types.json.Jsonb(submission.metadata),
                        submission.collection_id,
                    ),
                )
                document_id = (await cur.fetchone())["id"]
            await conn.commit()

    # Fire async ingestion task
    ingest_document.delay(str(document_id))

    return {
        "document_id": str(document_id),
        "status": "queued",
        "content_hash": content_hash,
    }

For collections that sync from an external source — a Confluence space, a GitHub repository, a shared drive — a batch sync job can enumerate all known document URIs, compute their hashes, and submit only the changed ones:

-- Query: find documents whose URIs appear in a submitted sync batch but whose
-- hashes differ, or that are entirely new to the collection.
-- Useful for the sync job to determine what actually needs processing.

WITH sync_batch (uri, new_hash) AS (
    -- In practice this comes from your application layer;
    -- shown here as a VALUES clause for illustration
    VALUES
        ('s3://docs-bucket/product-guide.pdf', 'abc123...'),
        ('s3://docs-bucket/api-reference.md',  'def456...'),
        ('s3://docs-bucket/changelog.md',       'ghi789...')
),
existing AS (
    SELECT source_uri, content_hash, ingestion_status
    FROM documents
    WHERE collection_id = '00000000-0000-0000-0000-000000000001'
)
SELECT
    sb.uri,
    sb.new_hash,
    e.content_hash AS stored_hash,
    CASE
        WHEN e.source_uri IS NULL      THEN 'new'
        WHEN e.content_hash != sb.new_hash THEN 'changed'
        ELSE                                     'unchanged'
    END AS action_needed
FROM sync_batch sb
LEFT JOIN existing e ON e.source_uri = sb.uri
WHERE e.source_uri IS NULL
   OR e.content_hash != sb.new_hash;

The same pattern applies for deletion. When a document is removed from the source, cascade deletes via the foreign keys in the schema automatically remove its chunks and embeddings. Your sync job just needs to identify URIs that no longer exist in the source and DELETE FROM documents WHERE source_uri = ANY(removed_uris).

14.6 Monitoring Pipeline Health

A pipeline that runs invisibly is a pipeline that fails invisibly. PostgreSQL's own tables are the monitoring backend — no external observability tool is needed to answer the most common operational questions.

-- Ingestion pipeline health dashboard queries

-- 1. Overall status distribution
SELECT
    ingestion_status,
    COUNT(*) AS doc_count,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS pct
FROM documents
GROUP BY ingestion_status
ORDER BY doc_count DESC;

-- 2. Documents stuck in intermediate states (likely stalled workers)
SELECT
    id,
    source_uri,
    ingestion_status,
    updated_at,
    EXTRACT(EPOCH FROM (now() - updated_at)) / 60 AS minutes_stuck
FROM documents
WHERE ingestion_status IN ('chunking', 'embedding')
  AND updated_at < now() - INTERVAL '30 minutes'
ORDER BY updated_at;

-- 3. Recent failures with error messages
SELECT
    d.id,
    d.source_uri,
    d.error_message,
    j.started_at,
    j.completed_at,
    j.retry_count,
    j.worker_id
FROM documents d
JOIN ingestion_jobs j ON j.document_id = d.id AND j.job_type = 'ingest'
WHERE d.ingestion_status = 'failed'
  AND j.created_at > now() - INTERVAL '24 hours'
ORDER BY j.created_at DESC
LIMIT 50;

-- 4. Throughput over time (chunks and embeddings per hour)
SELECT
    DATE_TRUNC('hour', completed_at) AS hour,
    SUM(chunks_created)     AS chunks_created,
    SUM(embeddings_created) AS embeddings_created,
    COUNT(*)                AS documents_completed
FROM ingestion_jobs
WHERE status = 'complete'
  AND completed_at > now() - INTERVAL '7 days'
GROUP BY 1
ORDER BY 1 DESC;

-- 5. Documents awaiting embedding (chunks exist but no embeddings yet)
SELECT
    d.collection_id,
    dc_name.name AS collection_name,
    COUNT(DISTINCT dc.document_id) AS docs_with_unembedded_chunks,
    COUNT(dc.id) AS total_unembedded_chunks
FROM document_chunks dc
JOIN documents d ON d.id = dc.document_id
LEFT JOIN document_collections dc_name ON dc_name.id = d.collection_id
LEFT JOIN chunk_embeddings ce
    ON ce.chunk_id = dc.id
    AND ce.embedding_model = 'text-embedding-3-small'
WHERE ce.id IS NULL
GROUP BY d.collection_id, dc_name.name
ORDER BY total_unembedded_chunks DESC;

-- 6. Embedding model coverage (what fraction of chunks have each model's embedding)
SELECT
    ce.embedding_model,
    COUNT(DISTINCT ce.chunk_id)                       AS chunks_embedded,
    (SELECT COUNT(*) FROM document_chunks)            AS total_chunks,
    ROUND(
        100.0 * COUNT(DISTINCT ce.chunk_id)
        / NULLIF((SELECT COUNT(*) FROM document_chunks), 0),
        1
    ) AS coverage_pct
FROM chunk_embeddings ce
GROUP BY ce.embedding_model
ORDER BY chunks_embedded DESC;

For automated alerting, wrap the "stuck documents" query in a scheduled function that sends a notification when the count exceeds a threshold:

-- pg_cron job: check every 5 minutes for stalled ingestion jobs
-- Requires pg_cron and pg_notify (or any notification mechanism)
CREATE OR REPLACE FUNCTION alert_stalled_ingestion()
RETURNS void LANGUAGE plpgsql AS $$
DECLARE
    stalled_count INT;
BEGIN
    SELECT COUNT(*) INTO stalled_count
    FROM documents
    WHERE ingestion_status IN ('chunking', 'embedding')
      AND updated_at < now() - INTERVAL '30 minutes';

    IF stalled_count > 0 THEN
        PERFORM pg_notify(
            'ingestion_alerts',
            json_build_object(
                'event', 'stalled_documents',
                'count', stalled_count,
                'checked_at', now()
            )::text
        );
    END IF;
END;
$$;

-- Schedule with pg_cron (requires pg_cron extension)
SELECT cron.schedule(
    'check-stalled-ingestion',
    '*/5 * * * *',
    'SELECT alert_stalled_ingestion()'
);

Your application layer subscribes to the ingestion_alerts channel via LISTEN and routes the notification to your alerting platform of choice — PagerDuty, Slack, or a metrics endpoint. The advantage over polling an external monitoring database is zero latency: the notification fires the moment the condition is evaluated, and it fires from within the same PostgreSQL instance that owns the data.

14.7 Re-embedding When Models Change

Embedding models are not static. When you migrate from text-embedding-ada-002 to text-embedding-3-small, or when your team decides to switch to a different provider's model, you need to regenerate all embeddings without interrupting query traffic.

The schema already supports this: the chunk_embeddings table stores embeddings keyed by (chunk_id, embedding_model). During migration, new embeddings can be generated in parallel with the old ones. Query code is updated to use the new model's embeddings only after the migration is complete. Here is the migration workflow:

-- Step 1: Check current embedding coverage before migration
SELECT
    embedding_model,
    COUNT(*) AS embedding_count,
    MIN(created_at) AS oldest_embedding,
    MAX(created_at) AS newest_embedding
FROM chunk_embeddings
GROUP BY embedding_model
ORDER BY embedding_count DESC;

-- Step 2: Identify chunks that need the new model's embeddings
-- This query drives the migration worker
SELECT
    dc.id AS chunk_id,
    dc.chunk_text,
    dc.document_id
FROM document_chunks dc
LEFT JOIN chunk_embeddings ce
    ON ce.chunk_id = dc.id
    AND ce.embedding_model = 'text-embedding-3-large'   -- target model
WHERE ce.id IS NULL
ORDER BY dc.created_at
LIMIT 1000;

-- Step 3: After generating new embeddings, verify coverage parity
SELECT
    old_model.embedding_model AS old_model,
    new_model.embedding_model AS new_model,
    old_model.cnt AS old_count,
    new_model.cnt AS new_count,
    new_model.cnt - old_model.cnt AS gap
FROM
    (SELECT embedding_model, COUNT(*) AS cnt
     FROM chunk_embeddings
     WHERE embedding_model = 'text-embedding-3-small'
     GROUP BY embedding_model) old_model
CROSS JOIN
    (SELECT embedding_model, COUNT(*) AS cnt
     FROM chunk_embeddings
     WHERE embedding_model = 'text-embedding-3-large'
     GROUP BY embedding_model) new_model;

-- Step 4: Once coverage is confirmed complete, drop old embeddings
-- Run this only after updating your query code to use the new model
DELETE FROM chunk_embeddings
WHERE embedding_model = 'text-embedding-3-small';

-- Step 5: Drop the now-unused partial index and create one for the new model
DROP INDEX IF EXISTS idx_embeddings_small;

CREATE INDEX idx_embeddings_large_hnsw ON chunk_embeddings
    USING hnsw (embedding vector_cosine_ops)
    WHERE embedding_model = 'text-embedding-3-large';

The re-embedding migration can be run as a background Celery task that processes chunks in batches, with no service interruption:

# migration_task.py — background re-embedding for model migration
@app.task(
    bind=True,
    name="tasks.migrate_embeddings",
    max_retries=10,
    default_retry_delay=60,
    time_limit=86400,       # 24 hours max; large corpora take time
)
def migrate_embeddings(
    self,
    source_model: str,
    target_model: str,
    batch_size: int = 256,
) -> dict:
    """
    Generate target_model embeddings for all chunks that currently
    have source_model embeddings but lack target_model embeddings.
    Safe to run concurrently with live query traffic.
    """
    stats = {"migrated": 0, "errors": 0, "batches": 0}

    async def _run_migration():
        embedder = OpenAIEmbedder(
            api_key=OPENAI_API_KEY,
            model=target_model,
            redis_url=REDIS_URL,
        )

        async with await psycopg.AsyncConnection.connect(
            DB_URL, row_factory=dict_row
        ) as conn:
            while True:
                # Fetch chunks that have source model embedding but not target
                async with conn.cursor() as cur:
                    await cur.execute(
                        """
                        SELECT dc.id, dc.chunk_text
                        FROM document_chunks dc
                        JOIN chunk_embeddings src_ce
                            ON src_ce.chunk_id = dc.id
                            AND src_ce.embedding_model = %s
                        LEFT JOIN chunk_embeddings tgt_ce
                            ON tgt_ce.chunk_id = dc.id
                            AND tgt_ce.embedding_model = %s
                        WHERE tgt_ce.id IS NULL
                        ORDER BY dc.created_at
                        LIMIT %s
                        FOR UPDATE OF dc SKIP LOCKED
                        """,
                        (source_model, target_model, batch_size),
                    )
                    rows = await cur.fetchall()

                if not rows:
                    break

                ids = [r["id"] for r in rows]
                texts = [r["chunk_text"] for r in rows]

                try:
                    embeddings = await embedder.embed_texts(texts)
                    await store_embeddings(conn, ids, embeddings, target_model)
                    await conn.commit()
                    stats["migrated"] += len(ids)
                    stats["batches"] += 1
                    logger.info(
                        f"Migration progress: {stats['migrated']} chunks "
                        f"migrated to {target_model}"
                    )
                except Exception as e:
                    await conn.rollback()
                    stats["errors"] += len(ids)
                    logger.error(f"Migration batch failed: {e}")
                    continue

        return stats

    result = asyncio.run(_run_migration())
    return result

A practical migration sequence for a production system:

1. Deploy the new idx_embeddings_large_hnsw index as a partial index (it covers no rows yet, so creation is instant).

2. Start migrate_embeddings.delay("text-embedding-3-small", "text-embedding-3-large"). This runs in the background.

3. Monitor coverage using the Step 2 query above. The gap should shrink steadily.

4. When coverage reaches 100%, update your retrieval query to use text-embedding-3-large.

5. Give the new model a burn-in period — a few days of production traffic — before deleting old embeddings.

6. Delete old embeddings and drop the old partial index.

This blue-green approach to embedding migration avoids any hard cutover and gives you a clean rollback path: if the new model underperforms, point the retrieval query back at the old model. The old embeddings are still there until you explicitly delete them.

14.8 Practical Considerations for Large Corpora

When the document corpus grows beyond tens of thousands of files, several aspects of the pipeline need explicit attention.

Table partitioning for chunk_embeddings. As chunks accumulate, the chunk_embeddings table can grow to hundreds of millions of rows. Partitioning by embedding_model maps naturally to the partial indexes already in use:

-- Convert chunk_embeddings to a partitioned table (new installations)
-- For existing tables, this requires a migration with pg_partman or manual steps

CREATE TABLE chunk_embeddings_partitioned (
    id              UUID NOT NULL DEFAULT gen_random_uuid(),
    chunk_id        UUID NOT NULL,
    embedding_model TEXT NOT NULL,
    embedding_dim   INT NOT NULL,
    embedding       vector(1536),
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
) PARTITION BY LIST (embedding_model);

CREATE TABLE chunk_embeddings_small
    PARTITION OF chunk_embeddings_partitioned
    FOR VALUES IN ('text-embedding-3-small');

CREATE TABLE chunk_embeddings_large
    PARTITION OF chunk_embeddings_partitioned
    FOR VALUES IN ('text-embedding-3-large');

CREATE TABLE chunk_embeddings_ada
    PARTITION OF chunk_embeddings_partitioned
    FOR VALUES IN ('text-embedding-ada-002');

-- HNSW index on each partition directly (not on the parent)
CREATE INDEX ON chunk_embeddings_small
    USING hnsw (embedding vector_cosine_ops);

CREATE INDEX ON chunk_embeddings_large
    USING hnsw (embedding vector_cosine_ops);

Queries that filter by embedding_model = 'text-embedding-3-small' hit only the relevant partition, and the HNSW index lives entirely on that partition rather than being spread across a combined table.

HNSW index build parameters. The default HNSW parameters (m=16, ef_construction=64) are conservative. For large corpora where recall quality matters more than index build time, increasing these values improves recall at the cost of more memory and longer build time:

-- Higher quality HNSW index for production retrieval
CREATE INDEX idx_embeddings_small_hq ON chunk_embeddings_small
    USING hnsw (embedding vector_cosine_ops)
    WITH (m = 32, ef_construction = 128);

The m parameter controls how many bidirectional links each node maintains in the graph; higher values improve recall but increase index size roughly linearly. The ef_construction parameter controls how many candidates are considered during index construction; values between 64 and 256 cover most production needs. Both parameters can be tuned empirically by measuring recall against a held-out set of known query-chunk pairs.

Parallel ingestion throughput. Celery workers for chunking and embedding should run on separate queues with different concurrency settings. Chunking is CPU-bound (PDF parsing, tokenization) so a worker concurrency equal to the number of CPU cores makes sense. Embedding is I/O-bound (waiting on API responses) so a higher concurrency — ten to twenty workers per machine — saturates available API quota without wasting CPU cycles.

# Procfile or supervisor configuration
worker_chunking: celery -A tasks worker -Q chunking --concurrency=4 --loglevel=info
worker_embedding: celery -A tasks worker -Q embedding --concurrency=16 --loglevel=info
worker_default:  celery -A tasks worker -Q default   --concurrency=4 --loglevel=info

Handling very large documents. PDFs with hundreds of pages can take minutes to parse and produce thousands of chunks. For these, it helps to split the document-level task into page-range subtasks, allowing multiple workers to process different sections of the same document concurrently. The chunk_index column ensures that the resulting chunks maintain their correct ordinal position regardless of which worker produced them.

Avoiding hot spots on document_chunks inserts. When many workers insert chunks simultaneously, contention on the UUID primary key's index can become a bottleneck. PostgreSQL's UUIDs generated with gen_random_uuid() are uniformly distributed, which avoids B-tree index hot spots far better than sequential integer keys would under high concurrent insert load. No special action is needed here — the default UUID primary key already handles this correctly.

Key Takeaways

  • → **Separate your schema into documents, chunks, and embeddings** rather than collapsing everything into one flat table. This separation allows re-embedding with new models without re-parsing documents, enables A/B comparisons between embedding models, and gives you the relational joins needed to answer operational questions about pipeline state.
  • → **Chunking strategy should match document structure**: Markdown benefits from header-aware splitting that preserves section context; PDFs need paragraph-boundary detection across pages; dense technical content benefits from semantic chunking that uses embedding similarity to find natural topical breakpoints. A fixed-size splitter is a reasonable default but rarely the best choice.
  • → **Use `FOR UPDATE ... SKIP LOCKED` for queue-style processing**: This PostgreSQL pattern lets multiple concurrent workers pull from the same queue of unprocessed items without double-processing, without a separate job broker, and with full transactional safety. The same pattern works for embedding workers, migration workers, and any other batch processor.
  • → **The `content_hash` column makes ingestion idempotent**: Hashing raw document bytes before any processing lets you skip unchanged documents on re-sync, detect updates reliably, and avoid the compounding cost of re-processing a ten-thousand-document corpus when only a handful of files actually changed.
  • → **Embed model migrations can run live with zero service interruption**: Because the schema stores embeddings keyed by model name, you can generate new model embeddings alongside existing ones, verify complete coverage, update retrieval queries, and clean up old embeddings — all without a maintenance window or hard cutover.
