Chapter 23: Tagging Strategy for Database Cost Allocation

Organizations that implement a disciplined database tagging strategy typically recover 15–30% of their cloud database spend within the first quarter—not by rightsizing instances or switching storage classes, but simply by discovering who owns what, which workloads are generating the bills, and where untagged or mistagged resources have been silently accumulating charges for months. A 500-instance RDS estate with inconsistent tagging can hide $40,000–$80,000 per month in costs that no team claims ownership of, no budget is allocated for, and no engineer is motivated to optimize. This chapter builds a complete tagging strategy from schema design through enforcement automation, covering AWS RDS, Azure SQL, and Google Cloud SQL, with cost allocation queries, policy enforcement scripts, and a scheduled audit pipeline that keeps your tag compliance above 95%.

---

23.1 Designing a Tag Schema That Finance and Engineering Both Respect

The most common tagging failure is not technical—it is organizational. Engineers apply tags that make sense for operations (env=prod, db=postgres) while Finance needs tags that map to budget lines (cost-center=CC-4421, project=Q3-Migration). The two systems never reconcile, showback reports are disputed, and the entire exercise collapses into a spreadsheet maintained by one person who eventually leaves.

A workable schema serves both audiences with a small, mandatory set of tags and an extended set of optional enrichment tags.

Mandatory Tag Set (enforce via policy)

| Tag Key | Example Values | Owner | Purpose |

|---|---|---|---|

| env | prod, staging, dev, sandbox | Engineering | Environment classification |

| team | payments, analytics, platform | Engineering | Team ownership |

| cost-center | CC-4421, CC-0012 | Finance | Budget line alignment |

| project | checkout-v2, data-warehouse | PM / Engineering | Project-level chargeback |

| application | order-service, reporting-api | Engineering | Application owner |

| managed-by | terraform, cloudformation, manual | Platform | IaC drift detection |

Extended Tag Set (recommended, not enforced)

| Tag Key | Example Values | Purpose |

|---|---|---|

| data-classification | pii, financial, internal | Compliance tagging |

| backup-policy | daily-7d, weekly-30d | Backup tier identification |

| dr-tier | tier1, tier2, tier3 | Recovery priority |

| schedule | business-hours, always-on | Scheduling automation (Chapter 24) |

| rightsizing-exempt | true, false | Block automated rightsizing |

AWS RDS Tagging Limits

AWS RDS supports up to 50 tags per resource. Tag keys are case-sensitive: Environment and environment are two different tags. Establish a naming convention enforced by policy—lowercase, hyphenated, no spaces. A tag key collision between teams (Env vs env vs ENV) is one of the most common reasons cost allocation reports produce duplicates that Finance refuses to trust.

Azure SQL Tagging

Azure SQL resources (servers, databases, elastic pools) support up to 50 tags. Tags applied at the resource group level do not automatically inherit to individual database resources—a common misconception that leaves individual Azure SQL databases untagged even when the resource group appears compliant.

Google Cloud SQL Labeling

GCP uses "labels" rather than "tags." Labels support up to 64 key-value pairs. GCP labels flow automatically into the BigQuery billing export, making them the primary mechanism for cost allocation queries in the gcp_billing_export dataset.

23.2 Discovering What Is Untagged Right Now

Before building enforcement pipelines, you need a baseline. The following queries and scripts identify every database resource across all three clouds that is missing one or more mandatory tags.

AWS: Find Untagged or Partially Tagged RDS Instances

#!/bin/bash
# audit_rds_tags.sh
# Scans all RDS instances across all regions and reports tag compliance
# Schedule: daily via EventBridge + Lambda or cron on a bastion host
# Output: CSV suitable for ingestion into cost dashboards

MANDATORY_TAGS=("env" "team" "cost-center" "project" "application")
REGIONS=$(aws ec2 describe-regions --query "Regions[].RegionName" --output text)

echo "region,db_instance,instance_class,monthly_est_usd,missing_tags"

for REGION in $REGIONS; do
  INSTANCES=$(aws rds describe-db-instances \
    --region "$REGION" \
    --query "DBInstances[*].[DBInstanceIdentifier,DBInstanceClass,DBInstanceArn]" \
    --output text 2>/dev/null)

  while IFS=$'\t' read -r DB_ID DB_CLASS DB_ARN; do
    [ -z "$DB_ID" ] && continue

    # Fetch existing tags for this instance
    EXISTING_TAGS=$(aws rds list-tags-for-resource \
      --resource-name "$DB_ARN" \
      --region "$REGION" \
      --query "TagList[].Key" \
      --output text 2>/dev/null | tr '\t' '\n' | tr '[:upper:]' '[:lower:]')

    MISSING=""
    for TAG in "${MANDATORY_TAGS[@]}"; do
      if ! echo "$EXISTING_TAGS" | grep -qx "$TAG"; then
        MISSING="$MISSING $TAG"
      fi
    done

    MISSING=$(echo "$MISSING" | xargs)  # trim whitespace

    if [ -n "$MISSING" ]; then
      # Rough monthly cost estimate based on instance class
      # Replace with aws ce get-cost-and-usage for exact figures
      MONTHLY_EST="unknown"
      echo "$REGION,$DB_ID,$DB_CLASS,$MONTHLY_EST,\"$MISSING\""
    fi
  done <<< "$INSTANCES"
done

Run this script on a schedule and pipe the output to an S3 bucket. The CSV becomes the input for your weekly tag compliance report. A 200-instance estate typically surfaces 40–80 instances with missing mandatory tags on the first run.

Azure: Identify Untagged Azure SQL Resources

#!/bin/bash
# audit_azure_sql_tags.sh
# Requires: az cli authenticated with Reader role on target subscriptions

MANDATORY_TAGS=("env" "team" "cost-center" "project" "application")
SUBSCRIPTIONS=$(az account list --query "[].id" --output tsv)

echo "subscription,resource_group,server,database,missing_tags"

for SUB in $SUBSCRIPTIONS; do
  az account set --subscription "$SUB" 2>/dev/null

  # Scan SQL servers
  SERVERS=$(az sql server list \
    --query "[*].[name,resourceGroup]" \
    --output tsv 2>/dev/null)

  while IFS=$'\t' read -r SERVER RG; do
    [ -z "$SERVER" ] && continue

    # Get databases under this server
    DATABASES=$(az sql db list \
      --server "$SERVER" \
      --resource-group "$RG" \
      --query "[?name!='master'].[name]" \
      --output tsv 2>/dev/null)

    while IFS=$'\t' read -r DB_NAME; do
      [ -z "$DB_NAME" ] && continue

      DB_TAGS=$(az sql db show \
        --name "$DB_NAME" \
        --server "$SERVER" \
        --resource-group "$RG" \
        --query "tags" \
        --output json 2>/dev/null)

      MISSING=""
      for TAG in "${MANDATORY_TAGS[@]}"; do
        if ! echo "$DB_TAGS" | python3 -c \
          "import sys,json; t=json.load(sys.stdin) or {}; \
           exit(0 if '$TAG' in {k.lower() for k in t.keys()} else 1)" 2>/dev/null; then
          MISSING="$MISSING $TAG"
        fi
      done

      MISSING=$(echo "$MISSING" | xargs)
      if [ -n "$MISSING" ]; then
        echo "$SUB,$RG,$SERVER,$DB_NAME,\"$MISSING\""
      fi

    done <<< "$DATABASES"
  done <<< "$SERVERS"
done

GCP: Find Cloud SQL Instances Missing Labels

#!/bin/bash
# audit_cloudsql_labels.sh
# Requires: gcloud authenticated with cloudsql.viewer on all projects

MANDATORY_LABELS=("env" "team" "cost-center" "project" "application")
PROJECTS=$(gcloud projects list --format="value(projectId)" 2>/dev/null)

echo "project,instance,tier,missing_labels"

for PROJECT in $PROJECTS; do
  INSTANCES=$(gcloud sql instances list \
    --project="$PROJECT" \
    --format="value(name,settings.tier)" 2>/dev/null)

  while IFS=$'\t' read -r INSTANCE TIER; do
    [ -z "$INSTANCE" ] && continue

    LABELS=$(gcloud sql instances describe "$INSTANCE" \
      --project="$PROJECT" \
      --format="json(settings.userLabels)" 2>/dev/null \
      | python3 -c \
        "import sys,json; d=json.load(sys.stdin); \
         labels=d.get('settings',{}).get('userLabels',{}); \
         print(' '.join(labels.keys()))")

    MISSING=""
    for LABEL in "${MANDATORY_LABELS[@]}"; do
      if ! echo "$LABELS" | grep -qw "$LABEL"; then
        MISSING="$MISSING $LABEL"
      fi
    done

    MISSING=$(echo "$MISSING" | xargs)
    if [ -n "$MISSING" ]; then
      echo "$PROJECT,$INSTANCE,$TIER,\"$MISSING\""
    fi
  done <<< "$INSTANCES"
done

23.3 Cost Allocation Queries: Turning Tags Into Budget Intelligence

Once resources are tagged, the second problem surfaces: the tagging is there, but no one is actually querying it. Finance is still allocating costs manually. The following queries demonstrate how to extract per-team and per-project database costs directly from each cloud's billing data.

AWS Cost Explorer: Per-Team RDS Cost Breakdown

#!/usr/bin/env python3
"""
rds_cost_by_team.py
Queries AWS Cost Explorer for RDS costs grouped by the 'team' tag.
Outputs a CSV and optionally posts a Slack summary.

Schedule: Weekly via EventBridge + Lambda or cron.
Requirements: boto3, AWS credentials with ce:GetCostAndUsage permission.
"""

import boto3
import csv
import io
import json
import os
from datetime import datetime, timedelta
from collections import defaultdict

def get_rds_cost_by_tag(tag_key: str = "team",
                         days_back: int = 30) -> list[dict]:
    """
    Returns RDS costs grouped by a tag key for the last N days.
    Includes both instance hours and storage costs.
    """
    ce = boto3.client("cost-explorer", region_name="us-east-1")

    end_date = datetime.today().strftime("%Y-%m-%d")
    start_date = (datetime.today() - timedelta(days=days_back)).strftime("%Y-%m-%d")

    response = ce.get_cost_and_usage(
        TimePeriod={"Start": start_date, "End": end_date},
        Granularity="MONTHLY",
        Filter={
            "And": [
                {
                    "Dimensions": {
                        "Key": "SERVICE",
                        "Values": ["Amazon Relational Database Service"]
                    }
                },
                {
                    # Exclude credits and refunds
                    "Not": {
                        "Dimensions": {
                            "Key": "RECORD_TYPE",
                            "Values": ["Credit", "Refund"]
                        }
                    }
                }
            ]
        },
        GroupBy=[
            {"Type": "TAG", "Key": tag_key},
            {"Type": "DIMENSION", "Key": "USAGE_TYPE"}
        ],
        Metrics=["UnblendedCost", "UsageQuantity"]
    )

    results = []
    for period in response["ResultsByTime"]:
        month = period["TimePeriod"]["Start"][:7]
        for group in period["Groups"]:
            tag_value = group["Keys"][0].replace(f"{tag_key}$", "")
            usage_type = group["Keys"][1]

            cost = float(group["Metrics"]["UnblendedCost"]["Amount"])
            quantity = float(group["Metrics"]["UsageQuantity"]["Amount"])

            if cost > 0.01:
                results.append({
                    "month": month,
                    tag_key: tag_value if tag_value else "UNTAGGED",
                    "usage_type": usage_type,
                    "cost_usd": round(cost, 2),
                    "usage_quantity": round(quantity, 2),
                    "unit": group["Metrics"]["UsageQuantity"]["Unit"]
                })

    return results


def summarize_by_team(results: list[dict], tag_key: str = "team") -> dict:
    """Aggregates detailed usage rows into per-team totals."""
    totals = defaultdict(float)
    for row in results:
        totals[row[tag_key]] += row["cost_usd"]
    return dict(sorted(totals.items(), key=lambda x: x[1], reverse=True))


def export_csv(results: list[dict], output_path: str) -> None:
    if not results:
        print("No results to export.")
        return
    with open(output_path, "w", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=results[0].keys())
        writer.writeheader()
        writer.writerows(results)
    print(f"Exported {len(results)} rows to {output_path}")


def post_slack_summary(totals: dict, webhook_url: str, period_label: str) -> None:
    """Posts a cost summary to Slack. Set SLACK_WEBHOOK_URL env variable."""
    import urllib.request

    lines = [f"*RDS Cost by Team — {period_label}*\n"]
    grand_total = sum(totals.values())
    for team, cost in totals.items():
        pct = (cost / grand_total * 100) if grand_total > 0 else 0
        lines.append(f"• `{team}`: ${cost:,.2f} ({pct:.1f}%)")
    lines.append(f"\n*Total: ${grand_total:,.2f}*")

    payload = json.dumps({"text": "\n".join(lines)}).encode()
    req = urllib.request.Request(
        webhook_url,
        data=payload,
        headers={"Content-Type": "application/json"}
    )
    urllib.request.urlopen(req)
    print("Slack summary posted.")


if __name__ == "__main__":
    results = get_rds_cost_by_tag(tag_key="team", days_back=30)
    totals = summarize_by_team(results, tag_key="team")

    print("\nRDS Cost by Team (last 30 days):")
    print("-" * 45)
    grand_total = sum(totals.values())
    for team, cost in totals.items():
        pct = (cost / grand_total * 100) if grand_total > 0 else 0
        print(f"  {team:<25} ${cost:>10,.2f}  ({pct:.1f}%)")
    print("-" * 45)
    print(f"  {'TOTAL':<25} ${grand_total:>10,.2f}")

    export_csv(results, "/tmp/rds_cost_by_team.csv")

    webhook = os.environ.get("SLACK_WEBHOOK_URL")
    if webhook:
        post_slack_summary(totals, webhook, "Last 30 Days")

GCP BigQuery: Cloud SQL Cost by Label

-- gcp_cloudsql_cost_by_label.sql
-- Queries the GCP billing export table in BigQuery
-- Replace 'your_project.billing_dataset.gcp_billing_export_v1_XXXXXX'
-- with your actual billing export table name.
-- Run in BigQuery console or schedule via Cloud Scheduler + BigQuery Data Transfer.

WITH

-- Flatten labels into a key-value structure per line item
labelled_costs AS (
  SELECT
    invoice.month                                           AS billing_month,
    project.id                                              AS gcp_project,
    service.description                                     AS service,
    sku.description                                         AS sku,

    -- Extract specific labels; NULLIF handles missing labels gracefully
    MAX(IF(label.key = 'team',         label.value, NULL))  AS team,
    MAX(IF(label.key = 'env',          label.value, NULL))  AS env,
    MAX(IF(label.key = 'cost-center',  label.value, NULL))  AS cost_center,
    MAX(IF(label.key = 'project',      label.value, NULL))  AS app_project,
    MAX(IF(label.key = 'application',  label.value, NULL))  AS application,

    SUM(cost)                                               AS total_cost_usd,
    SUM(cost_at_list)                                       AS list_cost_usd,

    -- Savings from committed use discounts
    SUM(cost_at_list) - SUM(cost)                          AS discount_usd

  FROM `your_project.billing_dataset.gcp_billing_export_v1_XXXXXX`,
  UNNEST(labels) AS label

  WHERE
    service.description LIKE '%Cloud SQL%'
    AND DATE(_PARTITIONTIME) >= DATE_SUB(CURRENT_DATE(), INTERVAL 3 MONTH)

  GROUP BY
    billing_month,
    gcp_project,
    service,
    sku
),

-- Identify line items where mandatory labels are missing
compliance_check AS (
  SELECT
    billing_month,
    gcp_project,
    team,
    env,
    cost_center,
    app_project,
    application,
    total_cost_usd,
    discount_usd,

    -- Tag completeness score: 1 point per present mandatory label
    (CASE WHEN team        IS NOT NULL THEN 1 ELSE 0 END +
     CASE WHEN env         IS NOT NULL THEN 1 ELSE 0 END +
     CASE WHEN cost_center IS NOT NULL THEN 1 ELSE 0 END +
     CASE WHEN app_project IS NOT NULL THEN 1 ELSE 0 END +
     CASE WHEN application IS NOT NULL THEN 1 ELSE 0 END
    )                                              AS label_score,

    -- 5 = fully labelled, <5 = partially or fully unlabelled
    CASE
      WHEN team IS NULL AND env IS NULL AND cost_center IS NULL
        THEN 'UNTAGGED'
      WHEN (CASE WHEN team        IS NOT NULL THEN 1 ELSE 0 END +
            CASE WHEN env         IS NOT NULL THEN 1 ELSE 0 END +
            CASE WHEN cost_center IS NOT NULL THEN 1 ELSE 0 END +
            CASE WHEN app_project IS NOT NULL THEN 1 ELSE 0 END +
            CASE WHEN application IS NOT NULL THEN 1 ELSE 0 END) < 5
        THEN 'PARTIAL'
      ELSE 'COMPLIANT'
    END                                            AS label_status

  FROM labelled_costs
)

-- Final summary: cost by team and label compliance status
SELECT
  billing_month,
  COALESCE(team, 'UNTAGGED')          AS team,
  COALESCE(env, 'unknown')            AS env,
  label_status,
  COUNT(*)                            AS line_item_count,
  ROUND(SUM(total_cost_usd), 2)       AS total_cost_usd,
  ROUND(SUM(discount_usd), 2)         AS total_discount_usd,
  ROUND(AVG(label_score), 2)          AS avg_label_score

FROM compliance_check

GROUP BY
  billing_month,
  team,
  env,
  label_status

ORDER BY
  billing_month DESC,
  total_cost_usd DESC;

Schedule this query to run on the first of each month via Cloud Scheduler. Export results to a Looker Studio dashboard that Finance can access without needing BigQuery access themselves.

23.4 Enforcing Tags at Resource Creation: AWS, Azure, and GCP Policies

Auditing after the fact catches problems late. The more cost-effective approach is enforcement at creation time: block or warn when a database resource is created without the required tags. Each cloud provides a native policy mechanism.

AWS: Service Control Policy (SCP) to Block Untagged RDS Creation

SCPs operate at the AWS Organization level and cannot be overridden by individual account administrators. The following SCP blocks RDS instance creation and restoration unless all mandatory tags are present.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "RequireMandatoryTagsOnRDSCreate",
      "Effect": "Deny",
      "Action": [
        "rds:CreateDBInstance",
        "rds:CreateDBCluster",
        "rds:RestoreDBInstanceFromDBSnapshot",
        "rds:RestoreDBClusterFromSnapshot",
        "rds:CreateDBInstanceReadReplica"
      ],
      "Resource": "*",
      "Condition": {
        "Null": {
          "aws:RequestTag/env":         "true",
          "aws:RequestTag/team":        "true",
          "aws:RequestTag/cost-center": "true",
          "aws:RequestTag/project":     "true"
        }
      }
    },
    {
      "Sid": "AllowTaggingOnCreate",
      "Effect": "Allow",
      "Action": "rds:AddTagsToResource",
      "Resource": "*"
    }
  ]
}

Apply this SCP to all non-root OUs. Leave the root OU unconditional to allow emergency break-glass actions. Communicate the rollout two weeks in advance—teams using CloudFormation or Terraform without tag blocks will see failed deployments.
