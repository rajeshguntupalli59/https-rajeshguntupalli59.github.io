Chapter 27: Logical Replication for Real-Time AI Triggers

Real-time AI systems live or die by the freshness of their context. When a customer updates their profile, your recommendation engine should know immediately. When a support ticket changes status, your AI agent should adapt its response strategy without waiting for the next scheduled batch run. This chapter shows you how to wire PostgreSQL's logical replication infrastructure directly into your AI application layer — turning database changes into AI triggers, embedding refreshes, and autonomous agent actions, all without polling, all without application-layer interceptors, and all without the brittleness of trigger-based queue hacks.

27.1 Logical Replication as an AI Event Bus

Most teams bolt an event queue onto their application layer and treat the database as a passive store. That approach creates a class of bugs that are genuinely difficult to eliminate: the application writes to the database and separately publishes an event, and the two can diverge under failure conditions. PostgreSQL's logical replication protocol solves this at the storage layer — it reads the write-ahead log directly, guaranteeing that every committed change, and only committed changes, flows downstream.

For AI applications this distinction matters more than it might appear. Consider embedding synchronization: if your application publishes a Kafka event that says "document 4421 was updated," but the transaction was later rolled back, your embedding pipeline may attempt to vectorize a document that no longer exists in that state. With logical replication decoding from the WAL, the event is physically impossible to generate for an uncommitted transaction.

The PostgreSQL logical replication stack has three layers that matter for AI work:

Publications define which tables and operations (INSERT, UPDATE, DELETE, TRUNCATE) should be exposed. A publication is a first-class PostgreSQL object — no application code required to maintain it.

Replication slots track consumer progress. The WAL is retained until the slowest consumer has processed it, which means your AI pipeline can fall behind during a traffic spike and catch up without losing events.

Logical decoding plugins translate the binary WAL format into something your application can consume. The built-in pgoutput plugin is what standard streaming replication uses. For AI pipelines, wal2json is often more practical because it emits JSON that maps directly to Python dictionaries.

-- Enable logical replication (requires restart if not already set)
-- Check current setting first
SHOW wal_level;

-- In postgresql.conf or via ALTER SYSTEM:
ALTER SYSTEM SET wal_level = 'logical';
ALTER SYSTEM SET max_replication_slots = 10;

*The consumer acknowledges the slot as soon as work is durably enqueued, not after the LLM call finishes — that decouples WAL retention from LLM latency.*

27.2 Building the WAL Consumer in Python

The Python psycopg2 library exposes the streaming replication protocol through its extras module. The pattern is straightforward: open a replication connection, start consuming the slot, and dispatch events to your AI handlers. For production, you want this running as a long-lived process — a Celery worker or a dedicated service managed by systemd or your container orchestrator.

# wal_consumer.py — Production WAL consumer for AI pipeline

# ─── Event Router ─────────────────────────────────────────────────────────────

class AIEventRouter:
    """
    Routes WAL change events to appropriate AI handlers.
    Each handler is keyed by (table_name, operation).
    """

    def __init__(self):
        self.handlers: dict[tuple[str, str], list[Callable]] = {}
        self.dedup_ttl = 30  # seconds — deduplicate identical events

    def register(self, table: str, operation: str):
        """Decorator to register an event handler."""
        def decorator(fn: Callable):
            key = (table, operation.upper())
            self.handlers.setdefault(key, []).append(fn)
            return fn
        return decorator

    def _dedup_key(self, table: str, row_id: Any, operation: str, lsn: str) -> str:
        return f"wal_dedup:{table}:{row_id}:{operation}:{lsn}"

    def dispatch(self, event: dict) -> None:
        table = event.get('table')
        operation = event.get('type', '').upper()
        columns = {
            col['name']: col['value']
            for col in event.get('columns', [])
        }
        old_columns = {
            col['name']: col['value']
            for col in event.get('identity', [])
        } if event.get('identity') else {}

        row_id = columns.get('id') or old_columns.get('id')
        lsn = event.get('nextlsn', '')

        # Deduplication: skip if we've seen this exact event recently
        dedup_key = self._dedup_key(table, row_id, operation, lsn)
        if redis_client.exists(dedup_key):
            logger.debug(f"Skipping duplicate event: {dedup_key}")
            return
        redis_client.setex(dedup_key, self.dedup_ttl, '1')

        handler_key = (table, operation)
        handlers = self.handlers.get(handler_key, [])

        if not handlers:
            logger.debug(f"No handlers registered for {table}:{operation}")
            return

        enriched_event = {
            'table': table,
            'operation': operation,
            'row_id': row_id,
            'columns': columns,
            'old_columns': old_columns,
            'lsn': lsn,
            'received_at': datetime.now(timezone.utc).isoformat(),
        }

        for handler in handlers:
            try:
                handler(enriched_event)
            except Exception as exc:
                logger.error(
                    f"Handler {handler.__name__} failed for {table}:{row_id}: {exc}",
                    exc_info=True
                )

router = AIEventRouter()

# ─── Event Handlers ───────────────────────────────────────────────────────────

@router.register('documents', 'INSERT')
@router.register('documents', 'UPDATE')
def handle_document_change(event: dict) -> None:
    """Trigger embedding refresh when document content changes."""
    columns = event['columns']
    old_columns = event.get('old_columns', {})

    # Skip if only non-content fields changed
    content_changed = (
        event['operation'] == 'INSERT' or
        columns.get('content_hash') != old_columns.get('content_hash')
    )

    if not content_changed:
        logger.info(f"Document {event['row_id']}: metadata-only change, skipping re-embed")
        return

    logger.info(f"Document {event['row_id']}: content changed, queuing embedding refresh")

    # Dispatch to Celery embedding queue
    celery_app.send_task(
        'tasks.refresh_embedding',
        kwargs={
            'document_id': event['row_id'],
            'content': columns.get('content'),
            'metadata': columns.get('metadata'),
            'model': columns.get('embedding_model', 'text-embedding-3-small'),
        },
        queue='embeddings',
        priority=5,
    )

@router.register('documents', 'DELETE')
def handle_document_delete(event: dict) -> None:
    """Clean up embeddings and notify agents when document is deleted."""
    doc_id = event['row_id']
    logger.info(f"Document {doc_id}: deleted, scheduling cleanup")

    celery_app.send_task(
        'tasks.cleanup_document_embeddings',
        kwargs={'document_id': doc_id},
        queue='embeddings',
    )

@router.register('support_tickets', 'UPDATE')
def handle_ticket_update(event: dict) -> None:
    """Route ticket status changes to AI triage agent."""
    old_status = event['old_columns'].get('status')
    new_status = event['columns'].get('status')

    if old_status == new_status:
        return

    # Only trigger AI analysis on escalation events
    escalation_transitions = {
        ('open', 'escalated'),
        ('in_progress', 'escalated'),
        ('open', 'urgent'),
    }

    if (old_status, new_status) in escalation_transitions:
        logger.info(
            f"Ticket {event['row_id']}: escalated {old_status} → {new_status}, "
            f"triggering AI analysis"
        )
        celery_app.send_task(
            'tasks.trigger_ai_analysis',
            kwargs={
                'ticket_id': event['row_id'],
                'old_status': old_status,
                'new_status': new_status,
                'description': event['columns'].get('description'),
                'priority': event['columns'].get('priority'),
                'customer_id': event['columns'].get('customer_id'),
            },
            queue='ai_analysis',
            priority=9,  # High priority for escalations
        )

@router.register('product_catalog', 'INSERT')
@router.register('product_catalog', 'UPDATE')
def handle_product_change(event: dict) -> None:
    """Refresh product embeddings and invalidate recommendation cache."""
    product_id = event['row_id']

    # Invalidate Redis cache for this product
    cache_keys = redis_client.keys(f"rec_cache:*:{product_id}:*")
    if cache_keys:
        redis_client.delete(*cache_keys)
        logger.info(f"Product {product_id}: invalidated {len(cache_keys)} cache entries")

    celery_app.send_task(
        'tasks.refresh_embedding',
        kwargs={
            'document_id': product_id,
            'content': (
                f"{event['columns'].get('name', '')} "
                f"{event['columns'].get('description', '')} "
                f"{json.dumps(event['columns'].get('attributes', {}))}"
            ),
            'metadata': {'type': 'product', 'price': event['columns'].get('price')},
            'model': 'text-embedding-3-small',
            'target_table': 'product_catalog',
        },
        queue='embeddings',
    )

# ─── WAL Consumer Main Loop ───────────────────────────────────────────────────

class WALConsumer:
    def __init__(self, dsn: str, slot_name: str, publication_name: str):
        self.dsn = dsn
        self.slot_name = slot_name
        self.publication_name = publication_name
        self.conn = None
        self.cursor = None
        self.running = False
        self._setup_signal_handlers()

    def _setup_signal_handlers(self):
        signal.signal(signal.SIGTERM, self._handle_shutdown)
        signal.signal(signal.SIGINT, self._handle_shutdown)

    def _handle_shutdown(self, signum, frame):
        logger.info(f"Received signal {signum}, initiating graceful shutdown")
        self.running = False

    def connect(self):
        self.conn = psycopg2.connect(
            self.dsn,
            connection_factory=psycopg2.extras.LogicalReplicationConnection
        )
        self.cursor = self.conn.cursor()
        logger.info(f"Connected to replication slot: {self.slot_name}")

    def start_streaming(self):
        """Start consuming the replication slot with wal2json options."""
        self.cursor.start_replication(
            slot_name=self.slot_name,
            decode=True,
            options={
                'pretty-print': '0',
                'include-lsn': '1',
                'include-timestamp': '1',
                'include-transaction': '1',
                'add-tables': (
                    'public.documents,'
                    'public.support_tickets,'
                    'public.user_profiles,'
                    'public.product_catalog'
                ),
            }
        )
        logger.info("Replication stream started")

    def process_message(self, msg):
        """Process a single WAL message from wal2json."""
        try:
            payload = json.loads(msg.payload)

            # wal2json wraps changes in a transaction envelope
            changes = payload.get('change', [])

            for change in changes:
                router.dispatch(change)

            # Acknowledge receipt — this advances the replication slot
            msg.cursor.send_feedback(flush_lsn=msg.data_start)

        except json.JSONDecodeError as exc:
            logger.error(f"Failed to parse WAL message: {exc}")
        except Exception as exc:
            logger.error(f"Error processing WAL message: {exc}", exc_info=True)
            # Don't acknowledge — let the slot replay from this LSN

    def run(self):
        self.running = True
        self.connect()
        self.start_streaming()

        logger.info("WAL consumer running — waiting for changes")

        while self.running:
            # consume_stream blocks until a message arrives or timeout
            self.cursor.consume_stream(
                self.process_message,
                keepalive_interval=10  # seconds
            )

        logger.info("WAL consumer stopped cleanly")
        if self.conn:
            self.conn.close()


if __name__ == '__main__':

    consumer = WALConsumer(
        dsn=os.environ['DATABASE_URL'],
        slot_name='ai_pipeline_slot',
        publication_name='ai_event_stream',
    )
    consumer.run()

27.3 Embedding Pipeline as a Celery Worker

The WAL consumer dispatches work to Celery, which runs the actual AI operations. This separation is important: the WAL consumer must stay responsive and lightweight because PostgreSQL is waiting for acknowledgment. Embedding calls to OpenAI can take 200–800ms — long enough to create backpressure if done synchronously in the consumer loop.

# tasks/embedding_tasks.py — Celery workers for AI operations
import hashlib
import json
import logging
import os
from typing import Optional

import psycopg2
import psycopg2.pool
from celery import Task
from openai import OpenAI
import anthropic
import redis

from wal_consumer import celery_app

logger = logging.getLogger('embedding_tasks')

openai_client = OpenAI(api_key=os.environ['OPENAI_API_KEY'])
anthropic_client = anthropic.Anthropic(api_key=os.environ['ANTHROPIC_API_KEY'])
redis_client = redis.Redis(host='localhost', port=6379, db=1, decode_responses=True)

# Connection pool — shared across Celery worker threads
db_pool = psycopg2.pool.ThreadedConnectionPool(
    minconn=2,
    maxconn=10,
    dsn=os.environ['DATABASE_URL']
)


class DatabaseTask(Task):
    """Base task class that handles DB connection lifecycle."""
    abstract = True

    def get_conn(self):
        return db_pool.getconn()

    def release_conn(self, conn):
        db_pool.putconn(conn)


# ─── Embedding Refresh Task ────────────────────────────────────────────────────

@celery_app.task(
    bind=True,
    base=DatabaseTask,
    name='tasks.refresh_embedding',
    max_retries=3,
    default_retry_delay=60,
    autoretry_for=(Exception,),
    retry_backoff=True,
    retry_backoff_max=300,
)
def refresh_embedding(
    self,
    document_id: int,
    content: str,
    metadata: Optional[dict] = None,
    model: str = 'text-embedding-3-small',
    target_table: str = 'documents',
) -> dict:
    """
    Generate embedding for changed content and write it back to PostgreSQL.
    Uses content hashing to skip redundant API calls.
    """
    content_hash = hashlib.md5(content.encode()).hexdigest()
    cache_key = f"embedding:{model}:{content_hash}"

    # Check embedding cache first — identical content doesn't need a new API call
    cached = redis_client.get(cache_key)
    if cached:
        embedding = json.loads(cached)
        logger.info(
            f"Cache hit for {target_table}:{document_id} "
            f"(hash {content_hash[:8]}...)"
        )
    else:
        # Call OpenAI embedding API
        response = openai_client.embeddings.create(
            model=model,
            input=content,
            dimensions=1536 if model == 'text-embedding-3-small' else None,
        )
        embedding = response.data[0].embedding

        # Cache for 24 hours — same content produces same embedding
        redis_client.setex(cache_key, 86400, json.dumps(embedding))
        logger.info(
            f"Generated embedding for {target_table}:{document_id} "
            f"via {model} ({len(embedding)} dims)"
        )

    # Write embedding back to PostgreSQL
    conn = self.get_conn()
    try:
        with conn.cursor() as cur:
            # Format as pgvector literal
            vector_literal = '[' + ','.join(str(x) for x in embedding) + ']'

            if target_table == 'documents':
                cur.execute("""
                    UPDATE documents
                    SET
                        embedding = %s::vector,
                        embedding_model = %s,
                        embedding_version = embedding_version + 1,
                        indexed_at = now()
                    WHERE id = %s
                      AND (
                        content_hash = %s
                        OR indexed_at IS NULL
                      )
                    RETURNING id, embedding_version
                """, (vector_literal, model, document_id, content_hash))

            elif target_table == 'product_catalog':
                cur.execute("""
                    UPDATE product_catalog
                    SET
                        embedding = %s::vector,
                        embedding_updated_at = now()
                    WHERE id = %s
                    RETURNING id
                """, (vector_literal, document_id))

            result = cur.fetchone()
            conn.commit()

            if result:
                # Log to AI pipeline audit table
                cur.execute("""
                    INSERT INTO ai_pipeline_events
                        (source_table, source_id, operation, change_data,
                         triggered_action, action_status, processed_at)
                    VALUES (%s, %s, 'UPDATE', %s, 'refresh_embedding', 'completed', now())
                """, (
                    target_table,
                    document_id,
                    json.dumps({'model': model, 'version': result[1] if len(result) > 1 else None})
                ))
                conn.commit()
                logger.info(f"Wrote embedding for {target_table}:{document_id}")
                return {'status': 'success', 'document_id': document_id}
            else:
                logger.info(
                    f"Skipped embedding write for {document_id}: "
                    f"content changed again before we finished"
                )
                return {'status': 'skipped', 'document_id': document_id}

    finally:
        self.release_conn(conn)


# ─── AI Analysis Task ──────────────────────────────────────────────────────────

@celery_app.task(
    bind=True,
    base=DatabaseTask,
    name='tasks.trigger_ai_analysis',
    max_retries=3,
    default_retry_delay=30,
    autoretry_for=(Exception,),
    retry_backoff=True,
    retry_backoff_max=120,
)
def trigger_ai_analysis(
    self,
    ticket_id: int,
    old_status: str,
    new_status: str,
    description: str,
    priority: str,
    customer_id: int,
) -> dict:
    """
    Run AI triage analysis on an escalated support ticket.
    Writes recommended action and reasoning back to PostgreSQL.
    """
    conn = self.get_conn()
    try:
        with conn.cursor() as cur:
            # Fetch full ticket history for context
            cur.execute("""
                SELECT
                    t.id,
                    t.description,
                    t.priority,
                    t.status,
                    t.created_at,
                    c.name AS customer_name,
                    c.tier AS customer_tier,
                    c.account_value,
                    COALESCE(
                        json_agg(
                            json_build_object(
                                'note', n.content,
                                'author', n.author,
                                'created_at', n.created_at
                            ) ORDER BY n.created_at
                        ) FILTER (WHERE n.id IS NOT NULL),
                        '[]'::json
                    ) AS notes
                FROM support_tickets t
                JOIN customers c ON c.id = t.customer_id
                LEFT JOIN ticket_notes n ON n.ticket_id = t.id
                WHERE t.id = %s
                GROUP BY t.id, c.name, c.tier, c.account_value
            """, (ticket_id,))
            row = cur.fetchone()
    finally:
        self.release_conn(conn)

    if not row:
        logger.warning(f"Ticket {ticket_id} not found — skipping AI analysis")
        return {'status': 'skipped', 'reason': 'ticket_not_found'}

    (
        t_id, t_description, t_priority, t_status, t_created_at,
        customer_name, customer_tier, account_value, notes
    ) = row

    # Build the prompt for Claude
    system_prompt = """You are a senior support triage AI. Given an escalated support ticket
and its history, you will:
1. Summarize the core issue in one sentence.
2. Identify the root cause category (billing, technical, account, feature-request, security).
3. Recommend the next action (assign-tier2, assign-engineering, offer-credit, schedule-call, close-with-note).
4. Estimate resolution urgency as: low / medium / high / critical.
5. Draft a brief internal note explaining your reasoning.

Respond in JSON with keys: summary, root_cause, recommended_action, urgency, reasoning."""

    user_message = f"""Ticket #{t_id} has been escalated from '{old_status}' to '{new_status}'.

Customer: {customer_name} (tier: {customer_tier})
Priority: {t_priority}
Description: {t_description}

Ticket notes:
{json.dumps(notes, indent=2, default=str)}

Please triage this ticket."""

    message = anthropic_client.messages.create(
        model='claude-3-5-sonnet-20241022',
        max_tokens=512,
        messages=[{'role': 'user', 'content': user_message}],
        system=system_prompt,
    )

    raw_response = message.content[0].text
    try:
        analysis = json.loads(raw_response)
    except json.JSONDecodeError:
        # Claude occasionally wraps JSON in markdown fences
        import re
        match = re.search(r'```(?:json)?\s*([\s\S]+?)```', raw_response)
        if match:
            analysis = json.loads(match.group(1))
        else:
            raise ValueError(f"Could not parse AI response as JSON: {raw_response[:200]}")

    # Write the AI analysis back to the ticket
    conn = self.get_conn()
    try:
        with conn.cursor() as cur:
            cur.execute("""
                UPDATE support_tickets
                SET
                    ai_triage_summary    = %s,
                    ai_root_cause        = %s,
                    ai_recommended_action = %s,
                    ai_urgency           = %s,
                    ai_reasoning         = %s,
                    ai_triaged_at        = now()
                WHERE id = %s
            """, (
                analysis.get('summary'),
                analysis.get('root_cause'),
                analysis.get('recommended_action'),
                analysis.get('urgency'),
                analysis.get('reasoning'),
                ticket_id,
            ))

            cur.execute("""
                INSERT INTO ai_pipeline_events
                    (source_table, source_id, operation, change_data,
                     triggered_action, action_status, processed_at)
                VALUES ('support_tickets', %s, 'UPDATE', %s,
                        'trigger_ai_analysis', 'completed', now())
            """, (
                ticket_id,
                json.dumps({
                    'old_status': old_status,
                    'new_status': new_status,
                    'urgency': analysis.get('urgency'),
                    'recommended_action': analysis.get('recommended_action'),
                }),
            ))
            conn.commit()

    finally:
        self.release_conn(conn)

    logger.info(

27.4 Slot Lag Management and Backpressure

A replication slot that falls too far behind creates a serious operational hazard: PostgreSQL cannot reclaim WAL segments until the slot's confirmed_flush_lsn advances, so disk usage grows without bound. For AI pipelines, which may intentionally slow down during LLM rate limiting, you need an active strategy for lag management.

The fundamental principle is that the WAL consumer's acknowledgment cursor — not the Celery queue depth — determines WAL retention. The consumer should acknowledge as soon as it has safely enqueued work, not after the work is complete. This keeps WAL retention tied to queue durability rather than LLM latency.

-- Monitoring view: replication slot health for AI pipeline
CREATE OR REPLACE VIEW ai_replication_health AS
SELECT
    rs.slot_name,
    rs.plugin,
    rs.active,
    rs.confirmed_flush_lsn,
    pg_current_wal_lsn()                                    AS current_lsn,
    pg_wal_lsn_diff(
        pg_current_wal_lsn(),
        rs.confirmed_flush_lsn
    )                                                        AS lag_bytes,
    pg_size_pretty(
        pg_wal_lsn_diff(
            pg_current_wal_lsn(),
            rs.confirmed_flush_lsn
        )
    )                                                        AS lag_pretty,
    rs.catalog_xmin,
    age(rs.catalog_xmin)                                     AS catalog_xmin_age,
    -- Estimate lag as event count from audit log
    (
        SELECT count(*)
        FROM ai_pipeline_events
        WHERE action_status = 'pending'
    )                                                        AS pending_events
FROM pg_replication_slots rs
WHERE rs.slot_name = 'ai_pipeline_slot';

-- Alert query: fire when lag exceeds a threshold
-- Run this from your monitoring system (Prometheus postgres_exporter, Datadog, etc.)
SELECT
    slot_name,
    lag_bytes,
    lag_pretty,
    pending_events,
    CASE
        WHEN lag_bytes > 1073741824 THEN 'CRITICAL'   -- > 1 GiB
        WHEN lag_bytes > 268435456  THEN 'WARNING'    -- > 256 MiB
        ELSE 'OK'
    END AS lag_status
FROM ai_replication_health;

-- Automated slot drop safety valve (run as a scheduled job)
-- If the slot is inactive AND lag exceeds threshold, drop and recreate
DO $$
DECLARE
    v_lag_bytes  BIGINT;
    v_active     BOOLEAN;
    v_threshold  BIGINT := 2 * 1024 * 1024 * 1024;  -- 2 GiB
BEGIN
    SELECT
        pg_wal_lsn_diff(pg_current_wal_lsn(), confirmed_flush_lsn),
        active
    INTO v_lag_bytes, v_active
    FROM pg_replication_slots
    WHERE slot_name = 'ai_pipeline_slot';

    IF NOT FOUND THEN
        RAISE NOTICE 'Slot ai_pipeline_slot does not exist — creating';
        PERFORM pg_create_logical_replication_slot('ai_pipeline_slot', 'wal2json');
        RETURN;
    END IF;

    IF NOT v_active AND v_lag_bytes > v_threshold THEN
        RAISE WARNING
            'Slot ai_pipeline_slot is inactive with % bytes of lag — dropping',
            v_lag_bytes;
        PERFORM pg_drop_replication_slot('ai_pipeline_slot');
        PERFORM pg_create_logical_replication_slot('ai_pipeline_slot', 'wal2json');
        RAISE NOTICE 'Slot recreated at current LSN (events between old and new LSN will be lost)';
    END IF;
END $$;

On the consumer side, implement an adaptive throttle that respects downstream LLM rate limits without stalling WAL acknowledgment:

# rate_aware_consumer.py — WAL consumer with adaptive backpressure
import threading
import time
from collections import deque
from dataclasses import dataclass, field


@dataclass
class RateLimiter:
    """
    Token bucket rate limiter for AI API calls.
    Tracks requests per minute to stay within provider limits.
    """
    max_rpm: int = 500              # OpenAI tier-1 default
    window_seconds: int = 60
    _timestamps: deque = field(default_factory=deque)
    _lock: threading.Lock = field(default_factory=threading.Lock)

    def acquire(self, timeout: float = 30.0) -> bool:
        """Block until a token is available, up to timeout seconds."""
        deadline = time.monotonic() + timeout
        while time.monotonic() < deadline:
            with self._lock:
                now = time.monotonic()
                # Evict timestamps outside the window
                while self._timestamps and self._timestamps[0] < now - self.window_seconds:
                    self._timestamps.popleft()

                if len(self._timestamps) < self.max_rpm:
                    self._timestamps.append(now)
                    return True

            time.sleep(0.1)
        return False  # timed out

    @property
    def current_rpm(self) -> int:
        with self._lock:
            now = time.monotonic()
            return sum(1 for t in self._timestamps if t >= now - self.window_seconds)


class BackpressureAwareRouter(AIEventRouter):
    """
    Extends AIEventRouter with rate limiting and queue depth awareness.
    The WAL consumer still acknowledges quickly; backpressure is applied
    to Celery task dispatch, not to LSN advancement.
    """

    def __init__(self, embedding_rpm: int = 500, analysis_rpm: int = 60):
        super().__init__()
        self.embedding_limiter = RateLimiter(max_rpm=embedding_rpm)
        self.analysis_limiter = RateLimiter(max_rpm=analysis_rpm)

    def _get_limiter_for_queue(self, queue_name: str) -> RateLimiter:
        if queue_name == 'embeddings':
            return self.embedding_limiter
        elif queue_name == 'ai_analysis':
            return self.analysis_limiter
        return self.embedding_limiter  # default

    def dispatch_with_backpressure(self, event: dict, queue: str) -> bool:
        """
        Attempt to dispatch event, respecting rate limits.
        Returns True if dispatched, False if rate limit prevented dispatch.
        """
        limiter = self._get_limiter_for_queue(queue)
        if not limiter.acquire(timeout=0.0):
            # Non-blocking check: if over limit, write to overflow table
            # instead of blocking the WAL consumer
            self._write_overflow(event, queue)
            return False
        return True

    def _write_overflow(self, event: dict, queue: str) -> None:
        """
        Persist overflow events to PostgreSQL for deferred processing.
        A separate worker drains this table when rate limit headroom exists.
        """
        import json
        import psycopg2
        import os
        conn = psycopg2.connect(os.environ['DATABASE_URL'])
        try:
            with conn.cursor() as cur:
                cur.execute("""
                    INSERT INTO ai_pipeline_overflow
                        (event_data, target_queue, created_at)
                    VALUES (%s, %s, now())
                """, (json.dumps(event), queue))
            conn.commit()
        finally:
            conn.close()

27.5 SQL Server Equivalent: Change Data Capture for AI Pipelines

SQL Server ships with Change Data Capture (CDC) as a built-in feature. The mechanism differs from PostgreSQL's logical replication — CDC reads the transaction log via a SQL Agent job that writes changes into system tables — but the end-to-end pattern for AI pipelines is equivalent.

-- SQL Server: Enable CDC on the database and target tables
-- Requires sysadmin or db_owner role

-- 1. Enable CDC at the database level
USE YourAIDatabase;
EXEC sys.sp_cdc_enable_db;

-- 2. Enable CDC on each AI-relevant table
EXEC sys.sp_cdc_enable_table
    @source_schema    = N'dbo',
    @source_name      = N'Documents',
    @role_name        = N'cdc_ai_pipeline',   -- only members of this role can query CDC tables
    @supports_net_changes = 1,                -- enables net-change function (latest state per key)
    @captured_column_list = N'Id, Title, Content, ContentHash, Metadata, UpdatedAt';

EXEC sys.sp_cdc_enable_table
    @source_schema    = N'dbo',
    @source_name      = N'SupportTickets',
    @role_name        = N'cdc_ai_pipeline',
    @supports_net_changes = 1,
    @captured_column_list = N'Id, Status, Priority, Description, CustomerId, UpdatedAt';

EXEC sys.sp_cdc_enable_table
    @source_schema    = N'dbo',
    @source_name      = N'ProductCatalog',
    @role_name        = N'cdc_ai_pipeline',
    @supports_net_changes = 1;

-- 3. Grant access to the AI pipeline role
CREATE ROLE cdc_ai_pipeline;
GRANT SELECT ON cdc.dbo_Documents_CT         TO cdc_ai_pipeline;
GRANT SELECT ON cdc.dbo_SupportTickets_CT    TO cdc_ai_pipeline;
GRANT SELECT ON cdc.dbo_ProductCatalog_CT    TO cdc_ai_pipeline;

-- Add the pipeline service account to the role
ALTER ROLE cdc_ai_pipeline ADD MEMBER ai_pipeline_svc;

-- 4. Query CDC changes — the Python consumer calls this pattern
-- The @from_lsn / @to_lsn window is tracked by the consumer (equivalent to LSN in Postgres)

-- All changes to Documents since a given LSN:
DECLARE @from_lsn BINARY(10) = sys.fn_cdc_get_min_lsn('dbo_Documents');
DECLARE @to_lsn   BINARY(10) = sys.fn_cdc_get_max_lsn();

SELECT
    sys.fn_cdc_map_lsn_to_time(__$start_lsn)   AS change_time,
    __$operation,    -- 1=delete, 2=insert, 3=before-update, 4=after-update
    __$update_mask,
    Id,
    Title,
    Content,
    ContentHash,
    Metadata,
    UpdatedAt
FROM cdc.fn_cdc_get_all_changes_dbo_Documents(
    @from_lsn, @to_lsn, N'all update old'
)
ORDER BY __$start_lsn, __$seqval;

-- Net changes (most recent state per row) — preferred for embedding refresh
SELECT
    __$operation,
    Id,
    Content,
    ContentHash,
    Metadata
FROM cdc.fn_cdc_get_net_changes_dbo_Documents(
    @from_lsn, @to_lsn, N'all with mask'
)
WHERE __$operation IN (2, 4)   -- insert or after-update
  AND sys.fn_cdc_has_column_changed(
        'dbo_Documents', 'Content', __$update_mask
      ) = 1;                   -- only rows where Content actually changed

-- 5. Persist the consumer's watermark between runs
-- CDC does not track consumer progress automatically (unlike Postgres replication slots)
CREATE TABLE dbo.AIPipelineWatermark (
    ConsumerName    NVARCHAR(128) PRIMARY KEY,
    LastProcessedLSN BINARY(10)  NOT NULL,
    LastProcessedAt  DATETIME2   NOT NULL DEFAULT SYSUTCDATETIME()
);

-- Read watermark at startup
SELECT LastProcessedLSN
FROM dbo.AIPipelineWatermark
WHERE ConsumerName = 'ai_embedding_consumer';

-- Advance watermark after successful batch
UPDATE dbo.AIPipelineWatermark
SET
    LastProcessedLSN = @to_lsn,
    LastProcessedAt  = SYSUTCDATETIME()
WHERE ConsumerName = 'ai_embedding_consumer';

-- Insert on first run
INSERT INTO dbo.AIPipelineWatermark (ConsumerName, LastProcessedLSN)
SELECT 'ai_embedding_consumer', sys.fn_cdc_get_min_lsn('dbo_Documents')
WHERE NOT EXISTS (
    SELECT 1 FROM dbo.AIPipelineWatermark
    WHERE ConsumerName = 'ai_embedding_consumer'
);

The Python consumer for SQL Server CDC follows a polling model rather than a streaming model — a meaningful architectural difference from PostgreSQL's push-based replication protocol:

# sql_server_cdc_consumer.py — CDC polling consumer for AI pipeline
import json
import logging
import os
import struct
import time
from datetime import datetime, timezone
from typing import Optional

import pyodbc

logger = logging.getLogger('cdc_consumer')

OPERATION_MAP = {
    1: 'DELETE',
    2: 'INSERT',
    3: 'UPDATE_BEFORE',
    4: 'UPDATE_AFTER',
}


class SQLServerCDCConsumer:
    """
    Polls SQL Server CDC tables on a configurable interval.
    Tracks consumer watermark in AIPipelineWatermark.
    Dispatches changes to the same AIEventRouter used by the PostgreSQL consumer.
    """

    def __init__(
        self,
        connection_string: str,
        consumer_name: str,
        poll_interval: float = 2.0,
    ):
        self.connection_string = connection_string
        self.consumer_name = consumer_name
        self.poll_interval = poll_interval
        self.conn: Optional[pyodbc.Connection] = None
        self.running = False

    def connect(self):
        self.conn = pyodbc.connect(self.connection_string, autocommit=False)
        logger.info(f"Connected to SQL Server CDC — consumer: {self.consumer_name}")

    def _lsn_to_hex(self, lsn_bytes: bytes) -> str:
        """Convert binary(10) LSN to readable hex string for logging."""
        return lsn_bytes.hex() if lsn_bytes else 'None'

    def _get_watermark(self) -> Optional[bytes]:
        cur = self.conn.cursor()
        cur.execute("""
            SELECT LastProcessedLSN
            FROM dbo.AIPipelineWatermark
            WHERE ConsumerName = ?
        """, self.consumer_name)
        row = cur.fetchone()
        return row[0] if row else None

    def _advance_watermark(self, new_lsn: bytes) -> None:
        cur = self.conn.cursor()
        cur.execute("""
            MERGE dbo.AIPipelineWatermark AS target
            USING (SELECT ? AS ConsumerName, ? AS LSN) AS source
            ON target.ConsumerName = source.ConsumerName
            WHEN MATCHED THEN
                UPDATE SET LastProcessedLSN = source.LSN,
                           LastProcessedAt  = SYSUTCDATETIME()
            WHEN NOT MATCHED THEN
                INSERT (ConsumerName, LastProcessedLSN)
                VALUES (source.ConsumerName, source.LSN);
        """, self.consumer_name, new_lsn)
        self.conn.commit()

    def _poll_documents(self, from_lsn: bytes, to_lsn: bytes) -> list[dict]:
        cur = self.conn.cursor()
        cur.execute("""
            SELECT
                __$operation,
                __$update_mask,
                Id,
                Title,
                Content,
                ContentHash,
                Metadata,
                UpdatedAt
            FROM cdc.fn_cdc_get_net_changes_dbo_Documents(?, ?, 'all with mask')
            WHERE __$operation IN (2, 4)
        """, from_lsn, to_lsn)

        rows = []
        for row in cur.fetchall():
            op_code, update_mask, doc_id, title, content, content_hash, metadata, updated_at = row
            rows.append({
                'table': 'documents',
                'operation': OPERATION_MAP.get(op_code, 'UNKNOWN'),
                'row_id': doc_id,
                'columns': {
                    'id': doc_id,
                    'title': title,
                    'content': content,
                    'content_hash': content_hash,
                    'metadata': json.loads(metadata) if metadata else {},
                    'updated_at': updated_at.isoformat() if updated_at else None,
                },
                'old_columns': {},  # net-changes mode returns only final state
            })
        return rows

    def _poll_support_tickets(self, from_lsn: bytes, to_lsn: bytes) -> list[dict]:
        cur = self.conn.cursor()
        cur.execute("""
            SELECT
                __$operation,
                Id,
                Status,
                Priority,
                Description,
                CustomerId,
                UpdatedAt
            FROM cdc.fn_cdc_get_all_changes_dbo_SupportTickets(?, ?, 'all update old')
            WHERE __$operation IN (3, 4)   -- before and after rows for UPDATE
            ORDER BY __$start_lsn, __$seqval
        """, from_lsn, to_lsn)

        # Pair up before/after rows for UPDATE operations
        rows_raw = cur.fetchall()
        events = []
        i = 0
        while i < len(rows_raw):
            op = rows_raw[i][0]
            if op == 3 and i + 1 < len(rows_raw) and rows_raw[i + 1][0] == 4:
                before = rows_raw[i]
                after  = rows_raw[i + 1]
                events.append({
                    'table': 'support_tickets',
                    'operation': 'UPDATE',
                    'row_id': after[1],
                    'columns': {
                        'id': after[1], 'status': after[2], 'priority': after[3],
                        'description': after[4], 'customer_id': after[5],
                    },
                    'old_columns': {
                        'id': before[1], 'status': before[2], 'priority': before[3],
                    },
                })
                i += 2
            else:
                i += 1
        return events

    def poll_once(self) -> int:
        """
        Poll all CDC-enabled tables for one interval.
        Returns the number of events dispatched.
        """
        cur = self.conn.cursor()
        cur.execute("SELECT sys.fn_cdc_get_max_lsn()")
        to_lsn = cur.fetchone()[0]

        if to_lsn is None:
            return 0  # CDC not yet populated

        from_lsn = self._get_watermark()
        if from_lsn is None:
            # First run: start from the minimum available LSN
            cur.execute("SELECT sys.fn_cdc_get_min_lsn('dbo_Documents')")
            from_lsn = cur.fetchone()[0]

        if from_lsn >= to_lsn:
            return 0  # Nothing new

        events = []
        events.extend(self._poll_documents(from_lsn, to_lsn))
        events.extend(self._poll_support_tickets(from_lsn, to_lsn))

        for event in events:
            try:
                router.dispatch(event)
            except Exception as exc:
                logger.error(f"Dispatch failed for {event}: {exc}", exc_info=True)

        if events:
            self._advance_watermark(to_lsn)
            logger.info(
                f"Processed {len(events)} CDC events "
                f"(LSN {self._lsn_to_hex(from_lsn)[:8]}… → "
                f"{self._lsn_to_hex(to_lsn)[:8]}…)"
            )

        return len(events)

    def run(self):
        self.running = True
        self.connect()
        logger.info(
            f"CDC consumer running — polling every {self.poll_interval}s"
        )
        while self.running:
            try:
                count = self.poll_once()
                if count == 0:
                    time.sleep(self.poll_interval)
            except Exception as exc:
                logger.error(f"Poll cycle failed: {exc}", exc_info=True)
                time.sleep(self.poll_interval * 5)  # back off on error

Key differences to keep in mind when operating both systems side by side:

| Aspect | PostgreSQL Logical Replication | SQL Server CDC |

|---|---|---|

| Delivery model | Push (streaming) | Pull (polling) |

| Consumer progress tracking | Replication slot (server-side) | Watermark table (application-side) |

| Uncommitted transaction safety | Guaranteed — WAL decoder only emits committed data | Guaranteed — log reader runs after commit |

| Disk pressure from slow consumer | WAL retention grows until slot advances | CDC tables accumulate rows until cleanup job runs |

| Minimum event latency | Sub-second (streaming) | Bounded by poll interval |

| Net-change support | Requires application logic | Built in (fn_cdc_get_net_changes) |

| Schema change handling | Publication must be updated manually | Requires re-enabling CDC on the table |

                UPDATE documents SET content = 'Changed content' WHERE id = %s

            'tasks.embedding_tasks.openai_client.embeddings.create',
            lambda **kw: type('R', (), {'data': [type('D', (), {'embedding': fake_embedding})()]})()
        )

            document_id=doc_id,
            content='Original content',  # content corresponding to original_hash
            model='text-embedding-3-small',
            target_table='documents',

        assert result['status'] == 'skipped'

27.7 Operational Runbook

Running a replication-based AI pipeline in production introduces operational concerns that have no analogue in batch pipelines. This section consolidates the patterns that tend to catch teams off guard.

Slot lifecycle management. Create replication slots only when the consumer is ready to start. An unused slot with no active consumer will cause WAL accumulation from the moment of creation. If you provision infrastructure in advance, use a startup check:

-- Safe slot initialization: create only if not exists, and only if consumer is ready
DO $$
BEGIN
    IF NOT EXISTS (
        SELECT 1 FROM pg_replication_slots WHERE slot_name = 'ai_pipeline_slot'
    ) THEN
        PERFORM pg_create_logical_replication_slot('ai_pipeline_slot', 'wal2json');
        RAISE NOTICE 'Created replication slot ai_pipeline_slot';
    END IF;
END $$;

Schema migrations under replication. Adding a column to a published table does not automatically include it in the publication's column list if you specified columns explicitly. After any schema migration on a published table, verify the publication reflects the new schema:

-- After ALTER TABLE documents ADD COLUMN summary TEXT:
-- Check what the publication currently exposes
SELECT
    p.pubname,
    pc.relname AS table_name,
    pa.attname AS column_name
FROM pg_publication p
JOIN pg_publication_rel pr ON pr.prpubid = p.oid
JOIN pg_class pc ON pc.oid = pr.prrelid
JOIN pg_attribute pa ON pa.attrelid = pc.oid AND pa.attnum > 0
WHERE p.pubname = 'ai_event_stream'
ORDER BY pc.relname, pa.attnum;

-- To add the new column to the publication:
ALTER PUBLICATION ai_event_stream
  SET TABLE documents (id, title, content, content_hash, metadata, summary, updated_at);

Standby promotion and slot failover. Logical replication slots are not replicated to physical standbys in PostgreSQL versions before 17. If your primary fails and you promote a standby, the slot does not exist on the new primary, and the consumer must start from the current WAL position — meaning events during the outage window are lost. Design your AI pipeline to handle this gracefully: on reconnection, trigger a reconciliation query that identifies records whose indexed_at < updated_at and re-queues them for embedding.

-- Reconciliation query: find documents that missed their embedding update
-- Run this on consumer startup after a failover event
INSERT INTO ai_pipeline_overflow (event_data, target_queue)
SELECT
    json_build_object(
        'table',     'documents',
        'operation', 'UPDATE',
        'row_id',    id,
        'columns',   json_build_object(
                         'id',      id,
                         'content', content,
                         'content_hash', content_hash,
                         'metadata', metadata,
                         'embedding_model', embedding_model
                     )
    ),
    'embeddings'
FROM documents
WHERE embedding IS NULL
   OR indexed_at IS NULL
   OR indexed_at < updated_at
ORDER BY updated_at DESC
LIMIT 10000;  -- process in bounded batches

Celery queue depth monitoring. The WAL consumer's health depends on Celery workers keeping up. Wire queue depth into your alerting:

# monitoring/queue_health.py — Celery queue depth metrics for Prometheus
from prometheus_client import Gauge
import redis

redis_client = redis.Redis(host='localhost', port=6379, db=0)

QUEUE_DEPTH = Gauge(
    'ai_pipeline_celery_queue_depth',
    'Number of pending tasks in Celery queue',
    ['queue_name']
)

REPLICATION_LAG = Gauge(
    'ai_pipeline_replication_lag_bytes',
    'PostgreSQL replication slot lag in bytes'
)


def collect_metrics(db_conn):
    # Celery queue depths (Redis list lengths)
    for queue in ['embeddings', 'ai_analysis', 'agents']:
        depth = redis_client.llen(queue)
        QUEUE_DEPTH.labels(queue_name=queue).set(depth)

    # Replication slot lag
    with db_conn.cursor() as cur:
        cur.execute("""
            SELECT
                pg_wal_lsn_diff(pg_current_wal_lsn(), confirmed_flush_lsn)
            FROM pg_replication_slots
            WHERE slot_name = 'ai_pipeline_slot'
        """)
        row = cur.fetchone()
        if row:
            REPLICATION_LAG.set(row[0])

Dead letter handling. Celery tasks that exhaust their retries end up in the dead letter queue. For AI pipelines, a failed embedding task means a document has stale or missing embeddings — a silent accuracy problem. Add a periodic job that audits the dead letter queue against your documents table:

-- Audit: documents with failed or missing embeddings
SELECT
    d.id,
    d.title,
    d.updated_at,
    d.indexed_at,
    d.embedding IS NULL          AS missing_embedding,
    d.indexed_at < d.updated_at  AS stale_embedding,
    e.action_status              AS last_pipeline_status,
    e.error_message
FROM documents d
LEFT JOIN LATERAL (
    SELECT action_status, error_message
    FROM ai_pipeline_events
    WHERE source_table = 'documents'
      AND source_id = d.id
      AND triggered_action = 'refresh_embedding'
    ORDER BY received_at DESC
    LIMIT 1
) e ON true
WHERE d.embedding IS NULL
   OR d.indexed_at IS NULL
   OR d.indexed_at < d.updated_at
ORDER BY d.updated_at DESC
LIMIT 100;

Key Takeaways

  • → **WAL-based event sourcing eliminates dual-write races.** Because logical replication decodes only committed WAL entries, your AI pipeline is physically incapable of receiving events for transactions that were rolled back — a guarantee that application-layer event publishing cannot provide without distributed transactions.
  • → **Acknowledge early, process asynchronously.** The WAL consumer should advance its `confirmed_flush_lsn` as soon as work is safely enqueued in a durable queue (Celery backed by Redis or a message broker), not after the embedding or LLM call completes. This decouples WAL retention from LLM latency.
  • → **Content hashing prevents redundant LLM API calls.** Embedding calls are expensive and rate-limited. Checking `content_hash` before dispatching, and again before writing the result back, eliminates wasted calls for metadata-only updates and handles the race condition where content changes twice before the first embedding task executes.
  • → **Replication slot lag is a disk-pressure risk, not just a latency metric.** PostgreSQL retains WAL segments until every slot has advanced past them. A consumer that stalls during an LLM provider outage or a traffic spike will cause unbounded WAL accumulation. Monitor lag in bytes and implement an automated safety valve that drops and recreates the slot — with event loss — before disk exhaustion occurs.
  • → **SQL Server CDC and PostgreSQL logical replication deliver the same semantic guarantee through different mechanics.** CDC polls system tables populated by the log reader agent, requiring the consumer to manage its own watermark; PostgreSQL streams directly from the WAL with server-side progress tracking via the replication slot. Design your event router to be database-agnostic so the same AI handlers serve both sources.
