Chapter 21: MCP and PostgreSQL: Direct AI Access to Your Database

The Model Context Protocol (MCP) changes how AI systems interact with databases. Instead of building custom tool integrations for every LLM application, MCP gives you a standardized interface that lets Claude, GPT-4, and any compliant AI model discover and invoke database capabilities directly — querying tables, running analytics, inspecting schemas, and executing transactions through a protocol the model understands natively. For PostgreSQL specifically, this means your database becomes a first-class participant in the AI reasoning loop, not just a backend storage system that humans translate for models. This chapter walks through building a production-grade MCP server backed by PostgreSQL, designing the schemas that make database exploration safe and powerful for AI agents, and the operational patterns that keep direct AI database access from becoming a liability.

---

What MCP Actually Is — And Why It Changes PostgreSQL Integration

Before MCP, connecting an LLM to PostgreSQL meant writing custom tool definitions for every capability you wanted to expose. You defined functions in your application layer, described them in whatever format your LLM framework expected, handled authentication, sanitized inputs, and translated results back into something the model could reason about. Every framework did this differently — LangChain tools, OpenAI function calling, Anthropic's tool use — each with its own schema, each requiring its own integration code.

MCP standardizes this at the protocol level. An MCP server exposes resources (things models can read), tools (functions models can call), and prompts (templates for common workflows). Any MCP-compatible client — Claude Desktop, a custom agent, an IDE plugin — can discover these capabilities automatically and invoke them without application-specific glue code.

For PostgreSQL, this is significant because your database already organizes information in ways that map cleanly to MCP concepts:

  • → **Tables and views** become resources — the model can list them, inspect their schemas, and read their contents
  • → **Functions and procedures** become tools — the model can call them with typed arguments
  • → **Query templates and common analytics** become prompts — reusable patterns the model can apply

    • The protocol runs over stdio or HTTP with a defined JSON-RPC message format. You build a server that speaks this protocol, connect it to PostgreSQL, and any MCP client gains structured, authenticated access to your database.

    Here's what the architecture looks like in practice:

    ┌─────────────────┐     MCP Protocol      ┌──────────────────┐
│  AI Client      │ ◄──────────────────► │  MCP Server      │
│  (Claude, etc.) │   (JSON-RPC/stdio)    │  (Python/Node)   │
└─────────────────┘                       └────────┬─────────┘
                                                   │
                                          ┌────────▼─────────┐
                                          │   PostgreSQL     │
                                          │  + PgBouncer     │
                                          │  + Row Security  │
                                          └──────────────────┘

    The MCP server is where you enforce policy: which tables are visible, which operations are allowed, what query complexity is acceptable, and how results get formatted for model consumption.

    Schema Design for MCP-Accessible PostgreSQL

    A database designed for direct AI access needs different affordances than one designed purely for application code. Schema legibility, access boundaries, and metadata richness matter more because the model navigating your database has no prior knowledge of your domain — it reads what's there.

    Start with a clean separation between AI-accessible and application-internal schemas:

    -- Core schema separation
CREATE SCHEMA IF NOT EXISTS ai_readable;      -- Views and functions the MCP layer exposes
CREATE SCHEMA IF NOT EXISTS ai_tools;         -- Stored procedures MCP can invoke
CREATE SCHEMA IF NOT EXISTS app_internal;     -- Application tables, never directly exposed
CREATE SCHEMA IF NOT EXISTS mcp_audit;        -- All AI-generated queries and their results

-- Role for AI access — no superuser, no DDL
CREATE ROLE mcp_agent_role NOINHERIT;
GRANT USAGE ON SCHEMA ai_readable TO mcp_agent_role;
GRANT USAGE ON SCHEMA ai_tools TO mcp_agent_role;
GRANT SELECT ON ALL TABLES IN SCHEMA ai_readable TO mcp_agent_role;
GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA ai_tools TO mcp_agent_role;

-- Audit table for every AI interaction
CREATE TABLE mcp_audit.query_log (
    id              BIGSERIAL PRIMARY KEY,
    session_id      UUID NOT NULL DEFAULT gen_random_uuid(),
    agent_id        TEXT NOT NULL,
    tool_name       TEXT NOT NULL,
    input_params    JSONB NOT NULL DEFAULT '{}',
    sql_executed    TEXT,
    rows_returned   INTEGER,
    execution_ms    INTEGER,
    error_message   TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX ON mcp_audit.query_log (agent_id, created_at DESC);
CREATE INDEX ON mcp_audit.query_log (session_id);
CREATE INDEX ON mcp_audit.query_log USING GIN (input_params);

-- Example: a product catalog in app_internal
CREATE TABLE app_internal.products (
    id              BIGSERIAL PRIMARY KEY,
    sku             TEXT NOT NULL UNIQUE,
    name            TEXT NOT NULL,
    description     TEXT,
    price_cents     INTEGER NOT NULL,
    category_id     INTEGER REFERENCES app_internal.categories(id),
    inventory_count INTEGER NOT NULL DEFAULT 0,
    is_active       BOOLEAN NOT NULL DEFAULT TRUE,
    metadata        JSONB NOT NULL DEFAULT '{}',
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Safe view for AI consumption — no PII, clear column names
CREATE VIEW ai_readable.products AS
SELECT
    id,
    sku,
    name,
    description,
    ROUND(price_cents / 100.0, 2)   AS price_usd,
    c.name                           AS category,
    inventory_count,
    is_active,
    -- Computed fields that help models reason
    CASE
        WHEN inventory_count = 0 THEN 'out_of_stock'
        WHEN inventory_count < 10 THEN 'low_stock'
        ELSE 'in_stock'
    END                              AS stock_status,
    metadata,
    created_at
FROM app_internal.products p
JOIN app_internal.categories c ON c.id = p.category_id;

COMMENT ON VIEW ai_readable.products IS
    'Product catalog. Use this to look up product details, pricing, and availability. '
    'price_usd is the retail price in US dollars. stock_status summarizes inventory.';

COMMENT ON COLUMN ai_readable.products.metadata IS
    'Unstructured product attributes as JSON. Common keys: brand, dimensions, weight_kg, tags.';

-- Comments are readable by MCP tools — they guide model behavior
COMMENT ON COLUMN ai_readable.products.sku IS
    'Stock Keeping Unit — unique product identifier used in orders and shipments.';

    Comments on tables and columns are not cosmetic here — your MCP server will expose them as part of schema introspection, and models use them to decide which fields to query and how to interpret results.

    Now define the tools schema — stored procedures that perform bounded, auditable operations:

    -- Parameterized search function — prevents freeform SQL injection
CREATE OR REPLACE FUNCTION ai_tools.search_products(
    search_query    TEXT,
    category_filter TEXT DEFAULT NULL,
    max_price_usd   NUMERIC DEFAULT NULL,
    in_stock_only   BOOLEAN DEFAULT FALSE,
    result_limit    INTEGER DEFAULT 20
)
RETURNS TABLE (
    id              BIGINT,
    sku             TEXT,
    name            TEXT,
    price_usd       NUMERIC,
    category        TEXT,
    stock_status    TEXT,
    relevance_score REAL
)
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = app_internal, ai_readable, public
AS $$
BEGIN
    -- Enforce reasonable limits — models can request large result sets
    result_limit := LEAST(result_limit, 100);

    RETURN QUERY
    SELECT
        p.id,
        p.sku,
        p.name,
        ROUND(p.price_cents / 100.0, 2)::NUMERIC AS price_usd,
        c.name                                    AS category,
        CASE
            WHEN p.inventory_count = 0 THEN 'out_of_stock'
            WHEN p.inventory_count < 10 THEN 'low_stock'
            ELSE 'in_stock'
        END                                       AS stock_status,
        ts_rank(
            to_tsvector('english', p.name || ' ' || COALESCE(p.description, '')),
            plainto_tsquery('english', search_query)
        )                                         AS relevance_score
    FROM app_internal.products p
    JOIN app_internal.categories c ON c.id = p.category_id
    WHERE
        p.is_active = TRUE
        AND to_tsvector('english', p.name || ' ' || COALESCE(p.description, ''))
            @@ plainto_tsquery('english', search_query)
        AND (category_filter IS NULL OR c.name ILIKE category_filter)
        AND (max_price_usd IS NULL OR p.price_cents <= (max_price_usd * 100)::INTEGER)
        AND (NOT in_stock_only OR p.inventory_count > 0)
    ORDER BY relevance_score DESC
    LIMIT result_limit;
END;
$$;

COMMENT ON FUNCTION ai_tools.search_products IS
    'Search products by keyword. Returns up to 100 results ordered by relevance. '
    'Use category_filter to narrow by product category, max_price_usd to cap results '
    'by price, in_stock_only=true to exclude unavailable items.';

-- Analytics tool — canned aggregations the model can call
CREATE OR REPLACE FUNCTION ai_tools.category_sales_summary(
    start_date  DATE DEFAULT CURRENT_DATE - INTERVAL '30 days',
    end_date    DATE DEFAULT CURRENT_DATE
)
RETURNS TABLE (
    category        TEXT,
    order_count     BIGINT,
    total_revenue   NUMERIC,
    avg_order_value NUMERIC,
    top_product     TEXT
)
LANGUAGE sql
SECURITY DEFINER
SET search_path = app_internal, public
AS $$
    WITH sales AS (
        SELECT
            c.name                          AS category,
            COUNT(DISTINCT o.id)            AS order_count,
            SUM(oi.quantity * oi.unit_price_cents) / 100.0 AS total_revenue,
            p.name                          AS product_name,
            ROW_NUMBER() OVER (
                PARTITION BY c.name
                ORDER BY SUM(oi.quantity * oi.unit_price_cents) DESC
            )                               AS product_rank
        FROM app_internal.orders o
        JOIN app_internal.order_items oi ON oi.order_id = o.id
        JOIN app_internal.products p    ON p.id = oi.product_id
        JOIN app_internal.categories c  ON c.id = p.category_id
        WHERE o.created_at::DATE BETWEEN start_date AND end_date
          AND o.status NOT IN ('cancelled', 'refunded')
        GROUP BY c.name, p.name
    )
    SELECT
        category,
        SUM(order_count)::BIGINT        AS order_count,
        SUM(total_revenue)              AS total_revenue,
        AVG(total_revenue / NULLIF(order_count, 0)) AS avg_order_value,
        MAX(CASE WHEN product_rank = 1 THEN product_name END) AS top_product
    FROM sales
    GROUP BY category
    ORDER BY total_revenue DESC;
$$;

    Building the MCP Server in Python

    The Python MCP SDK (mcp) handles protocol negotiation, capability advertisement, and message routing. Your job is to wire it to PostgreSQL with appropriate safety controls. Here's a complete, production-structured MCP server:

    # mcp_postgres_server.py
import asyncio
import json
import time
import logging
from contextlib import asynccontextmanager
from typing import Any, Optional
from uuid import uuid4

import asyncpg
from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp import types

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

# ─── Database connection pool ────────────────────────────────────────────────

DB_DSN = "postgresql://mcp_agent_user:secret@localhost:5432/myapp"

pool: Optional[asyncpg.Pool] = None


async def get_pool() -> asyncpg.Pool:
    global pool
    if pool is None:
        pool = await asyncpg.create_pool(
            dsn=DB_DSN,
            min_size=2,
            max_size=10,
            command_timeout=30,        # AI queries can be slow — be reasonable
            max_inactive_connection_lifetime=300,
        )
    return pool


# ─── Audit logging ───────────────────────────────────────────────────────────

async def log_tool_call(
    agent_id: str,
    session_id: str,
    tool_name: str,
    input_params: dict,
    sql_executed: Optional[str],
    rows_returned: Optional[int],
    execution_ms: int,
    error_message: Optional[str] = None,
):
    p = await get_pool()
    async with p.acquire() as conn:
        await conn.execute(
            """
            INSERT INTO mcp_audit.query_log
                (session_id, agent_id, tool_name, input_params,
                 sql_executed, rows_returned, execution_ms, error_message)
            VALUES ($1, $2, $3, $4, $5, $6, $7, $8)
            """,
            session_id,
            agent_id,
            tool_name,
            json.dumps(input_params),
            sql_executed,
            rows_returned,
            execution_ms,
            error_message,
        )


# ─── MCP Server definition ───────────────────────────────────────────────────

app = Server("postgres-mcp-server")

SESSION_ID = str(uuid4())
AGENT_ID = "default-agent"  # Override from environment or client headers


@app.list_resources()
async def list_resources() -> list[types.Resource]:
    """Advertise AI-readable database resources."""
    p = await get_pool()
    async with p.acquire() as conn:
        # Discover views in the ai_readable schema dynamically
        rows = await conn.fetch(
            """
            SELECT
                table_name,
                obj_description(
                    (quote_ident(table_schema) || '.' || quote_ident(table_name))::regclass,
                    'pg_class'
                ) AS description
            FROM information_schema.tables
            WHERE table_schema = 'ai_readable'
              AND table_type = 'VIEW'
            ORDER BY table_name
            """
        )

    resources = []
    for row in rows:
        resources.append(
            types.Resource(
                uri=f"postgres://ai_readable/{row['table_name']}",
                name=row["table_name"].replace("_", " ").title(),
                description=row["description"] or f"Database view: {row['table_name']}",
                mimeType="application/json",
            )
        )
    return resources


@app.read_resource()
async def read_resource(uri: str) -> str:
    """Read the first N rows from an ai_readable view."""
    # Parse: postgres://ai_readable/{view_name}
    parts = uri.replace("postgres://", "").split("/")
    if len(parts) != 2 or parts[0] != "ai_readable":
        raise ValueError(f"Unknown resource URI: {uri}")

    view_name = parts[1]

    # Whitelist: only views that actually exist in ai_readable
    p = await get_pool()
    async with p.acquire() as conn:
        exists = await conn.fetchval(
            """
            SELECT COUNT(*) FROM information_schema.tables
            WHERE table_schema = 'ai_readable'
              AND table_name = $1
              AND table_type = 'VIEW'
            """,
            view_name,
        )
        if not exists:
            raise ValueError(f"Resource not found: {view_name}")

        # Limit reads — models shouldn't dump entire tables
        rows = await conn.fetch(
            f'SELECT * FROM ai_readable."{view_name}" LIMIT 50'
        )

        # Include schema information alongside data
        columns = await conn.fetch(
            """
            SELECT
                column_name,
                data_type,
                col_description(
                    (quote_ident(table_schema) || '.' || quote_ident(table_name))::regclass,
                    ordinal_position
                ) AS description
            FROM information_schema.columns
            WHERE table_schema = 'ai_readable'
              AND table_name = $1
            ORDER BY ordinal_position
            """,
            view_name,
        )

    schema_info = [
        {
            "column": col["column_name"],
            "type": col["data_type"],
            "description": col["description"],
        }
        for col in columns
    ]

    data = [dict(row) for row in rows]

    result = {
        "view": view_name,
        "schema": schema_info,
        "row_count_shown": len(data),
        "note": "Showing first 50 rows. Use search_products or other tools for filtered queries.",
        "data": data,
    }

    return json.dumps(result, default=str, indent=2)

@app.call_tool()
async def call_tool(name: str, arguments: dict) -> list[types.TextContent]:
    """Dispatch MCP tool calls to PostgreSQL functions."""
    start_time = time.time()
    p = await get_pool()
    result_data = None
    sql_executed = None
    error_message = None

    try:
        async with p.acquire() as conn:
            # Set agent context for RLS and audit
            await conn.execute(
                "SELECT set_config('mcp.agent_id', $1, TRUE)", AGENT_ID
            )

            if name == "search_products":
                sql_executed = "SELECT * FROM ai_tools.search_products(...)"
                rows = await conn.fetch(
                    """
                    SELECT * FROM ai_tools.search_products(
                        search_query    => $1,
                        category_filter => $2,
                        max_price_usd   => $3,
                        in_stock_only   => $4,
                        result_limit    => $5
                    )
                    """,
                    arguments.get("query"),
                    arguments.get("category"),
                    arguments.get("max_price_usd"),
                    arguments.get("in_stock_only", False),
                    arguments.get("limit", 20),
                )
                result_data = {
                    "results": [dict(r) for r in rows],
                    "count": len(rows),
                }

            elif name == "get_schema_info":
                table_name = arguments["table_name"]
                sql_executed = f"SELECT column info for {table_name}"
                rows = await conn.fetch(
                    """
                    SELECT
                        c.column_name,
                        c.data_type,
                        c.is_nullable,
                        col_description(
                            (quote_ident(c.table_schema) || '.' || quote_ident(c.table_name))::regclass,
                            c.ordinal_position
                        ) AS column_description
                    FROM information_schema.columns c
                    WHERE c.table_schema = 'ai_readable'
                      AND c.table_name = $1
                    ORDER BY c.ordinal_position
                    """,
                    table_name,
                )
                if not rows:
                    result_data = {"error": f"Table '{table_name}' not found in ai_readable schema."}
                else:
                    view_desc = await conn.fetchval(
                        """
                        SELECT obj_description(
                            (quote_ident('ai_readable') || '.' || quote_ident($1))::regclass,
                            'pg_class'
                        )
                        """,
                        table_name,
                    )
                    result_data = {
                        "table": table_name,
                        "description": view_desc,
                        "columns": [dict(r) for r in rows],
                    }

            elif name == "category_sales_summary":
                sql_executed = "SELECT * FROM ai_tools.category_sales_summary(...)"
                rows = await conn.fetch(
                    """
                    SELECT * FROM ai_tools.category_sales_summary(
                        start_date => $1::DATE,
                        end_date   => $2::DATE
                    )
                    """,
                    arguments.get("start_date"),
                    arguments.get("end_date"),
                )
                result_data = {
                    "summary": [dict(r) for r in rows],
                    "period": {
                        "start": arguments.get("start_date", "last 30 days"),
                        "end": arguments.get("end_date", "today"),
                    },
                }

            elif name == "get_low_stock_alerts":
                threshold = arguments.get("threshold", 10)
                sql_executed = f"SELECT low stock products below {threshold}"
                rows = await conn.fetch(
                    """
                    SELECT
                        sku,
                        name,
                        category,
                        inventory_count,
                        stock_status
                    FROM ai_readable.products
                    WHERE inventory_count < $1
                      AND is_active = TRUE
                    ORDER BY inventory_count ASC
                    LIMIT 200
                    """,
                    threshold,
                )
                result_data = {
                    "alerts": [dict(r) for r in rows],
                    "count": len(rows),
                    "threshold": threshold,
                }

            else:
                raise ValueError(f"Unknown tool: {name}")

        execution_ms = int((time.time() - start_time) * 1000)
        rows_returned = (
            len(result_data.get("results", result_data.get("summary", result_data.get("alerts", []))))
            if result_data else 0
        )

        await log_tool_call(
            agent_id=AGENT_ID,
            session_id=SESSION_ID,
            tool_name=name,
            input_params=arguments,
            sql_executed=sql_executed,
            rows_returned=rows_returned,
            execution_ms=execution_ms,
        )

        return [
            types.TextContent(
                type="text",
                text=json.dumps(result_data, default=str, indent=2),
            )
        ]

    except Exception as e:
        execution_ms = int((time.time() - start_time) * 1000)
        error_message = str(e)
        logger.error(f"Tool call failed: {name} — {e}")

        await log_tool_call(
            agent_id=AGENT_ID,
            session_id=SESSION_ID,
            tool_name=name,
            input_params=arguments,
            sql_executed=sql_executed,
            rows_returned=None,
            execution_ms=execution_ms,
            error_message=error_message,
        )

        return [
            types.TextContent(
                type="text",
                text=json.dumps({"error": error_message}, indent=2),
            )
        ]

    This server handles the full lifecycle: pool management, audit logging, RLS context setting, and clean error propagation back to the model. Notice that even in the error path you log the attempt — an AI agent that repeatedly fails against the same tool is a signal worth capturing.

    sequenceDiagram
    participant Client as AI Client (Claude, etc.)
    participant MCP as MCP Server
    participant PG as PostgreSQL

    Client->>MCP: list_tools() / list_resources()
    MCP->>PG: introspect ai_readable / ai_tools schemas
    PG-->>MCP: view + function metadata, comments
    MCP-->>Client: advertised tools & resources

    Client->>MCP: call_tool("search_products", args)
    MCP->>PG: SET mcp.agent_id (RLS context)
    MCP->>PG: SELECT * FROM ai_tools.search_products(...)
    PG-->>MCP: result rows
    MCP->>PG: INSERT INTO mcp_audit.query_log
    MCP-->>Client: TextContent(json results)

    *Every tool call passes through the same choke point: set the agent's RLS context, invoke a bounded stored function, then log the attempt regardless of outcome.*

    Registering the Server with Claude Desktop

    Once your server is running, register it in Claude Desktop's configuration file:

    {
  "mcpServers": {
    "postgres-store": {
      "command": "python",
      "args": ["/path/to/mcp_postgres_server.py"],
      "env": {
        "DATABASE_URL": "postgresql://mcp_agent_user:secret@localhost:5432/myapp",
        "MCP_AGENT_ID": "claude-desktop-session"
      }
    }
  }
}

    Claude Desktop starts the process via stdio, negotiates capabilities, and from that point the model can discover and invoke your tools in any conversation. You can verify the server is advertising correctly by checking Claude's tool panel — it should list search_products, get_schema_info, category_sales_summary, and get_low_stock_alerts with the descriptions you defined.

    Safety Controls and Query Governance

    Direct AI access to databases introduces failure modes that don't exist with traditional application code. Models can misunderstand schemas, construct semantically incorrect queries, or — in the case of tools that accept freeform SQL — generate statements with catastrophic side effects. The layered defense here is more important than in most application contexts.

    Never expose raw SQL execution as an MCP tool. The temptation is strong — a run_sql tool is maximally flexible and requires minimal server-side code. But it gives models write access, DDL capability, and the ability to construct queries that scan entire tables. Every tool your MCP server exposes should have a defined, bounded contract.

    If you genuinely need ad-hoc query capability (for internal analytics agents, not customer-facing ones), constrain it aggressively:

    -- A safer ad-hoc query executor — for internal use only
CREATE OR REPLACE FUNCTION ai_tools.execute_readonly_query(
    query_text TEXT
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = ai_readable, public
SET default_transaction_read_only = on   -- Block writes at session level
AS $$
DECLARE
    result     JSONB;
    row_count  INTEGER;
BEGIN
    -- Reject anything that looks like DDL or DML
    IF query_text ~* '^\s*(INSERT|UPDATE|DELETE|DROP|CREATE|ALTER|TRUNCATE|GRANT|REVOKE)' THEN
        RAISE EXCEPTION 'Only SELECT queries are permitted via this tool';
    END IF;

    -- Reject subqueries targeting non-ai_readable schemas
    -- (This is a heuristic — not a substitute for schema-level permissions)
    IF query_text ~* 'app_internal|mcp_audit|pg_catalog|information_schema' THEN
        RAISE EXCEPTION 'Queries targeting internal schemas are not permitted';
    END IF;

    -- Execute with statement timeout as extra backstop
    SET LOCAL statement_timeout = '10s';

    EXECUTE 'SELECT jsonb_agg(row_to_json(q)) FROM (' || query_text || ') q'
    INTO result;

    RETURN COALESCE(result, '[]'::JSONB);
END;
$$;

-- Grant only to a special elevated role, not the default mcp_agent_role
REVOKE ALL ON FUNCTION ai_tools.execute_readonly_query FROM PUBLIC;
GRANT EXECUTE ON FUNCTION ai_tools.execute_readonly_query TO mcp_analyst_role;

    Even this function is imperfect — regex-based SQL parsing can be bypassed. The stronger control is the SET search_path restriction and the read-only transaction mode, which the database enforces rather than the application layer.

    Set statement timeouts at the connection level, not just per query. An MCP server that connects to PostgreSQL should enforce a session-level timeout so that a runaway AI-generated query doesn't hold a connection indefinitely:

    async def get_pool() -> asyncpg.Pool:

            dsn=DB_DSN,

async def _configure_connection(conn: asyncpg.Connection):
    """Apply safety settings to every new connection."""
    await conn.execute("""
        SET statement_timeout = '15s';
        SET lock_timeout = '5s';
        SET idle_in_transaction_session_timeout = '30s';
    """)

    Rate-limit tool calls per agent. A model in an agentic loop can issue hundreds of tool calls before a human notices. Track call frequency in your MCP server and apply backpressure:

    import time
from collections import defaultdict

# Simple in-process rate limiter — use Redis for multi-process deployments
_call_counts: dict[str, list[float]] = defaultdict(list)
RATE_LIMIT_CALLS = 60
RATE_LIMIT_WINDOW = 60.0  # seconds


def check_rate_limit(agent_id: str) -> None:
    now = time.time()
    window_start = now - RATE_LIMIT_WINDOW
    calls = _call_counts[agent_id]

    # Purge old entries
    _call_counts[agent_id] = [t for t in calls if t > window_start]

    if len(_call_counts[agent_id]) >= RATE_LIMIT_CALLS:
        raise RuntimeError(
            f"Rate limit exceeded: {RATE_LIMIT_CALLS} calls per {int(RATE_LIMIT_WINDOW)}s. "
            f"Slow down and consolidate queries where possible."
        )

    _call_counts[agent_id].append(now)

    Call check_rate_limit(AGENT_ID) at the top of your call_tool handler before touching the database.

    Validate argument types before passing them to PostgreSQL. asyncpg parameterizes queries correctly, which prevents SQL injection, but it doesn't prevent a model from passing a string like "'; DROP TABLE products; --" as a date parameter and getting a confusing error back. Explicit validation gives you cleaner error messages to return to the model:

    from datetime import date


def validate_date(value: Any, field_name: str) -> Optional[str]:
    """Return None if valid, error string if not."""
    if value is None:
        return None
    try:
        date.fromisoformat(str(value))
        return None
    except ValueError:
        return f"Invalid date for '{field_name}': '{value}'. Use YYYY-MM-DD format."

    Monitoring AI Database Access in Production

    Your audit table is the foundation, but raw log rows aren't operational visibility. Build views and alerting queries on top of mcp_audit.query_log that surface actionable patterns:

    -- Tool usage frequency over last 24 hours
CREATE OR REPLACE VIEW mcp_audit.tool_usage_24h AS
SELECT
    tool_name,
    agent_id,
    COUNT(*)                                    AS call_count,
    AVG(execution_ms)                           AS avg_latency_ms,
    PERCENTILE_CONT(0.95) WITHIN GROUP
        (ORDER BY execution_ms)                 AS p95_latency_ms,
    MAX(execution_ms)                           AS max_latency_ms,
    SUM(CASE WHEN error_message IS NOT NULL
             THEN 1 ELSE 0 END)                 AS error_count,
    ROUND(
        100.0 * SUM(CASE WHEN error_message IS NOT NULL
                         THEN 1 ELSE 0 END) / COUNT(*), 2
    )                                           AS error_rate_pct
FROM mcp_audit.query_log
WHERE created_at > NOW() - INTERVAL '24 hours'
GROUP BY tool_name, agent_id
ORDER BY call_count DESC;

-- Anomaly detection: sessions with unusually high call volume
CREATE OR REPLACE VIEW mcp_audit.high_volume_sessions AS
SELECT
    session_id,
    agent_id,
    COUNT(*)                AS total_calls,
    MIN(created_at)         AS session_start,
    MAX(created_at)         AS last_call,
    EXTRACT(EPOCH FROM (MAX(created_at) - MIN(created_at)))::INT AS duration_seconds,
    ROUND(COUNT(*) * 60.0 /
        NULLIF(EXTRACT(EPOCH FROM (MAX(created_at) - MIN(created_at))), 0),
    1)                      AS calls_per_minute
FROM mcp_audit.query_log
WHERE created_at > NOW() - INTERVAL '1 hour'
GROUP BY session_id, agent_id
HAVING COUNT(*) > 30
ORDER BY calls_per_minute DESC NULLS LAST;

-- Slow query tracking — candidates for optimization
CREATE OR REPLACE VIEW mcp_audit.slow_tool_calls AS
SELECT
    id,
    agent_id,
    tool_name,
    input_params,
    execution_ms,
    rows_returned,
    created_at
FROM mcp_audit.query_log
WHERE execution_ms > 5000
  AND created_at > NOW() - INTERVAL '7 days'
ORDER BY execution_ms DESC;

    Hook these views into your existing alerting system. A session with more than thirty calls per minute likely indicates an agentic loop that isn't converging — worth interrupting before it runs up database load or API costs. Slow tool calls above your SLA threshold (typically around five seconds for interactive AI sessions) point to missing indexes or functions that need optimization.

    For a Prometheus-compatible metrics endpoint, you can extend the HTTP server with a /metrics path that queries these views and emits gauge and counter metrics. This integrates MCP database activity into the same dashboards you use for application performance.

    p.sku,

-- Parameterized search stored procedure
CREATE OR ALTER PROCEDURE ai_tools.search_products
    @search_query    NVARCHAR(500),
    @category_filter NVARCHAR(255) = NULL,
    @max_price_usd   DECIMAL(10,2) = NULL,
    @in_stock_only   BIT           = 0,
    @result_limit    INT           = 20
AS
BEGIN
    SET NOCOUNT ON;

    -- Enforce max result cap
    IF @result_limit > 100 SET @result_limit = 100;

    SELECT TOP (@result_limit)
        p.id,
        p.sku,
        p.name,
        CAST(p.price_cents AS DECIMAL(10,2)) / 100  AS price_usd,
        c.name                                       AS category,
        CASE
            WHEN p.inventory_count = 0 THEN 'out_of_stock'
            WHEN p.inventory_count < 10 THEN 'low_stock'
            ELSE 'in_stock'
        END                                          AS stock_status
    FROM dbo.products p
    JOIN dbo.categories c ON c.id = p.category_id
    WHERE
        p.is_active = 1
        AND (
            p.name LIKE '%' + @search_query + '%'
            OR p.description LIKE '%' + @search_query + '%'
        )
        AND (@category_filter IS NULL OR c.name LIKE @category_filter)
        AND (@max_price_usd IS NULL
             OR p.price_cents <= CAST(@max_price_usd * 100 AS INT))
        AND (@in_stock_only = 0 OR p.inventory_count > 0)
    ORDER BY
        -- Simple relevance: exact name match ranks higher
        CASE WHEN p.name LIKE @search_query + '%' THEN 0 ELSE 1 END,
        p.name;
END;
GO

    Note that SQL Server lacks PostgreSQL's plainto_tsquery full-text ranking — you either use the LIKE-based approach above (adequate for moderate catalog sizes), SQL Server Full-Text Search with CONTAINSTABLE for relevance ranking, or Azure Cognitive Search as an external index. The MCP server code adapts straightforwardly: replace asyncpg with aioodbc or pyodbc, adjust the SQL dialect, and use stored procedure calls instead of function calls:

    Combining MCP with Vector Search

    MCP tools and pgvector complement each other naturally. A product search that uses both keyword matching and semantic similarity gives models richer results than either approach alone. Extend your tools schema with a hybrid search function:

    -- Requires pgvector extension and an embeddings column on products
ALTER TABLE app_internal.products
    ADD COLUMN IF NOT EXISTS name_embedding VECTOR(1536);

CREATE INDEX ON app_internal.products
    USING ivfflat (name_embedding vector_cosine_ops)
    WITH (lists = 100);

-- Hybrid search: keyword + semantic, with RRF fusion
CREATE OR REPLACE FUNCTION ai_tools.hybrid_search_products(
    search_query      TEXT,
    query_embedding   VECTOR(1536),
    category_filter   TEXT DEFAULT NULL,
    result_limit      INTEGER DEFAULT 20
)
RETURNS TABLE (
    id              BIGINT,
    sku             TEXT,
    name            TEXT,
    price_usd       NUMERIC,
    category        TEXT,
    stock_status    TEXT,
    hybrid_score    DOUBLE PRECISION
)
LANGUAGE sql
SECURITY DEFINER
SET search_path = app_internal, ai_readable, public
AS $$
    WITH keyword_results AS (
        SELECT
            p.id,
            ROW_NUMBER() OVER (
                ORDER BY ts_rank(
                    to_tsvector('english', p.name || ' ' || COALESCE(p.description, '')),
                    plainto_tsquery('english', search_query)
                ) DESC
            ) AS keyword_rank
        FROM app_internal.products p
        WHERE
            p.is_active = TRUE
            AND to_tsvector('english', p.name || ' ' || COALESCE(p.description, ''))
                @@ plainto_tsquery('english', search_query)
    ),
    vector_results AS (
        SELECT
            p.id,
            ROW_NUMBER() OVER (
                ORDER BY p.name_embedding <=> query_embedding
            ) AS vector_rank
        FROM app_internal.products p
        WHERE p.is_active = TRUE
          AND p.name_embedding IS NOT NULL
        ORDER BY p.name_embedding <=> query_embedding
        LIMIT 100
    ),
    -- Reciprocal Rank Fusion
    fused AS (
        SELECT
            COALESCE(k.id, v.id)          AS id,
            COALESCE(1.0 / (60 + k.keyword_rank), 0) +
            COALESCE(1.0 / (60 + v.vector_rank), 0)  AS rrf_score
        FROM keyword_results k
        FULL OUTER JOIN vector_results v ON v.id = k.id
    )
    SELECT
        p.id,
        p.sku,
        p.name,
        ROUND(p.price_cents / 100.0, 2)::NUMERIC AS price_usd,
        c.name                                    AS category,
        CASE
            WHEN p.inventory_count = 0 THEN 'out_of_stock'
            WHEN p.inventory_count < 10 THEN 'low_stock'
            ELSE 'in_stock'
        END                                       AS stock_status,
        f.rrf_score                               AS hybrid_score
    FROM fused f
    JOIN app_internal.products p ON p.id = f.id
    JOIN app_internal.categories c ON c.id = p.category_id
    WHERE
        (category_filter IS NULL OR c.name ILIKE category_filter)
    ORDER BY rrf_score DESC
    LIMIT result_limit;
$$;

    Handling Large Result Sets

    Models have finite context windows, and raw database result sets can quickly fill them. Build result shaping into your MCP layer rather than letting the model request arbitrarily large responses:

    def shape_results_for_model(
    rows: list[dict],
    max_rows: int = 50,
    summarize_above: int = 20,
) -> dict:
    """
    Return a context-efficient representation of query results.
    For small result sets, return full data. For large ones, include
    a summary alongside the full set so models can decide what to explore further.
    """
    total = len(rows)
    truncated = rows[:max_rows]

    result = {
        "total_count": total,
        "shown_count": len(truncated),
        "data": truncated,
    }

    if total > summarize_above:
        # Add lightweight summary so model understands what's not shown
        result["note"] = (
            f"Showing {len(truncated)} of {total} results. "
            f"Use more specific filters to narrow results."
        )

    return result

    For analytics tools that return aggregated data, consider adding a "key_insight" field computed in Python before returning to the model:

    def add_insights(summary_rows: list[dict]) -> dict:
    if not summary_rows:
        return {"summary": [], "insights": ["No data found for this period."]}

    total_revenue = sum(r.get("total_revenue", 0) or 0 for r in summary_rows)
    top_category = summary_rows[0]["category"] if summary_rows else None
    top_share = (
        (summary_rows[0].get("total_revenue", 0) or 0) / total_revenue * 100
        if total_revenue > 0 else 0
    )

    insights = [
        f"Total revenue across all categories: ${total_revenue:,.2f}",
        f"Top category '{top_category}' accounts for {top_share:.1f}% of revenue.",
    ]

    zero_revenue = [r["category"] for r in summary_rows if (r.get("total_revenue") or 0) == 0]
    if zero_revenue:
        insights.append(f"Categories with no recorded revenue: {', '.join(zero_revenue)}.")

    return {"summary": summary_rows, "insights": insights}

    These small additions meaningfully improve model reasoning quality. A model that receives pre-computed totals and share percentages alongside raw rows reaches correct conclusions faster than one that has to reconstruct them from JSON arrays.

  • → **MCP standardizes AI-to-database access** at the protocol level, replacing per-framework tool integration code with a single server that any compliant client can discover and invoke. For PostgreSQL, this means schema design, security boundaries, and audit infrastructure become first-class concerns rather than afterthoughts.
  • → **Schema separation is the foundation of safe AI database access.** Keeping AI-readable views and AI-callable functions in dedicated schemas, under a role with no write permissions and no DDL capability, limits the blast radius of model errors while giving the model clear, well-documented data to reason about.
  • → **Every MCP tool call must be audited.** The `mcp_audit.query_log` table — capturing agent identity, tool name, parameters, SQL executed, and execution time — is not optional. It's the primary debugging and governance mechanism when AI behavior needs investigation, and the source of operational metrics for capacity planning.
  • → **Constrain tools aggressively; never expose raw SQL execution to general agents.** Parameterized stored functions with hard-coded result limits, argument validation, statement timeouts, and rate limiting at the MCP server layer prevent the failure modes unique to AI-driven database access: runaway queries, agentic loops, and unexpected data exposure.
  • → **Hybrid search via pgvector plus keyword ranking, generated server-side within the MCP layer, gives models the most relevant results** without requiring model-side embedding generation. The embedding API call happens transparently inside the tool handler, keeping the tool interface simple while delivering semantic search quality that scales to large, unstructured product catalogs.
