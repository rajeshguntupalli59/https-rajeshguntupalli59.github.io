Chapter 13: End-to-End RAG Pipeline with PostgreSQL

Retrieval-Augmented Generation is where most PostgreSQL teams start their AI journey, and for good reason: you already have the data, you already trust the database, and pgvector gives you a production-grade vector store without spinning up yet another infrastructure component. But most RAG tutorials stop at the happy path — embed some text, store a vector, run a similarity search, hand it to the LLM. Real RAG pipelines have ingestion queues, metadata filtering, reranking, caching, multi-tenant isolation, citation tracking, and observability. This chapter builds the entire stack from raw document to grounded LLM response, using PostgreSQL as the backbone at every layer.

graph LR
    Doc[Document ingested] --> Chunk[Chunked + embedded]
    Chunk --> Store[(documents / document_chunks)]
    Query[User query] --> Cache{Semantic cache hit?}
    Cache -->|yes| Answer[Return cached answer]
    Cache -->|no| Embed[Embed query]
    Embed --> Hybrid[hybrid_retrieve: vector + full-text, RRF-fused]
    Store --> Hybrid
    Hybrid --> Log[(retrieval_log)]
    Hybrid --> Prompt[Assemble system prompt with citations]
    Prompt --> LLM[Call LLM]
    LLM --> Answer
    LLM --> Turn[(conversation_turns)]

*The stages in this chapter, end to end: ingestion feeds the store, retrieval and caching sit in front of the LLM call, and every step writes an audit trail.*

13.1 Designing the RAG Schema

Before writing a single line of Python, the schema design determines everything. A well-designed RAG schema handles the full document lifecycle: ingestion status, chunking, embedding storage, retrieval metadata, and answer audit trails. Getting this wrong means rebuilding under production load.

The core tables form a directed graph: documents → document_chunks → chunk_embeddings. A separate retrieval_log table captures what was retrieved for each query, enabling offline evaluation of retrieval quality. The conversations and conversation_turns tables store the multi-turn context that transforms a one-shot Q&A system into an actual assistant.

-- Complete RAG schema with production-ready structure

CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pg_trgm;    -- for hybrid text search
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- Tenants table for multi-tenant RAG deployments
CREATE TABLE tenants (
    tenant_id       UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    name            TEXT NOT NULL UNIQUE,
    embedding_model TEXT NOT NULL DEFAULT 'text-embedding-3-small',
    llm_model       TEXT NOT NULL DEFAULT 'gpt-4o',
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Source document registry
CREATE TABLE documents (
    document_id     UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    tenant_id       UUID NOT NULL REFERENCES tenants(tenant_id),
    title           TEXT NOT NULL,
    source_uri      TEXT,                          -- s3://, file://, https://
    content_type    TEXT NOT NULL DEFAULT 'text/plain',
    raw_content     TEXT,
    metadata        JSONB NOT NULL DEFAULT '{}',   -- author, tags, version, etc.
    word_count      INTEGER,
    status          TEXT NOT NULL DEFAULT 'pending'
                    CHECK (status IN ('pending','processing','embedded','failed')),
    error_detail    TEXT,
    ingested_at     TIMESTAMPTZ,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_documents_tenant     ON documents(tenant_id);
CREATE INDEX idx_documents_status     ON documents(status);
CREATE INDEX idx_documents_metadata   ON documents USING GIN(metadata);

-- Chunks produced from each document
CREATE TABLE document_chunks (
    chunk_id        UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    document_id     UUID NOT NULL REFERENCES documents(document_id) ON DELETE CASCADE,
    tenant_id       UUID NOT NULL REFERENCES tenants(tenant_id),
    chunk_index     INTEGER NOT NULL,              -- position within document
    content         TEXT NOT NULL,
    token_count     INTEGER,
    chunk_metadata  JSONB NOT NULL DEFAULT '{}',   -- page_number, section, etc.
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE(document_id, chunk_index)
);

CREATE INDEX idx_chunks_document   ON document_chunks(document_id);
CREATE INDEX idx_chunks_tenant     ON document_chunks(tenant_id);
-- GIN index for keyword fallback search
CREATE INDEX idx_chunks_content_fts ON document_chunks
    USING GIN(to_tsvector('english', content));
-- Trigram index for fuzzy matching
CREATE INDEX idx_chunks_trgm ON document_chunks USING GIN(content gin_trgm_ops);

-- Embedding storage — separate table allows model migrations
CREATE TABLE chunk_embeddings (
    embedding_id    UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    chunk_id        UUID NOT NULL REFERENCES document_chunks(chunk_id) ON DELETE CASCADE,
    tenant_id       UUID NOT NULL REFERENCES tenants(tenant_id),
    model_name      TEXT NOT NULL,
    embedding       vector(1536),                  -- OpenAI small; adjust per model
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE(chunk_id, model_name)
);

-- IVFFlat index — tune lists based on row count (rows / 1000, min 10)
CREATE INDEX idx_embeddings_vector ON chunk_embeddings
    USING ivfflat (embedding vector_cosine_ops)
    WITH (lists = 100);

-- Conversations
CREATE TABLE conversations (
    conversation_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    tenant_id       UUID NOT NULL REFERENCES tenants(tenant_id),
    user_id         TEXT,
    title           TEXT,
    metadata        JSONB NOT NULL DEFAULT '{}',
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_active_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE conversation_turns (
    turn_id         UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    conversation_id UUID NOT NULL REFERENCES conversations(conversation_id),
    tenant_id       UUID NOT NULL REFERENCES tenants(tenant_id),
    role            TEXT NOT NULL CHECK (role IN ('user','assistant','system')),
    content         TEXT NOT NULL,
    turn_index      INTEGER NOT NULL,
    model_used      TEXT,
    prompt_tokens   INTEGER,
    completion_tokens INTEGER,
    latency_ms      INTEGER,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_turns_conversation ON conversation_turns(conversation_id, turn_index);

-- Retrieval audit: what did we retrieve for each query?
CREATE TABLE retrieval_log (
    retrieval_id    UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    turn_id         UUID REFERENCES conversation_turns(turn_id),
    tenant_id       UUID NOT NULL REFERENCES tenants(tenant_id),
    query_text      TEXT NOT NULL,
    query_embedding vector(1536),
    retrieved_chunks JSONB NOT NULL DEFAULT '[]', -- [{chunk_id, score, rank}]
    retrieval_strategy TEXT,                      -- 'vector','hybrid','reranked'

);

CREATE POLICY tenant_isolation ON document_chunks
    USING (tenant_id = current_setting('app.current_tenant_id')::UUID);
CREATE POLICY tenant_isolation ON chunk_embeddings
    USING (tenant_id = current_setting('app.current_tenant_id')::UUID);
CREATE POLICY tenant_isolation ON conversations
    USING (tenant_id = current_setting('app.current_tenant_id')::UUID);
CREATE POLICY tenant_isolation ON conversation_turns
    USING (tenant_id = current_setting('app.current_tenant_id')::UUID);
CREATE POLICY tenant_isolation ON retrieval_log
    USING (tenant_id = current_setting('app.current_tenant_id')::UUID);

The separation of document_chunks and chunk_embeddings pays off immediately when you want to re-embed with a new model. You keep the same chunks, add new rows to chunk_embeddings with model_name = 'text-embedding-3-large', and can run both models in parallel during a migration without touching the chunking logic. The retrieval_log table is underused in most systems but is the foundation of offline RAG evaluation — once you have it, you can compute MRR and NDCG against ground-truth queries without any external tooling.

13.2 Async Document Ingestion Pipeline

Ingestion is where RAG systems fall apart in production. Synchronous ingestion — a user uploads a document and waits for the API to embed it — fails immediately at scale. PDFs take variable amounts of time to parse, embedding APIs have rate limits, and a single large document might produce hundreds of chunks requiring dozens of API calls. The answer is a Celery-based async pipeline where the API accepts documents immediately, writes to PostgreSQL, and notifies workers via pg_notify.

# ingestion/tasks.py — Celery worker for document processing

import os
import re
import hashlib
import asyncio
from typing import Optional
from uuid import UUID

import psycopg2
import psycopg2.extras
from celery import Celery
from openai import OpenAI
import tiktoken

DATABASE_URL = os.environ["DATABASE_URL"]
REDIS_URL    = os.environ["REDIS_URL"]

app = Celery("rag_ingestion", broker=REDIS_URL, backend=REDIS_URL)
openai_client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])
tokenizer = tiktoken.get_encoding("cl100k_base")

# ── Chunking ──────────────────────────────────────────────────────────────────

def chunk_text(
    text: str,
    chunk_size: int = 512,
    overlap: int = 64,
) -> list[dict]:
    """
    Token-aware chunking with overlap.
    Returns list of {content, token_count, chunk_index}.
    """
    tokens = tokenizer.encode(text)
    chunks = []
    start = 0
    idx = 0

    while start < len(tokens):
        end = min(start + chunk_size, len(tokens))
        chunk_tokens = tokens[start:end]
        chunk_text = tokenizer.decode(chunk_tokens)
        chunks.append({
            "content":     chunk_text,
            "token_count": len(chunk_tokens),
            "chunk_index": idx,
        })
        start += chunk_size - overlap
        idx   += 1

    return chunks


# ── Embedding ─────────────────────────────────────────────────────────────────

def embed_batch(texts: list[str], model: str = "text-embedding-3-small") -> list[list[float]]:
    """Embed a batch of texts, respecting OpenAI batch limits."""
    response = openai_client.embeddings.create(input=texts, model=model)
    return [item.embedding for item in response.data]


# ── Main Celery task ──────────────────────────────────────────────────────────

@app.task(
    bind=True,
    autoretry_for=(Exception,),
    retry_backoff=True,
    retry_backoff_max=300,
    max_retries=5,
    name="ingestion.process_document",
)
def process_document(self, document_id: str, tenant_id: str):
    """
    Full ingestion pipeline for a single document:
    1. Mark as processing
    2. Load raw content
    3. Chunk
    4. Insert chunks
    5. Embed in batches
    6. Insert embeddings
    7. Mark as embedded, notify via pg_notify
    """
    conn = psycopg2.connect(DATABASE_URL)
    conn.autocommit = False

    try:
        with conn.cursor(cursor_factory=psycopg2.extras.RealDictCursor) as cur:

            # ── 1. Lock and mark processing ───────────────────────────────
            cur.execute("""
                UPDATE documents
                SET    status = 'processing', updated_at = NOW()
                WHERE  document_id = %s AND status = 'pending'
                RETURNING document_id, raw_content, metadata, title
            """, (document_id,))
            row = cur.fetchone()

            if not row:
                # Already picked up by another worker, idempotent exit
                return {"skipped": True, "document_id": document_id}

            raw_content = row["raw_content"]
            if not raw_content or not raw_content.strip():
                raise ValueError("Document has no content to process")

            conn.commit()

            # ── 2. Chunk ──────────────────────────────────────────────────
            chunks = chunk_text(raw_content, chunk_size=512, overlap=64)

            # ── 3. Insert chunks ──────────────────────────────────────────
            chunk_rows = []
            for chunk in chunks:
                cur.execute("""
                    INSERT INTO document_chunks
                        (document_id, tenant_id, chunk_index, content, token_count)
                    VALUES (%s, %s, %s, %s, %s)
                    RETURNING chunk_id
                """, (
                    document_id,
                    tenant_id,
                    chunk["chunk_index"],
                    chunk["content"],
                    chunk["token_count"],
                ))
                chunk_id = cur.fetchone()["chunk_id"]
                chunk_rows.append((chunk_id, chunk["content"]))

            conn.commit()

            # ── 4. Embed in batches of 100 ────────────────────────────────
            batch_size = 100
            for i in range(0, len(chunk_rows), batch_size):
                batch = chunk_rows[i : i + batch_size]
                chunk_ids = [r[0] for r in batch]
                texts     = [r[1] for r in batch]

                embeddings = embed_batch(texts, model="text-embedding-3-small")

                for chunk_id, embedding in zip(chunk_ids, embeddings):
                    cur.execute("""
                        INSERT INTO chunk_embeddings
                            (chunk_id, tenant_id, model_name, embedding)
                        VALUES (%s, %s, %s, %s::vector)
                        ON CONFLICT (chunk_id, model_name) DO NOTHING
                    """, (
                        str(chunk_id),
                        tenant_id,
                        "text-embedding-3-small",
                        str(embedding),
                    ))

            conn.commit()

            # ── 5. Mark embedded, update word count ───────────────────────
            word_count = len(raw_content.split())
            cur.execute("""
                UPDATE documents
                SET status      = 'embedded',
                    word_count  = %s,
                    ingested_at = NOW(),
                    updated_at  = NOW()
                WHERE document_id = %s
            """, (word_count, document_id))

            # ── 6. Notify downstream listeners ────────────────────────────
            cur.execute(
                "SELECT pg_notify('document_embedded', %s)",
                (f'{{"document_id":"{document_id}","tenant_id":"{tenant_id}"}}',)
            )
            conn.commit()

        return {"status": "embedded", "document_id": document_id, "chunks": len(chunks)}

    except Exception as exc:
        conn.rollback()
        with conn.cursor() as cur:
            cur.execute("""
                UPDATE documents
                SET status = 'failed', error_detail = %s, updated_at = NOW()
                WHERE document_id = %s
            """, (str(exc)[:2000], document_id))
            conn.commit()
        raise self.retry(exc=exc)

    finally:
        conn.close()


# ── pg_notify listener (run as a separate process) ────────────────────────────

def listen_for_documents():
    """
    Listens on 'document_ingestion_requests' channel.
    External systems drop a document_id and we dispatch to Celery.
    """
    conn = psycopg2.connect(DATABASE_URL)
    conn.autocommit = True

    with conn.cursor() as cur:
        cur.execute("LISTEN document_ingestion_requests;")
        print("Listening for ingestion requests...")

        import select
        while True:
            if select.select([conn], [], [], 30) != ([], [], []):
                conn.poll()
                while conn.notifies:
                    notify = conn.notifies.pop(0)
                    import json
                    payload = json.loads(notify.payload)
                    process_document.delay(
                        payload["document_id"],
                        payload["tenant_id"],
                    )
                    print(f"Queued: {payload['document_id']}")
# Start the Celery worker with concurrency tuned for I/O-bound embedding calls
celery -A ingestion.tasks worker \
  --concurrency=16 \
  --loglevel=info \
  --queues=ingestion \
  --max-tasks-per-child=100

# Start the pg_notify listener in a separate process
python -m ingestion.listener

# Check worker queue depth
celery -A ingestion.tasks inspect active
celery -A ingestion.tasks inspect reserved

The ON CONFLICT DO NOTHING on embedding insertion makes the pipeline idempotent — if a worker crashes mid-batch and Celery retries, you don't get duplicate embeddings or errors. The pg_notify at the end of ingestion lets you hook downstream processes (cache invalidation, index rebuilding, webhook delivery) without polling. The listener pattern means any system that can write to PostgreSQL can trigger ingestion — no message broker configuration needed beyond what you already have.

13.3 Hybrid Retrieval: Vector + Full-Text

Pure vector similarity search has a well-documented weakness: it struggles with exact matches. Ask a RAG system about "CVE-2024-1234" or a specific product SKU and cosine similarity between embeddings often retrieves tangentially related chunks rather than the exact document containing that identifier. Hybrid search combines vector similarity with PostgreSQL's full-text search, then applies a reciprocal rank fusion to merge the two result sets.

-- Stored function for hybrid retrieval with RRF reranking
-- This runs entirely inside PostgreSQL — no round-trips to Python for ranking

CREATE OR REPLACE FUNCTION hybrid_retrieve(
    p_tenant_id       UUID,
    p_query_embedding vector(1536),
    p_query_text      TEXT,
    p_top_k           INTEGER DEFAULT 20,
    p_rrf_k           INTEGER DEFAULT 60,    -- RRF constant, 60 is standard
    p_metadata_filter JSONB   DEFAULT NULL   -- e.g. '{"source": "manual_v2"}'
)
RETURNS TABLE (
    chunk_id          UUID,
    document_id       UUID,
    content           TEXT,
    chunk_index       INTEGER,
    chunk_metadata    JSONB,
    vector_score      FLOAT,
    fts_score         FLOAT,
    rrf_score         FLOAT,
    source_title      TEXT
)
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN QUERY
    WITH

    -- ── Vector retrieval arm ──────────────────────────────────────────────
    vector_results AS (
        SELECT
            dc.chunk_id,
            dc.document_id,
            dc.content,
            dc.chunk_index,
            dc.chunk_metadata,
            1 - (ce.embedding <=> p_query_embedding) AS score,
            ROW_NUMBER() OVER (
                ORDER BY ce.embedding <=> p_query_embedding
            ) AS rank
        FROM chunk_embeddings ce
        JOIN document_chunks  dc ON dc.chunk_id   = ce.chunk_id
        JOIN documents         d ON d.document_id = dc.document_id
        WHERE ce.tenant_id  = p_tenant_id
          AND d.status      = 'embedded'
          AND (p_metadata_filter IS NULL
               OR d.metadata @> p_metadata_filter)
        ORDER BY ce.embedding <=> p_query_embedding
        LIMIT p_top_k * 2    -- retrieve wider set before fusion
    ),

    -- ── Full-text retrieval arm ───────────────────────────────────────────
    fts_results AS (
        SELECT
            dc.chunk_id,
            dc.document_id,
            dc.content,
            dc.chunk_index,
            dc.chunk_metadata,
            ts_rank_cd(
                to_tsvector('english', dc.content),
                plainto_tsquery('english', p_query_text)
            ) AS score,
            ROW_NUMBER() OVER (
                ORDER BY ts_rank_cd(
                    to_tsvector('english', dc.content),
                    plainto_tsquery('english', p_query_text)
                ) DESC
            ) AS rank
        FROM document_chunks dc
        JOIN documents         d ON d.document_id = dc.document_id
        WHERE dc.tenant_id  = p_tenant_id
          AND d.status      = 'embedded'
          AND (p_metadata_filter IS NULL
               OR d.metadata @> p_metadata_filter)
          AND to_tsvector('english', dc.content)
              @@ plainto_tsquery('english', p_query_text)
        ORDER BY score DESC
        LIMIT p_top_k * 2
    ),

    -- ── Reciprocal Rank Fusion ────────────────────────────────────────────
    fused AS (
        SELECT
            COALESCE(vr.chunk_id,    fr.chunk_id)    AS chunk_id,
            COALESCE(vr.document_id, fr.document_id) AS document_id,
            COALESCE(vr.content,     fr.content)     AS content,
            COALESCE(vr.chunk_index, fr.chunk_index) AS chunk_index,
            COALESCE(vr.chunk_metadata, fr.chunk_metadata) AS chunk_metadata,
            COALESCE(vr.score, 0.0) AS vector_score,
            COALESCE(fr.score, 0.0) AS fts_score,
            -- RRF formula: 1/(k + rank) for each arm, summed
            COALESCE(1.0 / (p_rrf_k + vr.rank), 0) +
            COALESCE(1.0 / (p_rrf_k + fr.rank), 0) AS rrf_score
        FROM      vector_results vr
        FULL JOIN fts_results    fr USING (chunk_id)
    )

    SELECT
        f.chunk_id,
        f.document_id,
        f.content,
        f.chunk_index,
        f.chunk_metadata,
        f.vector_score,
        f.fts_score,
        f.rrf_score,
        d.title AS source_title
    FROM fused f
    JOIN documents d ON d.document_id = f.document_id
    ORDER BY f.rrf_score DESC
    LIMIT p_top_k;
END;
$$;


-- Convenience view: retrieval with document context collapsed
CREATE OR REPLACE VIEW retrieval_with_context AS
SELECT
    hr.*,
    d.metadata AS document_metadata,
    d.source_uri
FROM hybrid_retrieve(
    NULL::UUID,
    NULL::vector(1536),
    '',
    10
) hr
JOIN documents d ON d.document_id = hr.document_id;

The metadata filter (d.metadata @> p_metadata_filter) uses PostgreSQL's JSONB containment operator, meaning you can narrow retrieval to a specific product line, document version, or date range without adding a separate column for every possible filter dimension. A query like '{"product": "enterprise", "version": "2.1"}' will match any document whose metadata contains those key-value pairs, and the GIN index on documents.metadata keeps that filter fast even across millions of documents.

The RRF constant k=60 comes from the original Cormack et al. paper and works well across a wide range of corpus sizes without tuning. If your FTS arm consistently returns high-quality results for your domain (technical documentation, legal text) you can lower k to weight rank more aggressively; for general prose corpora the default holds up well.

13.4 The Query Pipeline in Python

With retrieval logic inside PostgreSQL, the Python query layer becomes thin: embed the query, call the stored function, assemble the prompt, call the LLM, write the audit trail. This is intentional — the database handles the retrieval logic because that's where the data lives, and the Python layer handles orchestration and streaming.

# query/pipeline.py — end-to-end RAG query handler

import os
import json
import time
import asyncio
from uuid import UUID, uuid4
from dataclasses import dataclass, field
from typing import AsyncGenerator, Optional

import asyncpg
from openai import AsyncOpenAI

OPENAI_API_KEY = os.environ["OPENAI_API_KEY"]
DATABASE_URL   = os.environ["DATABASE_URL"]

openai_client = AsyncOpenAI(api_key=OPENAI_API_KEY)


# ── Data structures ────────────────────────────────────────────────────────────

@dataclass
class RetrievedChunk:
    chunk_id:       str
    document_id:    str
    content:        str
    chunk_index:    int
    chunk_metadata: dict
    vector_score:   float
    fts_score:      float
    rrf_score:      float
    source_title:   str


@dataclass
class RAGResponse:
    answer:          str
    chunks:          list[RetrievedChunk]
    conversation_id: str
    turn_id:         str
    retrieval_ms:    int
    total_ms:        int
    prompt_tokens:   int
    completion_tokens: int


# ── System prompt factory ──────────────────────────────────────────────────────

def build_system_prompt(chunks: list[RetrievedChunk]) -> str:
    context_blocks = []
    for i, chunk in enumerate(chunks, 1):
        context_blocks.append(
            f"[{i}] Source: {chunk.source_title}\n"
            f"    Score: {chunk.rrf_score:.4f}\n"
            f"    Content: {chunk.content}"
        )
    context = "\n\n".join(context_blocks)

    return f"""You are a precise question-answering assistant. Answer the user's question
using ONLY the provided context. If the answer is not in the context, say so explicitly.
When you use information from a source, cite it with its number in square brackets, e.g. [1].

CONTEXT:
{context}

INSTRUCTIONS:
- Base your answer strictly on the context above.
- Cite every factual claim with its source number.
- If multiple sources support a point, cite all of them, e.g. [1][3].
- Do not speculate or use knowledge outside the provided context.
- If the context is insufficient, state clearly what information is missing."""


# ── Core pipeline class ────────────────────────────────────────────────────────

class RAGPipeline:

    def __init__(self, pool: asyncpg.Pool):
        self.pool = pool

    # ── Query embedding ────────────────────────────────────────────────────────

    async def embed_query(self, text: str, model: str = "text-embedding-3-small") -> list[float]:
        response = await openai_client.embeddings.create(
            input=[text],
            model=model,
        )
        return response.data[0].embedding

    # ── Retrieve ────────────────────────────────────────────────────────────────

    async def retrieve(
        self,
        tenant_id:       str,
        query_text:      str,
        query_embedding: list[float],
        top_k:           int = 10,
        metadata_filter: Optional[dict] = None,
    ) -> tuple[list[RetrievedChunk], int]:
        """
        Call the hybrid_retrieve stored function and return ranked chunks.
        Returns (chunks, retrieval_ms).
        """
        t0 = time.monotonic()
        embedding_str = "[" + ",".join(str(x) for x in query_embedding) + "]"

        async with self.pool.acquire() as conn:
            rows = await conn.fetch("""
                SELECT * FROM hybrid_retrieve(
                    $1::uuid,
                    $2::vector,
                    $3,
                    $4,
                    60,
                    $5::jsonb
                )
            """,
                tenant_id,
                embedding_str,
                query_text,
                top_k,
                json.dumps(metadata_filter) if metadata_filter else None,
            )

        retrieval_ms = int((time.monotonic() - t0) * 1000)
        chunks = [
            RetrievedChunk(
                chunk_id=str(row["chunk_id"]),
                document_id=str(row["document_id"]),
                content=row["content"],
                chunk_index=row["chunk_index"],
                chunk_metadata=dict(row["chunk_metadata"] or {}),
                vector_score=float(row["vector_score"]),
                fts_score=float(row["fts_score"]),
                rrf_score=float(row["rrf_score"]),
                source_title=row["source_title"],
            )
            for row in rows
        ]
        return chunks, retrieval_ms

    # ── Write audit trail ──────────────────────────────────────────────────────

    async def log_retrieval(
        self,
        tenant_id:         str,
        turn_id:           Optional[str],
        query_text:        str,
        query_embedding:   list[float],
        chunks:            list[RetrievedChunk],
        retrieval_strategy: str,
        retrieval_ms:      int,
    ) -> str:
        retrieved_chunks_json = json.dumps([
            {
                "chunk_id": c.chunk_id,
                "rrf_score": c.rrf_score,
                "vector_score": c.vector_score,
                "fts_score": c.fts_score,
                "rank": i + 1,
            }
            for i, c in enumerate(chunks)
        ])
        embedding_str = "[" + ",".join(str(x) for x in query_embedding) + "]"

        async with self.pool.acquire() as conn:
            row = await conn.fetchrow("""
                INSERT INTO retrieval_log
                    (turn_id, tenant_id, query_text, query_embedding,
                     retrieved_chunks, retrieval_strategy, retrieval_ms)
                VALUES ($1::uuid, $2::uuid, $3, $4::vector, $5::jsonb, $6, $7)
                RETURNING retrieval_id
            """,
                turn_id,
                tenant_id,
                query_text,
                embedding_str,
                retrieved_chunks_json,
                retrieval_strategy,
                retrieval_ms,
            )
        return str(row["retrieval_id"])

    # ── Save conversation turn ─────────────────────────────────────────────────

    async def save_turn(
        self,
        tenant_id:         str,
        conversation_id:   str,
        role:              str,
        content:           str,
        turn_index:        int,
        model_used:        Optional[str] = None,
        prompt_tokens:     Optional[int] = None,
        completion_tokens: Optional[int] = None,
        latency_ms:        Optional[int] = None,
    ) -> str:
        async with self.pool.acquire() as conn:
            row = await conn.fetchrow("""
                INSERT INTO conversation_turns
                    (conversation_id, tenant_id, role, content, turn_index,
                     model_used, prompt_tokens, completion_tokens, latency_ms)
                VALUES ($1::uuid, $2::uuid, $3, $4, $5, $6, $7, $8, $9)
                RETURNING turn_id
            """,
                conversation_id,
                tenant_id,
                role,
                content,
                turn_index,
                model_used,
                prompt_tokens,
                completion_tokens,
                latency_ms,
            )
            # Update conversation last_active_at
            await conn.execute("""
                UPDATE conversations
                SET last_active_at = NOW()
                WHERE conversation_id = $1
            """, conversation_id)
        return str(row["turn_id"])

    # ── Load conversation history ──────────────────────────────────────────────

    async def load_history(
        self,
        conversation_id: str,
        max_turns:       int = 10,
    ) -> list[dict]:
        """Return the last N turns as OpenAI message dicts."""
        async with self.pool.acquire() as conn:
            rows = await conn.fetch("""
                SELECT role, content
                FROM conversation_turns
                WHERE conversation_id = $1
                ORDER BY turn_index DESC
                LIMIT $2
            """, conversation_id, max_turns)
        # Reverse to chronological order
        return [{"role": r["role"], "content": r["content"]} for r in reversed(rows)]

    # ── Full RAG query (non-streaming) ─────────────────────────────────────────

    async def query(
        self,
        tenant_id:       str,
        query_text:      str,
        conversation_id: Optional[str] = None,
        top_k:           int = 10,
        model:           str = "gpt-4o",
        metadata_filter: Optional[dict] = None,
    ) -> RAGResponse:
        t_start = time.monotonic()

        # Create conversation if not provided
        if conversation_id is None:
            async with self.pool.acquire() as conn:
                row = await conn.fetchrow("""
                    INSERT INTO conversations (tenant_id)
                    VALUES ($1::uuid)
                    RETURNING conversation_id
                """, tenant_id)
            conversation_id = str(row["conversation_id"])

        # Determine next turn index
        async with self.pool.acquire() as conn:
            count = await conn.fetchval("""
                SELECT COUNT(*) FROM conversation_turns
                WHERE conversation_id = $1
            """, conversation_id)
        turn_index = int(count)

        # Save user turn
        user_turn_id = await self.save_turn(
            tenant_id=tenant_id,
            conversation_id=conversation_id,
            role="user",
            content=query_text,
            turn_index=turn_index,
        )

        # Embed query
        query_embedding = await self.embed_query(query_text)

        # Retrieve
        chunks, retrieval_ms = await self.retrieve(
            tenant_id=tenant_id,
            query_text=query_text,
            query_embedding=query_embedding,
            top_k=top_k,
            metadata_filter=metadata_filter,
        )

        # Log retrieval against the user turn
        await self.log_retrieval(
            tenant_id=tenant_id,
            turn_id=user_turn_id,
            query_text=query_text,
            query_embedding=query_embedding,
            chunks=chunks,
            retrieval_strategy="hybrid_rrf",
            retrieval_ms=retrieval_ms,
        )

        # Build messages
        history = await self.load_history(conversation_id, max_turns=8)
        system_prompt = build_system_prompt(chunks)

        messages = [{"role": "system", "content": system_prompt}]
        # Include prior turns minus the current user message (already in history)
        messages.extend(history[:-1])  # exclude the turn we just added
        messages.append({"role": "user", "content": query_text})

        # Call LLM
        t_llm = time.monotonic()
        response = await openai_client.chat.completions.create(
            model=model,
            messages=messages,
            temperature=0.1,
            max_tokens=1024,
        )
        llm_ms = int((time.monotonic() - t_llm) * 1000)

        answer            = response.choices[0].message.content
        prompt_tokens     = response.usage.prompt_tokens
        completion_tokens = response.usage.completion_tokens
        total_ms          = int((time.monotonic() - t_start) * 1000)

        # Save assistant turn
        assistant_turn_id = await self.save_turn(
            tenant_id=tenant_id,
            conversation_id=conversation_id,
            role="assistant",
            content=answer,
            turn_index=turn_index + 1,
            model_used=model,
            prompt_tokens=prompt_tokens,
            completion_tokens=completion_tokens,
            latency_ms=llm_ms,
        )

        return RAGResponse(
            answer=answer,
            chunks=chunks,
            conversation_id=conversation_id,
            turn_id=assistant_turn_id,
            retrieval_ms=retrieval_ms,
            total_ms=total_ms,
            prompt_tokens=prompt_tokens,
            completion_tokens=completion_tokens,
        )

    # ── Streaming variant ──────────────────────────────────────────────────────

    async def query_stream(
        self,
        tenant_id:       str,
        query_text:      str,
        conversation_id: Optional[str] = None,
        top_k:           int = 10,
        model:           str = "gpt-4o",
        metadata_filter: Optional[dict] = None,
    ) -> AsyncGenerator[dict, None]:
        """
        Yields server-sent-event-style dicts:
          {"type": "chunks",  "data": [chunk dicts]}
          {"type": "token",   "data": "word "}
          {"type": "done",    "data": {"turn_id": ..., "retrieval_ms": ...}}
          {"type": "error",   "data": "message"}
        """
        t_start = time.monotonic()

        try:
            if conversation_id is None:
                async with self.pool.acquire() as conn:
                    row = await conn.fetchrow("""
                        INSERT INTO conversations (tenant_id)
                        VALUES ($1::uuid)
                        RETURNING conversation_id
                    """, tenant_id)
                conversation_id = str(row["conversation_id"])

            async with self.pool.acquire() as conn:
                count = await conn.fetchval("""
                    SELECT COUNT(*) FROM conversation_turns
                    WHERE conversation_id = $1
                """, conversation_id)
            turn_index = int(count)

            user_turn_id = await self.save_turn(
                tenant_id=tenant_id,
                conversation_id=conversation_id,
                role="user",
                content=query_text,
                turn_index=turn_index,
            )

            query_embedding = await self.embed_query(query_text)
            chunks, retrieval_ms = await self.retrieve(
                tenant_id=tenant_id,
                query_text=query_text,
                query_embedding=query_embedding,
                top_k=top_k,
                metadata_filter=metadata_filter,
            )

            await self.log_retrieval(
                tenant_id=tenant_id,
                turn_id=user_turn_id,
                query_text=query_text,
                query_embedding=query_embedding,
                chunks=chunks,
                retrieval_strategy="hybrid_rrf",
                retrieval_ms=retrieval_ms,
            )

            # Yield retrieved chunks immediately so the UI can show sources
            yield {
                "type": "chunks",
                "data": [
                    {
                        "chunk_id":    c.chunk_id,
                        "source_title": c.source_title,
                        "rrf_score":   c.rrf_score,
                        "content":     c.content[:200] + "..." if len(c.content) > 200 else c.content,
                    }
                    for c in chunks
                ],
            }

            history = await self.load_history(conversation_id, max_turns=8)
            system_prompt = build_system_prompt(chunks)
            messages = [{"role": "system", "content": system_prompt}]
            messages.extend(history[:-1])
            messages.append({"role": "user", "content": query_text})

            # Stream LLM tokens
            full_answer = []
            prompt_tokens = 0
            completion_tokens = 0

            async with await openai_client.chat.completions.create(
                model=model,
                messages=messages,
                temperature=0.1,
                max_tokens=1024,
                stream=True,
            ) as stream:
                async for chunk in stream:
                    delta = chunk.choices[0].delta
                    if delta.content:
                        full_answer.append(delta.content)
                        yield {"type": "token", "data": delta.content}
                    if chunk.usage:
                        prompt_tokens     = chunk.usage.prompt_tokens
                        completion_tokens = chunk.usage.completion_tokens

            answer   = "".join(full_answer)
            total_ms = int((time.monotonic() - t_start) * 1000)

            assistant_turn_id = await self.save_turn(
                tenant_id=tenant_id,
                conversation_id=conversation_id,
                role="assistant",
                content=answer,
                turn_index=turn_index + 1,
                model_used=model,
                prompt_tokens=prompt_tokens,
                completion_tokens=completion_tokens,
                latency_ms=total_ms,
            )

            yield {
                "type": "done",
                "data": {
                    "turn_id":         assistant_turn_id,
                    "conversation_id": conversation_id,
                    "retrieval_ms":    retrieval_ms,
                    "total_ms":        total_ms,
                    "prompt_tokens":   prompt_tokens,
                    "completion_tokens": completion_tokens,
                },
            }

        except Exception as exc:
            yield {"type": "error", "data": str(exc)}
            raise

The streaming variant yields retrieved chunks before the first LLM token arrives. This matters for user experience: if retrieval takes 80 ms and the LLM's first token arrives 600 ms later, the UI can display source cards in that 520 ms gap rather than showing a spinner. Users see supporting evidence before the answer, which also builds trust in the response.

13.5 Semantic Caching

Embedding every query and running a vector search is fast — typically under 100 ms — but for high-traffic deployments with repetitive queries (support bots, FAQ systems), the embedding API call and LLM generation are the dominant costs. Semantic caching stores previous query-answer pairs and returns cached answers when a new query is semantically close enough to a prior one.

-- Semantic cache table
CREATE TABLE semantic_cache (
    cache_id        UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    tenant_id       UUID NOT NULL REFERENCES tenants(tenant_id),
    query_text      TEXT NOT NULL,
    query_embedding vector(1536) NOT NULL,
    answer          TEXT NOT NULL,
    retrieved_chunks JSONB NOT NULL DEFAULT '[]',
    hit_count       INTEGER NOT NULL DEFAULT 0,
    similarity_threshold FLOAT NOT NULL DEFAULT 0.92,
    expires_at      TIMESTAMPTZ,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_hit_at     TIMESTAMPTZ
);

    WHERE expires_at IS NOT NULL;


-- Cache lookup function
CREATE OR REPLACE FUNCTION semantic_cache_lookup(
    p_tenant_id       UUID,
    p_query_embedding vector(1536),
    p_threshold       FLOAT DEFAULT 0.92
)
RETURNS TABLE (
    cache_id  UUID,
    answer    TEXT,
    retrieved_chunks JSONB,
    similarity FLOAT
)
LANGUAGE sql
AS $$
    SELECT
        cache_id,
        answer,
        retrieved_chunks,
        1 - (query_embedding <=> p_query_embedding) AS similarity
    FROM semantic_cache
    WHERE tenant_id = p_tenant_id
      AND (expires_at IS NULL OR expires_at > NOW())
      AND 1 - (query_embedding <=> p_query_embedding) >= p_threshold
    ORDER BY query_embedding <=> p_query_embedding
    LIMIT 1;
$$;


-- Cache write function (upsert-style)
CREATE OR REPLACE FUNCTION semantic_cache_write(
    p_tenant_id      UUID,
    p_query_text     TEXT,
    p_query_embedding vector(1536),
    p_answer         TEXT,
    p_retrieved_chunks JSONB,
    p_ttl_seconds    INTEGER DEFAULT 86400   -- 24 hours default
)
RETURNS UUID
LANGUAGE sql
AS $$
    INSERT INTO semantic_cache
        (tenant_id, query_text, query_embedding, answer, retrieved_chunks, expires_at)
    VALUES (
        p_tenant_id,
        p_query_text,
        p_query_embedding,
        p_answer,
        p_retrieved_chunks,
        NOW() + (p_ttl_seconds || ' seconds')::INTERVAL
    )
    RETURNING cache_id;
$$;


-- Increment hit counter atomically
CREATE OR REPLACE FUNCTION semantic_cache_hit(p_cache_id UUID)
RETURNS VOID
LANGUAGE sql
AS $$
    UPDATE semantic_cache
    SET hit_count  = hit_count + 1,
        last_hit_at = NOW()
    WHERE cache_id = p_cache_id;
$$;

class SemanticCache:
    """
    Wraps the semantic_cache PostgreSQL functions.
    Sits in front of the full RAG pipeline.
    """

    def __init__(self, pool: asyncpg.Pool, default_threshold: float = 0.92):
        self.pool = pool
        self.default_threshold = default_threshold

    async def lookup(
        self,
        tenant_id:       str,
        query_embedding: list[float],
        threshold:       Optional[float] = None,
    ) -> Optional[dict]:
        threshold = threshold or self.default_threshold
        embedding_str = "[" + ",".join(str(x) for x in query_embedding) + "]"

        async with self.pool.acquire() as conn:
            row = await conn.fetchrow("""
                SELECT * FROM semantic_cache_lookup($1::uuid, $2::vector, $3)
            """, tenant_id, embedding_str, threshold)

        if row is None:
            return None

        # Fire-and-forget hit counter update
        asyncio.create_task(self._record_hit(str(row["cache_id"])))

        return {
            "cache_id":        str(row["cache_id"]),
            "answer":          row["answer"],
            "retrieved_chunks": json.loads(row["retrieved_chunks"]),
            "similarity":      float(row["similarity"]),
            "from_cache":      True,
        }

    async def _record_hit(self, cache_id: str):
        try:
            async with self.pool.acquire() as conn:
                await conn.execute(
                    "SELECT semantic_cache_hit($1::uuid)", cache_id
                )
        except Exception:
            pass  # Cache hit recording is best-effort

    async def write(
        self,
        tenant_id:       str,
        query_text:      str,
        query_embedding: list[float],
        answer:          str,
        chunks:          list[RetrievedChunk],
        ttl_seconds:     int = 86400,
    ) -> str:
        embedding_str = "[" + ",".join(str(x) for x in query_embedding) + "]"
        chunks_json = json.dumps([
            {"chunk_id": c.chunk_id, "rrf_score": c.rrf_score, "source_title": c.source_title}
            for c in chunks
        ])

        async with self.pool.acquire() as conn:
            row = await conn.fetchrow("""
                SELECT semantic_cache_write(
                    $1::uuid, $2, $3::vector, $4, $5::jsonb, $6
                )
            """, tenant_id, query_text, embedding_str, answer, chunks_json, ttl_seconds)
        return str(row["semantic_cache_write"])
# Integrating the cache into the pipeline — patch the query() method

class CachedRAGPipeline(RAGPipeline):

    def __init__(self, pool: asyncpg.Pool, cache_threshold: float = 0.92):
        super().__init__(pool)
        self.cache = SemanticCache(pool, default_threshold=cache_threshold)

    async def query(self, tenant_id, query_text, **kwargs) -> RAGResponse:
        # Embed first so we can check the cache
        query_embedding = await self.embed_query(query_text)

        # Cache lookup before touching retrieval or LLM
        cached = await self.cache.lookup(tenant_id, query_embedding)
        if cached:
            # Return a lightweight response indicating cache hit
            return RAGResponse(
                answer=cached["answer"],
                chunks=[],           # chunks not re-hydrated from cache for brevity
                conversation_id=kwargs.get("conversation_id", ""),
                turn_id="",
                retrieval_ms=0,
                total_ms=0,
                prompt_tokens=0,
                completion_tokens=0,
            )

        # Full pipeline
        response = await super().query(
            tenant_id=tenant_id,
            query_text=query_text,
            **kwargs,
        )

        # Write to cache asynchronously — don't block the response
        asyncio.create_task(
            self.cache.write(
                tenant_id=tenant_id,
                query_text=query_text,
                query_embedding=query_embedding,
                answer=response.answer,
                chunks=response.chunks,
                ttl_seconds=kwargs.get("cache_ttl", 86400),
            )
        )

        return response

The threshold of 0.92 is conservative on purpose. Semantic similarity at 0.92 cosine score means the queries are nearly identical in meaning — "What is the return policy?" and "How do I return an item?" will hit the cache, but "What is the return policy for international orders?" will miss and trigger a fresh retrieval. Setting the threshold too low (say, 0.85) risks returning answers to subtly different questions, which is a correctness hazard worse than a cache miss. Monitor your cache hit rate in semantic_cache and adjust the threshold empirically for your query distribution.

13.6 Evaluating Retrieval Quality

A RAG system without evaluation is a black box. You can tune chunk size, overlap, top-k, and RRF weights until exhaustion, but without ground-truth metrics you're guessing. The retrieval_log table you built in section 13.1 is now your evaluation foundation.

-- Evaluation schema: ground truth and scored runs

CREATE TABLE eval_datasets (

    tenant_id    UUID NOT NULL REFERENCES tenants(tenant_id),

-- MRR computation from retrieval_log against eval ground truth
-- Run after filling retrieval_log via a test harness

CREATE OR REPLACE FUNCTION compute_mrr(
    p_dataset_id UUID,
    p_run_label  TEXT        -- matches retrieval_strategy in retrieval_log
)
RETURNS FLOAT
LANGUAGE plpgsql
AS $$
DECLARE
    v_mrr        FLOAT := 0;
    v_query_count INTEGER := 0;
    rec          RECORD;
BEGIN
    FOR rec IN
        SELECT
            eq.query_id,
            eq.relevant_chunk_ids,
            rl.retrieved_chunks
        FROM eval_queries    eq
        JOIN retrieval_log   rl ON rl.query_text = eq.query_text
        WHERE eq.dataset_id        = p_dataset_id
          AND rl.retrieval_strategy = p_run_label
    LOOP
        v_query_count := v_query_count + 1;
        -- Find the rank of the first relevant chunk
        DECLARE
            v_rank       INTEGER := 0;
            chunk_item   JSONB;
        BEGIN
            FOR chunk_item IN
                SELECT value
                FROM jsonb_array_elements(rec.retrieved_chunks)
                ORDER BY (value->>'rank')::int
            LOOP
                v_rank := v_rank + 1;
                IF (chunk_item->>'chunk_id')::UUID = ANY(rec.relevant_chunk_ids) THEN
                    v_mrr := v_mrr + (1.0 / v_rank);
                    EXIT;
                END IF;
            END LOOP;
        END;
    END LOOP;

    IF v_query_count = 0 THEN
        RETURN NULL;
    END IF;

    RETURN v_mrr / v_query_count;
END;
$$;


-- Quick retrieval quality report
CREATE VIEW retrieval_quality_summary AS
SELECT
    DATE_TRUNC('day', rl.created_at)  AS day,
    rl.retrieval_strategy,
    COUNT(*)                           AS query_count,
    AVG(rl.retrieval_ms)               AS avg_retrieval_ms,
    PERCENTILE_CONT(0.95) WITHIN GROUP (ORDER BY rl.retrieval_ms)
                                       AS p95_retrieval_ms,
    -- Proxy for result diversity: avg unique document count per query
    AVG(
        (SELECT COUNT(DISTINCT value->>'document_id')
         FROM jsonb_array_elements(rl.retrieved_chunks))
    )                                  AS avg_unique_docs
FROM retrieval_log rl
GROUP BY 1, 2
ORDER BY 1 DESC, 2;
# eval/harness.py — automated evaluation runner

import asyncio
import json
from uuid import UUID
import asyncpg


async def run_eval(
    pool: asyncpg.Pool,
    dataset_id: str,
    pipeline,               # RAGPipeline instance
    tenant_id: str,
    strategy_label: str = "hybrid_rrf",
    top_k: int = 10,
) -> dict:
    """
    Runs every query in an eval dataset through the retrieval pipeline,
    writes results to retrieval_log, then computes MRR and Precision@5.
    Returns a dict of metric scores.
    """

    async with pool.acquire() as conn:
        queries = await conn.fetch("""
            SELECT query_id, query_text, relevant_chunk_ids
            FROM eval_queries
            WHERE dataset_id = $1::uuid
        """, dataset_id)

    if not queries:
        raise ValueError(f"No queries found for dataset {dataset_id}")

    mrr_sum           = 0.0
    precision5_sum    = 0.0
    recall10_sum      = 0.0
    total             = len(queries)

    for q in queries:
        query_text         = q["query_text"]
        relevant_ids       = set(str(cid) for cid in q["relevant_chunk_ids"])

        query_embedding = await pipeline.embed_query(query_text)
        chunks, retrieval_ms = await pipeline.retrieve(
            tenant_id=tenant_id,
            query_text=query_text,
            query_embedding=query_embedding,
            top_k=top_k,
        )

        await pipeline.log_retrieval(
            tenant_id=tenant_id,
            turn_id=None,
            query_text=query_text,
            query_embedding=query_embedding,
            chunks=chunks,
            retrieval_strategy=strategy_label,
            retrieval_ms=retrieval_ms,
        )

        # MRR: reciprocal rank of first relevant chunk
        rr = 0.0
        for rank, chunk in enumerate(chunks, 1):
            if chunk.chunk_id in relevant_ids:
                rr = 1.0 / rank
                break
        mrr_sum += rr

        # Precision@5: fraction of top-5 that are relevant
        top5_relevant = sum(
            1 for c in chunks[:5] if c.chunk_id in relevant_ids
        )
        precision5_sum += top5_relevant / 5.0

        # Recall@10: fraction of all relevant docs found in top-10
        if relevant_ids:
            top10_found = sum(
                1 for c in chunks[:10] if c.chunk_id in relevant_ids
            )
            recall10_sum += top10_found / len(relevant_ids)

    metrics = {
        "strategy":      strategy_label,
        "top_k":         top_k,
        "query_count":   total,
        "mrr":           round(mrr_sum / total, 4),
        "precision_at_5": round(precision5_sum / total, 4),
        "recall_at_10":  round(recall10_sum / total, 4),
    }

    # Persist run metrics
    async with pool.acquire() as conn:
        await conn.execute("""
            INSERT INTO eval_runs
                (dataset_id, strategy, top_k, parameters, mrr, precision_at_5, recall_at_10)
            VALUES ($1::uuid, $2, $3, $4::jsonb, $5, $6, $7)
        """,
            dataset_id,
            strategy_label,
            top_k,
            json.dumps({"top_k": top_k}),
            metrics["mrr"],
            metrics["precision_at_5"],
            metrics["recall_at_10"],
        )

    return metrics


async def compare_strategies(
    pool: asyncpg.Pool,
    dataset_id: str,
    pipeline,
    tenant_id: str,
) -> list[dict]:
    """
    Run the same eval dataset under multiple retrieval strategies
    and return a ranked comparison table.
    """
    strategies = [
        ("vector_only",  10),
        ("hybrid_rrf",   10),
        ("hybrid_rrf",   20),
    ]

    results = []
    for strategy, top_k in strategies:
        metrics = await run_eval(
            pool=pool,
            dataset_id=dataset_id,
            pipeline=pipeline,
            tenant_id=tenant_id,
            strategy_label=strategy,
            top_k=top_k,
        )
        results.append(metrics)
        print(f"{strategy:20s} top_k={top_k:2d}  "
              f"MRR={metrics['mrr']:.4f}  "
              f"P@5={metrics['precision_at_5']:.4f}  "
              f"R@10={metrics['recall_at_10']:.4f}")

    return sorted(results, key=lambda r: r["mrr"], reverse=True)

Building the eval dataset is the most time-consuming part of this work, but it only needs to happen once per knowledge domain. Write twenty to fifty representative queries with their ground-truth relevant chunks, and you have a regression test that will catch retrieval regressions every time you change chunk size, overlap, embedding model, or index type. The compare_strategies function runs the same queries under each strategy configuration so you can make evidence-based decisions about which retrieval path to serve in production.

#### Index Maintenance

IVFFlat indexes require periodic rebuilding as new vectors are inserted. Unlike B-tree indexes, which update incrementally, IVFFlat computes centroids at build time. Inserts after build are still indexed — they're assigned to the nearest existing centroid — but as the data distribution shifts, retrieval quality degrades gradually. Rebuild the index when the row count has grown by more than roughly 20 percent since the last build, or on a weekly schedule for active ingestion pipelines.

-- Rebuild the vector index without blocking reads (CONCURRENTLY)
-- Run this from a maintenance script or pg_cron job

-- Step 1: Build a new index with updated list count
CREATE INDEX CONCURRENTLY idx_embeddings_vector_new
    ON chunk_embeddings
    USING ivfflat (embedding vector_cosine_ops)
    WITH (lists = 200);    -- recalculate: total_rows / 1000, capped at 1000

-- Step 2: Swap atomically in a transaction
BEGIN;
DROP INDEX idx_embeddings_vector;
ALTER INDEX idx_embeddings_vector_new RENAME TO idx_embeddings_vector;
COMMIT;

-- Or schedule it directly via pg_cron (weekly Sunday midnight)
SELECT cron.schedule(
    'rebuild-vector-index',
    '0 0 * * 0',
    $$
    CREATE INDEX CONCURRENTLY idx_embeddings_vector_rebuild
        ON chunk_embeddings USING ivfflat (embedding vector_cosine_ops)
        WITH (lists = GREATEST(10, (SELECT COUNT(*)::int / 1000 FROM chunk_embeddings)));
    $$
);

#### Rate Limiting Ingestion Workers

Embedding APIs enforce per-minute token limits. Without rate limiting in the Celery workers, a burst of large documents will exhaust the limit and trigger 429 errors, causing retries that amplify the burst further. The cleanest fix is a token bucket implemented inside PostgreSQL — shared state that all workers read without needing Redis.

-- Token bucket rate limiter table
CREATE TABLE rate_limits (
    bucket_id    TEXT PRIMARY KEY,             -- e.g. 'openai_embed_tenant_xyz'
    tokens       FLOAT NOT NULL,
    capacity     FLOAT NOT NULL,
    refill_rate  FLOAT NOT NULL,               -- tokens per second
    last_refill  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE OR REPLACE FUNCTION consume_tokens(
    p_bucket_id  TEXT,
    p_requested  FLOAT,
    p_capacity   FLOAT DEFAULT 100000,         -- 100k tokens/min = ~1667/sec
    p_refill_rate FLOAT DEFAULT 1667
)
RETURNS BOOLEAN                                -- TRUE if tokens available
LANGUAGE plpgsql
AS $$
DECLARE
    v_now          TIMESTAMPTZ := NOW();
    v_elapsed      FLOAT;
    v_new_tokens   FLOAT;
    v_available    FLOAT;
BEGIN
    -- Upsert to create bucket on first call
    INSERT INTO rate_limits (bucket_id, tokens, capacity, refill_rate)
    VALUES (p_bucket_id, p_capacity, p_capacity, p_refill_rate)
    ON CONFLICT (bucket_id) DO NOTHING;

    -- Lock the row
    SELECT tokens,
           EXTRACT(EPOCH FROM (v_now - last_refill))
    INTO   v_available, v_elapsed
    FROM   rate_limits
    WHERE  bucket_id = p_bucket_id
    FOR UPDATE;

    -- Refill based on elapsed time
    v_new_tokens := LEAST(p_capacity, v_available + v_elapsed * p_refill_rate);

    IF v_new_tokens < p_requested THEN
        -- Not enough tokens — update refill timestamp but don't consume
        UPDATE rate_limits
        SET    tokens      = v_new_tokens,
               last_refill = v_now
        WHERE  bucket_id   = p_bucket_id;
        RETURN FALSE;
    END IF;

    -- Consume tokens
    UPDATE rate_limits
    SET    tokens      = v_new_tokens - p_requested,
           last_refill = v_now
    WHERE  bucket_id   = p_bucket_id;
    RETURN TRUE;
END;
$$;
# In the Celery task, before calling embed_batch:

async def rate_limited_embed(conn, tenant_id: str, texts: list[str], model: str) -> list:
    """
    Check token budget before embedding. Retry with backoff if budget exhausted.
    Assumes ~1 token per 4 characters as a rough estimate for budget tracking.
    """
    estimated_tokens = sum(len(t) // 4 for t in texts)
    bucket_id = f"openai_embed_{tenant_id}"

    max_attempts = 10
    for attempt in range(max_attempts):
        allowed = await conn.fetchval(
            "SELECT consume_tokens($1, $2)",
            bucket_id,
            float(estimated_tokens),
        )
        if allowed:
            return embed_batch(texts, model=model)

        wait = min(2 ** attempt, 30)
        await asyncio.sleep(wait)

    raise RuntimeError(f"Rate limit exhausted for {bucket_id} after {max_attempts} attempts")

#### Graceful Degradation

When the OpenAI API is unreachable — network partition, outage, or regional incident — the system should degrade to full-text search rather than fail completely. The query pipeline can detect embedding failures and fall back to FTS-only retrieval, which still returns useful results for most queries.

# In RAGPipeline.query(), replace the embed+retrieve block:

async def retrieve_with_fallback(
    self,
    tenant_id:       str,
    query_text:      str,
    top_k:           int = 10,
    metadata_filter: Optional[dict] = None,
) -> tuple[list[RetrievedChunk], int, str]:
    """
    Returns (chunks, retrieval_ms, strategy_used).
    Falls back to FTS-only if embedding API is unavailable.
    """
    try:
        query_embedding = await asyncio.wait_for(
            self.embed_query(query_text),
            timeout=5.0,
        )
        chunks, ms = await self.retrieve(
            tenant_id=tenant_id,
            query_text=query_text,
            query_embedding=query_embedding,
            top_k=top_k,
            metadata_filter=metadata_filter,
        )
        return chunks, ms, "hybrid_rrf"

    except (asyncio.TimeoutError, Exception) as exc:
        # Log degradation event
        print(f"[DEGRADED] Embedding failed ({exc}), falling back to FTS")

        t0 = time.monotonic()
        async with self.pool.acquire() as conn:
            rows = await conn.fetch("""
                SELECT
                    dc.chunk_id,
                    dc.document_id,
                    dc.content,
                    dc.chunk_index,
                    dc.chunk_metadata,
                    0.0::float         AS vector_score,
                    ts_rank_cd(
                        to_tsvector('english', dc.content),
                        plainto_tsquery('english', $2)
                    )                  AS fts_score,
                    0.0::float         AS rrf_score,
                    d.title            AS source_title
                FROM document_chunks dc
                JOIN documents        d ON d.document_id = dc.document_id
                WHERE dc.tenant_id   = $1::uuid
                  AND d.status       = 'embedded'
                  AND to_tsvector('english', dc.content)
                      @@ plainto_tsquery('english', $2)
                ORDER BY fts_score DESC
                LIMIT $3
            """, tenant_id, query_text, top_k)

        ms = int((time.monotonic() - t0) * 1000)
        chunks = [
            RetrievedChunk(
                chunk_id=str(r["chunk_id"]),
                document_id=str(r["document_id"]),
                content=r["content"],
                chunk_index=r["chunk_index"],
                chunk_metadata=dict(r["chunk_metadata"] or {}),
                vector_score=0.0,
                fts_score=float(r["fts_score"]),
                rrf_score=0.0,
                source_title=r["source_title"],
            )
            for r in rows
        ]
        return chunks, ms, "fts_fallback"

Full-text fallback is not a permanent state — it's a bridge. The GIN index on document_chunks.content handles the fallback query entirely inside PostgreSQL with no external dependencies, so it remains available even during a total LLM API outage. The retrieval_strategy field in retrieval_log lets you audit how often degraded mode was invoked and set up alerts when it becomes the norm rather than the exception.

Key Takeaways

  • → **Schema design drives everything downstream.** The separation of `documents`, `document_chunks`, and `chunk_embeddings` into three tables gives you independent lifecycle management for chunking and embedding, making model migrations non-destructive and reversible.
  • → **Hybrid retrieval with RRF outperforms pure vector search on real query distributions.** Exact-match queries (product SKUs, error codes, proper nouns) fail silently with cosine similarity alone; the FTS arm of the hybrid pipeline recovers these without any query classification overhead.
  • → **Semantic caching belongs in PostgreSQL, not Redis.** The same IVFFlat index that powers retrieval powers cache lookups. You avoid a second infrastructure component, and the cache participates in the same RLS policies as the rest of the data, giving you tenant isolation for free.
  • → **The `retrieval_log` table is your single most valuable investment.** Every query that flows through the system writes to this table, and that accumulated data becomes the ground truth for MRR/NDCG evaluation, the input for offline tuning experiments, and the audit trail for compliance requirements — all without any external tooling.
  • → **Graceful degradation to FTS keeps the system useful during API outages.** The GIN index on chunk content allows full-text retrieval with zero external dependencies. Combined with the `retrieval_strategy` field in the audit log, degraded-mode events are visible and alertable before they affect enough queries to constitute a user-visible incident.
