Chapter 30: Change Data Capture for AI Feature Pipelines

When your PostgreSQL database changes, your AI features should respond. A customer updates their profile — their personalization embeddings should refresh. A product description changes — the semantic search index needs updating. A support ticket gets resolved — the RAG knowledge base should reflect the new resolution. Without a systematic way to detect and act on these changes, your AI application operates on stale data, and stale data means wrong answers.

Change Data Capture (CDC) is the mechanism that connects your operational database to your AI feature pipeline. This chapter covers how to use PostgreSQL's logical replication system, pg_notify, and trigger-based patterns to build reactive AI pipelines that keep embeddings fresh, feature stores synchronized, and LLM context up to date — without polling, without full table scans, and without the latency that kills real-time AI applications.

---

30.1 The CDC Foundation: Logical Replication and pg_notify

PostgreSQL ships with two CDC primitives worth building on. The first is logical replication, which reads the write-ahead log (WAL) and emits row-level changes as structured events. The second is pg_notify, a lightweight pub/sub system built directly into the database. For AI feature pipelines, these serve different purposes: logical replication gives you durability and ordering guarantees for high-volume change streams, while pg_notify gives you sub-millisecond latency for real-time embedding updates on targeted tables.

Understanding when to use each is the first design decision. If you need every change captured reliably and processed exactly once — think embedding refreshes for a product catalog — logical replication is correct. If you need low-latency notification for conversational features — think invalidating a cached user context when preferences change — pg_notify wins on simplicity.

graph LR
    Table[Source Table] -->|row change| WAL[Write-Ahead Log]
    Table -->|trigger| Notify[pg_notify]
    WAL --> Slot[Logical Replication Slot]
    Slot --> Consumer[Python WAL Consumer]
    Notify --> Listener[Async LISTEN Handler]
    Consumer --> Celery[Celery: batch embedding refresh]
    Listener --> Debounce[Debounce buffer] --> Celery
    Celery --> Embed[OpenAI Embedding API]
    Embed --> Store[(Embedding table)]
    Consumer -.dead consumer.-> LagAlert[WAL lag / disk risk]

*Two CDC paths into the same downstream work: durable, ordered WAL consumption for batch/backfill-safe refreshes, and low-latency pg_notify for real-time invalidation. Both funnel into the same Celery embedding workers.*

Start by enabling logical replication if it isn't already active:

# Check current WAL level
psql -U postgres -c "SHOW wal_level;"

# If not logical, update postgresql.conf
echo "wal_level = logical" >> /etc/postgresql/16/main/postgresql.conf
echo "max_replication_slots = 10" >> /etc/postgresql/16/main/postgresql.conf
echo "max_wal_senders = 10" >> /etc/postgresql/16/main/postgresql.conf

# Restart PostgreSQL (plan for a brief outage)
systemctl restart postgresql@16-main

# Verify
psql -U postgres -c "SHOW wal_level;"

Now build the schema that supports CDC-driven AI pipelines. The design centers on a change event table that acts as a durable queue, decoupling the moment of change from the moment of AI processing:

-- Core tables for a product catalog with AI features
CREATE TABLE products (
    product_id      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    sku             TEXT UNIQUE NOT NULL,
    name            TEXT NOT NULL,
    description     TEXT,
    category        TEXT NOT NULL,
    price           NUMERIC(12, 2),
    attributes      JSONB DEFAULT '{}',
    is_active       BOOLEAN DEFAULT TRUE,
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW()
);

-- Tracks which fields affect embeddings, to avoid unnecessary recomputation
CREATE TABLE embedding_sensitive_columns (
    table_name      TEXT NOT NULL,
    column_name     TEXT NOT NULL,
    weight          NUMERIC(3, 2) DEFAULT 1.0,  -- relative importance for reranking
    PRIMARY KEY (table_name, column_name)
);

INSERT INTO embedding_sensitive_columns VALUES
    ('products', 'name', 1.0),
    ('products', 'description', 1.0),
    ('products', 'category', 0.7),
    ('products', 'attributes', 0.5);

-- Durable change event queue for AI pipeline processing
CREATE TABLE ai_change_events (
    event_id        BIGSERIAL PRIMARY KEY,
    event_type      TEXT NOT NULL CHECK (event_type IN ('INSERT', 'UPDATE', 'DELETE')),
    table_name      TEXT NOT NULL,
    record_id       TEXT NOT NULL,
    old_data        JSONB,
    new_data        JSONB,
    changed_columns TEXT[],
    requires_embedding_refresh BOOLEAN GENERATED ALWAYS AS (
        -- Only flag if embedding-sensitive columns changed
        (new_data IS NOT NULL)
    ) STORED,
    pipeline_status TEXT DEFAULT 'pending' CHECK (
        pipeline_status IN ('pending', 'processing', 'completed', 'failed', 'skipped')
    ),
    retry_count     INT DEFAULT 0,
    error_message   TEXT,
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    processed_at    TIMESTAMPTZ
);

CREATE INDEX idx_change_events_status ON ai_change_events (pipeline_status, created_at)
    WHERE pipeline_status IN ('pending', 'failed');
CREATE INDEX idx_change_events_table ON ai_change_events (table_name, record_id);

-- Product embeddings table (pgvector)
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE product_embeddings (
    product_id      UUID PRIMARY KEY REFERENCES products(product_id) ON DELETE CASCADE,
    embedding       VECTOR(1536),
    embedding_model TEXT NOT NULL DEFAULT 'text-embedding-3-small',
    source_text     TEXT NOT NULL,  -- the text that was embedded, for drift detection
    source_hash     TEXT NOT NULL,  -- SHA-256 of source_text, for quick staleness check
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_product_embeddings_vector
    ON product_embeddings USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 64);

-- Trigger to capture changes and emit notifications
CREATE OR REPLACE FUNCTION capture_ai_change_event()
RETURNS TRIGGER AS $$
DECLARE
    v_record_id     TEXT;
    v_changed_cols  TEXT[];
    v_event_id      BIGINT;
    v_old_data      JSONB;
    v_new_data      JSONB;
BEGIN
    -- Determine record ID (assume first PK-like column or use a naming convention)
    v_record_id := COALESCE(
        (row_to_json(NEW) ->> TG_TABLE_NAME || '_id'),
        (row_to_json(NEW) ->> 'id'),
        'unknown'
    );

    IF TG_OP = 'INSERT' THEN
        v_new_data := row_to_json(NEW)::JSONB;
        v_old_data := NULL;
        v_changed_cols := ARRAY(SELECT jsonb_object_keys(v_new_data));
    ELSIF TG_OP = 'UPDATE' THEN
        v_new_data := row_to_json(NEW)::JSONB;
        v_old_data := row_to_json(OLD)::JSONB;
        -- Identify only changed columns
        SELECT ARRAY_AGG(key) INTO v_changed_cols
        FROM (
            SELECT jsonb_object_keys(v_new_data) AS key
            EXCEPT
            SELECT jsonb_object_keys(
                jsonb_strip_nulls(v_old_data) - ARRAY(
                    SELECT k FROM jsonb_each_text(v_new_data) n
                    JOIN jsonb_each_text(v_old_data) o USING (key)
                    WHERE n.value = o.value
                )
            )
        ) changed;
    ELSIF TG_OP = 'DELETE' THEN
        v_old_data := row_to_json(OLD)::JSONB;
        v_new_data := NULL;
        v_changed_cols := NULL;
    END IF;

    INSERT INTO ai_change_events (
        event_type, table_name, record_id,
        old_data, new_data, changed_columns
    ) VALUES (
        TG_OP, TG_TABLE_NAME, v_record_id,
        v_old_data, v_new_data, v_changed_cols
    )
    RETURNING event_id INTO v_event_id;

    -- Emit real-time notification with minimal payload
    PERFORM pg_notify(
        'ai_pipeline_events',
        json_build_object(
            'event_id', v_event_id,
            'table', TG_TABLE_NAME,
            'op', TG_OP,
            'id', v_record_id
        )::TEXT
    );

    IF TG_OP = 'DELETE' THEN
        RETURN OLD;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- Attach trigger to products table
CREATE TRIGGER trg_products_ai_cdc
    AFTER INSERT OR UPDATE OR DELETE ON products
    FOR EACH ROW EXECUTE FUNCTION capture_ai_change_event();

-- Auto-update timestamp
CREATE OR REPLACE FUNCTION update_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_products_updated_at
    BEFORE UPDATE ON products
    FOR EACH ROW EXECUTE FUNCTION update_updated_at();

30.2 The Logical Replication Consumer

For high-volume tables where triggers add write overhead, or where you need to capture changes from tables you can't modify (third-party schemas, audit tables), logical replication via a replication slot is the right tool. The pgoutput plugin ships with PostgreSQL and requires no extensions. Build a consumer that translates WAL events into AI pipeline tasks.

First, create the publication and replication slot:

-- Create a publication covering AI-relevant tables
CREATE PUBLICATION ai_feature_pipeline
    FOR TABLE products, orders, customer_profiles, support_tickets
    WITH (publish = 'insert, update, delete');

-- Create a replication slot using the pgoutput plugin
-- This must be done as a superuser or replication role
SELECT pg_create_logical_replication_slot(
    'ai_pipeline_slot',
    'pgoutput'
);

-- Verify
SELECT slot_name, plugin, slot_type, active, restart_lsn
FROM pg_replication_slots
WHERE slot_name = 'ai_pipeline_slot';

-- Check current WAL consumption (monitor this — unconsumed WAL grows disk usage)
SELECT
    slot_name,
    pg_size_pretty(pg_wal_lsn_diff(pg_current_wal_lsn(), restart_lsn)) AS lag_size,
    active
FROM pg_replication_slots;

Now build the Python consumer. This runs as a long-lived service, streaming WAL changes and dispatching them to Celery for async processing:

# cdc_consumer.py — Logical replication consumer for AI feature pipeline
import asyncio
import json
import logging
import os
import signal
from datetime import datetime
from typing import Any

import psycopg
from psycopg.rows import dict_row
from celery import Celery

# Configure structured logging
logging.basicConfig(
    level=logging.INFO,
    format='{"timestamp": "%(asctime)s", "level": "%(levelname)s", "message": "%(message)s"}'
)
logger = logging.getLogger(__name__)

# Celery app pointing at Redis
celery_app = Celery(
    'ai_pipeline',
    broker=os.getenv('REDIS_URL', 'redis://localhost:6379/0'),
    backend=os.getenv('REDIS_URL', 'redis://localhost:6379/0')
)

# Tables that require embedding refresh and which columns trigger it
EMBEDDING_SENSITIVE_TABLES = {
    'products': {'name', 'description', 'category', 'attributes'},
    'support_tickets': {'title', 'body', 'resolution'},
    'customer_profiles': {'bio', 'preferences', 'tags'},
}

class WALConsumer:
    """
    Consumes PostgreSQL logical replication stream and dispatches
    AI pipeline tasks based on the nature of each change.
    """

    def __init__(self, dsn: str, slot_name: str, publication: str):
        self.dsn = dsn
        self.slot_name = slot_name
        self.publication = publication
        self.running = True
        self._processed_count = 0
        self._skipped_count = 0

    def _should_refresh_embedding(
        self,
        table_name: str,
        changed_columns: list[str] | None
    ) -> bool:
        if table_name not in EMBEDDING_SENSITIVE_TABLES:
            return False
        if changed_columns is None:
            return True  # INSERT — always embed
        sensitive = EMBEDDING_SENSITIVE_TABLES[table_name]
        return bool(sensitive.intersection(set(changed_columns)))

    def _extract_record_id(self, table_name: str, data: dict) -> str | None:
        # Convention: <table_singular>_id or just 'id'
        id_col = f"{table_name.rstrip('s')}_id"
        return str(data.get(id_col) or data.get('id') or data.get('uuid'))

    def _dispatch_pipeline_tasks(
        self,
        operation: str,
        table_name: str,
        record_id: str,
        old_data: dict | None,
        new_data: dict | None,
        changed_columns: list[str] | None
    ):
        """Route change events to appropriate Celery tasks."""

        if operation == 'DELETE':
            # Remove stale embeddings and cached features
            celery_app.send_task(
                'tasks.delete_embedding',
                args=[table_name, record_id],
                queue='embedding_ops'
            )
            celery_app.send_task(
                'tasks.invalidate_feature_cache',
                args=[table_name, record_id],
                queue='cache_ops'
            )
            return

        needs_embed = self._should_refresh_embedding(table_name, changed_columns)

        if needs_embed:
            celery_app.send_task(
                'tasks.refresh_embedding',
                args=[table_name, record_id, new_data],
                queue='embedding_ops',
                # Exponential backoff retry policy
                retry=True,
                retry_policy={
                    'max_retries': 3,
                    'interval_start': 2,
                    'interval_step': 4,
                    'interval_max': 30,
                }
            )
            self._processed_count += 1
        else:
            self._skipped_count += 1
            logger.debug(
                f"Skipping embedding refresh for {table_name}/{record_id} "
                f"— changed columns {changed_columns} not embedding-sensitive"
            )

        # Always update the feature store for downstream ML models
        celery_app.send_task(
            'tasks.update_feature_store',
            args=[table_name, record_id, new_data, changed_columns],
            queue='feature_ops'
        )

    async def run(self):
        """Main consumer loop using psycopg3 async logical replication."""

        conn_info = self.dsn + " replication=database"

        async with await psycopg.AsyncConnection.connect(
            conn_info,
            autocommit=True
        ) as conn:
            logger.info(
                f"Connected to logical replication slot: {self.slot_name}"
            )

            # Start the replication stream
            await conn.execute(
                f"START_REPLICATION SLOT {self.slot_name} LOGICAL 0/0 "
                f"(proto_version '1', publication_names '{self.publication}')"
            )

            async for msg in conn.cursor():
                if not self.running:
                    break

                # pgoutput protocol parsing
                # In production, use python-replication or pg_logical_emit
                payload = msg.payload
                if payload[0:1] == b'w':  # WAL data
                    data = json.loads(payload[1:])
                    operation = data.get('action')
                    table_name = data.get('table')

                    if operation in ('I', 'U', 'D'):
                        op_map = {'I': 'INSERT', 'U': 'UPDATE', 'D': 'DELETE'}
                        old_data = data.get('old')
                        new_data = data.get('new') or data.get('columns')
                        changed_columns = None

                        if operation == 'U' and old_data and new_data:
                            changed_columns = [
                                k for k in new_data
                                if new_data.get(k) != old_data.get(k)
                            ]

                        record_id = self._extract_record_id(
                            table_name,
                            new_data or old_data or {}
                        )

                        self._dispatch_pipeline_tasks(
                            op_map[operation],
                            table_name,
                            record_id,
                            old_data,
                            new_data,
                            changed_columns
                        )

                        # Acknowledge WAL position
                        await conn.execute(
                            f"SELECT pg_replication_slot_advance("
                            f"'{self.slot_name}', '{msg.data_start}')"
                        )

                        if self._processed_count % 100 == 0:
                            logger.info(
                                f"Pipeline stats — processed: {self._processed_count}, "
                                f"skipped: {self._skipped_count}"
                            )

    def shutdown(self):
        logger.info("Shutting down WAL consumer gracefully...")
        self.running = False


async def main():
    consumer = WALConsumer(
        dsn=os.getenv('DATABASE_URL', 'postgresql://postgres@localhost/myapp'),
        slot_name='ai_pipeline_slot',
        publication='ai_feature_pipeline'
    )

    loop = asyncio.get_event_loop()
    for sig in (signal.SIGTERM, signal.SIGINT):
        loop.add_signal_handler(sig, consumer.shutdown)

    await consumer.run()


if __name__ == '__main__':
    asyncio.run(main())

30.3 Celery Workers for Async Embedding Refresh

The Celery task layer is where the actual AI work happens. Each task receives a record ID and its data, generates embeddings via the OpenAI API, and writes them back to PostgreSQL. The design matters here: tasks must be idempotent (safe to retry), they must detect whether embeddings are actually stale before calling the API (costs money), and they should use connection pooling through PgBouncer rather than opening direct connections.

# tasks.py — Celery workers for AI feature pipeline
import hashlib
import json
import logging
import os
from typing import Any

import redis
from celery import Celery, Task
from celery.utils.log import get_task_logger
from openai import OpenAI
import psycopg
from psycopg.rows import dict_row
from psycopg_pool import ConnectionPool

logger = get_task_logger(__name__)

# App configuration
celery_app = Celery('ai_pipeline')
celery_app.config_from_object({
    'broker_url': os.getenv('REDIS_URL', 'redis://localhost:6379/0'),
    'result_backend': os.getenv('REDIS_URL', 'redis://localhost:6379/0'),
    'task_serializer': 'json',
    'result_serializer': 'json',
    'accept_content': ['json'],
    'task_acks_late': True,          # Only ack after successful completion
    'task_reject_on_worker_lost': True,
    'worker_prefetch_multiplier': 4,
    'task_routes': {
        'tasks.refresh_embedding': {'queue': 'embedding_ops'},
        'tasks.delete_embedding': {'queue': 'embedding_ops'},
        'tasks.update_feature_store': {'queue': 'feature_ops'},
        'tasks.invalidate_feature_cache': {'queue': 'cache_ops'},
        'tasks.batch_reembed_table': {'queue': 'batch_ops'},
    }
})

# PgBouncer connection pool — uses transaction pooling mode
# Note: statement-level pooling won't work with LISTEN/NOTIFY
PGBOUNCER_DSN = os.getenv(
    'PGBOUNCER_URL',
    'postgresql://app_user:secret@pgbouncer:5432/myapp'
)

db_pool = ConnectionPool(
    PGBOUNCER_DSN,
    min_size=2,
    max_size=20,
    kwargs={'row_factory': dict_row}
)

openai_client = OpenAI(api_key=os.getenv('OPENAI_API_KEY'))
redis_client = redis.Redis.from_url(
    os.getenv('REDIS_URL', 'redis://localhost:6379/0'),
    decode_responses=True
)

# Embedding model configuration
EMBEDDING_CONFIG = {
    'model': 'text-embedding-3-small',
    'dimensions': 1536,
    'cache_ttl_seconds': 3600 * 24,  # 24h cache for identical text
}


def build_product_source_text(data: dict) -> str:
    """
    Construct the text representation of a product for embedding.
    Deterministic ordering matters — same product always produces same string.
    """
    parts = []
    if data.get('name'):
        parts.append(f"Product: {data['name']}")
    if data.get('category'):
        parts.append(f"Category: {data['category']}")
    if data.get('description'):
        parts.append(f"Description: {data['description']}")
    if data.get('attributes'):
        attrs = data['attributes']
        if isinstance(attrs, str):
            attrs = json.loads(attrs)
        attr_str = ', '.join(f"{k}: {v}" for k, v in attrs.items())
        parts.append(f"Attributes: {attr_str}")
    return '\n'.join(parts)


def build_source_text(table_name: str, data: dict) -> str:
    """Route to the appropriate text builder for each table type."""
    builders = {
        'products': build_product_source_text,
        'support_tickets': lambda d: f"{d.get('title', '')}\n{d.get('body', '')}\n{d.get('resolution', '')}",
        'customer_profiles': lambda d: f"{d.get('bio', '')} {json.dumps(d.get('preferences', {}))}",
    }
    builder = builders.get(table_name, lambda d: json.dumps(d))
    return builder(data).strip()


def get_embedding_with_cache(text: str) -> list[float]:
    """
    Fetch embedding from OpenAI, with Redis caching keyed on SHA-256 of text.
    Identical text never hits the API twice within cache TTL.
    """
    text_hash = hashlib.sha256(text.encode()).hexdigest()
    cache_key = f"emb:{EMBEDDING_CONFIG['model']}:{text_hash}"

    cached = redis_client.get(cache_key)
    if cached:
        logger.debug(f"Embedding cache hit for hash {text_hash[:8]}...")
        return json.loads(cached)

    response = openai_client.embeddings.create(
        input=text,
        model=EMBEDDING_CONFIG['model'],
        dimensions=EMBEDDING_CONFIG['dimensions']
    )
    embedding = response.data[0].embedding

    redis_client.setex(
        cache_key,
        EMBEDDING_CONFIG['cache_ttl_seconds'],
        json.dumps(embedding)
    )
    return embedding
@celery_app.task(
    name='tasks.refresh_embedding',
    bind=True,
    max_retries=3,
    default_retry_delay=5,
    acks_late=True
)
def refresh_embedding(
    self: Task,
    table_name: str,
    record_id: str,
    data: dict[str, Any]
) -> dict:
    """
    Refresh the embedding for a single record. Idempotent — checks source hash
    before calling the embedding API to avoid redundant work and API costs.
    """
    try:
        source_text = build_source_text(table_name, data)
        if not source_text:
            logger.warning(f"Empty source text for {table_name}/{record_id}, skipping")
            return {'status': 'skipped', 'reason': 'empty_source_text'}

        source_hash = hashlib.sha256(source_text.encode()).hexdigest()

        with db_pool.connection() as conn:
            # Check whether the current stored hash matches — if so, skip API call
            existing = conn.execute(
                """
                SELECT source_hash
                FROM product_embeddings
                WHERE product_id = %s::uuid
                """,
                (record_id,)
            ).fetchone()

            if existing and existing['source_hash'] == source_hash:
                logger.debug(
                    f"Embedding for {table_name}/{record_id} is current "
                    f"(hash match), skipping API call"
                )
                return {'status': 'skipped', 'reason': 'hash_match'}

            # Generate embedding — may hit Redis cache for identical text
            embedding = get_embedding_with_cache(source_text)

            # Upsert into the embeddings table
            conn.execute(
                """
                INSERT INTO product_embeddings
                    (product_id, embedding, embedding_model, source_text, source_hash, updated_at)
                VALUES
                    (%s::uuid, %s::vector, %s, %s, %s, NOW())
                ON CONFLICT (product_id) DO UPDATE SET
                    embedding       = EXCLUDED.embedding,
                    embedding_model = EXCLUDED.embedding_model,
                    source_text     = EXCLUDED.source_text,
                    source_hash     = EXCLUDED.source_hash,
                    updated_at      = NOW()
                """,
                (
                    record_id,
                    str(embedding),
                    EMBEDDING_CONFIG['model'],
                    source_text,
                    source_hash
                )
            )

            # Mark the change event as completed
            conn.execute(
                """
                UPDATE ai_change_events
                SET pipeline_status = 'completed',
                    processed_at    = NOW()
                WHERE table_name = %s
                  AND record_id   = %s
                  AND pipeline_status IN ('pending', 'processing')
                """,
                (table_name, record_id)
            )

        logger.info(
            f"Embedding refreshed for {table_name}/{record_id} "
            f"(model={EMBEDDING_CONFIG['model']}, hash={source_hash[:8]}...)"
        )
        return {'status': 'success', 'record_id': record_id, 'hash': source_hash}

    except Exception as exc:
        logger.error(
            f"Embedding refresh failed for {table_name}/{record_id}: {exc}",
            exc_info=True
        )
        # Mark as failed in the change events table
        try:
            with db_pool.connection() as conn:
                conn.execute(
                    """
                    UPDATE ai_change_events
                    SET pipeline_status = 'failed',
                        retry_count     = retry_count + 1,
                        error_message   = %s
                    WHERE table_name = %s
                      AND record_id   = %s
                      AND pipeline_status IN ('pending', 'processing')
                    """,
                    (str(exc), table_name, record_id)
                )
        except Exception:
            pass  # Don't let DB logging failure mask the original error

        raise self.retry(exc=exc)


@celery_app.task(name='tasks.delete_embedding', acks_late=True)
def delete_embedding(table_name: str, record_id: str) -> dict:
    """Remove embeddings for a deleted record. Safe to call multiple times."""
    with db_pool.connection() as conn:
        result = conn.execute(
            """
            DELETE FROM product_embeddings
            WHERE product_id = %s::uuid
            RETURNING product_id
            """,
            (record_id,)
        ).fetchone()

    if result:
        logger.info(f"Deleted embedding for {table_name}/{record_id}")
        return {'status': 'deleted', 'record_id': record_id}
    else:
        logger.debug(f"No embedding found to delete for {table_name}/{record_id}")
        return {'status': 'not_found', 'record_id': record_id}


@celery_app.task(name='tasks.invalidate_feature_cache', acks_late=True)
def invalidate_feature_cache(table_name: str, record_id: str) -> dict:
    """Invalidate all Redis cache keys associated with a record."""
    pattern = f"feature:{table_name}:{record_id}:*"
    keys = redis_client.keys(pattern)
    if keys:
        redis_client.delete(*keys)
        logger.info(f"Invalidated {len(keys)} cache keys for {table_name}/{record_id}")
    return {'status': 'ok', 'invalidated': len(keys)}


@celery_app.task(name='tasks.update_feature_store', acks_late=True)
def update_feature_store(
    table_name: str,
    record_id: str,
    data: dict[str, Any],
    changed_columns: list[str] | None
) -> dict:
    """
    Write computed features to the feature store for downstream ML models.
    This is a stub — replace with your actual feature store client
    (Feast, Tecton, Redis, etc.).
    """
    feature_key = f"features:{table_name}:{record_id}"
    features = {
        'record_id': record_id,
        'table': table_name,
        'updated_at': str(__import__('datetime').datetime.utcnow()),

    }
    redis_client.hset(feature_key, mapping=features)
    redis_client.expire(feature_key, 3600 * 72)  # 72-hour TTL
    return {'status': 'ok', 'feature_key': feature_key}

30.4 Batch Backfill and Catch-Up Processing

New AI features often need embeddings for every existing row before real-time CDC takes over. The same thing happens after a model upgrade — you need to re-embed the entire table with the new model. Do this with a batch task that pages through the table using keyset pagination rather than OFFSET (which degrades at scale), and applies the same idempotency logic as the real-time worker.

# tasks.py (continued) — batch backfill

@celery_app.task(
    name='tasks.batch_reembed_table',
    bind=True,
    max_retries=5,
    soft_time_limit=3600,   # 1-hour soft limit per batch page
    time_limit=3900
)
def batch_reembed_table(
    self: Task,
    table_name: str,
    model_name: str | None = None,
    batch_size: int = 100,
    last_id: str | None = None,
    force_refresh: bool = False
) -> dict:
    """
    Page through a table and enqueue embedding refresh tasks for all records
    that are missing embeddings or have stale ones (hash mismatch).
    Uses keyset pagination for stable, efficient traversal.
    """
    model_name = model_name or EMBEDDING_CONFIG['model']
    processed = 0
    enqueued = 0

    with db_pool.connection() as conn:
        # Keyset pagination: always march forward by primary key
        rows = conn.execute(
            """
            SELECT p.product_id::text AS id,
                   p.name, p.description, p.category, p.attributes,
                   pe.source_hash AS stored_hash,
                   pe.embedding_model AS stored_model
            FROM products p
            LEFT JOIN product_embeddings pe ON pe.product_id = p.product_id
            WHERE p.is_active = TRUE
              AND (%s::uuid IS NULL OR p.product_id > %s::uuid)
            ORDER BY p.product_id
            LIMIT %s
            """,
            (last_id, last_id, batch_size)
        ).fetchall()

    if not rows:
        logger.info(f"Batch reembed complete for {table_name} — {processed} pages processed")
        return {'status': 'complete', 'table': table_name, 'total_enqueued': enqueued}

    for row in rows:
        processed += 1
        record_data = {
            'name': row['name'],
            'description': row['description'],
            'category': row['category'],
            'attributes': row['attributes'],
        }
        source_text = build_source_text(table_name, record_data)
        current_hash = hashlib.sha256(source_text.encode()).hexdigest()

        needs_refresh = (
            force_refresh
            or row['stored_hash'] is None
            or row['stored_hash'] != current_hash
            or row['stored_model'] != model_name
        )

        if needs_refresh:
            refresh_embedding.apply_async(
                args=[table_name, row['id'], record_data],
                queue='embedding_ops'
            )
            enqueued += 1

    # Enqueue the next page
    next_last_id = rows[-1]['id']
    batch_reembed_table.apply_async(
        args=[table_name],
        kwargs={
            'model_name': model_name,
            'batch_size': batch_size,
            'last_id': next_last_id,
            'force_refresh': force_refresh,
        },
        queue='batch_ops',
        countdown=1  # Brief pause to avoid overwhelming the embedding API
    )

    logger.info(
        f"Batch page complete: table={table_name}, processed={processed}, "
        f"enqueued={enqueued}, next_cursor={next_last_id[:8]}..."
    )
    return {
        'status': 'in_progress',
        'page_processed': processed,
        'page_enqueued': enqueued,
        'next_cursor': next_last_id
    }

30.5 pg_notify for Low-Latency Real-Time Updates

For scenarios where you need subsecond reaction times — live search, real-time personalization, streaming dashboards — pg_notify provides a direct channel from PostgreSQL to your application without any queue intermediary. The trigger we built in section 30.1 already emits notifications; now build the async listener that acts on them immediately.

# realtime_listener.py — pg_notify consumer for low-latency AI updates
import asyncio
import json
import logging
import os
import signal
from collections import defaultdict
from datetime import datetime, timedelta

import psycopg
from openai import AsyncOpenAI

logger = logging.getLogger(__name__)
logging.basicConfig(level=logging.INFO)

openai_client = AsyncOpenAI(api_key=os.getenv('OPENAI_API_KEY'))

# Debounce window: if the same record is modified multiple times within
# this window, only process it once (avoids redundant embedding calls
# during bulk updates or rapid edits)
DEBOUNCE_SECONDS = 2.0


class RealtimeEmbeddingUpdater:
    """
    Listens on pg_notify channel 'ai_pipeline_events' and applies
    real-time embedding updates with debouncing to prevent API storms.
    """

    def __init__(self, dsn: str):
        self.dsn = dsn
        self.running = True
        # pending_updates[table][record_id] = (event_id, timestamp)
        self.pending_updates: dict[str, dict[str, tuple]] = defaultdict(dict)
        self._debounce_task: asyncio.Task | None = None

    async def _fetch_record(
        self,
        conn: psycopg.AsyncConnection,
        table_name: str,
        record_id: str
    ) -> dict | None:
        """Fetch the current state of a record directly."""
        # Table-specific fetch queries
        queries = {
            'products': """
                SELECT product_id::text AS id, name, description,
                       category, attributes
                FROM products
                WHERE product_id = %s::uuid AND is_active = TRUE
            """,
        }
        query = queries.get(table_name)
        if not query:
            return None
        row = await conn.execute(query, (record_id,))
        result = await row.fetchone()
        return dict(result) if result else None

    async def _apply_embedding_update(
        self,
        conn: psycopg.AsyncConnection,
        table_name: str,
        record_id: str
    ):
        """Fetch current record, compute embedding, write back."""
        import hashlib

        data = await self._fetch_record(conn, table_name, record_id)
        if data is None:
            logger.debug(
                f"Record {table_name}/{record_id} not found "
                f"(may have been deleted)"
            )
            return

        source_text = build_source_text(table_name, data)
        source_hash = hashlib.sha256(source_text.encode()).hexdigest()

        # Check if hash already matches stored value
        existing = await (
            await conn.execute(
                "SELECT source_hash FROM product_embeddings "
                "WHERE product_id = %s::uuid",
                (record_id,)
            )
        ).fetchone()

        if existing and existing[0] == source_hash:
            logger.debug(
                f"Realtime: {table_name}/{record_id} already current, skipping"
            )
            return

        # Async OpenAI call
        response = await openai_client.embeddings.create(
            input=source_text,
            model='text-embedding-3-small',
            dimensions=1536
        )
        embedding = response.data[0].embedding

        await conn.execute(
            """
            INSERT INTO product_embeddings
                (product_id, embedding, embedding_model, source_text, source_hash, updated_at)
            VALUES (%s::uuid, %s::vector, %s, %s, %s, NOW())
            ON CONFLICT (product_id) DO UPDATE SET
                embedding       = EXCLUDED.embedding,
                embedding_model = EXCLUDED.embedding_model,
                source_text     = EXCLUDED.source_text,
                source_hash     = EXCLUDED.source_hash,
                updated_at      = NOW()
            """,
            (record_id, str(embedding), 'text-embedding-3-small', source_text, source_hash)
        )
        logger.info(
            f"Realtime embedding updated: {table_name}/{record_id}"
        )

    async def _process_debounced_updates(self):
        """
        Periodically drain the debounce buffer, processing only the most
        recent notification for each record.
        """
        while self.running:
            await asyncio.sleep(DEBOUNCE_SECONDS)
            if not self.pending_updates:
                continue

            snapshot = {
                table: dict(records)
                for table, records in self.pending_updates.items()
            }
            self.pending_updates.clear()

            async with await psycopg.AsyncConnection.connect(
                self.dsn, row_factory=psycopg.rows.dict_row
            ) as conn:
                async with conn.transaction():
                    for table_name, records in snapshot.items():
                        for record_id, (event_id, ts) in records.items():
                            try:
                                await self._apply_embedding_update(
                                    conn, table_name, record_id
                                )
                            except Exception as e:
                                logger.error(
                                    f"Realtime update failed for "
                                    f"{table_name}/{record_id}: {e}",
                                    exc_info=True
                                )

    async def run(self):
        """Listen on pg_notify channel and buffer incoming events."""
        self._debounce_task = asyncio.create_task(
            self._process_debounced_updates()
        )

        async with await psycopg.AsyncConnection.connect(
            self.dsn, autocommit=True
        ) as conn:
            await conn.execute("LISTEN ai_pipeline_events")
            logger.info("Listening on channel: ai_pipeline_events")

            async for notify in conn.notifies():
                if not self.running:
                    break

                try:
                    payload = json.loads(notify.payload)
                    table_name = payload.get('table')
                    record_id = payload.get('id')
                    event_id = payload.get('event_id')
                    op = payload.get('op')

                    if op == 'DELETE':
                        # Deletes don't need debouncing — act immediately
                        async with await psycopg.AsyncConnection.connect(
                            self.dsn
                        ) as del_conn:
                            await del_conn.execute(
                                "DELETE FROM product_embeddings "
                                "WHERE product_id = %s::uuid",
                                (record_id,)
                            )
                        continue

                    # Buffer for debouncing
                    self.pending_updates[table_name][record_id] = (
                        event_id,
                        datetime.utcnow()
                    )

                except json.JSONDecodeError:
                    logger.warning(
                        f"Invalid JSON in notification: {notify.payload}"
                    )

        if self._debounce_task:
            self._debounce_task.cancel()

    def shutdown(self):
        self.running = False


async def main():
    updater = RealtimeEmbeddingUpdater(
        dsn=os.getenv('DATABASE_URL', 'postgresql://postgres@localhost/myapp')
    )
    loop = asyncio.get_event_loop()
    for sig in (signal.SIGTERM, signal.SIGINT):
        loop.add_signal_handler(sig, updater.shutdown)
    await updater.run()


if __name__ == '__main__':
    asyncio.run(main())

The debounce mechanism deserves explanation. When a user edits a product description character by character through a rich-text editor, the database might fire dozens of UPDATE events within a two-second window. Without debouncing, each event triggers an API call. With the buffer, only the final state is embedded — the one that actually matters for search. The window (two seconds here) should be tuned to your update patterns: longer for editors, shorter for transactional systems where each update is distinct.

30.6 Drift Detection and Staleness Monitoring

Over time, embeddings drift from the data they represent. A product description changes but the embedding refresh fails silently. A model upgrade is deployed but old embeddings remain. A bulk import populates thousands of rows before CDC is wired up. Systematic drift detection is the safety net that catches these gaps.

-- View: identify records with potentially stale embeddings
-- Run this as a scheduled job and alert if count exceeds threshold

CREATE OR REPLACE VIEW v_embedding_staleness AS
WITH current_hashes AS (
    -- Compute what the source hash should be for each product
    -- This mirrors the Python build_product_source_text logic
    SELECT
        p.product_id,
        p.updated_at AS record_updated_at,
        encode(
            sha256(
                TRIM(
                    COALESCE('Product: ' || p.name, '') || E'\n' ||
                    COALESCE('Category: ' || p.category, '') || E'\n' ||
                    COALESCE('Description: ' || p.description, '') || E'\n' ||
                    COALESCE('Attributes: ' || p.attributes::text, '')
                )::bytea
            ),
            'hex'
        ) AS expected_hash
    FROM products p
    WHERE p.is_active = TRUE
)
SELECT
    p.product_id,
    p.name,
    p.updated_at                                    AS product_updated_at,
    pe.updated_at                                   AS embedding_updated_at,
    pe.embedding_model,
    ch.expected_hash,
    pe.source_hash                                  AS stored_hash,
    pe.product_id IS NULL                           AS missing_embedding,
    pe.source_hash != ch.expected_hash              AS hash_mismatch,
    pe.embedding_model != 'text-embedding-3-small'  AS model_outdated,
    CASE
        WHEN pe.product_id IS NULL                        THEN 'missing'
        WHEN pe.source_hash != ch.expected_hash           THEN 'stale_content'
        WHEN pe.embedding_model != 'text-embedding-3-small' THEN 'outdated_model'
        ELSE 'current'
    END AS staleness_status,
    EXTRACT(EPOCH FROM (NOW() - pe.updated_at)) / 3600 AS hours_since_embed
FROM products p
JOIN current_hashes ch ON ch.product_id = p.product_id
LEFT JOIN product_embeddings pe ON pe.product_id = p.product_id
WHERE p.is_active = TRUE;

-- Summary query for alerting and dashboards
SELECT
    staleness_status,
    COUNT(*)                                      AS record_count,
    AVG(hours_since_embed)::NUMERIC(10, 1)        AS avg_hours_stale,
    MAX(hours_since_embed)::NUMERIC(10, 1)        AS max_hours_stale
FROM v_embedding_staleness
GROUP BY staleness_status
ORDER BY staleness_status;

Wire this into a scheduled monitoring job that alerts when staleness exceeds your SLA:

# drift_monitor.py — scheduled staleness detection
import os
import logging
from datetime import datetime

import psycopg
from psycopg.rows import dict_row

logger = logging.getLogger(__name__)

STALENESS_THRESHOLDS = {
    'missing': 0,        # Any missing embedding is an alert
    'stale_content': 50, # Alert if more than 50 records have stale content
    'outdated_model': 0, # Any outdated model embedding is an alert
}

ALERT_WEBHOOK = os.getenv('ALERT_WEBHOOK_URL')


async def check_embedding_drift():
    dsn = os.getenv('DATABASE_URL', 'postgresql://postgres@localhost/myapp')

    async with await psycopg.AsyncConnection.connect(dsn) as conn:
        conn.row_factory = dict_row
        rows = await (
            await conn.execute(
                """
                SELECT staleness_status, COUNT(*) AS cnt,
                       MAX(hours_since_embed) AS max_hours
                FROM v_embedding_staleness
                GROUP BY staleness_status
                """
            )
        ).fetchall()

    alerts = []
    for row in rows:
        status = row['staleness_status']
        count = row['cnt']
        threshold = STALENESS_THRESHOLDS.get(status)

        if threshold is not None and count > threshold:
            alerts.append({
                'status': status,
                'count': count,
                'max_hours_stale': row['max_hours'],
                'threshold': threshold
            })

    if alerts:
        logger.warning(f"Embedding drift detected: {alerts}")
        if ALERT_WEBHOOK:
            import httpx
            async with httpx.AsyncClient() as client:
                await client.post(ALERT_WEBHOOK, json={
                    'text': f":warning: Embedding drift alert at {datetime.utcnow().isoformat()}Z",
                    'attachments': alerts
                })
    else:
        logger.info("Embedding drift check passed — all records current")

    return alerts


if __name__ == '__main__':
    import asyncio
    asyncio.run(check_embedding_drift())

30.7 SQL Server Equivalent: Change Tracking and Service Broker

SQL Server provides two CDC-equivalent mechanisms. Change Tracking records the fact of a row change (which rows changed and their current state) while Change Data Capture records the actual before/after values from the transaction log. For AI feature pipelines where you need full before/after data, SQL Server CDC is the right choice. For lower overhead when you only need current state, Change Tracking suffices.

Enable Change Data Capture on SQL Server:

-- SQL Server: Enable CDC at the database level
USE MyAppDB;
EXEC sys.sp_cdc_enable_db;

-- Enable CDC on the products table, capturing all columns
EXEC sys.sp_cdc_enable_table
    @source_schema = N'dbo',
    @source_name   = N'products',
    @role_name     = N'cdc_reader',  -- role that can query CDC tables
    @supports_net_changes = 1;       -- enables net-change queries

-- Verify CDC is active
SELECT name, is_cdc_enabled
FROM sys.databases
WHERE name = DB_NAME();

SELECT source_schema, source_table, capture_instance,
       start_lsn, object_id, supports_net_changes
FROM cdc.change_tables;

Query the CDC change tables to build an equivalent to PostgreSQL's ai_change_events:

-- SQL Server: Read CDC changes since last processed LSN
-- Store @last_lsn in a control table between runs

DECLARE @from_lsn BINARY(10) = sys.fn_cdc_get_min_lsn('dbo_products');
DECLARE @to_lsn   BINARY(10) = sys.fn_cdc_get_max_lsn();

-- Net changes: only the final state of each row in the window
SELECT
    CT.__$operation       AS operation_code,  -- 1=delete, 2=insert, 4=update (after)
    CT.__$update_mask     AS update_mask,
    CT.product_id,
    CT.name,
    CT.description,
    CT.category,
    CT.attributes,
    CT.__$start_lsn       AS change_lsn
FROM cdc.fn_cdc_get_net_changes_dbo_products(
    @from_lsn, @to_lsn, N'all with mask'
) AS CT
WHERE CT.__$operation IN (1, 2, 4)  -- delete, insert, update-after
ORDER BY CT.__$start_lsn;

-- Decode which columns changed using the update mask
SELECT
    CT.product_id,
    CASE CT.__$operation
        WHEN 1 THEN 'DELETE'
        WHEN 2 THEN 'INSERT'
        WHEN 4 THEN 'UPDATE'
    END AS operation,
    sys.fn_cdc_is_bit_set(
        sys.fn_cdc_get_column_ordinal('dbo_products', 'name'),
        CT.__$update_mask
    ) AS name_changed,
    sys.fn_cdc_is_bit_set(
        sys.fn_cdc_get_column_ordinal('dbo_products', 'description'),
        CT.__$update_mask
    ) AS description_changed,
    sys.fn_cdc_is_bit_set(
        sys.fn_cdc_get_column_ordinal('dbo_products', 'category'),
        CT.__$update_mask
    ) AS category_changed
FROM cdc.fn_cdc_get_net_changes_dbo_products(
    @from_lsn, @to_lsn, N'all with mask'
) AS CT;

For the Service Broker equivalent of pg_notify, SQL Server provides asynchronous message queues that activate stored procedures:

-- SQL Server: Service Broker for real-time AI pipeline notifications

-- Create message type, contract, queues, and service
CREATE MESSAGE TYPE [//ai/ChangeEvent]
    VALIDATION = WELL_FORMED_XML;

CREATE CONTRACT [//ai/ChangeEventContract]
    ([//ai/ChangeEvent] SENT BY INITIATOR);

CREATE QUEUE AIFeaturePipelineQueue
    WITH STATUS = ON, RETENTION = OFF;

CREATE SERVICE [//ai/FeaturePipelineService]
    ON QUEUE AIFeaturePipelineQueue
    ([//ai/ChangeEventContract]);

-- Trigger that sends a Service Broker message on product changes
CREATE OR ALTER TRIGGER trg_products_ai_notify
ON dbo.products
AFTER INSERT, UPDATE, DELETE
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @dialog   UNIQUEIDENTIFIER;
    DECLARE @message  NVARCHAR(MAX);

    -- Build XML payload for each changed row
    SELECT @message = (
        SELECT
            CASE
                WHEN EXISTS (SELECT 1 FROM inserted) AND EXISTS (SELECT 1 FROM deleted)
                    THEN 'UPDATE'
                WHEN EXISTS (SELECT 1 FROM inserted)
                    THEN 'INSERT'
                ELSE 'DELETE'
            END AS [operation],
            COALESCE(
                (SELECT TOP 1 product_id FROM inserted),
                (SELECT TOP 1 product_id FROM deleted)
            ) AS [record_id],
            GETUTCDATE() AS [event_time]
        FOR XML PATH('ChangeEvent'), ROOT('Payload')
    );

    BEGIN DIALOG CONVERSATION @dialog
        FROM SERVICE [//ai/FeaturePipelineService]
        TO SERVICE '//ai/FeaturePipelineService'
        ON CONTRACT [//ai/ChangeEventContract]
        WITH ENCRYPTION = OFF;

    SEND ON CONVERSATION @dialog
        MESSAGE TYPE [//ai/ChangeEvent]
        (@message);
END;
GO

-- Activated stored procedure: reads from queue and writes to a processing table
CREATE OR ALTER PROCEDURE dbo.ProcessAIChangeEvent
AS
BEGIN
    DECLARE @dialog   UNIQUEIDENTIFIER;
    DECLARE @message  NVARCHAR(MAX);
    DECLARE @msg_typeSYSNAME;

    WAITFOR (
        RECEIVE TOP (1)
            @dialog   = conversation_handle,
            @message  = CAST(message_body AS NVARCHAR(MAX)),
            @msg_type = message_type_name
        FROM AIFeaturePipelineQueue
    ), TIMEOUT 5000;

    IF @dialog IS NULL RETURN;

    IF @msg_type = '//ai/ChangeEvent'
    BEGIN
        DECLARE @operation  NVARCHAR(20);
        DECLARE @record_id  UNIQUEIDENTIFIER;

        SELECT
            @operation = x.value('(//operation)[1]',  'NVARCHAR(20)'),
            @record_id = x.value('(//record_id)[1]', 'UNIQUEIDENTIFIER')
        FROM (SELECT CAST(@message AS XML) AS x) t(x);

        -- Write to the AI change event processing table
        INSERT INTO dbo.AIChangeEvents
            (operation, table_name, record_id, pipeline_status, created_at)
        VALUES
            (@operation, 'products', @record_id, 'pending', GETUTCDATE());

        END CONVERSATION @dialog;
    END
    ELSE IF @msg_type = 'http://schemas.microsoft.com/SQL/ServiceBroker/EndDialog'
    BEGIN
        END CONVERSATION @dialog;
    END
END;
GO

-- Wire the stored procedure to activate automatically when messages arrive
ALTER QUEUE AIFeaturePipelineQueue
    WITH ACTIVATION (
        STATUS    = ON,
        PROCEDURE_NAME = dbo.ProcessAIChangeEvent,
        MAX_QUEUE_READERS = 5,
        EXECUTE AS OWNER
    );

The consumer on the Python side polls the SQL Server AIChangeEvents table using the same Celery dispatch logic as the PostgreSQL consumer. While SQL Server lacks a direct equivalent to pg_notify's push semantics, the Service Broker activation pattern achieves near-equivalent latency because the stored procedure fires immediately when a message arrives in the queue.

For Change Tracking (the lighter-weight alternative when you only need to know *which* rows changed, not the full before/after diff):

-- SQL Server: Enable Change Tracking (lower overhead than CDC)
ALTER DATABASE MyAppDB
SET CHANGE_TRACKING = ON
(CHANGE_RETENTION = 7 DAYS, AUTO_CLEANUP = ON);

ALTER TABLE dbo.products
ENABLE CHANGE_TRACKING
WITH (TRACK_COLUMNS_UPDATED = ON);

-- Query changes since a known version number
-- Store @last_sync_version in a control table
DECLARE @last_sync_version BIGINT = 0;

SELECT
    CT.product_id,
    CT.SYS_CHANGE_OPERATION  AS operation,   -- I, U, or D
    CT.SYS_CHANGE_COLUMNS    AS changed_cols_bitmap,
    P.name,
    P.description,
    P.category,
    P.attributes,
    CHANGE_TRACKING_IS_COLUMN_IN_MASK(
        COLUMNPROPERTY(OBJECT_ID('dbo.products'), 'name', 'ColumnId'),
        CT.SYS_CHANGE_COLUMNS
    ) AS name_changed,
    CHANGE_TRACKING_IS_COLUMN_IN_MASK(
        COLUMNPROPERTY(OBJECT_ID('dbo.products'), 'description', 'ColumnId'),
        CT.SYS_CHANGE_COLUMNS
    ) AS description_changed
FROM CHANGETABLE(CHANGES dbo.products, @last_sync_version) AS CT
LEFT JOIN dbo.products P ON P.product_id = CT.product_id
ORDER BY CT.SYS_CHANGE_VERSION;

-- Advance the version counter after successful processing
SELECT @last_sync_version = CHANGE_TRACKING_CURRENT_VERSION();

Use Change Tracking over CDC when write throughput is high and you only need the current row state for embedding — the lower log overhead is worth the trade-off. Use CDC when you need full before/after deltas for audit, feature attribution, or rollback scenarios.

30.8 Operational Concerns: WAL Lag, Slot Management, and Dead Letter Handling

A CDC pipeline that works during development often fails in production due to three operational issues: WAL lag from an inactive consumer, accumulated failed events that block the pipeline, and replication slot bloat that fills the disk.

WAL lag monitoring is non-negotiable. If your consumer falls behind or dies, PostgreSQL continues accumulating WAL to preserve data for the slot. Left unchecked this fills the disk and crashes the database. Monitor it with a Prometheus metric:

-- PostgreSQL: WAL lag per replication slot
SELECT
    slot_name,
    plugin,
    active,
    pg_size_pretty(
        pg_wal_lsn_diff(pg_current_wal_lsn(), confirmed_flush_lsn)
    )                                                         AS confirmed_lag,
    pg_size_pretty(
        pg_wal_lsn_diff(pg_current_wal_lsn(), restart_lsn)
    )                                                         AS restart_lag,
    EXTRACT(EPOCH FROM (NOW() - pg_last_xact_replay_timestamp())) AS seconds_since_activity
FROM pg_replication_slots
WHERE slot_name = 'ai_pipeline_slot';

-- Alert if restart_lag exceeds a threshold (e.g., 1 GB)
SELECT
    slot_name,
    pg_wal_lsn_diff(pg_current_wal_lsn(), restart_lsn) AS lag_bytes
FROM pg_replication_slots
WHERE pg_wal_lsn_diff(pg_current_wal_lsn(), restart_lsn) > 1073741824;  -- 1 GB

Add an automatic safety valve: if the consumer has been inactive for longer than your retention policy allows, drop the slot rather than crash the database:

# slot_watchdog.py — monitor and protect against WAL bloat
import asyncio
import os
import logging
import psycopg

logger = logging.getLogger(__name__)

LAG_ALERT_BYTES = 512 * 1024 * 1024   # 512 MB — send alert
LAG_DROP_BYTES  = 2 * 1024 * 1024 * 1024  # 2 GB — drop slot automatically

async def check_slot_health():
    dsn = os.getenv('DATABASE_URL')
    async with await psycopg.AsyncConnection.connect(dsn) as conn:
        rows = await (
            await conn.execute(
                """
                SELECT
                    slot_name,
                    active,
                    pg_wal_lsn_diff(
                        pg_current_wal_lsn(), restart_lsn
                    ) AS lag_bytes
                FROM pg_replication_slots
                WHERE slot_name = 'ai_pipeline_slot'
                """
            )
        ).fetchall()

        for row in rows:
            slot_name, active, lag_bytes = row
            lag_bytes = lag_bytes or 0

            if not active and lag_bytes > LAG_DROP_BYTES:
                logger.critical(
                    f"Slot {slot_name} lag={lag_bytes:,} bytes exceeds drop threshold. "
                    f"Dropping slot to protect disk."
                )
                await conn.execute(
                    "SELECT pg_drop_replication_slot(%s)",
                    (slot_name,)
                )
                # Alert operations team — they will need to re-create the slot
                # and run a backfill to catch up on missed changes
                send_ops_alert(
                    f"Replication slot {slot_name} dropped due to WAL lag. "
                    f"Backfill required."
                )
            elif lag_bytes > LAG_ALERT_BYTES:
                logger.warning(
                    f"Slot {slot_name} lag={lag_bytes:,} bytes — consumer may be behind"
                )


def send_ops_alert(message: str):
    # Integrate with PagerDuty, OpsGenie, or your alerting system
    logger.critical(f"OPS ALERT: {message}")

Dead letter handling ensures failed embedding tasks don't silently disappear. Build a dead letter queue into the change events table and a recovery job that replays failures after fixing the underlying issue:

-- PostgreSQL: Dead letter queue — events that failed all retries
CREATE TABLE ai_dead_letter_events (
    dl_event_id     BIGSERIAL PRIMARY KEY,
    original_event  JSONB NOT NULL,   -- full copy of ai_change_events row
    failure_reason  TEXT NOT NULL,
    failed_at       TIMESTAMPTZ DEFAULT NOW(),
    replayed_at     TIMESTAMPTZ,
    replay_status   TEXT
);

-- Move terminally failed events to dead letter
INSERT INTO ai_dead_letter_events (original_event, failure_reason)
SELECT
    to_jsonb(e.*),
    e.error_message
FROM ai_change_events e
WHERE e.pipeline_status = 'failed'
  AND e.retry_count >= 3
  AND e.created_at < NOW() - INTERVAL '1 hour';

-- After inserting to dead letter, mark originals as archived
UPDATE ai_change_events
SET pipeline_status = 'archived'
WHERE pipeline_status = 'failed'
  AND retry_count >= 3
  AND created_at < NOW() - INTERVAL '1 hour';

-- Replay dead letter events after fixing the underlying issue
UPDATE ai_change_events
SET pipeline_status = 'pending',
    retry_count     = 0,
    error_message   = NULL
WHERE event_id IN (
    SELECT (original_event->>'event_id')::BIGINT
    FROM ai_dead_letter_events
    WHERE replayed_at IS NULL
);

UPDATE ai_dead_letter_events
SET replayed_at   = NOW(),
    replay_status = 'queued'
WHERE replayed_at IS NULL;

Partitioning the change events table extends its useful life. As the table grows, queries against pipeline_status become slower. Partition by created_at and drop old partitions rather than running expensive deletes:

-- PostgreSQL: Convert ai_change_events to a partitioned table
-- (Best done at initial creation; retrofitting requires pg_partman or a cutover)

CREATE TABLE ai_change_events_partitioned (
    event_id        BIGSERIAL,
    event_type      TEXT NOT NULL,
    table_name      TEXT NOT NULL,
    record_id       TEXT NOT NULL,
    old_data        JSONB,
    new_data        JSONB,
    changed_columns TEXT[],
    pipeline_status TEXT DEFAULT 'pending',
    retry_count     INT DEFAULT 0,
    error_message   TEXT,
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    processed_at    TIMESTAMPTZ,
    PRIMARY KEY (event_id, created_at)
) PARTITION BY RANGE (created_at);

-- Create monthly partitions
CREATE TABLE ai_change_events_2025_01
    PARTITION OF ai_change_events_partitioned
    FOR VALUES FROM ('2025-01-01') TO ('2025-02-01');

CREATE TABLE ai_change_events_2025_02
    PARTITION OF ai_change_events_partitioned
    FOR VALUES FROM ('2025-02-01') TO ('2025-03-01');

-- Automate with pg_partman in production
-- Drop partitions older than retention policy:
DROP TABLE IF EXISTS ai_change_events_2024_10;

30.9 End-to-End Pipeline Verification

Before shipping to production, verify that every layer of the pipeline behaves correctly under controlled conditions. This test harness inserts a record, waits for the embedding to appear, and asserts correctness:

# test_cdc_pipeline.py — integration test for the full CDC → embedding flow
import asyncio
import hashlib
import json
import os
import time
import uuid

import psycopg
from psycopg.rows import dict_row


async def test_insert_triggers_embedding():
    """
    Verify that inserting a product record results in an embedding
    being generated within the expected latency window.
    """
    dsn = os.getenv('DATABASE_URL', 'postgresql://postgres@localhost/myapp')
    product_id = str(uuid.uuid4())
    max_wait_seconds = 30
    poll_interval = 0.5

    async with await psycopg.AsyncConnection.connect(dsn, row_factory=dict_row) as conn:
        # Insert a test product
        await conn.execute(
            """
            INSERT INTO products (product_id, sku, name, description, category, price)
            VALUES (%s::uuid, %s, %s, %s, %s, %s)
            """,
            (
                product_id,
                f"TEST-{product_id[:8]}",
                "Widget Pro 3000",
                "A high-performance widget for demanding applications.",
                "Tools",
                49.99
            )
        )
        insert_time = time.monotonic()

        # Poll until embedding appears or timeout
        embedding_found = False
        for _ in range(int(max_wait_seconds / poll_interval)):
            await asyncio.sleep(poll_interval)
            row = await (
                await conn.execute(
                    """
                    SELECT product_id, source_hash, embedding_model,
                           EXTRACT(EPOCH FROM (updated_at - %s::timestamptz)) AS latency_s
                    FROM product_embeddings
                    WHERE product_id = %s::uuid
                    """,
                    (f"now() - interval '{max_wait_seconds} seconds'", product_id)
                )
            ).fetchone()

            if row:
                embedding_found = True
                latency = time.monotonic() - insert_time
                print(
                    f"✓ Embedding generated in {latency:.2f}s "
                    f"(model={row['embedding_model']}, "
                    f"hash={row['source_hash'][:8]}...)"
                )
                break

        assert embedding_found, (
            f"No embedding found for product {product_id} "
            f"after {max_wait_seconds}s"
        )

        # Verify change event was marked completed
        event = await (
            await conn.execute(
                """
                SELECT pipeline_status, retry_count
                FROM ai_change_events
                WHERE table_name = 'products'
                  AND record_id = %s
                ORDER BY created_at DESC
                LIMIT 1
                """,
                (product_id,)
            )
        ).fetchone()

        assert event is not None, "No change event recorded"
        assert event['pipeline_status'] == 'completed', (
            f"Expected 'completed', got '{event['pipeline_status']}'"
        )
        assert event['retry_count'] == 0, (
            f"Expected 0 retries, got {event['retry_count']}"
        )

        # Clean up
        await conn.execute(
            "DELETE FROM products WHERE product_id = %s::uuid",
            (product_id,)
        )
        print("✓ Cleanup complete")


async def test_update_only_refreshes_on_sensitive_columns():
    """
    Verify that updating a non-embedding-sensitive column (price)
    does NOT trigger a new embedding call.
    """
    dsn = os.getenv('DATABASE_URL', 'postgresql://postgres@localhost/myapp')
    product_id = str(uuid.uuid4())

    async with await psycopg.AsyncConnection.connect(dsn, row_factory=dict_row) as conn:
        await conn.execute(
            """
            INSERT INTO products (product_id, sku, name, description, category, price)
            VALUES (%s::uuid, %s, %s, %s, %s, %s)
            """,
            (product_id, f"TEST-{product_id[:8]}", "Test Widget",
             "Description for testing.", "Test", 10.00)
        )

        # Wait for initial embedding
        await asyncio.sleep(5)

        initial_embed = await (
            await conn.execute(
                "SELECT source_hash, updated_at FROM product_embeddings "
                "WHERE product_id = %s::uuid",
                (product_id,)
            )
        ).fetchone()
        assert initial_embed, "Initial embedding not created"

        # Update a non-sensitive column
        await conn.execute(
            "UPDATE products SET price = 12.99 WHERE product_id = %s::uuid",
            (product_id,)
        )

        await asyncio.sleep(5)

        updated_embed = await (
            await conn.execute(
                "SELECT source_hash, updated_at FROM product_embeddings "
                "WHERE product_id = %s::uuid",
                (product_id,)
            )
        ).fetchone()

        assert updated_embed['source_hash'] == initial_embed['source_hash'], (
            "Embedding hash changed after non-sensitive column update — "
            "unnecessary API call was made"
        )
        print("✓ Price-only update did not trigger embedding refresh")

        await conn.execute(
            "DELETE FROM products WHERE product_id = %s::uuid",
            (product_id,)
        )


if __name__ == '__main__':
    asyncio.run(test_insert_triggers_embedding())
    asyncio.run(test_update_only_refreshes_on_sensitive_columns())
    print("\nAll CDC pipeline tests passed.")

Run these tests against a staging environment that mirrors production topology — including PgBouncer, Celery workers, and a live embedding API (or a local mock). Tests that only touch the database without the full pipeline will miss integration failures.

Key Takeaways

  • → **PostgreSQL offers two CDC primitives for AI pipelines**: logical replication via WAL provides durable, ordered, high-volume change streams suitable for batch embedding pipelines, while `pg_notify` provides sub-millisecond notification latency for real-time feature invalidation — choose based on your latency and throughput requirements, and use both where the use cases differ within the same application.
  • → **Idempotency and hash-based staleness detection are foundational**: before calling any embedding API, compute the SHA-256 hash of the source text and compare it against the stored hash; this single check eliminates redundant API calls during retries, bulk updates, and consumer restarts, and directly reduces operational cost at scale.
  • → **Debouncing is essential for high-frequency update sources**: when a record can change dozens of times per second (rich-text editors, streaming sensor data, high-write transactional tables), buffering notifications and processing only the most recent state within a time window prevents API storms without sacrificing eventual consistency.
  • → **WAL lag from inactive replication slots is a production availability risk**: an unconsumed slot causes PostgreSQL to retain WAL indefinitely; instrument lag monitoring from day one, set thresholds for alerting and automatic slot teardown, and always plan a backfill path so that dropping a slot to protect disk does not permanently lose change history.
  • → **SQL Server provides equivalent CDC primitives with different trade-offs**: CDC via transaction log capture gives you full before/after row state at the cost of log reader overhead, while Change Tracking gives you lighter-weight change detection with only current state — pair either mechanism with Service Broker activation for near-real-time pipeline dispatch, mirroring the `pg_notify` pattern on the PostgreSQL side.
