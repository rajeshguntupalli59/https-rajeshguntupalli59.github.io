Chapter 17: Knowledge Base Updates: Incremental Indexing

A knowledge base that never changes is a liability. Documents get updated, records become stale, new content arrives continuously, and the embeddings that power your RAG pipeline need to reflect the current state of your data — not last Tuesday's snapshot. This chapter covers how to build an incremental indexing system where PostgreSQL drives change detection, queuing, re-embedding, and vector store maintenance without full reprocessing. You will build pipelines that are correct under concurrent load, cost-efficient with embedding API calls, and observable enough that you know exactly what your knowledge base contains and when it was last synchronized.

---

17.1 The Problem with Batch Re-indexing

Most RAG systems start with a one-time indexing script. You dump your documents, call the embeddings API in batches, insert rows into a chunks table with a pgvector column, and ship. This works fine for a static corpus. The moment your content changes — a support article is revised, a product is discontinued, a policy document is superseded — you face a choice: re-index everything or build something smarter.

Re-indexing everything is expensive in three ways: embedding API costs scale linearly with corpus size, indexing jobs consume database I/O that affects production queries, and there is always a window where your search results return stale or contradictory information. A 500,000-chunk corpus at text-embedding-3-small pricing costs roughly $10 per full re-index. Run that nightly and it adds up; run it hourly and it becomes untenable.

The smarter approach treats knowledge base updates as a stream of events. Each time a source document changes, only the affected chunks get re-embedded. The rest of the corpus remains intact. This is incremental indexing, and PostgreSQL is unusually well-suited to implement it because it already owns your source data, has native change notification via pg_notify, and supports the row-level bookkeeping you need through triggers, audit tables, and JSONB metadata.

The schema design starts with separating concerns cleanly.

-- Core tables for an incremental indexing system

CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- Source documents: the raw content before chunking
CREATE TABLE documents (
    id              UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    source_uri      TEXT NOT NULL UNIQUE,          -- file path, URL, S3 key, etc.
    title           TEXT,
    content_hash    TEXT NOT NULL,                  -- SHA-256 of raw content
    raw_content     TEXT NOT NULL,
    metadata        JSONB NOT NULL DEFAULT '{}',
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    indexed_at      TIMESTAMPTZ,                    -- NULL = never indexed
    index_version   INTEGER NOT NULL DEFAULT 0,
    status          TEXT NOT NULL DEFAULT 'pending'
        CHECK (status IN ('pending', 'indexing', 'indexed', 'failed', 'deleted'))
);

CREATE INDEX idx_documents_status ON documents (status);
CREATE INDEX idx_documents_content_hash ON documents (content_hash);
CREATE INDEX idx_documents_indexed_at ON documents (indexed_at) WHERE indexed_at IS NOT NULL;

-- Chunks: the indexed units your retrieval system searches
CREATE TABLE document_chunks (
    id              UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    document_id     UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    chunk_index     INTEGER NOT NULL,               -- position within document
    chunk_text      TEXT NOT NULL,
    chunk_hash      TEXT NOT NULL,                  -- SHA-256 of chunk_text
    embedding       VECTOR(1536),                   -- OpenAI text-embedding-3-small
    token_count     INTEGER,
    metadata        JSONB NOT NULL DEFAULT '{}',
    embedded_at     TIMESTAMPTZ,
    embedding_model TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (document_id, chunk_index)
);

CREATE INDEX idx_chunks_document_id ON document_chunks (document_id);
CREATE INDEX idx_chunks_embedding ON document_chunks
    USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 64);
CREATE INDEX idx_chunks_chunk_hash ON document_chunks (chunk_hash);

-- Indexing queue: work items for the ingestion worker
CREATE TABLE indexing_queue (
    id              BIGSERIAL PRIMARY KEY,
    document_id     UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    operation       TEXT NOT NULL CHECK (operation IN ('index', 'reindex', 'delete')),
    priority        INTEGER NOT NULL DEFAULT 5,     -- lower = higher priority
    payload         JSONB NOT NULL DEFAULT '{}',
    scheduled_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    started_at      TIMESTAMPTZ,
    completed_at    TIMESTAMPTZ,
    attempts        INTEGER NOT NULL DEFAULT 0,
    last_error      TEXT,
    status          TEXT NOT NULL DEFAULT 'pending'
        CHECK (status IN ('pending', 'processing', 'completed', 'failed', 'cancelled'))
);

CREATE INDEX idx_queue_status_priority ON indexing_queue (status, priority, scheduled_at)
    WHERE status = 'pending';
CREATE INDEX idx_queue_document_id ON indexing_queue (document_id);

This schema separates the source document (documents), the indexed chunks (document_chunks), and the work queue (indexing_queue). The content_hash column on documents is what makes incremental indexing possible: you compare the incoming hash against the stored hash, and only queue a reindex when they differ.

17.2 Change Detection with Triggers and pg_notify

PostgreSQL triggers give you change detection at the database layer, below the application. Any process that updates a document — a sync job, a CMS webhook, a user edit — automatically fires the trigger without the application needing to know about the indexing system.

-- Trigger function: detect changes and queue indexing work
CREATE OR REPLACE FUNCTION fn_document_change_trigger()
RETURNS TRIGGER AS $$
DECLARE
    v_operation TEXT;
    v_queue_id  BIGINT;
    v_payload   JSONB;
BEGIN
    IF TG_OP = 'DELETE' THEN
        -- Document deleted: queue a cleanup operation
        INSERT INTO indexing_queue (document_id, operation, priority, payload)
        VALUES (OLD.id, 'delete', 1, jsonb_build_object(
            'source_uri', OLD.source_uri,
            'deleted_at', NOW()
        ));

        -- Notify workers immediately
        PERFORM pg_notify(
            'indexing_events',
            jsonb_build_object(
                'operation', 'delete',
                'document_id', OLD.id,
                'source_uri', OLD.source_uri
            )::text
        );
        RETURN OLD;
    END IF;

    IF TG_OP = 'INSERT' THEN
        v_operation := 'index';
    ELSIF TG_OP = 'UPDATE' THEN
        -- Only reindex if content actually changed
        IF OLD.content_hash = NEW.content_hash THEN
            RETURN NEW;  -- metadata-only update, no reindex needed
        END IF;
        v_operation := 'reindex';
        -- Cancel any pending queue items for this document
        UPDATE indexing_queue
        SET status = 'cancelled'
        WHERE document_id = NEW.id
          AND status = 'pending';
    END IF;

    v_payload := jsonb_build_object(
        'source_uri',     NEW.source_uri,
        'content_hash',   NEW.content_hash,
        'operation',      v_operation,
        'triggered_at',   NOW()
    );

    INSERT INTO indexing_queue (document_id, operation, priority, payload)
    VALUES (NEW.id, v_operation, 5, v_payload)
    RETURNING id INTO v_queue_id;

    -- Update document status
    UPDATE documents SET status = 'pending' WHERE id = NEW.id;

    -- Notify async workers via pg_notify
    PERFORM pg_notify(
        'indexing_events',
        jsonb_build_object(
            'queue_id',    v_queue_id,
            'operation',   v_operation,
            'document_id', NEW.id
        )::text
    );

    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- Attach triggers to the documents table
CREATE TRIGGER trg_document_insert
    AFTER INSERT ON documents
    FOR EACH ROW EXECUTE FUNCTION fn_document_change_trigger();

CREATE TRIGGER trg_document_update
    AFTER UPDATE ON documents
    FOR EACH ROW EXECUTE FUNCTION fn_document_change_trigger();

CREATE TRIGGER trg_document_delete
    BEFORE DELETE ON documents
    FOR EACH ROW EXECUTE FUNCTION fn_document_change_trigger();

-- Function to auto-update updated_at
CREATE OR REPLACE FUNCTION fn_set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at := NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_documents_updated_at
    BEFORE UPDATE ON documents
    FOR EACH ROW EXECUTE FUNCTION fn_set_updated_at();

-- View to monitor queue health at a glance
CREATE VIEW v_indexing_queue_stats AS
SELECT
    operation,
    status,
    COUNT(*) AS count,
    MIN(scheduled_at) AS oldest_item,
    AVG(EXTRACT(EPOCH FROM (completed_at - started_at)))
        FILTER (WHERE completed_at IS NOT NULL) AS avg_processing_seconds
FROM indexing_queue
GROUP BY operation, status
ORDER BY operation, status;

The trigger has one subtle but important behavior: when a document is updated, it cancels any existing pending queue items before inserting a new one. Without this, a document that changes five times in quick succession will generate five reindex jobs when only the final state matters.

The pg_notify call is what makes the system responsive. Workers listening on the indexing_events channel wake up within milliseconds of a change rather than polling the queue table on a fixed interval.

17.3 The Ingestion Worker

The ingestion worker is where the actual embedding work happens. It listens for notifications, claims queue items using SELECT ... FOR UPDATE SKIP LOCKED to prevent concurrent workers from double-processing, chunks the document text, calls the embeddings API, and writes results back to PostgreSQL. Celery handles distribution and retries.

# worker/ingestion_worker.py
# Celery-based ingestion worker with pg_notify listener

import asyncio
import hashlib
import json
import logging
import os
import select
import textwrap
from datetime import datetime, timezone
from typing import Generator

import psycopg2
import psycopg2.extras
from celery import Celery
from openai import OpenAI
import tiktoken

logger = logging.getLogger(__name__)

DATABASE_URL = os.environ["DATABASE_URL"]
OPENAI_API_KEY = os.environ["OPENAI_API_KEY"]
EMBEDDING_MODEL = "text-embedding-3-small"
EMBEDDING_DIMENSIONS = 1536
MAX_CHUNK_TOKENS = 512
CHUNK_OVERLAP_TOKENS = 64

# Celery setup with Redis as broker
celery_app = Celery(
    "ingestion",
    broker=os.environ.get("REDIS_URL", "redis://localhost:6379/0"),
    backend=os.environ.get("REDIS_URL", "redis://localhost:6379/0"),
)

celery_app.conf.update(
    task_serializer="json",
    result_serializer="json",
    accept_content=["json"],
    task_acks_late=True,           # Only ack after successful completion
    worker_prefetch_multiplier=1,  # One task at a time per worker
    task_max_retries=3,
)

openai_client = OpenAI(api_key=OPENAI_API_KEY)
tokenizer = tiktoken.encoding_for_model("text-embedding-3-small")


def get_db_connection():
    return psycopg2.connect(DATABASE_URL, cursor_factory=psycopg2.extras.RealDictCursor)


def chunk_text(text: str, max_tokens: int = MAX_CHUNK_TOKENS,
               overlap_tokens: int = CHUNK_OVERLAP_TOKENS) -> Generator[str, None, None]:
    """
    Split text into overlapping chunks by token count.
    Tries to split on sentence boundaries within the token budget.
    """
    tokens = tokenizer.encode(text)
    total_tokens = len(tokens)

    if total_tokens <= max_tokens:
        yield text
        return

    start = 0
    while start < total_tokens:
        end = min(start + max_tokens, total_tokens)
        chunk_tokens = tokens[start:end]
        chunk_text_decoded = tokenizer.decode(chunk_tokens)

        # Try to end on a sentence boundary if we're not at the end
        if end < total_tokens:
            last_period = chunk_text_decoded.rfind(". ")
            last_newline = chunk_text_decoded.rfind("\n\n")
            boundary = max(last_period, last_newline)
            if boundary > len(chunk_text_decoded) * 0.5:
                chunk_text_decoded = chunk_text_decoded[: boundary + 1]

        yield chunk_text_decoded.strip()
        # Advance by max_tokens minus overlap
        start += max_tokens - overlap_tokens


def compute_hash(text: str) -> str:
    return hashlib.sha256(text.encode("utf-8")).hexdigest()


def embed_texts(texts: list[str]) -> list[list[float]]:
    """Call OpenAI embeddings API with batching."""
    all_embeddings = []
    batch_size = 100  # OpenAI allows up to 2048 inputs but we keep batches small

    for i in range(0, len(texts), batch_size):
        batch = texts[i : i + batch_size]
        response = openai_client.embeddings.create(
            input=batch,
            model=EMBEDDING_MODEL,
            dimensions=EMBEDDING_DIMENSIONS,
        )
        batch_embeddings = [item.embedding for item in response.data]
        all_embeddings.extend(batch_embeddings)

    return all_embeddings


@celery_app.task(bind=True, max_retries=3, default_retry_delay=60)
def process_indexing_job(self, queue_id: int):
    """
    Main indexing task. Claims a queue item, processes the document,
    and updates the database with results.
    """
    conn = get_db_connection()
    try:
        with conn:
            with conn.cursor() as cur:
                # Claim the queue item atomically
                cur.execute(
                    """
                    UPDATE indexing_queue
                    SET status = 'processing',
                        started_at = NOW(),
                        attempts = attempts + 1
                    WHERE id = %s
                      AND status IN ('pending', 'failed')
                    RETURNING id, document_id, operation, payload
                    """,
                    (queue_id,),
                )
                row = cur.fetchone()

                if not row:
                    logger.warning(f"Queue item {queue_id} not claimable (already processing or done)")
                    return

                document_id = str(row["document_id"])
                operation = row["operation"]

                if operation == "delete":
                    _handle_delete(cur, document_id)
                elif operation in ("index", "reindex"):
                    _handle_index(cur, document_id, operation)

                # Mark queue item complete
                cur.execute(
                    """
                    UPDATE indexing_queue
                    SET status = 'completed', completed_at = NOW()
                    WHERE id = %s
                    """,
                    (queue_id,),
                )

    except Exception as exc:
        logger.exception(f"Failed to process queue item {queue_id}: {exc}")
        with conn:
            with conn.cursor() as cur:
                cur.execute(
                    """
                    UPDATE indexing_queue
                    SET status = 'failed',
                        last_error = %s
                    WHERE id = %s
                    """,
                    (str(exc), queue_id),
                )
        # Retry with exponential backoff
        raise self.retry(exc=exc, countdown=60 * (2 ** self.request.retries))
    finally:
        conn.close()


def _handle_delete(cur, document_id: str):
    """Remove all chunks for a deleted document."""
    cur.execute(
        "DELETE FROM document_chunks WHERE document_id = %s",
        (document_id,)
    )
    deleted = cur.rowcount
    logger.info(f"Deleted {deleted} chunks for document {document_id}")


def _handle_index(cur, document_id: str, operation: str):
    """Chunk a document and embed only the chunks that changed."""
    # Fetch the document
    cur.execute(
        "SELECT id, raw_content, content_hash, metadata FROM documents WHERE id = %s",
        (document_id,),
    )
    doc = cur.fetchone()
    if not doc:
        raise ValueError(f"Document {document_id} not found")

    # Fetch existing chunk hashes for diffing
    cur.execute(
        """
        SELECT chunk_index, chunk_hash, id
        FROM document_chunks
        WHERE document_id = %s
        ORDER BY chunk_index
        """,
        (document_id,),
    )
    existing_chunks = {row["chunk_index"]: row for row in cur.fetchall()}

    # Generate new chunks
    new_chunks = list(chunk_text(doc["raw_content"]))
    new_chunk_hashes = [compute_hash(c) for c in new_chunks]

    # Determine which chunks actually changed
    chunks_to_embed = []
    chunks_to_embed_indices = []
    for idx, (text, hash_val) in enumerate(zip(new_chunks, new_chunk_hashes)):
        existing = existing_chunks.get(idx)
        if existing is None or existing["chunk_hash"] != hash_val:
            chunks_to_embed.append(text)
            chunks_to_embed_indices.append(idx)

    logger.info(
        f"Document {document_id}: {len(new_chunks)} chunks total, "
        f"{len(chunks_to_embed)} need embedding"
    )

    # Embed only changed chunks
    if chunks_to_embed:
        embeddings = embed_texts(chunks_to_embed)
    else:
        embeddings = []

    embedding_map = dict(zip(chunks_to_embed_indices, embeddings))

    # Delete chunks that no longer exist (document got shorter)
    indices_to_keep = list(range(len(new_chunks)))
    if existing_chunks:
        cur.execute(
            """
            DELETE FROM document_chunks
            WHERE document_id = %s
              AND chunk_index > %s
            """,
            (document_id, len(new_chunks) - 1),
        )

    # Upsert each chunk
    for idx, (text, hash_val) in enumerate(zip(new_chunks, new_chunk_hashes)):
        token_count = len(tokenizer.encode(text))
        embedding = embedding_map.get(idx)
        embedding_str = f"[{','.join(str(v) for v in embedding)}]" if embedding else None

        cur.execute(
            """
            INSERT INTO document_chunks
                (document_id, chunk_index, chunk_text, chunk_hash,
                 embedding, token_count, embedded_at, embedding_model, metadata)
            VALUES (%s, %s, %s, %s, %s::vector, %s, %s, %s, %s)
            ON CONFLICT (document_id, chunk_index) DO UPDATE SET
                chunk_text      = EXCLUDED.chunk_text,
                chunk_hash      = EXCLUDED.chunk_hash,
                embedding       = COALESCE(EXCLUDED.embedding, document_chunks.embedding),
                token_count     = EXCLUDED.token_count,
                embedded_at     = COALESCE(EXCLUDED.embedded_at, document_chunks.embedded_at),
                embedding_model = COALESCE(EXCLUDED.embedding_model, document_chunks.embedding_model),
                metadata        = EXCLUDED.metadata
            """,
            (
                document_id,
                idx,
                text,
                hash_val,
                embedding_str,
                token_count,
                datetime.now(timezone.utc) if embedding else None,
                EMBEDDING_MODEL if embedding else None,
                json.dumps(doc["metadata"]),
            ),
        )

    # Mark document as indexed
    cur.execute(
        """
        UPDATE documents
        SET status = 'indexed',
            indexed_at = NOW(),
            index_version = index_version + 1
        WHERE id = %s
        """,
        (document_id,),
    )


# pg_notify listener that dispatches Celery tasks
def run_notify_listener():
    """
    Long-running process that listens for pg_notify events
    and dispatches Celery tasks in response.
    """
    conn = psycopg2.connect(DATABASE_URL)
    conn.set_isolation_level(psycopg2.extensions.ISOLATION_LEVEL_AUTOCOMMIT)

    with conn.cursor() as cur:
        cur.execute("LISTEN indexing_events;")

    logger.info("Listening for indexing events on channel 'indexing_events'")

    while True:
        # Wait up to 30 seconds for a notification
        if select.select([conn], [], [], 30) == ([], [], []):
            # Timeout: poll for any missed queue items
            _poll_missed_items()
        else:
            conn.poll()
            while conn.notifies:
                notify = conn.notifies.pop(0)
                try:
                    payload = json.loads(notify.payload)
                    queue_id = payload.get("queue_id")
                    if queue_id:
                        process_indexing_job.apply_async(
                            args=[queue_id],
                            priority=payload.get("priority", 5),
                        )
                        logger.info(f"Dispatched task for queue_id={queue_id}")
                except Exception as exc:
                    logger.exception(f"Failed to dispatch task: {exc}")


def _poll_missed_items():
    """Catch any queue items that were missed (worker restart, etc.)."""
    conn = get_db_connection()
    try:
        with conn:
            with conn.cursor() as cur:
                cur.execute(
                    """
                    SELECT id FROM indexing_queue
                    WHERE status = 'pending'
                      AND scheduled_at < NOW() - INTERVAL '5 minutes'
                    ORDER BY priority, scheduled_at
                    LIMIT 50
                    """
                )
                for row in cur.fetchall():
                    process_indexing_job.apply_async(args=[row["id"]])
    finally:
        conn.close()


if __name__ == "__main__":
    logging.basicConfig(level=logging.INFO)
    run_notify_listener()

The ON CONFLICT DO UPDATE SET embedding = COALESCE(EXCLUDED.embedding, document_chunks.embedding) pattern is worth explaining. When a chunk's text has not changed, the upsert preserves the existing embedding rather than writing NULL. This means that if you need to update chunk metadata without touching the text, the embedding survives.

17.4 Conflict-Free Re-indexing Under Concurrent Load

Production knowledge bases see concurrent writes. Multiple sync jobs, webhook handlers, and user actions can modify documents simultaneously. The naive queue approach fails here: two workers might both claim the same document, embed it twice, and race to write results. PostgreSQL's locking primitives solve this cleanly.

--Function to safely claim the next available queue item
CREATE OR REPLACE FUNCTION fn_claim_queue_item(p_worker_id TEXT)
RETURNS TABLE (
    queue_id    BIGINT,
    document_id UUID,
    operation   TEXT,
    payload     JSONB
) AS $$
BEGIN
    RETURN QUERY
    UPDATE indexing_queue q
    SET status     = 'processing',
        started_at = NOW(),
        attempts   = attempts + 1,
        payload    = payload || jsonb_build_object('worker_id', p_worker_id)
    FROM (
        SELECT id
        FROM indexing_queue
        WHERE status = 'pending'
          AND scheduled_at <= NOW()
        ORDER BY priority ASC, scheduled_at ASC
        LIMIT 1
        FOR UPDATE SKIP LOCKED
    ) sub
    WHERE q.id = sub.id
    RETURNING q.id, q.document_id, q.operation, q.payload;
END;
$$ LANGUAGE plpgsql;

-- Function to detect and recover stalled items (worker crashed mid-job)
CREATE OR REPLACE FUNCTION fn_recover_stalled_items(p_stall_threshold_minutes INTEGER DEFAULT 15)
RETURNS INTEGER AS $$
DECLARE
    v_recovered INTEGER;
BEGIN
    UPDATE indexing_queue
    SET status     = 'pending',
        started_at = NULL,
        last_error = FORMAT(
            'Recovered from stall after %s minutes (attempt %s)',
            p_stall_threshold_minutes,
            attempts
        )
    WHERE status = 'processing'
      AND started_at < NOW() - (p_stall_threshold_minutes || ' minutes')::INTERVAL
      AND attempts < 3;

    GET DIAGNOSTICS v_recovered = ROW_COUNT;

    -- Permanently fail items that have exceeded retry limit
    UPDATE indexing_queue
    SET status     = 'failed',
        last_error = FORMAT('Exceeded maximum attempts (%s)', attempts)
    WHERE status = 'processing'
      AND started_at < NOW() - (p_stall_threshold_minutes || ' minutes')::INTERVAL
      AND attempts >= 3;

    RETURN v_recovered;
END;
$$ LANGUAGE plpgsql;

-- Prevent duplicate pending items for the same document+operation
CREATE UNIQUE INDEX idx_queue_dedup
    ON indexing_queue (document_id, operation)
    WHERE status = 'pending';

The partial unique index WHERE status = 'pending' is the concurrency safety net. No matter how many processes try to enqueue the same document, the database enforces exactly one pending item per document-operation combination. The trigger's cancel-and-reinsert pattern works precisely because this constraint allows only one pending row: the UPDATE ... SET status = 'cancelled' removes the uniqueness conflict before the new INSERT runs.

On the SQL Server side, the equivalent pattern uses WITH (UPDLOCK, READPAST) hints rather than FOR UPDATE SKIP LOCKED:

-- SQL Server equivalent: safe queue claim with READPAST
-- Requires a queue table equivalent to indexing_queue

CREATE OR ALTER PROCEDURE dbo.usp_ClaimQueueItem
    @WorkerId NVARCHAR(100)
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @ClaimedId BIGINT;

    BEGIN TRANSACTION;

    SELECT TOP 1 @ClaimedId = id
    FROM dbo.indexing_queue WITH (UPDLOCK, READPAST)
    WHERE status = N'pending'
      AND scheduled_at <= GETUTCDATE()
    ORDER BY priority ASC, scheduled_at ASC;

    IF @ClaimedId IS NOT NULL
    BEGIN
        UPDATE dbo.indexing_queue
        SET status     = N'processing',
            started_at = GETUTCDATE(),
            attempts   = attempts + 1,
            payload    = JSON_MODIFY(payload, '$.worker_id', @WorkerId)
        WHERE id = @ClaimedId;

        SELECT id         AS queue_id,
               document_id,
               operation,
               payload
        FROM dbo.indexing_queue
        WHERE id = @ClaimedId;
    END

    COMMIT TRANSACTION;
END;
GO

-- SQL Server: recover stalled items
CREATE OR ALTER PROCEDURE dbo.usp_RecoverStalledItems
    @StallThresholdMinutes INT = 15
AS
BEGIN
    SET NOCOUNT ON;

    UPDATE dbo.indexing_queue
    SET status     = N'pending',
        started_at = NULL,
        last_error = CONCAT(
            N'Recovered from stall after ', @StallThresholdMinutes,
            N' minutes (attempt ', CAST(attempts AS NVARCHAR(10)), N')'
        )
    WHERE status = N'processing'
      AND started_at < DATEADD(MINUTE, -@StallThresholdMinutes, GETUTCDATE())
      AND attempts < 3;

    UPDATE dbo.indexing_queue
    SET status     = N'failed',
        last_error = CONCAT(N'Exceeded maximum attempts (', CAST(attempts AS NVARCHAR(10)), N')')
    WHERE status = N'processing'
      AND started_at < DATEADD(MINUTE, -@StallThresholdMinutes, GETUTCDATE())
      AND attempts >= 3;
END;
GO

Both approaches achieve the same goal: exactly-once processing under concurrent workers, with automatic recovery from crashes. The PostgreSQL version is more composable — SKIP LOCKED works inside any query, not just stored procedures — but the pattern of lock-then-update is identical.

17.5 Hash-Based Diffing: Avoiding Redundant API Calls

The content hash comparison in the trigger handles the document level, but embedding costs are determined at the chunk level. A document with a hundred chunks where only one paragraph changed should generate exactly one embedding API call, not a hundred.

The worker already implements this with the per-chunk hash comparison in _handle_index. This section formalizes the diffing strategy and adds an important optimization: chunk-level deduplication across documents.

If your knowledge base contains duplicate or near-duplicate content across documents — a legal disclaimer repeated in fifty contracts, a standard introduction in every support article — you should not embed the same text multiple times. A chunk hash cache lets you look up an embedding by hash and reuse it.

-- Embedding cache: store embeddings by content hash
-- This table is append-only; hashes are immutable
CREATE TABLE embedding_cache (
    chunk_hash      TEXT PRIMARY KEY,
    embedding       VECTOR(1536) NOT NULL,
    embedding_model TEXT NOT NULL,
    token_count     INTEGER,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    hit_count       INTEGER NOT NULL DEFAULT 0
);

-- Index for the cache itself (lookup by hash is the PK, but we also want
-- analytics on hit_count and cleanup of stale model versions)
CREATE INDEX idx_cache_model ON embedding_cache (embedding_model);

-- Function to look up or register a cache hit
CREATE OR REPLACE FUNCTION fn_cache_lookup(p_chunk_hash TEXT)
RETURNS TABLE (embedding VECTOR(1536), model TEXT) AS $$
BEGIN
    UPDATE embedding_cache
    SET hit_count = hit_count + 1
    WHERE chunk_hash = p_chunk_hash;

    RETURN QUERY
    SELECT ec.embedding, ec.embedding_model
    FROM embedding_cache ec
    WHERE ec.chunk_hash = p_chunk_hash;
END;
$$ LANGUAGE plpgsql;

-- View: cache efficiency report
CREATE VIEW v_embedding_cache_stats AS
SELECT
    embedding_model,
    COUNT(*)                            AS cached_embeddings,
    SUM(hit_count)                      AS total_cache_hits,
    SUM(hit_count) * 1.0 / NULLIF(COUNT(*) + SUM(hit_count), 0)
                                        AS hit_rate,
    pg_size_pretty(
        SUM(octet_length(embedding::text))::BIGINT
    )                                   AS approx_storage
FROM embedding_cache
GROUP BY embedding_model;

Now update the Python worker to consult this cache before calling the API:

# worker/embedding_cache.py

def embed_texts_with_cache(
    texts: list[str],
    hashes: list[str],
    cur,  # psycopg2 cursor
) -> list[list[float]]:
    """
    Embed a list of texts, using the database cache to skip
    texts whose hash is already known.
    """
    result_map: dict[int, list[float]] = {}
    uncached_indices: list[int] = []
    uncached_texts: list[str] = []

    # Batch lookup in cache
    cur.execute(
        """
        SELECT chunk_hash, embedding
        FROM embedding_cache
        WHERE chunk_hash = ANY(%s)
          AND embedding_model = %s
        """,
        (hashes, EMBEDDING_MODEL),
    )
    cache_hits = {row["chunk_hash"]: row["embedding"] for row in cur.fetchall()}

    # Update hit counts in bulk
    if cache_hits:
        cur.execute(
            """
            UPDATE embedding_cache
            SET hit_count = hit_count + 1
            WHERE chunk_hash = ANY(%s)
            """,
            (list(cache_hits.keys()),),
        )

    for idx, (text, hash_val) in enumerate(zip(texts, hashes)):
        if hash_val in cache_hits:
            result_map[idx] = cache_hits[hash_val]
        else:
            uncached_indices.append(idx)
            uncached_texts.append(text)

    logger.info(
        f"Cache: {len(cache_hits)} hits, {len(uncached_texts)} misses "
        f"out of {len(texts)} chunks"
    )

    # Call API only for cache misses
    if uncached_texts:
        new_embeddings = embed_texts(uncached_texts)

        # Store new embeddings in cache
        cache_rows = []
        for i, (text, embedding) in enumerate(zip(uncached_texts, new_embeddings)):
            original_idx = uncached_indices[i]
            result_map[original_idx] = embedding
            cache_rows.append((
                hashes[uncached_indices[i]],
                f"[{','.join(str(v) for v in embedding)}]",
                EMBEDDING_MODEL,
                len(tokenizer.encode(text)),
            ))

        # Bulk insert into cache (ignore conflicts — another worker may have
        # inserted the same hash concurrently)
        psycopg2.extras.execute_values(
            cur,
            """
            INSERT INTO embedding_cache (chunk_hash, embedding, embedding_model, token_count)
            VALUES %s
            ON CONFLICT (chunk_hash) DO NOTHING
            """,
            cache_rows,
            template="(%s, %s::vector, %s, %s)",
        )

    # Return in original order
    return [result_map[i] for i in range(len(texts))]

The ON CONFLICT DO NOTHING on cache insertion handles the race condition where two workers simultaneously embed the same chunk. One wins, the other silently discards its result. The embedding stored is identical regardless of which worker wins, so consistency is preserved.

17.6 Monitoring Freshness and Index Lag

An incremental indexing system that silently falls behind is worse than one that fails loudly. You need metrics that answer: how many documents are waiting to be indexed, how old is the oldest unprocessed item, and which documents have never been indexed at all.

-- Comprehensive freshness dashboard
CREATE VIEW v_indexing_freshness AS
WITH queue_summary AS (
    SELECT
        status,
        COUNT(*) AS count,
        MIN(scheduled_at) AS oldest_scheduled,
        MAX(attempts) AS max_attempts
    FROM indexing_queue
    WHERE status IN ('pending', 'processing', 'failed')
    GROUP BY status
),
document_summary AS (
    SELECT
        status,
        COUNT(*) AS count,
        MAX(updated_at) AS most_recent_update,
        MIN(indexed_at) AS oldest_indexed,
        COUNT(*) FILTER (WHERE indexed_at IS NULL) AS never_indexed,
        COUNT(*) FILTER (
            WHERE indexed_at IS NOT NULL
              AND updated_at > indexed_at
        ) AS stale_indexed
    FROM documents
    GROUP BY status
)
SELECT
    'queue'         AS category,
    qs.status       AS sub_category,
    qs.count,
    qs.oldest_scheduled AS reference_time,
    EXTRACT(EPOCH FROM (NOW() - qs.oldest_scheduled)) / 60
                    AS lag_minutes,
    qs.max_attempts AS extra_info_int,
    NULL::TEXT      AS extra_info_text
FROM queue_summary qs
UNION ALL
SELECT
    'documents'     AS category,
    ds.status       AS sub_category,
    ds.count,
    ds.most_recent_update AS reference_time,
    NULL            AS lag_minutes,
    ds.never_indexed AS extra_info_int,
    ds.stale_indexed::TEXT AS extra_info_text
FROM document_summary ds
ORDER BY category, sub_category;

-- Alert query: documents that should have been indexed but weren't
CREATE OR REPLACE FUNCTION fn_check_indexing_health()
RETURNS TABLE (
    check_name      TEXT,
    severity        TEXT,
    count           BIGINT,
    details         TEXT
) AS $$
BEGIN
    -- Check 1: Pending items older than 10 minutes
    RETURN QUERY
    SELECT
        'stale_pending_queue_items'::TEXT,
        CASE WHEN COUNT(*) > 100 THEN 'critical'
             WHEN COUNT(*) > 20  THEN 'warning'
             ELSE 'ok' END::TEXT,
        COUNT(*),
        FORMAT('%s items waiting more than 10 minutes', COUNT(*))
    FROM indexing_queue
    WHERE status = 'pending'
      AND scheduled_at < NOW() - INTERVAL '10 minutes';

    -- Check 2: Failed items that haven't been retried
    RETURN QUERY
    SELECT
        'failed_queue_items'::TEXT,
        CASE WHEN COUNT(*) > 0 THEN 'warning' ELSE 'ok' END::TEXT,
        COUNT(*),
        FORMAT('%s items permanently failed', COUNT(*))
    FROM indexing_queue
    WHERE status = 'failed';

    -- Check 3: Documents with stale embeddings
    RETURN QUERY
    SELECT
        'stale_documents'::TEXT,
        CASE WHEN COUNT(*) > 50 THEN 'warning' ELSE 'ok' END::TEXT,
        COUNT(*),
        FORMAT('%s documents updated after last index run', COUNT(*))
    FROM documents
    WHERE updated_at > indexed_at
      AND status NOT IN ('deleted', 'pending');

    -- Check 4: Documents with no embedding at all
    RETURN QUERY
    SELECT
        'unindexed_documents'::TEXT,
        CASE WHEN COUNT(*) > 0 THEN 'warning' ELSE 'ok' END::TEXT,
        COUNT(*),
        FORMAT('%s documents have never been indexed', COUNT(*))
    FROM documents
    WHERE indexed_at IS NULL
      AND status NOT IN ('deleted', 'pending', 'indexing');

    -- Check 5: Chunks with NULL embeddings
    RETURN QUERY
    SELECT
        'chunks_missing_embeddings'::TEXT,
        CASE WHEN COUNT(*) > 0 THEN 'critical' ELSE 'ok' END::TEXT,
        COUNT(*),
        FORMAT('%s chunks exist with no embedding vector', COUNT(*))
    FROM document_chunks
    WHERE embedding IS NULL;
END;
$$ LANGUAGE plpgsql;

Run SELECT * FROM fn_check_indexing_health() from your monitoring system (Datadog, Grafana, or a simple cron job) and alert on any row where severity != 'ok'. The five checks together cover queue backlog, permanent failures, stale content, never-indexed content, and the most dangerous state of all: chunks that exist in your vector store without embeddings, which will silently return wrong similarity scores.

-- Assumes equivalent tables: documents, indexing_queue, document_chunks

CREATE OR ALTER PROCEDURE dbo.usp_CheckIndexingHealth
AS

    SET NOCOUNT ON;

    -- Stale pending items

        COUNT(*),
        CONCAT(CAST(COUNT(*) AS NVARCHAR(20)), N' chunks exist with no embedding vector')
    FROM dbo.document_chunks
    WHERE embedding IS NULL;

17.7 Handling Document Deletion and Versioning

Deletion is trickier than it appears. When a document is deleted from the source system, you need to remove its chunks from the vector store — but you may also want to preserve a history of what was indexed for audit purposes. The soft-delete pattern handles both requirements.

-- Extend the documents table with soft-delete support
ALTER TABLE documents ADD COLUMN IF NOT EXISTS deleted_at TIMESTAMPTZ;

-- Function to soft-delete a document and queue chunk cleanup
CREATE OR REPLACE FUNCTION fn_soft_delete_document(p_document_id UUID)
RETURNS VOID AS $$
BEGIN
    UPDATE documents
    SET status     = 'deleted',
        deleted_at = NOW(),
        updated_at = NOW()
    WHERE id = p_document_id
      AND status != 'deleted';

    IF NOT FOUND THEN
        RAISE EXCEPTION 'Document % not found or already deleted', p_document_id;
    END IF;

    -- The UPDATE trigger will fire fn_document_change_trigger,
    -- but because content_hash didn't change, it won't queue a reindex.
    -- We need to explicitly queue the delete operation:
    INSERT INTO indexing_queue (document_id, operation, priority, payload)
    VALUES (
        p_document_id,
        'delete',
        1,
        jsonb_build_object('reason', 'soft_delete', 'deleted_at', NOW())
    )
    ON CONFLICT DO NOTHING;
END;
$$ LANGUAGE plpgsql;

-- Document version history: optional but valuable for audit trails
CREATE TABLE document_versions (
    id              BIGSERIAL PRIMARY KEY,
    document_id     UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    index_version   INTEGER NOT NULL,
    content_hash    TEXT NOT NULL,
    chunk_count     INTEGER,
    indexed_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    metadata        JSONB NOT NULL DEFAULT '{}'
);

CREATE INDEX idx_doc_versions_document ON document_versions (document_id, index_version DESC);

-- Trigger to record version history on each successful index
CREATE OR REPLACE FUNCTION fn_record_document_version()
RETURNS TRIGGER AS $$
BEGIN
    -- Fire when status changes to 'indexed'
    IF NEW.status = 'indexed' AND (OLD.status != 'indexed' OR OLD.index_version != NEW.index_version) THEN
        INSERT INTO document_versions (document_id, index_version, content_hash, indexed_at, metadata)
        SELECT
            NEW.id,
            NEW.index_version,
            NEW.content_hash,
            NOW(),
            jsonb_build_object(
                'chunk_count', (
                    SELECT COUNT(*) FROM document_chunks WHERE document_id = NEW.id
                ),
                'source_uri', NEW.source_uri
            );
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_document_version
    AFTER UPDATE ON documents
    FOR EACH ROW EXECUTE FUNCTION fn_record_document_version();

The version history table makes it possible to answer questions like "what did the knowledge base know about topic X before last Tuesday's update?" — a capability that becomes important when users report incorrect answers that trace back to recently changed documents.

17.8 Backpressure and Rate Limiting

Embedding API providers enforce rate limits measured in tokens per minute. A large batch of document updates — a site migration, an import from a legacy system — can exhaust your quota and cause the worker to fail with 429 errors. Backpressure in the queue prevents this.

# worker/rate_limiter.py

import time
import threading
from collections import deque


class TokenBucketRateLimiter:
    """
    Token bucket rate limiter for embedding API calls.
    Tracks tokens-per-minute to stay within provider limits.
    """
    def __init__(self, tokens_per_minute: int):
        self.tokens_per_minute = tokens_per_minute
        self.tokens_per_second = tokens_per_minute / 60.0
        self._lock = threading.Lock()
        self._usage_window: deque[tuple[float, int]] = deque()

    def wait_for_capacity(self, token_count: int) -> None:
        """Block until there is capacity to process token_count tokens."""
        while True:
            with self._lock:
                now = time.monotonic()
                window_start = now - 60.0

                # Remove usage records outside the 1-minute window
                while self._usage_window and self._usage_window[0][0] < window_start:
                    self._usage_window.popleft()

                tokens_used = sum(t for _, t in self._usage_window)
                available = self.tokens_per_minute - tokens_used

                if available >= token_count:
                    self._usage_window.append((now, token_count))
                    return

                # Calculate how long to wait for enough tokens to free up
                if self._usage_window:
                    oldest_ts, oldest_tokens = self._usage_window[0]
                    wait_seconds = (oldest_ts + 60.0) - now
                else:
                    wait_seconds = 0.1

            time.sleep(max(0.1, wait_seconds))


# Global limiter: text-embedding-3-small allows up to 1,000,000 TPM
# on paid tiers; use a conservative limit here
_rate_limiter = TokenBucketRateLimiter(tokens_per_minute=500_000)


def embed_texts_rate_limited(texts: list[str], token_counts: list[int]) -> list[list[float]]:
    """Embed texts, respecting rate limits."""
    total_tokens = sum(token_counts)
    _rate_limiter.wait_for_capacity(total_tokens)
    return embed_texts(texts)

In addition to per-worker rate limiting, the queue itself should implement a global throttle. If the queue depth exceeds a configurable threshold, new pg_notify dispatches should pause rather than flood the worker pool:

# In run_notify_listener():
# Before dispatching a task, check queue depth

def _should_throttle() -> bool:
    """Return True if the queue is deep enough to warrant slowing dispatch."""
    conn = get_db_connection()
    try:
        with conn.cursor() as cur:
            cur.execute(
                "SELECT COUNT(*) AS cnt FROM indexing_queue WHERE status = 'processing'"
            )
            processing = cur.fetchone()["cnt"]
            return processing > 50  # Tune based on your worker count
    finally:
        conn.close()

17.9 Putting It Together: A Complete Update Scenario

Walk through what happens when a technical writer edits a support article and saves it through a CMS:

1. The CMS calls a REST endpoint that executes UPDATE documents SET raw_content = $1, content_hash = $2 WHERE source_uri = $3.

2. The trg_document_update trigger fires. It compares OLD.content_hash != NEW.content_hash, cancels any existing pending queue item, inserts a new reindex queue item, sets status = 'pending', and calls pg_notify('indexing_events', ...).

3. The notify listener receives the notification within milliseconds and dispatches process_indexing_job.apply_async(args=[queue_id]).

4. A Celery worker claims the job using UPDATE indexing_queue SET status = 'processing' WHERE id = %s AND status IN ('pending', 'failed'). If another worker tries the same claim, it gets zero rows back and stops.

5. The worker loads the document, generates new chunks, and computes hashes. It compares chunk hashes against the existing document_chunks rows.

6. For chunks that changed, it consults embedding_cache. Cache hits reuse stored embeddings. Cache misses call the OpenAI API, subject to rate limiting.

7. New embeddings are inserted into embedding_cache with ON CONFLICT DO NOTHING.

8. All chunks are upserted into document_chunks with COALESCE to preserve embeddings for unchanged chunks.

9. Chunks beyond the new document length are deleted.

10. The document's status is set to 'indexed', indexed_at is updated, and index_version increments.

11. The trg_document_version trigger fires and records a row in document_versions.

12. The queue item is marked completed.

graph TD
    A[CMS UPDATE documents] --> B[trg_document_update trigger]
    B --> C[Cancel pending queue items]
    C --> D[Insert reindex queue item]
    D --> E[pg_notify indexing_events]
    E --> F[Notify listener dispatches Celery task]
    F --> G[Worker claims job FOR UPDATE SKIP LOCKED]
    G --> H[Diff chunk hashes vs existing]
    H --> I{Chunk changed?}
    I -->|yes, cache miss| J[Call embeddings API]
    I -->|yes, cache hit| K[Reuse embedding_cache]
    I -->|no| L[Keep existing embedding]
    J --> M[Upsert document_chunks]
    K --> M
    L --> M
    M --> N[Mark document indexed + record version]

*The full incremental-update path: a single content edit triggers hash comparison, queuing, and re-embedding of only the chunks that actually changed.*

The support article is now searchable in your RAG system within seconds of the writer hitting save, at a cost proportional only to the content that actually changed.

Key Takeaways

  • → **Hash-based change detection at two levels** — document hashes prevent unnecessary queue entries; chunk hashes within the worker prevent unnecessary API calls. Together they make the system cost-proportional to the actual delta.
  • → **`SELECT ... FOR UPDATE SKIP LOCKED` is the correct primitive for job queues in PostgreSQL.** Combined with a partial unique index on pending items, it guarantees exactly-once processing under concurrent workers without external coordination.
  • → **`pg_notify` converts a polling queue into an event-driven system.** Workers wake up within milliseconds of a change, but the fallback `_poll_missed_items` ensures no work is lost if a worker restarts between a notification and its handler.
  • → **An embedding cache keyed on chunk hash eliminates redundant API calls** for duplicate and near-duplicate content across your corpus. The `ON CONFLICT DO NOTHING` pattern handles concurrent insertions safely without requiring distributed locks.
  • → **Operational visibility requires monitoring at three layers:** queue depth and lag (are items being processed fast enough?), document freshness (are indexed documents current with their source?), and chunk integrity (do all chunks have valid embeddings?). A health-check function that returns severity-coded rows integrates naturally with any alerting system.
