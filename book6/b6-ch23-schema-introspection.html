Chapter 23: Schema Introspection for AI Query Generation

When you give an LLM access to a database, the single most important context you can provide is an accurate, well-structured description of what's actually in that database. Schema introspection — the act of reading PostgreSQL's own catalog tables to understand tables, columns, relationships, constraints, indexes, and statistics — transforms a generic language model into a database-aware reasoning engine. This chapter covers how to build that introspection layer: how to extract schema metadata programmatically, how to format it for LLM consumption, how to keep it fresh, and how to wire it into a text-to-SQL pipeline that generates correct queries instead of plausible-sounding ones.

---

23.1 What PostgreSQL Knows About Itself

PostgreSQL maintains a rich system catalog — a set of internal tables and views that describe every object in every database. Before you can feed schema context to an LLM, you need to understand what's available and how to read it efficiently.

The primary views you'll use are concentrated in two schemas: information_schema (SQL-standard, portable) and pg_catalog (PostgreSQL-native, more complete). For AI query generation, pg_catalog wins on depth. It exposes foreign key relationships, index structures, table statistics, and column-level statistics that information_schema either omits or buries.

-- Foundational catalog query: tables, columns, types, nullability, defaults
-- Run this to understand your schema extraction baseline
SELECT
    t.table_schema,
    t.table_name,
    c.column_name,
    c.ordinal_position,
    c.data_type,
    c.udt_name,                          -- actual type name (e.g., vector, jsonb, uuid)
    c.character_maximum_length,
    c.numeric_precision,
    c.is_nullable,
    c.column_default,
    pg_catalog.col_description(
        (quote_ident(t.table_schema) || '.' || quote_ident(t.table_name))::regclass::oid,
        c.ordinal_position
    ) AS column_comment
FROM information_schema.tables t
JOIN information_schema.columns c
    ON t.table_schema = c.table_schema
    AND t.table_name = c.table_name
WHERE t.table_schema NOT IN ('pg_catalog', 'information_schema', 'pg_toast')
    AND t.table_type = 'BASE TABLE'
ORDER BY t.table_schema, t.table_name, c.ordinal_position;

-- Foreign key relationships — the relational structure LLMs need for JOINs
SELECT
    tc.table_schema,
    tc.table_name,
    kcu.column_name,
    ccu.table_schema AS foreign_table_schema,
    ccu.table_name   AS foreign_table_name,
    ccu.column_name  AS foreign_column_name,
    tc.constraint_name,
    rc.update_rule,
    rc.delete_rule
FROM information_schema.table_constraints tc
JOIN information_schema.key_column_usage kcu
    ON tc.constraint_name = kcu.constraint_name
    AND tc.table_schema = kcu.table_schema
JOIN information_schema.referential_constraints rc
    ON tc.constraint_name = rc.constraint_name
JOIN information_schema.constraint_column_usage ccu
    ON ccu.constraint_name = rc.unique_constraint_name
WHERE tc.constraint_type = 'FOREIGN KEY'
ORDER BY tc.table_schema, tc.table_name;

-- Check constraints — important for telling LLMs what values are legal
SELECT
    tc.table_schema,
    tc.table_name,
    tc.constraint_name,
    cc.check_clause
FROM information_schema.table_constraints tc
JOIN information_schema.check_constraints cc
    ON tc.constraint_name = cc.constraint_name
WHERE tc.constraint_type = 'CHECK'
    AND tc.table_schema NOT IN ('pg_catalog', 'information_schema')
ORDER BY tc.table_schema, tc.table_name;

-- Index information — helps LLM understand what columns are fast to filter on
SELECT
    schemaname,
    tablename,
    indexname,
    indexdef,
    pg_catalog.pg_relation_size(indexname::regclass) AS index_size_bytes
FROM pg_catalog.pg_indexes
WHERE schemaname NOT IN ('pg_catalog', 'information_schema')
ORDER BY schemaname, tablename, indexname;

-- Table row counts and size estimates — context for query planning explanations
SELECT
    schemaname,
    relname AS tablename,
    n_live_tup AS estimated_row_count,
    pg_catalog.pg_total_relation_size(relid) AS total_size_bytes,
    last_analyze,
    last_autoanalyze
FROM pg_catalog.pg_stat_user_tables
ORDER BY n_live_tup DESC;

The col_description function deserves attention. It reads the comments you set with COMMENT ON COLUMN, and those comments become some of the highest-value context you can give an LLM. A column named amt is ambiguous. A column named amt with the comment "Invoice amount in USD cents, always positive" tells the LLM exactly how to use it in a query.

Add comments to your production tables specifically because you're building an AI layer:

-- Make your schema self-documenting for LLM consumption
COMMENT ON TABLE orders IS 'Customer purchase orders. Each row is one order placed via the web app or API.';
COMMENT ON COLUMN orders.status IS 'Order lifecycle state: pending, confirmed, shipped, delivered, cancelled, refunded';
COMMENT ON COLUMN orders.total_cents IS 'Order total in USD cents (divide by 100 for display). Includes tax, excludes shipping.';
COMMENT ON COLUMN orders.customer_id IS 'FK to customers.id. Never null — orders always belong to a customer.';
COMMENT ON COLUMN orders.metadata IS 'JSONB bag for flexible attributes: promo codes, A/B variants, partner data. Schema varies.';

-- Enum types — LLMs need to know legal values
COMMENT ON TYPE order_status_enum IS 'Valid values: pending, confirmed, shipped, delivered, cancelled, refunded';

-- Views are queryable too — document them clearly
COMMENT ON VIEW active_subscriptions IS 
    'Current active subscriptions only. Excludes cancelled and expired. 
     Joins subscriptions + customers + plans. Use this instead of raw subscriptions table for most queries.';

23.2 Building the Schema Introspection Layer

A schema introspection layer has three responsibilities: extract metadata from the catalog, format it for LLM consumption, and cache it so you're not running catalog queries on every user request. Here's a production-ready implementation.

# schema_introspector.py
# Full schema introspection pipeline: PostgreSQL catalog → structured metadata → LLM context

import asyncio
import hashlib
import json
import logging
from dataclasses import dataclass, field
from datetime import datetime, timedelta
from typing import Optional

import asyncpg
import redis.asyncio as redis
from pydantic import BaseModel

logger = logging.getLogger(__name__)


class ColumnMetadata(BaseModel):
    name: str
    data_type: str
    udt_name: str  # actual PostgreSQL type (vector, jsonb, uuid, etc.)
    is_nullable: bool
    column_default: Optional[str]
    comment: Optional[str]
    is_primary_key: bool = False
    is_foreign_key: bool = False
    foreign_table: Optional[str] = None
    foreign_column: Optional[str] = None


class IndexMetadata(BaseModel):
    name: str
    definition: str
    size_bytes: int


class TableMetadata(BaseModel):
    schema_name: str
    table_name: str
    table_comment: Optional[str]
    columns: list[ColumnMetadata]
    indexes: list[IndexMetadata]
    foreign_keys: list[dict]
    check_constraints: list[str]
    estimated_row_count: int
    total_size_bytes: int


class SchemaMetadata(BaseModel):
    database_name: str
    extracted_at: datetime
    tables: list[TableMetadata]
    schema_hash: str  # for cache invalidation


class SchemaIntrospector:
    """
    Extracts PostgreSQL schema metadata and formats it for LLM context injection.
    Caches results in Redis to avoid catalog overhead on every query.
    """

    CACHE_TTL_SECONDS = 300  # 5 minutes — adjust based on schema change frequency
    CACHE_KEY_PREFIX = "schema_meta:"

    def __init__(self, dsn: str, redis_url: str, target_schemas: list[str] = None):
        self.dsn = dsn
        self.redis_url = redis_url
        self.target_schemas = target_schemas or ["public"]
        self._pool: Optional[asyncpg.Pool] = None
        self._redis: Optional[redis.Redis] = None

    async def initialize(self):
        self._pool = await asyncpg.create_pool(self.dsn, min_size=2, max_size=5)
        self._redis = redis.from_url(self.redis_url, encoding="utf-8", decode_responses=True)

    async def close(self):
        if self._pool:
            await self._pool.close()
        if self._redis:
            await self._redis.aclose()

    async def get_schema_metadata(self, force_refresh: bool = False) -> SchemaMetadata:
        """Main entry point. Returns cached metadata or extracts fresh."""
        cache_key = f"{self.CACHE_KEY_PREFIX}{':'.join(sorted(self.target_schemas))}"

        if not force_refresh:
            cached = await self._redis.get(cache_key)
            if cached:
                logger.debug("Schema metadata served from cache")
                return SchemaMetadata.model_validate_json(cached)

        logger.info("Extracting schema metadata from PostgreSQL catalog")
        metadata = await self._extract_metadata()

        await self._redis.setex(
            cache_key,
            self.CACHE_TTL_SECONDS,
            metadata.model_dump_json(),
        )
        return metadata

    async def _extract_metadata(self) -> SchemaMetadata:
        async with self._pool.acquire() as conn:
            # Run all extractions in parallel for speed
            tables_data, fk_data, check_data, index_data, stats_data, pk_data = await asyncio.gather(
                self._fetch_columns(conn),
                self._fetch_foreign_keys(conn),
                self._fetch_check_constraints(conn),
                self._fetch_indexes(conn),
                self._fetch_table_stats(conn),
                self._fetch_primary_keys(conn),
            )

        db_name = await self._get_database_name()
        tables = self._assemble_tables(
            tables_data, fk_data, check_data, index_data, stats_data, pk_data
        )

        schema_json = json.dumps([t.model_dump(mode="json") for t in tables], default=str)
        schema_hash = hashlib.sha256(schema_json.encode()).hexdigest()[:12]

        return SchemaMetadata(
            database_name=db_name,
            extracted_at=datetime.utcnow(),
            tables=tables,
            schema_hash=schema_hash,
        )

    async def _fetch_columns(self, conn: asyncpg.Connection) -> list[dict]:
        placeholders = ",".join(f"${i+1}" for i in range(len(self.target_schemas)))
        query = f"""
            SELECT
                t.table_schema,
                t.table_name,
                pg_catalog.obj_description(
                    (quote_ident(t.table_schema) || '.' || quote_ident(t.table_name))::regclass::oid,
                    'pg_class'
                ) AS table_comment,
                c.column_name,
                c.ordinal_position,
                c.data_type,
                c.udt_name,
                c.is_nullable = 'YES' AS is_nullable,
                c.column_default,
                pg_catalog.col_description(
                    (quote_ident(t.table_schema) || '.' || quote_ident(t.table_name))::regclass::oid,
                    c.ordinal_position
                ) AS column_comment
            FROM information_schema.tables t
            JOIN information_schema.columns c
                ON t.table_schema = c.table_schema
                AND t.table_name = c.table_name
            WHERE t.table_schema IN ({placeholders})
                AND t.table_type = 'BASE TABLE'
            ORDER BY t.table_schema, t.table_name, c.ordinal_position
        """
        rows = await conn.fetch(query, *self.target_schemas)
        return [dict(r) for r in rows]

    async def _fetch_foreign_keys(self, conn: asyncpg.Connection) -> list[dict]:
        placeholders = ",".join(f"${i+1}" for i in range(len(self.target_schemas)))
        query = f"""
            SELECT
                tc.table_schema,
                tc.table_name,
                kcu.column_name,
                ccu.table_schema AS foreign_table_schema,
                ccu.table_name   AS foreign_table_name,
                ccu.column_name  AS foreign_column_name
            FROM information_schema.table_constraints tc
            JOIN information_schema.key_column_usage kcu
                ON tc.constraint_name = kcu.constraint_name
                AND tc.table_schema = kcu.table_schema
            JOIN information_schema.referential_constraints rc
                ON tc.constraint_name = rc.constraint_name
            JOIN information_schema.constraint_column_usage ccu
                ON ccu.constraint_name = rc.unique_constraint_name
            WHERE tc.constraint_type = 'FOREIGN KEY'
                AND tc.table_schema IN ({placeholders})
        """
        rows = await conn.fetch(query, *self.target_schemas)
        return [dict(r) for r in rows]

    async def _fetch_primary_keys(self, conn: asyncpg.Connection) -> list[dict]:
        placeholders = ",".join(f"${i+1}" for i in range(len(self.target_schemas)))
        query = f"""
            SELECT
                tc.table_schema,
                tc.table_name,
                kcu.column_name
            FROM information_schema.table_constraints tc
            JOIN information_schema.key_column_usage kcu
                ON tc.constraint_name = kcu.constraint_name
                AND tc.table_schema = kcu.table_schema
            WHERE tc.constraint_type = 'PRIMARY KEY'
                AND tc.table_schema IN ({placeholders})
        """
        rows = await conn.fetch(query, *self.target_schemas)
        return [dict(r) for r in rows]

    async def _fetch_check_constraints(self, conn: asyncpg.Connection) -> list[dict]:
        placeholders = ",".join(f"${i+1}" for i in range(len(self.target_schemas)))
        query = f"""
            SELECT
                tc.table_schema,
                tc.table_name,
                cc.check_clause
            FROM information_schema.table_constraints tc
            JOIN information_schema.check_constraints cc
                ON tc.constraint_name = cc.constraint_name
                AND tc.table_schema = cc.constraint_schema
            WHERE tc.constraint_type = 'CHECK'
                AND tc.table_schema IN ({placeholders})
        """
        rows = await conn.fetch(query, *self.target_schemas)
        return [dict(r) for r in rows]

    async def _fetch_indexes(self, conn: asyncpg.Connection) -> list[dict]:
        placeholders = ",".join(f"${i+1}" for i in range(len(self.target_schemas)))
        query = f"""
            SELECT
                schemaname,
                tablename,
                indexname,
                indexdef,
                COALESCE(pg_catalog.pg_relation_size(
                    (quote_ident(schemaname) || '.' || quote_ident(indexname))::regclass
                ), 0) AS index_size_bytes
            FROM pg_catalog.pg_indexes
            WHERE schemaname IN ({placeholders})
            ORDER BY schemaname, tablename, indexname
        """
        rows = await conn.fetch(query, *self.target_schemas)
        return [dict(r) for r in rows]

    async def _fetch_table_stats(self, conn: asyncpg.Connection) -> list[dict]:
        placeholders = ",".join(f"${i+1}" for i in range(len(self.target_schemas)))
        query = f"""
            SELECT
                schemaname,
                relname AS tablename,
                n_live_tup AS estimated_row_count,
                pg_catalog.pg_total_relation_size(relid) AS total_size_bytes
            FROM pg_catalog.pg_stat_user_tables
            WHERE schemaname IN ({placeholders})
        """
        rows = await conn.fetch(query, *self.target_schemas)
        return [dict(r) for r in rows]

    async def _get_database_name(self) -> str:
        async with self._pool.acquire() as conn:
            return await conn.fetchval("SELECT current_database()")

    def _assemble_tables(
        self,
        columns_data: list[dict],
        fk_data: list[dict],
        check_data: list[dict],
        index_data: list[dict],
        stats_data: list[dict],
        pk_data: list[dict],
    ) -> list[TableMetadata]:
        # Build lookup structures
        fk_lookup: dict[tuple, list] = {}
        for fk in fk_data:
            key = (fk["table_schema"], fk["table_name"])
            fk_lookup.setdefault(key, []).append(fk)

        pk_lookup: dict[tuple, set] = {}
        for pk in pk_data:
            key = (pk["table_schema"], pk["table_name"])
            pk_lookup.setdefault(key, set()).add(pk["column_name"])

        check_lookup: dict[tuple, list] = {}
        for cc in check_data:
            key = (cc["table_schema"], cc["table_name"])
            check_lookup.setdefault(key, []).append(cc["check_clause"])

        index_lookup: dict[tuple, list] = {}
        for idx in index_data:
            key = (idx["schemaname"], idx["tablename"])
            index_lookup.setdefault(key, []).append(idx)

        stats_lookup: dict[tuple, dict] = {}
        for stat in stats_data:
            key = (stat["schemaname"], stat["tablename"])
            stats_lookup[key] = stat

        # Group columns by table
        tables_dict: dict[tuple, dict] = {}
        for row in columns_data:
            key = (row["table_schema"], row["table_name"])
            if key not in tables_dict:
                tables_dict[key] = {
                    "schema_name": row["table_schema"],
                    "table_name": row["table_name"],
                    "table_comment": row["table_comment"],
                    "columns": [],
                }
            tables_dict[key]["columns"].append(row)

        result = []
        for key, tdata in tables_dict.items():
            fks = fk_lookup.get(key, [])
            fk_columns = {fk["column_name"]: fk for fk in fks}
            pks = pk_lookup.get(key, set())
            stats = stats_lookup.get(key, {})
            raw_indexes = index_lookup.get(key, [])

            columns = []
            for col in tdata["columns"]:
                fk_info = fk_columns.get(col["column_name"])
                columns.append(ColumnMetadata(
                    name=col["column_name"],
                    data_type=col["data_type"],
                    udt_name=col["udt_name"],
                    is_nullable=col["is_nullable"],
                    column_default=col["column_default"],
                    comment=col["column_comment"],
                    is_primary_key=col["column_name"] in pks,
                    is_foreign_key=fk_info is not None,
                    foreign_table=f"{fk_info['foreign_table_schema']}.{fk_info['foreign_table_name']}" if fk_info else None,
                    foreign_column=fk_info["foreign_column_name"] if fk_info else None,
                ))

            indexes = [
                IndexMetadata(
                    name=idx["indexname"],
                    definition=idx["indexdef"],
                    size_bytes=idx["index_size_bytes"],
                )
                for idx in raw_indexes
            ]

            result.append(TableMetadata(
                schema_name=key[0],
                table_name=key[1],
                table_comment=tdata["table_comment"],
                columns=columns,
                indexes=indexes,
                foreign_keys=fks,
                check_constraints=check_lookup.get(key, []),
                estimated_row_count=stats.get("estimated_row_count", 0),
                total_size_bytes=stats.get("total_size_bytes", 0),
            ))

        return sorted(result, key=lambda t: (t.schema_name, t.table_name))

23.3 Formatting Schema Context for LLM Consumption

Raw metadata is not LLM context. You need a formatter that converts structured metadata into text or structured representations that maximize LLM comprehension while fitting within context window limits. Different tasks need different formats: a CREATE TABLE style representation for SQL generation differs from a JSON-Schema style for JSON output tasks.

# schema_formatter.py
# Convert SchemaMetadata into LLM-consumable context strings

from typing import Literal
from schema_introspector import SchemaMetadata, TableMetadata, ColumnMetadata


class SchemaFormatter:
    """
    Formats schema metadata into text representations optimized for LLM context injection.

    Strategy:
    - DDL format: Best for text-to-SQL — LLMs trained on SQL naturally parse CREATE TABLE
    - Compact format: Token-efficient for large schemas with many tables
    - Selective format: Only include tables relevant to the user's question
    """

    def format_as_ddl(
        self,
        metadata: SchemaMetadata,
        include_indexes: bool = True,
        include_row_counts: bool = True,
        max_tables: int = 50,
    ) -> str:
        """
        Formats schema as CREATE TABLE statements — the format LLMs understand best
        for SQL generation tasks.
        """
        parts = [
            f"-- Database: {metadata.database_name}",
            f"-- Schema extracted at: {metadata.extracted_at.isoformat()}",
            f"-- Schema hash: {metadata.schema_hash}",
            "",
        ]

        for table in metadata.tables[:max_tables]:
            parts.append(self._format_table_ddl(table, include_indexes, include_row_counts))
            parts.append("")

        if len(metadata.tables) > max_tables:
            parts.append(
                f"-- NOTE: {len(metadata.tables) - max_tables} additional tables omitted for brevity."
            )

        return "\n".join(parts)

    def _format_table_ddl(
        self,
        table: TableMetadata,
        include_indexes: bool,
        include_row_counts: bool,
    ) -> str:
        lines = []

        # Table comment
        if table.table_comment:
            lines.append(f"-- {table.table_comment}")

        # Row count context
        if include_row_counts and table.estimated_row_count > 0:
            size_str = self._format_size(table.total_size_bytes)
            lines.append(
                f"-- Estimated rows: {table.estimated_row_count:,}  |  Size: {size_str}"
            )

        lines.append(f"CREATE TABLE {table.schema_name}.{table.table_name} (")

        col_lines = []
        for col in table.columns:
            col_lines.append(self._format_column_ddl(col))

        # Add primary key constraint if we have PK columns
        pk_cols = [c.name for c in table.columns if c.is_primary_key]
        if pk_cols:
            col_lines.append(f"    PRIMARY KEY ({', '.join(pk_cols)})")

        # Add foreign key constraints inline
        for fk in table.foreign_keys:
            col_lines.append(
                f"    FOREIGN KEY ({fk['column_name']}) "
                f"REFERENCES {fk['foreign_table_schema']}.{fk['foreign_table_name']}({fk['foreign_column_name']})"
            )

        # Add check constraints
        for cc in table.check_constraints:
            col_lines.append(f"    CHECK ({cc})")

        lines.append(",\n".join(col_lines))
        lines.append(");")

        # Indexes as separate statements
        if include_indexes:
            non_pk_indexes = [
                idx for idx in table.indexes
                if "pkey" not in idx.name.lower()
            ]
            for idx in non_pk_indexes:
                lines.append(idx.definition + ";")

        return "\n".join(lines)

    def _format_column_ddl(self, col: ColumnMetadata) -> str:
        # Use udt_name for custom types (vector, jsonb, uuid), data_type for standard
        type_str = col.udt_name if col.udt_name not in (
            "int4", "int8", "int2", "float4", "float8", "bool", "text", "date",
            "timestamp", "timestamptz", "numeric", "varchar", "bpchar"
        ) else col.data_type

        nullable = "" if col.is_nullable else " NOT NULL"
        default = f" DEFAULT {col.column_default}" if col.column_default else ""

        comment_parts = []
        if col.comment:
            comment_parts.append(col.comment)
        if col.is_foreign_key and col.foreign_table:
            comment_parts.append(f"FK → {col.foreign_table}.{col.foreign_column}")

        comment_str = ""
        if comment_parts:
            comment_str = f"  -- {'; '.join(comment_parts)}"

        return f"    {col.name} {type_str}{nullable}{default}{comment_str}"

    def format_compact(self, metadata: SchemaMetadata, max_tables: int = 100) -> str:
        """
        Compact format: table(col:type, col:type, ...) — maximally token-efficient.
        Use when you have many tables and need to fit schema in a small context budget.
        """
        lines = [f"-- Database: {metadata.database_name} | Hash: {metadata.schema_hash}"]
        for table in metadata.tables[:max_tables]:
            col_parts = []
            for col in table.columns:
                pk = "*" if col.is_primary_key else ""
                fk = f"→{col.foreign_table}" if col.is_foreign_key and col.foreign_table else ""
                null = "?" if col.is_nullable else ""
                col_parts.append(f"{col.name}{pk}{null}:{col.udt_name}{fk}")
            lines.append(
                f"{table.schema_name}.{table.table_name}"
                f"({', '.join(col_parts)})"
                f"  -- {table.estimated_row_count:,} rows"
            )
        return "\n".join(lines)

    def format_for_tables(
        self,
        metadata: SchemaMetadata,
        table_names: list[str],
        include_related: bool = True,
    ) -> str:
        """
        Selective format: only include specified tables and their FK-related tables.
        Use when the question can be answered from a known subset of the schema.
        """
        requested = set(table_names)

        if include_related:
            # Also include tables referenced by FK from requested tables
            for table in metadata.tables:
                full_name = f"{table.schema_name}.{table.table_name}"
                if full_name in requested or table.table_name in requested:
                    for fk in table.foreign_keys:
                        requested.add(
                            f"{fk['foreign_table_schema']}.{fk['foreign_table_name']}"
                        )

        selected = [
            t for t in metadata.tables
            if f"{t.schema_name}.{t.table_name}" in requested
            or t.table_name in requested
        ]

        filtered = SchemaMetadata(
            database_name=metadata.database_name,
            extracted_at=metadata.extracted_at,
            tables=selected,
            schema_hash=metadata.schema_hash,
        )
        return self.format_as_ddl(filtered, include_indexes=True, include_row_counts=True)

    def estimate_token_count(self, text: str) -> int:
        """Rough token estimate: ~4 characters per token for English/SQL text."""
        return len(text) // 4

    @staticmethod
    def _format_size(size_bytes: int) -> str:
        for unit in ("B", "KB", "MB", "GB"):
            if size_bytes < 1024:
                return f"{size_bytes:.1f} {unit}"
            size_bytes //= 1024
        return f"{size_bytes:.1f} TB"

The DDL format works remarkably well because LLMs are trained on enormous amounts of SQL DDL from open-source repositories, Stack Overflow, and database documentation. Presenting schema as CREATE TABLE statements exploits that training distribution — the model already has strong priors for how to read table definitions, FK references, and CHECK constraints.

The compact format becomes necessary when your schema is large. A database with 200 tables and their DDL representations can easily consume tens of thousands of tokens, leaving little room for the actual question and generated SQL. In those cases, the selective formatter — which retrieves only the tables relevant to a given query — is essential for keeping context windows manageable.

23.4 Table Relevance Ranking

For large schemas, you can't include everything. You need a way to determine which tables are relevant to a given question before you construct the prompt. This is a retrieval problem, and it has several solutions: keyword matching, embedding-based semantic search, or a hybrid approach.

# table_ranker.py
# Determine which tables are relevant to a natural language question

import re
from dataclasses import dataclass
from typing import Optional

import numpy as np
from openai import AsyncOpenAI

from schema_introspector import SchemaMetadata, TableMetadata


@dataclass
class TableRelevanceScore:
    table: TableMetadata
    score: float
    match_reasons: list[str]


class TableRanker:
    """
    Ranks tables by relevance to a natural language question.
    Uses a combination of keyword matching and embedding similarity.
    """

    def __init__(self, openai_client: AsyncOpenAI, embed_model: str = "text-embedding-3-small"):
        self.client = openai_client
        self.embed_model = embed_model
        self._table_embeddings: dict[str, np.ndarray] = {}
        self._metadata: Optional[SchemaMetadata] = None

    async def index_schema(self, metadata: SchemaMetadata) -> None:
        """
        Pre-compute embeddings for all tables. Call this when schema changes.
        Each table is represented as a descriptive text string combining its
        name, comment, and column names/comments.
        """
        self._metadata = metadata
        texts = {}
        for table in metadata.tables:
            full_name = f"{table.schema_name}.{table.table_name}"
            texts[full_name] = self._table_to_text(table)

        if not texts:
            return

        # Batch embed all tables
        table_names = list(texts.keys())
        table_texts = list(texts.values())

        # OpenAI embeddings API supports up to 2048 inputs per batch
        batch_size = 100
        all_embeddings = []
        for i in range(0, len(table_texts), batch_size):
            batch = table_texts[i : i + batch_size]
            response = await self.client.embeddings.create(
                model=self.embed_model,
                input=batch,
            )
            all_embeddings.extend([e.embedding for e in response.data])

        for name, embedding in zip(table_names, all_embeddings):
            self._table_embeddings[name] = np.array(embedding, dtype=np.float32)

    def _table_to_text(self, table: TableMetadata) -> str:
        """Convert table metadata to searchable text representation."""
        parts = [
            f"Table: {table.schema_name}.{table.table_name}",
        ]
        if table.table_comment:
            parts.append(f"Description: {table.table_comment}")

        col_descriptions = []
        for col in table.columns:
            col_desc = f"{col.name} ({col.udt_name})"
            if col.comment:
                col_desc += f": {col.comment}"
            col_descriptions.append(col_desc)

        parts.append("Columns: " + ", ".join(col_descriptions))
        return ". ".join(parts)

    async def rank_tables(
        self,
        question: str,
        top_k: int = 10,
        keyword_weight: float = 0.3,
        semantic_weight: float = 0.7,
    ) -> list[TableRelevanceScore]:
        """
        Returns tables ranked by combined keyword + semantic relevance.
        Returns at most top_k tables.
        """
        if not self._metadata:
            raise RuntimeError("Call index_schema() before rank_tables()")

        keyword_scores = self._keyword_scores(question)
        semantic_scores = await self._semantic_scores(question)

        results = []
        for table in self._metadata.tables:
            full_name = f"{table.schema_name}.{table.table_name}"
            kw_score = keyword_scores.get(full_name, 0.0)
            sem_score = semantic_scores.get(full_name, 0.0)
            combined = keyword_weight * kw_score + semantic_weight * sem_score

            reasons = []
            if kw_score > 0.3:
                reasons.append(f"keyword match ({kw_score:.2f})")
            if sem_score > 0.7:
                reasons.append(f"semantic match ({sem_score:.2f})")

            results.append(TableRelevanceScore(
                table=table,
                score=combined,
                match_reasons=reasons,
            ))

        results.sort(key=lambda r: r.score, reverse=True)
        return results[:top_k]

    def _keyword_scores(self, question: str) -> dict[str, float]:
        """
        Simple keyword scoring: check if table name or column names appear in question.
        Normalized 0–1.
        """
        question_lower = question.lower()
        # Extract word tokens from question
        question_words = set(re.findall(r'\b\w+\b', question_lower))

        scores = {}
        for table in self._metadata.tables:
            full_name = f"{table.schema_name}.{table.table_name}"
            hits = 0
            total = 0

            # Table name words
            table_words = set(re.split(r'[_\s]+', table.table_name.lower()))
            table_words.discard("")
            for word in table_words:
                total += 2  # table name hits are worth more
                if word in question_words:
                    hits += 2

            # Column name words
            for col in table.columns:
                col_words = set(re.split(r'[_\s]+', col.name.lower()))
                col_words.discard("")
                for word in col_words:
                    total += 1
                    if word in question_words:
                        hits += 1

            scores[full_name] = (hits / total) if total > 0 else 0.0

        return scores

    async def _semantic_scores(self, question: str) -> dict[str, float]:
        """
        Cosine similarity between question embedding and pre-computed table embeddings.
        """
        if not self._table_embeddings:
            return {}

        response = await self.client.embeddings.create(
            model=self.embed_model,
            input=[question],
        )
        q_vec = np.array(response.data[0].embedding, dtype=np.float32)
        q_norm = np.linalg.norm(q_vec)
        if q_norm == 0:
            return {}
        q_vec = q_vec / q_norm

        scores = {}
        for name, t_vec in self._table_embeddings.items():
            t_norm = np.linalg.norm(t_vec)
            if t_norm == 0:
                scores[name] = 0.0
            else:
                scores[name] = float(np.dot(q_vec, t_vec / t_norm))

        return scores

The hybrid ranking approach — combining lexical keyword matching with semantic similarity — handles two failure modes that each technique has alone. Pure keyword matching misses questions that use synonyms or domain language different from the table names (a question about "revenue" might need the invoices table, not a table literally named revenue). Pure semantic search can miss exact-match cases where a user types a table name verbatim. Weighting semantic similarity more heavily (0.7 vs 0.3 here) reflects that LLM-generated questions tend to describe intent rather than name tables literally, but you should tune these weights against your own query log.

23.5 The Text-to-SQL Pipeline

With schema introspection and table ranking in place, you can build a complete text-to-SQL pipeline. The pipeline has five stages: understand the question, rank relevant tables, select schema context, generate SQL, and validate the SQL before executing it.

# text_to_sql.py
# End-to-end text-to-SQL pipeline with schema introspection and validation

import asyncio
import logging
import re
from dataclasses import dataclass
from typing import Optional

import asyncpg
from openai import AsyncOpenAI

from schema_formatter import SchemaFormatter
from schema_introspector import SchemaIntrospector, SchemaMetadata
from table_ranker import TableRanker

logger = logging.getLogger(__name__)


@dataclass
class SQLGenerationResult:
    question: str
    generated_sql: str
    tables_used: list[str]
    schema_context_tokens: int
    validation_passed: bool
    validation_error: Optional[str]
    execution_result: Optional[list[dict]]
    error: Optional[str]


SYSTEM_PROMPT = """You are a PostgreSQL SQL generation assistant. Your job is to convert natural language questions into correct, safe, read-only PostgreSQL SELECT queries.

Rules you must follow:
1. Only generate SELECT statements. Never generate INSERT, UPDATE, DELETE, DROP, CREATE, ALTER, TRUNCATE, or any DDL/DML.
2. Always qualify column names with table aliases when joining multiple tables.
3. Use explicit JOIN syntax (not implicit comma-separated tables).
4. Respect the data types shown in the schema — do not cast unnecessarily.
5. If a column has an enum-like CHECK constraint or a comment listing valid values, only filter on those values.
6. When a question is ambiguous, choose the most conservative interpretation.
7. Do not add LIMIT unless the question asks for a "top N" result or you see a specific count requested.
8. Output ONLY the SQL query — no explanation, no markdown fences, no preamble.

The schema you are working with will be provided in each message."""


class TextToSQLPipeline:
    """
    Converts natural language questions to validated PostgreSQL SELECT queries.
    """

    def __init__(
        self,
        introspector: SchemaIntrospector,
        ranker: TableRanker,
        formatter: SchemaFormatter,
        openai_client: AsyncOpenAI,
        db_pool: asyncpg.Pool,
        model: str = "gpt-4o",
        max_schema_tables: int = 15,
    ):
        self.introspector = introspector
        self.ranker = ranker
        self.formatter = formatter
        self.client = openai_client
        self.pool = db_pool
        self.model = model
        self.max_schema_tables = max_schema_tables

    async def generate(
        self,
        question: str,
        execute: bool = False,
        row_limit: int = 500,
    ) -> SQLGenerationResult:
        """
        Full pipeline: question → ranked tables → schema context → SQL → validate → (execute).
        """
        try:
            # Stage 1: Get fresh (possibly cached) schema metadata
            metadata = await self.introspector.get_schema_metadata()

            # Stage 2: Rank tables by relevance
            ranked = await self.ranker.rank_tables(
                question,
                top_k=self.max_schema_tables,
            )
            relevant_table_names = [
                f"{r.table.schema_name}.{r.table.table_name}"
                for r in ranked
            ]

            # Stage 3: Format schema context for selected tables
            schema_context = self.formatter.format_for_tables(
                metadata,
                table_names=relevant_table_names,
                include_related=True,  # pull in FK-related tables automatically
            )
            token_estimate = self.formatter.estimate_token_count(schema_context)

            # Stage 4: Generate SQL
            user_message = f"""Schema:
{schema_context}

Question: {question}

Generate a PostgreSQL SELECT query to answer this question."""

            response = await self.client.chat.completions.create(
                model=self.model,
                messages=[
                    {"role": "system", "content": SYSTEM_PROMPT},
                    {"role": "user", "content": user_message},
                ],
                temperature=0,  # deterministic for SQL generation
                max_tokens=1024,
            )

            raw_sql = response.choices[0].message.content.strip()

            # Clean up any accidental markdown fences despite the system prompt
            sql = self._strip_markdown(raw_sql)

            # Stage 5: Validate SQL (parse check + safety check)
            valid, error = await self._validate_sql(sql)

            # Stage 6 (optional): Execute
            result_rows = None
            if execute and valid:
                result_rows = await self._execute_safe(sql, row_limit)

            return SQLGenerationResult(
                question=question,
                generated_sql=sql,
                tables_used=relevant_table_names,
                schema_context_tokens=token_estimate,
                validation_passed=valid,
                validation_error=error,
                execution_result=result_rows,
                error=None,
            )

        except Exception as exc:
            logger.exception("Text-to-SQL pipeline error for question: %s", question)
            return SQLGenerationResult(
                question=question,
                generated_sql="",
                tables_used=[],
                schema_context_tokens=0,
                validation_passed=False,
                validation_error=None,
                execution_result=None,
                error=str(exc),
            )

    async def _validate_sql(self, sql: str) -> tuple[bool, Optional[str]]:
        """
        Two-phase validation:
        1. Safety check: reject anything that isn't a SELECT
        2. Parse check: use PostgreSQL's EXPLAIN to catch syntax errors without executing
        """
        # Safety: only SELECT statements allowed
        stripped = sql.strip().upper()
        if not stripped.startswith("SELECT") and not stripped.startswith("WITH"):
            return False, f"Non-SELECT statement rejected: starts with '{sql.strip()[:20]}'"

        # Block obviously dangerous keywords (belt-and-suspenders)
        dangerous = re.compile(
            r'\b(INSERT|UPDATE|DELETE|DROP|CREATE|ALTER|TRUNCATE|GRANT|REVOKE|COPY|EXECUTE)\b',
            re.IGNORECASE,
        )
        if dangerous.search(sql):
            return False, "Query contains prohibited DML/DDL keyword"

        # Parse validation via EXPLAIN — catches syntax errors cheaply
        try:
            async with self.pool.acquire() as conn:
                # Use a read-only transaction so nothing can accidentally commit
                async with conn.transaction():
                    await conn.execute(f"EXPLAIN {sql}")
                    # Roll back the transaction — EXPLAIN itself doesn't change data
                    # but we're being explicit about isolation
                    raise asyncpg.exceptions.PostgresError  # force rollback
        except asyncpg.exceptions.PostgresError as e:
            error_msg = str(e)
            # Distinguish a real parse error from our intentional rollback
            if "PostgresError" in type(e).__name__ and not error_msg:
                # Our forced rollback — SQL parsed fine
                return True, None
            return False, f"SQL parse error: {error_msg}"
        except Exception:
            # If EXPLAIN itself raises something unexpected, treat as valid
            # (don't block on validation infrastructure failures)
            return True, None

        return True, None

    async def _execute_safe(self, sql: str, row_limit: int) -> list[dict]:
        """Execute in a read-only transaction with row limit guard."""
        # Wrap with LIMIT if not present to prevent runaway result sets
        if "LIMIT" not in sql.upper():
            wrapped = f"SELECT * FROM ({sql}) _q LIMIT {row_limit}"
        else:
            wrapped = sql

        async with self.pool.acquire() as conn:
            # readonly=True asks asyncpg to manage the transaction as
            # read-only itself — issuing a manual "ROLLBACK" inside a
            # conn.transaction() block would desync asyncpg's own state
            # machine from the underlying connection.
            async with conn.transaction(readonly=True):
                rows = await conn.fetch(wrapped)
                return [dict(r) for r in rows]

    @staticmethod
    def _strip_markdown(text: str) -> str:
        """Remove markdown code fences that LLMs sometimes add despite instructions."""
        text = re.sub(r'^```(?:sql)?\s*', '', text, flags=re.MULTILINE)
        text = re.sub(r'\s*```$', '', text, flags=re.MULTILINE)
        return text.strip()

The validation approach here — using EXPLAIN inside a transaction that always rolls back — is a cheap way to catch syntax errors without actually executing the query. A successful EXPLAIN means PostgreSQL parsed the query and built a query plan, which requires all referenced tables and columns to actually exist. This catches the most common LLM error modes: hallucinated column names, wrong table names, type mismatches in WHERE clauses, and malformed JOIN conditions.

The forced rollback pattern in _validate_sql is intentionally blunt. Rather than inspecting exception types in detail, we raise inside the transaction to trigger a rollback, and then distinguish between "we caused this" and "PostgreSQL complained about the SQL." In production you'd replace this with a cleaner pattern using conn.transaction() as an async context manager and letting it roll back naturally.

23.6 Schema Change Detection and Cache Invalidation

Schema introspection is only useful if it reflects the current schema. In active development environments, tables get added, columns change types, and new indexes appear. Your caching layer needs a way to detect schema changes and invalidate stale context.

# schema_watcher.py
# Detect schema changes and invalidate cached metadata

import asyncio
import hashlib
import logging
from typing import Callable, Awaitable

import asyncpg

logger = logging.getLogger(__name__)


class SchemaWatcher:
    """
    Polls PostgreSQL's pg_stat_user_tables and pg_catalog object timestamps
    to detect schema changes. When a change is detected, fires registered callbacks.

    For high-frequency change detection in development, use lower poll intervals.
    In production, 60–300 seconds is typically sufficient.
    """

    def __init__(
        self,
        dsn: str,
        poll_interval_seconds: int = 60,
        target_schemas: list[str] = None,
    ):
        self.dsn = dsn
        self.poll_interval = poll_interval_seconds
        self.target_schemas = target_schemas or ["public"]
        self._last_hash: str = ""
        self._callbacks: list[Callable[[], Awaitable[None]]] = []
        self._running = False

    def on_change(self, callback: Callable[[], Awaitable[None]]) -> None:
        """Register a callback that fires when schema changes are detected."""
        self._callbacks.append(callback)

    async def start(self) -> None:
        """Start the polling loop. Runs until stop() is called."""
        self._running = True
        conn = await asyncpg.connect(self.dsn)
        try:
            self._last_hash = await self._compute_schema_hash(conn)
            logger.info("SchemaWatcher started. Initial hash: %s", self._last_hash)

            while self._running:
                await asyncio.sleep(self.poll_interval)
                try:
                    current_hash = await self._compute_schema_hash(conn)
                    if current_hash != self._last_hash:
                        logger.info(
                            "Schema change detected. Old: %s  New: %s",
                            self._last_hash,
                            current_hash,
                        )
                        self._last_hash = current_hash
                        for cb in self._callbacks:
                            try:
                                await cb()
                            except Exception:
                                logger.exception("Schema change callback error")
                except asyncpg.PostgresError:
                    logger.warning("SchemaWatcher: DB error during poll, will retry")
        finally:
            await conn.close()

    async def stop(self) -> None:
        self._running = False

    async def _compute_schema_hash(self, conn: asyncpg.Connection) -> str:
        """
        Compute a fingerprint of the current schema state by hashing:
        - Table and column counts per schema
        - Column definitions (name, type, nullability)
        - Index definitions

        This is intentionally lightweight — we want fast change detection,
        not a full catalog dump.
        """
        placeholders = ",".join(f"${i+1}" for i in range(len(self.target_schemas)))
        query = f"""
            SELECT
                c.table_schema,
                c.table_name,
                c.column_name,
                c.data_type,
                c.udt_name,
                c.is_nullable,
                c.column_default
            FROM information_schema.columns c
            JOIN information_schema.tables t
                ON c.table_schema = t.table_schema
                AND c.table_name = t.table_name
            WHERE c.table_schema IN ({placeholders})
                AND t.table_type = 'BASE TABLE'
            ORDER BY c.table_schema, c.table_name, c.ordinal_position
        """
        rows = await conn.fetch(query, *self.target_schemas)

        # Also include index definitions in the hash
        idx_query = f"""
            SELECT schemaname, tablename, indexname, indexdef
            FROM pg_catalog.pg_indexes
            WHERE schemaname IN ({placeholders})
            ORDER BY schemaname, tablename, indexname
        """
        idx_rows = await conn.fetch(idx_query, *self.target_schemas)

        fingerprint = (
            str([dict(r) for r in rows])
            + str([dict(r) for r in idx_rows])
        )
        return hashlib.sha256(fingerprint.encode()).hexdigest()[:16]

Wiring the watcher to the introspector is straightforward:

# Initialization snippet — connect watcher to introspector cache invalidation
async def setup_schema_pipeline(dsn: str, redis_url: str) -> tuple[SchemaIntrospector, SchemaWatcher]:
    introspector = SchemaIntrospector(dsn=dsn, redis_url=redis_url)
    await introspector.initialize()

    watcher = SchemaWatcher(dsn=dsn, poll_interval_seconds=120)

    async def on_schema_change():
        logger.info("Invalidating schema cache due to detected schema change")
        await introspector.get_schema_metadata(force_refresh=True)

    watcher.on_change(on_schema_change)

    # Run the watcher in the background
    asyncio.create_task(watcher.start())

    return introspector, watcher

PostgreSQL also supports a lightweight notification mechanism via LISTEN/NOTIFY that can replace polling for environments where DDL changes are made through a controlled migration tool. If your migration tool fires NOTIFY schema_changed after each migration, the watcher can react immediately rather than waiting for the next poll cycle:

-- In your migration tool's post-migration hook
SELECT pg_notify('schema_changed', json_build_object(
    'schema', current_schema(),

)::text);
# LISTEN-based watcher — more responsive than polling
async def listen_for_schema_changes(
    dsn: str,
    callback: Callable[[], Awaitable[None]],
) -> None:
    conn = await asyncpg.connect(dsn)
    await conn.add_listener(
        "schema_changed",
        lambda _conn, _pid, _channel, payload: asyncio.create_task(callback()),
    )
    await conn.execute("LISTEN schema_changed")
    logger.info("Listening for schema_changed notifications")

    while True:
        await asyncio.sleep(60)

The two approaches — polling and LISTEN/NOTIFY — serve different environments. Polling is self-contained and works regardless of how schema changes happen. LISTEN/NOTIFY is lower-latency but requires your migration workflow to cooperate by sending the notification. In practice, many production systems use both: LISTEN/NOTIFY for fast response to controlled migrations, and a slow background poll as a safety net for out-of-band changes.

23.7 SQL Server Equivalent: sys Catalog Introspection

SQL Server exposes equivalent schema information through its own system catalog — the sys schema views. The pattern is identical: extract metadata, format it, cache it. The SQL differs.

-- SQL Server: tables and columns with comments (extended properties)
SELECT
    s.name                              AS table_schema,
    t.name                              AS table_name,
    c.name                              AS column_name,
    c.column_id                         AS ordinal_position,
    tp.name                             AS data_type,
    c.max_length,
    c.precision,
    c.scale,
    c.is_nullable,
    dc.definition                       AS column_default,
    CAST(ep_t.value AS NVARCHAR(MAX))   AS table_comment,
    CAST(ep_c.value AS NVARCHAR(MAX))   AS column_comment
FROM sys.tables t
JOIN sys.schemas s
    ON t.schema_id = s.schema_id
JOIN sys.columns c
    ON t.object_id = c.object_id
JOIN sys.types tp
    ON c.user_type_id = tp.user_type_id
LEFT JOIN sys.default_constraints dc
    ON c.default_object_id = dc.object_id
-- Table-level extended properties (equivalent to PostgreSQL COMMENT ON TABLE)
LEFT JOIN sys.extended_properties ep_t
    ON ep_t.major_id = t.object_id
    AND ep_t.minor_id = 0
    AND ep_t.name = 'MS_Description'
-- Column-level extended properties (equivalent to PostgreSQL COMMENT ON COLUMN)
LEFT JOIN sys.extended_properties ep_c
    ON ep_c.major_id = c.object_id
    AND ep_c.minor_id = c.column_id
    AND ep_c.name = 'MS_Description'
WHERE s.name NOT IN ('sys', 'INFORMATION_SCHEMA', 'guest')
ORDER BY s.name, t.name, c.column_id;

    ON i.object_id = ic.object_id
    AND i.index_id = ic.index_id
JOIN sys.columns c
    ON ic.object_id = c.object_id
    AND ic.column_id = c.column_id
LEFT JOIN sys.partitions p
    ON i.object_id = p.object_id
    AND i.index_id = p.index_id
LEFT JOIN sys.allocation_units a
    ON p.partition_id = a.container_id
WHERE i.type > 0  -- exclude heaps
    AND s.name NOT IN ('sys', 'INFORMATION_SCHEMA', 'guest')
GROUP BY s.name, t.name, i.name, i.type_desc, i.is_unique, i.is_primary_key
ORDER BY s.name, t.name, i.name;

-- SQL Server: row count and size estimates from sys.dm_db_partition_stats
SELECT
    s.name              AS schema_name,
    t.name              AS table_name,
    SUM(ps.row_count)   AS estimated_row_count,
    SUM(ps.used_page_count) * 8 * 1024 AS total_size_bytes
FROM sys.tables t
JOIN sys.schemas s
    ON t.schema_id = s.schema_id
JOIN sys.dm_db_partition_stats ps
    ON t.object_id = ps.object_id
WHERE ps.index_id IN (0, 1)  -- heap or clustered index only
    AND s.name NOT IN ('sys', 'INFORMATION_SCHEMA', 'guest')
GROUP BY s.name, t.name
ORDER BY estimated_row_count DESC;

The SQL Server introspector follows the same structure as the PostgreSQL one, with two meaningful differences. First, SQL Server uses extended properties (sys.extended_properties with name = 'MS_Description') where PostgreSQL uses first-class COMMENT ON syntax. The functional result is the same — column-level documentation that an LLM can use — but populating extended properties in SQL Server requires calling sp_addextendedproperty or sp_updateextendedproperty rather than a simple COMMENT ON statement. Second, SQL Server's STRING_AGG for index columns is only available from SQL Server 2017 onward; for earlier versions, replace it with the FOR XML PATH concatenation idiom.

Here is a condensed Python adapter that wraps the SQL Server queries using pyodbc:

# sql_server_introspector.py
# SQL Server schema introspection using pyodbc + aioodbc

import asyncio
import hashlib
import json
import logging
from datetime import datetime
from typing import Optional

import aioodbc
from pydantic import BaseModel

from schema_introspector import (
    ColumnMetadata, IndexMetadata, SchemaMetadata, TableMetadata
)

logger = logging.getLogger(__name__)


class SQLServerSchemaIntrospector:
    """
    SQL Server equivalent of SchemaIntrospector.
    Uses sys catalog views instead of information_schema / pg_catalog.
    """

    def __init__(self, dsn: str, target_schemas: list[str] = None):
        self.dsn = dsn
        self.target_schemas = target_schemas or ["dbo"]
        self._pool: Optional[aioodbc.Pool] = None

    async def initialize(self):
        self._pool = await aioodbc.create_pool(dsn=self.dsn, minsize=2, maxsize=5)

    async def close(self):
        if self._pool:
            self._pool.close()
            await self._pool.wait_closed()

    async def get_schema_metadata(self) -> SchemaMetadata:
        async with self._pool.acquire() as conn:
            columns_data, fk_data, check_data, index_data, stats_data, pk_data = await asyncio.gather(
                self._fetch_columns(conn),
                self._fetch_foreign_keys(conn),
                self._fetch_check_constraints(conn),
                self._fetch_indexes(conn),
                self._fetch_table_stats(conn),
                self._fetch_primary_keys(conn),
            )

        db_name = await self._get_database_name()
        tables = self._assemble_tables(
            columns_data, fk_data, check_data, index_data, stats_data, pk_data
        )

        schema_json = json.dumps(
            [t.model_dump(mode="json") for t in tables], default=str
        )
        schema_hash = hashlib.sha256(schema_json.encode()).hexdigest()[:12]

        return SchemaMetadata(
            database_name=db_name,
            extracted_at=datetime.utcnow(),
            tables=tables,
            schema_hash=schema_hash,
        )

    async def _fetch_columns(self, conn) -> list[dict]:
        schema_list = ", ".join(f"'{s}'" for s in self.target_schemas)
        query = f"""
            SELECT
                s.name          AS table_schema,
                t.name          AS table_name,
                c.name          AS column_name,
                c.column_id     AS ordinal_position,
                tp.name         AS data_type,
                c.is_nullable,
                dc.definition   AS column_default,
                CAST(ep_t.value AS NVARCHAR(MAX)) AS table_comment,
                CAST(ep_c.value AS NVARCHAR(MAX)) AS column_comment
            FROM sys.tables t
            JOIN sys.schemas s ON t.schema_id = s.schema_id
            JOIN sys.columns c ON t.object_id = c.object_id
            JOIN sys.types tp  ON c.user_type_id = tp.user_type_id
            LEFT JOIN sys.default_constraints dc
                ON c.default_object_id = dc.object_id
            LEFT JOIN sys.extended_properties ep_t
                ON ep_t.major_id = t.object_id
                AND ep_t.minor_id = 0
                AND ep_t.name = 'MS_Description'
            LEFT JOIN sys.extended_properties ep_c
                ON ep_c.major_id = c.object_id
                AND ep_c.minor_id = c.column_id
                AND ep_c.name = 'MS_Description'
            WHERE s.name IN ({schema_list})
            ORDER BY s.name, t.name, c.column_id
        """
        async with conn.cursor() as cur:
            await cur.execute(query)
            cols = [d[0] for d in cur.description]
            rows = await cur.fetchall()
        return [dict(zip(cols, row)) for row in rows]

    async def _fetch_foreign_keys(self, conn) -> list[dict]:
        schema_list = ", ".join(f"'{s}'" for s in self.target_schemas)
        query = f"""
            SELECT
                s_from.name   AS table_schema,
                t_from.name   AS table_name,
                c_from.name   AS column_name,
                s_to.name     AS foreign_table_schema,
                t_to.name     AS foreign_table_name,
                c_to.name     AS foreign_column_name
            FROM sys.foreign_keys fk
            JOIN sys.foreign_key_columns fkc
                ON fk.object_id = fkc.constraint_object_id
            JOIN sys.tables t_from   ON fkc.parent_object_id     = t_from.object_id
            JOIN sys.schemas s_from  ON t_from.schema_id          = s_from.schema_id
            JOIN sys.columns c_from
                ON fkc.parent_object_id = c_from.object_id
                AND fkc.parent_column_id = c_from.column_id
            JOIN sys.tables t_to     ON fkc.referenced_object_id  = t_to.object_id
            JOIN sys.schemas s_to    ON t_to.schema_id             = s_to.schema_id
            JOIN sys.columns c_to
                ON fkc.referenced_object_id = c_to.object_id
                AND fkc.referenced_column_id = c_to.column_id
            WHERE s_from.name IN ({schema_list})
        """
        async with conn.cursor() as cur:
            await cur.execute(query)
            cols = [d[0] for d in cur.description]
            rows = await cur.fetchall()
        return [dict(zip(cols, row)) for row in rows]

    async def _fetch_primary_keys(self, conn) -> list[dict]:
        schema_list = ", ".join(f"'{s}'" for s in self.target_schemas)
        query = f"""
            SELECT
                s.name  AS table_schema,
                t.name  AS table_name,
                c.name  AS column_name
            FROM sys.indexes i
            JOIN sys.tables t   ON i.object_id  = t.object_id
            JOIN sys.schemas s  ON t.schema_id  = s.schema_id
            JOIN sys.index_columns ic
                ON i.object_id = ic.object_id AND i.index_id = ic.index_id
            JOIN sys.columns c
                ON ic.object_id = c.object_id AND ic.column_id = c.column_id
            WHERE i.is_primary_key = 1
                AND s.name IN ({schema_list})
        """
        async with conn.cursor() as cur:
            await cur.execute(query)
            cols = [d[0] for d in cur.description]
            rows = await cur.fetchall()
        return [dict(zip(cols, row)) for row in rows]

    async def _fetch_check_constraints(self, conn) -> list[dict]:
        schema_list = ", ".join(f"'{s}'" for s in self.target_schemas)
        query = f"""
            SELECT
                s.name          AS table_schema,
                t.name          AS table_name,
                cc.definition   AS check_clause
            FROM sys.check_constraints cc
            JOIN sys.tables t  ON cc.parent_object_id = t.object_id
            JOIN sys.schemas s ON t.schema_id          = s.schema_id
            WHERE s.name IN ({schema_list})
        """
        async with conn.cursor() as cur:
            await cur.execute(query)
            cols = [d[0] for d in cur.description]
            rows = await cur.fetchall()
        return [dict(zip(cols, row)) for row in rows]

    async def _fetch_indexes(self, conn) -> list[dict]:
        schema_list = ", ".join(f"'{s}'" for s in self.target_schemas)
        query = f"""
            SELECT
                s.name      AS schemaname,
                t.name      AS tablename,
                i.name      AS indexname,
                i.type_desc AS indexdef,
                0           AS index_size_bytes
            FROM sys.indexes i
            JOIN sys.tables t  ON i.object_id = t.object_id
            JOIN sys.schemas s ON t.schema_id  = s.schema_id
            WHERE i.type > 0
                AND s.name IN ({schema_list})
            ORDER BY s.name, t.name, i.name
        """
        async with conn.cursor() as cur:
            await cur.execute(query)
            cols = [d[0] for d in cur.description]
            rows = await cur.fetchall()
        return [dict(zip(cols, row)) for row in rows]

    async def _fetch_table_stats(self, conn) -> list[dict]:
        schema_list = ", ".join(f"'{s}'" for s in self.target_schemas)
        query = f"""
            SELECT
                s.name              AS schemaname,
                t.name              AS tablename,
                SUM(ps.row_count)   AS estimated_row_count,
                SUM(ps.used_page_count) * 8 * 1024 AS total_size_bytes
            FROM sys.tables t
            JOIN sys.schemas s ON t.schema_id = s.schema_id
            JOIN sys.dm_db_partition_stats ps ON t.object_id = ps.object_id
            WHERE ps.index_id IN (0, 1)
                AND s.name IN ({schema_list})
            GROUP BY s.name, t.name
        """
        async with conn.cursor() as cur:
            await cur.execute(query)
            cols = [d[0] for d in cur.description]
            rows = await cur.fetchall()
        return [dict(zip(cols, row)) for row in rows]

    async def _get_database_name(self) -> str:
        async with self._pool.acquire() as conn:
            async with conn.cursor() as cur:
                await cur.execute("SELECT DB_NAME()")
                row = await cur.fetchone()
                return row[0]

    def _assemble_tables(
        self,
        columns_data, fk_data, check_data, index_data, stats_data, pk_data
    ) -> list[TableMetadata]:
        # Identical assembly logic to the PostgreSQL version —
        # the data shapes are the same once extracted
        fk_lookup: dict[tuple, list] = {}
        for fk in fk_data:
            key = (fk["table_schema"], fk["table_name"])
            fk_lookup.setdefault(key, []).append(fk)

        pk_lookup: dict[tuple, set] = {}
        for pk in pk_data:
            key = (pk["table_schema"], pk["table_name"])
            pk_lookup.setdefault(key, set()).add(pk["column_name"])

        check_lookup: dict[tuple, list] = {}
        for cc in check_data:
            key = (cc["table_schema"], cc["table_name"])
            check_lookup.setdefault(key, []).append(cc["check_clause"])

        index_lookup: dict[tuple, list] = {}
        for idx in index_data:
            key = (idx["schemaname"], idx["tablename"])
            index_lookup.setdefault(key, []).append(idx)

        stats_lookup: dict[tuple, dict] = {}
        for stat in stats_data:
            key = (stat["schemaname"], stat["tablename"])
            stats_lookup[key] = stat

        tables_dict: dict[tuple, dict] = {}
        for row in columns_data:
            key = (row["table_schema"], row["table_name"])
            if key not in tables_dict:
                tables_dict[key] = {
                    "schema_name": row["table_schema"],
                    "table_name": row["table_name"],
                    "table_comment": row.get("table_comment"),
                    "columns": [],
                }
            tables_dict[key]["columns"].append(row)

        result = []
        for key, tdata in tables_dict.items():
            fks = fk_lookup.get(key, [])
            fk_columns = {fk["column_name"]: fk for fk in fks}
            pks = pk_lookup.get(key, set())
            stats = stats_lookup.get(key, {})
            raw_indexes = index_lookup.get(key, [])

            columns = []
            for col in tdata["columns"]:
                fk_info = fk_columns.get(col["column_name"])
                columns.append(ColumnMetadata(
                    name=col["column_name"],
                    data_type=col["data_type"],
                    udt_name=col["data_type"],  # SQL Server has no udt_name distinction
                    is_nullable=bool(col["is_nullable"]),
                    column_default=col.get("column_default"),
                    comment=col.get("column_comment"),
                    is_primary_key=col["column_name"] in pks,
                    is_foreign_key=fk_info is not None,
                    foreign_table=(
                        f"{fk_info['foreign_table_schema']}.{fk_info['foreign_table_name']}"
                        if fk_info else None
                    ),
                    foreign_column=fk_info["foreign_column_name"] if fk_info else None,
                ))

            indexes = [
                IndexMetadata(
                    name=idx["indexname"],
                    definition=idx["indexdef"],
                    size_bytes=idx["index_size_bytes"],
                )
                for idx in raw_indexes
            ]

            result.append(TableMetadata(
                schema_name=key[0],
                table_name=key[1],
                table_comment=tdata["table_comment"],
                columns=columns,
                indexes=indexes,
                foreign_keys=fks,
                check_constraints=check_lookup.get(key, []),
                estimated_row_count=stats.get("estimated_row_count", 0),
                total_size_bytes=stats.get("total_size_bytes", 0),
            ))

        return sorted(result, key=lambda t: (t.schema_name, t.table_name))

Notice that the _assemble_tables method in SQLServerSchemaIntrospector is nearly identical to its PostgreSQL counterpart — once the raw catalog rows are normalized into the same Python dictionary shape, the assembly logic is database-agnostic. This is the payoff of defining the SchemaMetadata, TableMetadata, and ColumnMetadata models as a shared abstraction: the formatter, ranker, and text-to-SQL pipeline all work unchanged regardless of which database backend produced the metadata.

23.8 Prompt Engineering for Schema-Aware SQL Generation

Schema context alone does not guarantee good SQL. The way you structure the prompt — how you introduce the schema, how you phrase the task, and what constraints you impose — materially affects output quality. Here are the patterns that work in practice.

Presenting schema before the question, not after. LLMs process context sequentially, and positioning the schema block before the natural language question means the model's internal representation of the schema is built before it encounters the question. This improves alignment between which tables and columns the model attends to and which ones the question actually needs.

Annotating the schema with query-relevant hints. Beyond column comments, you can add a preamble block that surfaces patterns specific to your database:

def build_query_preamble(metadata: SchemaMetadata) -> str:
    """
    Generate a preamble that explains database-specific conventions to the LLM.
    This supplements the schema DDL with contextual rules that aren't expressible
    in DDL alone.
    """
    return f"""
-- QUERY CONVENTIONS FOR {metadata.database_name.upper()}
-- 
-- Monetary amounts: all _cents columns store values in USD cents (integer).
--   Divide by 100.0 for display. Never do arithmetic directly on mixed _cents and non-cents columns.
--
-- Soft deletes: tables with a `deleted_at` column are soft-deleted.
--   Always add: WHERE deleted_at IS NULL (unless the question explicitly asks for deleted records).
--
-- Timestamps: all timestamp columns are stored in UTC (TIMESTAMPTZ).
--   Use AT TIME ZONE 'UTC' only when converting for display; filter directly on UTC values.
--
-- Status columns: use the exact enum values shown in comments. Do not infer or abbreviate.
--
-- Pagination: do not add LIMIT unless the question requests "top N" or a specific count.
--
-- Current time: use NOW() or CURRENT_TIMESTAMP, not hardcoded dates.
"""

Multi-turn correction patterns. A single-shot prompt will sometimes generate SQL with logical errors that pass syntactic validation but return wrong results. A more robust pipeline adds a correction turn:

async def generate_with_correction(
    self,
    question: str,
    schema_context: str,
    max_attempts: int = 2,
) -> str:
    """
    Generate SQL, optionally run it, and if results look wrong,
    pass the error or unexpected result back for a correction attempt.
    """
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {
            "role": "user",
            "content": f"Schema:\n{schema_context}\n\nQuestion: {question}\n\nGenerate a PostgreSQL SELECT query.",
        },
    ]

    for attempt in range(max_attempts):
        response = await self.client.chat.completions.create(
            model=self.model,
            messages=messages,
            temperature=0,
            max_tokens=1024,
        )
        sql = self._strip_markdown(response.choices[0].message.content.strip())

        valid, error = await self._validate_sql(sql)
        if valid:
            return sql

        # Add the error to the conversation and ask for a correction
        messages.append({"role": "assistant", "content": sql})
        messages.append({
            "role": "user",
            "content": (
                f"That query has an error: {error}\n\n"
                f"Please fix the query. Output only the corrected SQL."
            ),
        })
        logger.info("SQL correction attempt %d for question: %s", attempt + 1, question)

    # Return last attempt even if still invalid — caller decides what to do
    return sql

Forbidden pattern enumeration. Rather than relying solely on the system prompt's general rules, you can enumerate the specific anti-patterns your database sees most often from LLMs. If your LLM consistently confuses orders.customer_id with customers.id in the wrong direction, name that pattern explicitly. If it tends to aggregate over non-aggregated columns without GROUP BY, state that. These targeted instructions reduce the probability of those specific failures without requiring a larger model.

def build_system_prompt_for_schema(metadata: SchemaMetadata) -> str:
    """
    Build a schema-specific system prompt that includes known anti-patterns
    observed in your query generation logs.
    """
    base = SYSTEM_PROMPT

    # Add schema-specific anti-patterns
    schema_specific = """

KNOWN ERRORS TO AVOID FOR THIS DATABASE:
- Do NOT join orders to customers using orders.id = customers.id.
  The correct join is: orders.customer_id = customers.id
- Do NOT filter on users.active = true. The column is users.is_active (boolean).
- The products table has both a `price_cents` column and a `discount_price_cents` column.
  Use `discount_price_cents` when the question asks for sale or discounted prices.
- When counting distinct customers, use COUNT(DISTINCT customer_id), not COUNT(*).
"""
    return base + schema_specific

These per-schema instructions should be generated from your actual query error logs, not invented ahead of time. The right workflow is: deploy, monitor failures, extract patterns, add them to the prompt. The prompt evolves as the system learns what your LLM gets wrong about your specific schema.

23.9 Exposing Schema Introspection as a Tool

If you're building an agent rather than a one-shot text-to-SQL endpoint, schema introspection is a natural tool. Rather than injecting the full schema into every message, give the agent tools to explore the schema on demand: list tables, describe a table, look up column details, find related tables. The agent decides which parts of the schema it needs.

# schema_tools.py
# Schema introspection exposed as LLM-callable tools (function calling)

import json
from schema_introspector import SchemaIntrospector, SchemaMetadata
from schema_formatter import SchemaFormatter


class SchemaTools:
    """
    Exposes schema introspection as tools the LLM can call during query generation.
    Each method maps to one tool definition in the OpenAI tools format.
    """

    def __init__(self, introspector: SchemaIntrospector, formatter: SchemaFormatter):
        self.introspector = introspector
        self.formatter = formatter
        self._metadata: SchemaMetadata | None = None

    async def _get_metadata(self) -> SchemaMetadata:
        if self._metadata is None:
            self._metadata = await self.introspector.get_schema_metadata()
        return self._metadata

    # --- Tool implementations ---

    async def list_tables(self, schema_name: str = None) -> str:
        """List all tables with brief descriptions. Optionally filter by schema."""
        metadata = await self._get_metadata()
        results = []
        for t in metadata.tables:
            if schema_name and t.schema_name != schema_name:
                continue
            comment = f" — {t.table_comment}" if t.table_comment else ""
            results.append(
                f"{t.schema_name}.{t.table_name}{comment} "
                f"({t.estimated_row_count:,} rows)"
            )
        return "\n".join(results) if results else "No tables found."

    async def describe_table(self, table_name: str) -> str:
        """Return full DDL description of a specific table including columns, indexes, and FK relationships."""
        metadata = await self._get_metadata()

        # Accept either schema.table or just table
        target_tables = [
            t for t in metadata.tables
            if t.table_name == table_name
            or f"{t.schema_name}.{t.table_name}" == table_name
        ]

        if not target_tables:
            return f"Table '{table_name}' not found. Use list_tables() to see available tables."

        from schema_introspector import SchemaMetadata as SM
        filtered = SM(
            database_name=metadata.database_name,
            extracted_at=metadata.extracted_at,
            tables=target_tables,
            schema_hash=metadata.schema_hash,
        )
        return self.formatter.format_as_ddl(filtered, include_indexes=True, include_row_counts=True)

    async def find_related_tables(self, table_name: str) -> str:
        """Find all tables that have a FK relationship with the given table (in either direction)."""
        metadata = await self._get_metadata()

        related = set()
        for t in metadata.tables:
            full_name = f"{t.schema_name}.{t.table_name}"
            if t.table_name == table_name or full_name == table_name:
                for fk in t.foreign_keys:
                    related.add(f"{fk['foreign_table_schema']}.{fk['foreign_table_name']}")
            for fk in t.foreign_keys:
                ref = f"{fk['foreign_table_schema']}.{fk['foreign_table_name']}"
                if fk["foreign_table_name"] == table_name or ref == table_name:
                    related.add(full_name)

        if not related:
            return f"No FK relationships found for '{table_name}'."
        return "Related tables:\n" + "\n".join(sorted(related))

    async def search_columns(self, search_term: str) -> str:
        """Find columns across all tables whose name or comment contains the search term."""
        metadata = await self._get_metadata()
        term = search_term.lower()
        results = []
        for t in metadata.tables:
            for col in t.columns:
                name_match = term in col.name.lower()
                comment_match = col.comment and term in col.comment.lower()
                if name_match or comment_match:
                    fk_info = f" → {col.foreign_table}.{col.foreign_column}" if col.is_foreign_key else ""
                    comment_str = f": {col.comment}" if col.comment else ""
                    results.append(
                        f"{t.schema_name}.{t.table_name}.{col.name} "
                        f"({col.udt_name}){fk_info}{comment_str}"
                    )
        if not results:
            return f"No columns matching '{search_term}' found."
        return f"Columns matching '{search_term}':\n" + "\n".join(results)

    # --- Tool definitions for OpenAI function calling ---

    @staticmethod
    def tool_definitions() -> list[dict]:
        return [

                    ),
                    "parameters": {
                        "type": "object",
                        "properties": {
                            "schema_name": {
                                "type": "string",
                                "description": "Optional PostgreSQL schema name to filter by (e.g., 'public'). Omit to list all schemas.",
                            }
                        },
                        "required": [],
                    },
                },
            },
            {
                "type": "function",
                "function": {

                    "description": (

                    ),
                    "parameters": {
                        "type": "object",
                        "properties": {
                            "table_name": {
                                "type": "string",
                                "description": "Table name, optionally qualified as schema.table (e.g., 'orders' or 'public.orders').",
                            }
                        },

                    },

                "type": "function",
                "function": {

                },
            },
        ]

    async def dispatch_tool_call(self, tool_name: str, arguments: dict) -> str:
        """Route a tool call from the LLM to the correct method."""
        dispatch = {
            "list_tables": self.list_tables,
            "describe_table": self.describe_table,
            "find_related_tables": self.find_related_tables,
            "search_columns": self.search_columns,
        }
        handler = dispatch.get(tool_name)
        if handler is None:
            return f"Unknown tool: {tool_name}"
        return await handler(**arguments)

With these tools defined, you can wire them into an agentic loop that lets the LLM build its own understanding of the schema before generating SQL:

# agentic_text_to_sql.py
# Agent loop: LLM explores schema via tools, then generates SQL

import json
import logging
from openai import AsyncOpenAI
from schema_tools import SchemaTools

logger = logging.getLogger(__name__)

AGENT_SYSTEM_PROMPT = """You are a PostgreSQL SQL generation agent. You have access to tools that let you explore the database schema.

Workflow:
1. Use list_tables() to get an overview of available tables.
2. Use describe_table() to get full details for tables that seem relevant.
3. Use find_related_tables() to discover JOIN paths when a question involves multiple entities.
4. Use search_columns() when you need to find where a specific piece of data lives.
5. Once you have enough schema context, generate a correct PostgreSQL SELECT query.

When generating the final SQL:
- Output ONLY the SQL query preceded by the exact token: FINAL_SQL:
- The SQL must be a SELECT statement only.
- Qualify all column references with table aliases when joining.
- Use explicit JOIN syntax.
"""


async def agentic_sql_generation(
    question: str,
    schema_tools: SchemaTools,
    client: AsyncOpenAI,
    model: str = "gpt-4o",
    max_tool_calls: int = 8,
) -> str:
    """
    Runs an agentic loop where the LLM uses schema exploration tools
    to build context before generating the final SQL.
    Returns the generated SQL string.
    """
    messages = [
        {"role": "system", "content": AGENT_SYSTEM_PROMPT},
        {"role": "user", "content": f"Question: {question}"},
    ]

    tool_call_count = 0

    while tool_call_count < max_tool_calls:
        response = await client.chat.completions.create(
            model=model,
            messages=messages,
            tools=SchemaTools.tool_definitions(),
            tool_choice="auto",
            temperature=0,
            max_tokens=2048,
        )

        choice = response.choices[0]
        messages.append({"role": "assistant", "content": choice.message.content, "tool_calls": choice.message.tool_calls})

        # Check if the model produced a final SQL answer
        content = choice.message.content or ""
        if "FINAL_SQL:" in content:
            sql_part = content.split("FINAL_SQL:", 1)[1].strip()
            # Strip any accidental markdown fences
            sql_part = sql_part.replace("```sql", "").replace("```", "").strip()
            return sql_part

        # If no tool calls and no FINAL_SQL, the model is done but didn't follow format
        if not choice.message.tool_calls:
            logger.warning("Agent finished without tool calls or FINAL_SQL token")
            return content.strip()

        # Process tool calls
        for tool_call in choice.message.tool_calls:
            tool_name = tool_call.function.name
            try:
                arguments = json.loads(tool_call.function.arguments)
            except json.JSONDecodeError:
                arguments = {}

            logger.debug("Agent calling tool: %s(%s)", tool_name, arguments)
            tool_result = await schema_tools.dispatch_tool_call(tool_name, arguments)
            tool_call_count += 1

            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": tool_result,
            })

    # Exceeded max tool calls — ask for final answer with what we have
    messages.append({
        "role": "user",
        "content": "You have explored the schema. Now generate the final SQL query. Start your response with FINAL_SQL:",
    })
    response = await client.chat.completions.create(
        model=model,
        messages=messages,
        temperature=0,
        max_tokens=1024,
    )
    content = response.choices[0].message.content or ""
    if "FINAL_SQL:" in content:
        return content.split("FINAL_SQL:", 1)[1].strip().replace("```sql", "").replace("```", "").strip()
    return content.strip()

The agentic approach trades latency for accuracy on complex queries. A simple question that touches one well-named table might be answered correctly from the injected system prompt alone. A complex question that spans six tables with non-obvious join paths benefits substantially from having the agent call find_related_tables and describe_table iteratively before committing to a query structure. In production, you can use the single-shot pipeline for simple questions (detected by table ranker confidence scores) and fall back to the agent for low-confidence or high-complexity cases.

For SQL quality testing — which is distinct from infrastructure testing — you need a golden dataset: a collection of natural language questions paired with known-correct SQL queries and their expected results. Build this dataset from your production query logs by sampling queries that human analysts have already written, then use those as ground truth. This approach is preferable to synthetically generated test cases because it tests the distribution of questions your actual users ask.

# quality_evaluator.py
# Evaluate text-to-SQL quality against a golden dataset

import asyncio
import json
from dataclasses import dataclass
from typing import Optional

import asyncpg


@dataclass
class GoldenQuery:
    question: str
    expected_sql: str
    expected_row_count: Optional[int]  # None means "don't check count"
    tags: list[str]  # e.g. ["join", "aggregation", "subquery"]


@dataclass
class EvalResult:
    question: str
    generated_sql: str
    expected_sql: str
    syntactically_valid: bool
    row_count_matches: bool
    result_set_matches: bool
    tags: list[str]


class SQLQualityEvaluator:
    """
    Runs generated SQL against expected SQL on a real database and compares results.
    Does not check textual SQL equivalence (two different SQL strings can be equally correct);
    instead compares the actual result sets.
    """

    def __init__(self, pool: asyncpg.Pool):
        self.pool = pool

    async def evaluate(
        self,
        generated_sql: str,
        golden: GoldenQuery,
        row_limit: int = 1000,
    ) -> EvalResult:
        syntactically_valid = True
        row_count_matches = False
        result_set_matches = False

        try:
            async with self.pool.acquire() as conn:
                # A bare "SET TRANSACTION READ ONLY" outside an explicit
                # BEGIN only applies to the single implicit statement-level
                # transaction it runs in, not the fetches that follow — use
                # conn.transaction(readonly=True) so it actually covers them.
                async with conn.transaction(readonly=True):
                    expected_rows = await conn.fetch(
                        f"SELECT * FROM ({golden.expected_sql}) _expected LIMIT {row_limit}"
                    )
                    generated_rows = await conn.fetch(
                        f"SELECT * FROM ({generated_sql}) _generated LIMIT {row_limit}"
                    )

                # Normalize rows for comparison (ignore column ordering differences)
                expected_set = self._normalize_rows(expected_rows)
                generated_set = self._normalize_rows(generated_rows)

                row_count_matches = len(expected_set) == len(generated_set)
                result_set_matches = expected_set == generated_set

        except asyncpg.PostgresError as e:
            syntactically_valid = False

        return EvalResult(
            question=golden.question,
            generated_sql=generated_sql,
            expected_sql=golden.expected_sql,
            syntactically_valid=syntactically_valid,
            row_count_matches=row_count_matches,
            result_set_matches=result_set_matches,
            tags=golden.tags,
        )

    def _normalize_rows(self, rows: list) -> frozenset:
        """Convert rows to a frozenset of sorted-key tuples for order-independent comparison."""
        normalized = set()
        for row in rows:
            d = dict(row)
            # Convert all values to strings for stable comparison
            normalized.add(tuple(sorted((k, str(v)) for k, v in d.items())))
        return frozenset(normalized)

    async def run_suite(
        self,
        golden_queries: list[GoldenQuery],
        pipeline,  # TextToSQLPipeline instance
    ) -> dict:
        """Run the full evaluation suite and return aggregate metrics."""
        results = []
        for golden in golden_queries:
            gen_result = await pipeline.generate(question=golden.question, execute=False)
            eval_result = await self.evaluate(gen_result.generated_sql, golden)
            results.append(eval_result)

        total = len(results)
        valid = sum(1 for r in results if r.syntactically_valid)
        count_match = sum(1 for r in results if r.row_count_matches)
        exact_match = sum(1 for r in results if r.result_set_matches)

        # Break down by tag
        tag_metrics: dict[str, dict] = {}
        for result in results:
            for tag in result.tags:
                if tag not in tag_metrics:
                    tag_metrics[tag] = {"total": 0, "exact_match": 0}
                tag_metrics[tag]["total"] += 1
                if result.result_set_matches:
                    tag_metrics[tag]["exact_match"] += 1

        return {
            "total_questions": total,
            "syntactic_validity_rate": valid / total if total else 0,
            "row_count_match_rate": count_match / total if total else 0,
            "exact_result_match_rate": exact_match / total if total else 0,
            "by_tag": {
                tag: {
                    "accuracy": m["exact_match"] / m["total"] if m["total"] else 0,
                    "total": m["total"],
                }
                for tag, m in tag_metrics.items()
            },
            "failures": [
                {
                    "question": r.question,
                    "generated_sql": r.generated_sql,
                    "expected_sql": r.expected_sql,
                    "error": "invalid" if not r.syntactically_valid else "wrong_results",
                }
                for r in results
                if not r.result_set_matches
            ],
        }

The result-set comparison approach — running both the expected and generated SQL and comparing their outputs — is more reliable than string-based SQL comparison because it treats semantically equivalent queries as equal. SELECT a, b FROM t and SELECT t.a, t.b FROM t produce identical results and should both pass. Pure string matching would fail the second one. The downside is that result comparison requires a live database seeded with representative data, which adds setup cost to your test pipeline. That cost is worth paying: a text-to-SQL system with unvalidated output quality is a liability, not a feature.

Key Takeaways

  • → **PostgreSQL's system catalog is the foundation of schema-aware AI.** The `pg_catalog` views — combined with `COMMENT ON TABLE` and `COMMENT ON COLUMN` documentation — give LLMs the precise, machine-readable context they need to generate correct SQL rather than plausible-sounding guesses. Investing in catalog comments pays dividends across every AI feature you build on top of your database.
  • → **Format schema as DDL for SQL generation tasks.** Presenting schema to an LLM as `CREATE TABLE` statements exploits the model's training distribution and produces better SQL than custom JSON or prose formats. For large schemas, the compact and selective formatters let you stay within context window budgets without sacrificing the tables the query actually needs.
  • → **Hybrid table ranking — keyword matching plus semantic embeddings — handles both exact-name queries and intent-based questions.** Neither technique alone is sufficient: keyword matching misses synonym-based questions, and pure semantic search can miss verbatim table name references. Pre-computing table embeddings at schema index time keeps per-query latency low.
  • → **Validate SQL with `EXPLAIN` before executing it.** A successful `EXPLAIN` inside a read-only transaction confirms that PostgreSQL parsed the query, resolved all table and column references, and built a query plan — catching the most common LLM failure modes without the cost or risk of actual execution. Layer safety checks on top to reject non-SELECT statements before they ever reach the database.
  • → **Schema introspection infrastructure must stay synchronized with the live schema.** Stale schema context generates wrong SQL as reliably as no schema context. Cache aggressively, but pair every cache with a change-detection mechanism — whether polling `pg_catalog` fingerprints or listening for `NOTIFY schema_changed` events — so your AI layer never reasons about a schema that no longer exists.
