Chapter 34: Caching AI Results in PostgreSQL

AI inference is expensive. A single GPT-4 call with a 2,000-token prompt costs real money, and at scale — thousands of users, millions of queries — those costs compound fast. Latency is equally punishing: users waiting 3–8 seconds for every response abandon features. This chapter builds a complete caching layer for AI results directly inside PostgreSQL, covering exact-match caching, semantic similarity caching with pgvector, cache invalidation strategies, and the operational patterns that keep your cache healthy in production. You'll see how PostgreSQL's combination of transactional safety, JSONB flexibility, and vector search makes it a uniquely capable caching backend — one that understands the meaning of queries, not just their text.

---

34.1 Why Cache AI Results — and Why PostgreSQL Is the Right Place

Every AI application has a distribution of queries that looks roughly the same: a fat tail of rare, unique queries and a surprisingly large bulk of semantically similar questions asked repeatedly in different words. "What are your business hours?" "When do you open?" "Are you open on Saturdays?" These are three different strings that map to the same answer. A naive string-match cache misses all of that. A vector similarity cache catches it.

PostgreSQL with pgvector is the right place for this cache because:

1. Your application data already lives there. Cache entries can reference users, sessions, documents, and products with foreign keys — giving you invalidation triggers when source data changes.

2. Transactional integrity. A cache write and a conversation history insert happen in one transaction. No partial states.

3. pgvector's <=> operator turns semantic matching into a standard SQL query with an index. No separate infrastructure.

4. Row-level security lets you scope caches per tenant without query-level filtering code.

5. pg_notify enables real-time cache invalidation across application servers.

The alternative — Redis + a separate vector store + your relational database — requires you to keep three systems in sync. PostgreSQL handles all three roles.

graph TD
    Q[Incoming prompt] --> N[Normalize text]
    N --> E{Exact-match hit?}
    E -->|yes| R1[Return cached response]
    E -->|no| S{Semantic similarity\nabove threshold?}
    S -->|yes| R2[Return cached response]
    S -->|no| L[Call LLM]
    L --> Store[Store response +\nembedding in cache]
    Store --> R3[Return fresh response]

*Two-tier lookup: cheap exact-match string matching first, pgvector cosine-similarity search second, and only a cache miss on both tiers reaches the LLM.*

#### Core schema design

-- Cache schema: all AI caching infrastructure lives here
CREATE SCHEMA IF NOT EXISTS ai_cache;

-- Exact-match cache for deterministic lookups
CREATE TABLE ai_cache.exact_results (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    tenant_id           UUID REFERENCES public.tenants(id) ON DELETE CASCADE,
    model               TEXT NOT NULL,           -- 'gpt-4o', 'claude-3-5-sonnet-20241022'
    prompt_hash         TEXT NOT NULL,           -- SHA-256 of the raw prompt
    normalized_prompt   TEXT NOT NULL,           -- lowercase, stripped prompt
    response_text       TEXT NOT NULL,
    response_metadata   JSONB NOT NULL DEFAULT '{}',  -- token counts, finish reason, etc.
    token_input         INTEGER,
    token_output        INTEGER,
    cost_usd            NUMERIC(10, 6),
    hit_count           INTEGER NOT NULL DEFAULT 0,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    expires_at          TIMESTAMPTZ,
    last_hit_at         TIMESTAMPTZ,
    invalidated_at      TIMESTAMPTZ,
    CONSTRAINT uq_exact_cache_key UNIQUE (cache_key)
);

-- Semantic similarity cache using pgvector
CREATE TABLE ai_cache.semantic_results (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id           UUID REFERENCES public.tenants(id) ON DELETE CASCADE,
    model               TEXT NOT NULL,
    embedding_model     TEXT NOT NULL DEFAULT 'text-embedding-3-small',
    prompt_text         TEXT NOT NULL,
    prompt_embedding    vector(1536) NOT NULL,
    response_text       TEXT NOT NULL,
    response_metadata   JSONB NOT NULL DEFAULT '{}',
    token_input         INTEGER,
    token_output        INTEGER,
    cost_usd            NUMERIC(10, 6),
    similarity_threshold NUMERIC(4, 3) NOT NULL DEFAULT 0.92,
    hit_count           INTEGER NOT NULL DEFAULT 0,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    expires_at          TIMESTAMPTZ,
    last_hit_at         TIMESTAMPTZ,
    invalidated_at      TIMESTAMPTZ,
    source_document_ids UUID[] DEFAULT '{}',     -- for invalidation when docs change
    tags                TEXT[] DEFAULT '{}'
);

-- HNSW index for fast approximate nearest-neighbor search
CREATE INDEX idx_semantic_cache_embedding
    ON ai_cache.semantic_results
    USING hnsw (prompt_embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 64);

-- Partial index: only active (non-invalidated, non-expired) entries
CREATE INDEX idx_semantic_cache_active
    ON ai_cache.semantic_results (tenant_id, model, created_at)
    WHERE invalidated_at IS NULL AND (expires_at IS NULL OR expires_at > now());

CREATE INDEX idx_exact_cache_active
    ON ai_cache.exact_results (cache_key)
    WHERE invalidated_at IS NULL AND (expires_at IS NULL OR expires_at > now());

-- Cache analytics table — track hits and costs saved
CREATE TABLE ai_cache.access_log (
    id              BIGSERIAL PRIMARY KEY,
    cache_type      TEXT NOT NULL CHECK (cache_type IN ('exact', 'semantic', 'miss')),
    cache_entry_id  UUID,
    tenant_id       UUID,
    model           TEXT,
    similarity      NUMERIC(6, 4),      -- NULL for exact hits
    latency_ms      INTEGER,
    cost_saved_usd  NUMERIC(10, 6),
    accessed_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_access_log_tenant_time
    ON ai_cache.access_log (tenant_id, accessed_at DESC);

34.2 Exact-Match Caching: The First Line of Defense

Exact-match caching is the cheapest, fastest layer. Before calling any LLM, normalize the prompt and compute a cache key. If that key exists in the cache and hasn't expired, return it immediately.

Normalization matters more than it seems. "What are your hours?" and "What are your hours? " (trailing space) are the same question. Lowercase folding, whitespace normalization, and stripping common filler phrases dramatically increase your exact-hit rate.

-- Function: normalize a prompt for exact cache lookup
CREATE OR REPLACE FUNCTION ai_cache.normalize_prompt(raw_prompt TEXT)
RETURNS TEXT
LANGUAGE plpgsql IMMUTABLE STRICT
AS $$
DECLARE
    normalized TEXT;
BEGIN
    -- Lowercase
    normalized := lower(raw_prompt);
    -- Collapse whitespace
    normalized := regexp_replace(normalized, '\s+', ' ', 'g');
    -- Strip leading/trailing whitespace
    normalized := trim(normalized);
    -- Remove trailing punctuation variations (optional, tune per use case)
    normalized := regexp_replace(normalized, '[.!?]+$', '', 'g');
    RETURN normalized;
END;
$$;

-- Function: compute cache key from model + normalized prompt
CREATE OR REPLACE FUNCTION ai_cache.compute_cache_key(
    p_model TEXT,
    p_normalized_prompt TEXT,
    p_tenant_id UUID DEFAULT NULL
)
RETURNS TEXT
LANGUAGE sql IMMUTABLE STRICT
AS $$
    SELECT encode(
        sha256(
            (COALESCE(p_tenant_id::TEXT, '') || '|' || p_model || '|' || p_normalized_prompt)::bytea
        ),
        'hex'
    );
$$;

-- Function: look up exact cache hit and bump hit counter atomically
CREATE OR REPLACE FUNCTION ai_cache.lookup_exact(
    p_model         TEXT,
    p_prompt        TEXT,
    p_tenant_id     UUID DEFAULT NULL
)
RETURNS TABLE (
    cache_id        UUID,
    response_text   TEXT,
    response_meta   JSONB,
    hit_count       INTEGER
)
LANGUAGE plpgsql
AS $$
DECLARE
    v_normalized    TEXT;
    v_cache_key     TEXT;
BEGIN
    v_normalized := ai_cache.normalize_prompt(p_prompt);
    v_cache_key  := ai_cache.compute_cache_key(p_model, v_normalized, p_tenant_id);

    RETURN QUERY
    UPDATE ai_cache.exact_results
    SET
        hit_count   = ai_cache.exact_results.hit_count + 1,
        last_hit_at = now()
    WHERE
        cache_key       = v_cache_key
        AND invalidated_at IS NULL
        AND (expires_at IS NULL OR expires_at > now())
    RETURNING
        id,
        ai_cache.exact_results.response_text,
        response_metadata,
        ai_cache.exact_results.hit_count;
END;
$$;

-- Function: store a new exact cache entry
CREATE OR REPLACE FUNCTION ai_cache.store_exact(
    p_model             TEXT,
    p_prompt            TEXT,
    p_response_text     TEXT,
    p_response_metadata JSONB,
    p_tenant_id         UUID DEFAULT NULL,
    p_token_input       INTEGER DEFAULT NULL,
    p_token_output      INTEGER DEFAULT NULL,
    p_cost_usd          NUMERIC DEFAULT NULL,
    p_ttl_seconds       INTEGER DEFAULT NULL
)
RETURNS UUID
LANGUAGE plpgsql
AS $$
DECLARE
    v_normalized    TEXT;
    v_cache_key     TEXT;
    v_prompt_hash   TEXT;
    v_expires_at    TIMESTAMPTZ;
    v_id            UUID;
BEGIN
    v_normalized  := ai_cache.normalize_prompt(p_prompt);
    v_cache_key   := ai_cache.compute_cache_key(p_model, v_normalized, p_tenant_id);
    v_prompt_hash := encode(sha256(p_prompt::bytea), 'hex');
    v_expires_at  := CASE WHEN p_ttl_seconds IS NOT NULL
                          THEN now() + (p_ttl_seconds || ' seconds')::interval
                          ELSE NULL END;

    INSERT INTO ai_cache.exact_results (
        cache_key, tenant_id, model, prompt_hash, normalized_prompt,
        response_text, response_metadata, token_input, token_output,
        cost_usd, expires_at
    )
    VALUES (
        v_cache_key, p_tenant_id, p_model, v_prompt_hash, v_normalized,
        p_response_text, p_response_metadata, p_token_input, p_token_output,
        p_cost_usd, v_expires_at
    )
    ON CONFLICT (cache_key) DO UPDATE
        SET response_text     = EXCLUDED.response_text,
            response_metadata = EXCLUDED.response_metadata,
            token_input       = EXCLUDED.token_input,
            token_output      = EXCLUDED.token_output,
            cost_usd          = EXCLUDED.cost_usd,
            expires_at        = EXCLUDED.expires_at,
            invalidated_at    = NULL  -- un-invalidate on refresh
    RETURNING id INTO v_id;

    RETURN v_id;
END;
$$;

34.3 Semantic Similarity Caching with pgvector

Exact caching handles repeats. Semantic caching handles paraphrases. The idea is simple: embed the incoming prompt, then search the cache for stored prompts whose embeddings are within a cosine similarity threshold. If you find one, return its cached response.

The threshold is the critical tuning knob. Too low (0.80) and you'll return answers to semantically adjacent but actually different questions. Too high (0.99) and you'll miss obvious paraphrases. A starting point of 0.92 works well for factual Q&A. For creative or nuanced tasks, raise it to 0.95.

-- Function: semantic cache lookup
CREATE OR REPLACE FUNCTION ai_cache.lookup_semantic(
    p_model             TEXT,
    p_prompt_embedding  vector(1536),
    p_tenant_id         UUID DEFAULT NULL,
    p_similarity_threshold NUMERIC DEFAULT 0.92,
    p_limit             INTEGER DEFAULT 1
)
RETURNS TABLE (
    cache_id        UUID,
    response_text   TEXT,
    response_meta   JSONB,
    similarity      NUMERIC,
    hit_count       INTEGER
)
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN QUERY
    WITH candidates AS (
        SELECT
            id,
            ai_cache.semantic_results.response_text,
            response_metadata,
            1 - (prompt_embedding <=> p_prompt_embedding) AS cosine_similarity,
            ai_cache.semantic_results.hit_count
        FROM ai_cache.semantic_results
        WHERE
            model           = p_model
            AND (tenant_id = p_tenant_id OR (tenant_id IS NULL AND p_tenant_id IS NULL))
            AND invalidated_at IS NULL
            AND (expires_at IS NULL OR expires_at > now())
        ORDER BY prompt_embedding <=> p_prompt_embedding
        LIMIT 10  -- retrieve top-10 candidates from HNSW, then filter
    )
    SELECT
        id,
        candidates.response_text,
        response_metadata,
        cosine_similarity::NUMERIC,
        candidates.hit_count
    FROM candidates
    WHERE cosine_similarity >= p_similarity_threshold
    ORDER BY cosine_similarity DESC
    LIMIT p_limit;

    -- Update hit count for the returned entry (fire and forget via a CTE)
    UPDATE ai_cache.semantic_results sr
    SET
        hit_count   = sr.hit_count + 1,
        last_hit_at = now()
    FROM (
        SELECT id FROM ai_cache.semantic_results
        WHERE
            model = p_model
            AND (tenant_id = p_tenant_id OR (tenant_id IS NULL AND p_tenant_id IS NULL))
            AND invalidated_at IS NULL
            AND (expires_at IS NULL OR expires_at > now())
        ORDER BY prompt_embedding <=> p_prompt_embedding
        LIMIT 1
    ) AS top
    WHERE sr.id = top.id
      AND (1 - (sr.prompt_embedding <=> p_prompt_embedding)) >= p_similarity_threshold;
END;
$$;

-- Function: store semantic cache entry
CREATE OR REPLACE FUNCTION ai_cache.store_semantic(
    p_model                 TEXT,
    p_embedding_model       TEXT,
    p_prompt_text           TEXT,
    p_prompt_embedding      vector(1536),
    p_response_text         TEXT,
    p_response_metadata     JSONB,
    p_tenant_id             UUID DEFAULT NULL,
    p_token_input           INTEGER DEFAULT NULL,
    p_token_output          INTEGER DEFAULT NULL,
    p_cost_usd              NUMERIC DEFAULT NULL,
    p_ttl_seconds           INTEGER DEFAULT NULL,
    p_source_document_ids   UUID[] DEFAULT '{}',
    p_tags                  TEXT[] DEFAULT '{}'
)
RETURNS UUID
LANGUAGE plpgsql
AS $$
DECLARE
    v_expires_at    TIMESTAMPTZ;
    v_id            UUID;
BEGIN
    v_expires_at := CASE WHEN p_ttl_seconds IS NOT NULL
                         THEN now() + (p_ttl_seconds || ' seconds')::interval
                         ELSE NULL END;

    INSERT INTO ai_cache.semantic_results (
        tenant_id, model, embedding_model, prompt_text, prompt_embedding,
        response_text, response_metadata, token_input, token_output,
        cost_usd, expires_at, source_document_ids, tags
    )
    VALUES (
        p_tenant_id, p_model, p_embedding_model, p_prompt_text, p_prompt_embedding,
        p_response_text, p_response_metadata, p_token_input, p_token_output,
        p_cost_usd, v_expires_at, p_source_document_ids, p_tags
    )
    RETURNING id INTO v_id;

    RETURN v_id;
END;
$$;

Now the Python application layer that ties both cache layers together:

# ai_cache_client.py — Full two-tier caching client
# pip install openai anthropic asyncpg numpy pgvector

import hashlib
import time
import asyncio
import logging
from dataclasses import dataclass
from typing import Optional, Any
from uuid import UUID

import asyncpg
import numpy as np
from openai import AsyncOpenAI

logger = logging.getLogger(__name__)

@dataclass
class CacheResult:
    hit: bool
    cache_type: str          # 'exact', 'semantic', 'miss'
    response_text: str
    cache_id: Optional[UUID]
    similarity: Optional[float]
    latency_ms: int
    cost_saved_usd: Optional[float]


@dataclass
class LLMConfig:
    model: str
    embedding_model: str = "text-embedding-3-small"
    max_tokens: int = 1024
    temperature: float = 0.0
    exact_ttl_seconds: int = 86400 * 7    # 7 days for exact matches
    semantic_ttl_seconds: int = 86400 * 3  # 3 days for semantic matches
    similarity_threshold: float = 0.92
    # Approximate cost per 1M tokens (input/output) for ROI tracking
    cost_per_1m_input: float = 2.50
    cost_per_1m_output: float = 10.00


class PostgreSQLAICache:
    """
    Two-tier AI response cache backed by PostgreSQL + pgvector.
    
    Layer 1: Exact match via SHA-256 cache key
    Layer 2: Semantic similarity via cosine distance on embeddings
    """

    def __init__(
        self,
        pg_pool: asyncpg.Pool,
        openai_client: AsyncOpenAI,
        config: LLMConfig,
        tenant_id: Optional[UUID] = None,
    ):
        self.pool = pg_pool
        self.openai = openai_client
        self.config = config
        self.tenant_id = tenant_id

    async def _embed(self, text: str) -> list[float]:
        """Embed text using OpenAI's embedding model."""
        response = await self.openai.embeddings.create(
            model=self.config.embedding_model,
            input=text,
            encoding_format="float",
        )
        return response.data[0].embedding

    def _estimate_cost(
        self, input_tokens: int, output_tokens: int
    ) -> float:
        input_cost = (input_tokens / 1_000_000) * self.config.cost_per_1m_input
        output_cost = (output_tokens / 1_000_000) * self.config.cost_per_1m_output
        return round(input_cost + output_cost, 6)

    async def get(
        self,
        prompt: str,
        skip_exact: bool = False,
        skip_semantic: bool = False,
    ) -> CacheResult:
        """
        Look up a prompt in the two-tier cache.
        Returns CacheResult with hit=False if no cache entry found.
        """
        start = time.monotonic()

        async with self.pool.acquire() as conn:
            # --- Layer 1: Exact match ---
            if not skip_exact:
                rows = await conn.fetch(
                    "SELECT cache_id, response_text, response_meta, hit_count "
                    "FROM ai_cache.lookup_exact($1, $2, $3)",
                    self.config.model,
                    prompt,
                    self.tenant_id,
                )
                if rows:
                    row = rows[0]
                    latency_ms = int((time.monotonic() - start) * 1000)
                    logger.info(
                        "Exact cache hit: id=%s hits=%d latency=%dms",
                        row["cache_id"], row["hit_count"], latency_ms
                    )
                    await self._log_access(
                        conn, "exact", row["cache_id"], None, latency_ms
                    )
                    return CacheResult(
                        hit=True,
                        cache_type="exact",
                        response_text=row["response_text"],
                        cache_id=row["cache_id"],
                        similarity=1.0,
                        latency_ms=latency_ms,
                        cost_saved_usd=None,  # populated from stored metadata
                    )

            # --- Layer 2: Semantic similarity ---
            if not skip_semantic:
                embedding = await self._embed(prompt)
                embedding_str = "[" + ",".join(str(x) for x in embedding) + "]"

                rows = await conn.fetch(
                    "SELECT cache_id, response_text, response_meta, similarity, hit_count "
                    "FROM ai_cache.lookup_semantic($1, $2::vector, $3, $4)",
                    self.config.model,
                    embedding_str,
                    self.tenant_id,
                    self.config.similarity_threshold,
                )
                if rows:
                    row = rows[0]
                    latency_ms = int((time.monotonic() - start) * 1000)
                    similarity = float(row["similarity"])
                    logger.info(
                        "Semantic cache hit: id=%s similarity=%.4f latency=%dms",
                        row["cache_id"], similarity, latency_ms
                    )
                    await self._log_access(
                        conn, "semantic", row["cache_id"], similarity, latency_ms
                    )
                    return CacheResult(
                        hit=True,
                        cache_type="semantic",
                        response_text=row["response_text"],
                        cache_id=row["cache_id"],
                        similarity=similarity,
                        latency_ms=latency_ms,
                        cost_saved_usd=None,
                    )

        latency_ms = int((time.monotonic() - start) * 1000)
        return CacheResult(
            hit=False,
            cache_type="miss",
            response_text="",
            cache_id=None,
            similarity=None,
            latency_ms=latency_ms,
            cost_saved_usd=None,
        )

    async def set(
        self,
        prompt: str,
        response_text: str,
        response_metadata: dict,
        input_tokens: int,
        output_tokens: int,
        source_document_ids: Optional[list[UUID]] = None,
        tags: Optional[list[str]] = None,
    ) -> dict[str, UUID]:
        """
        Store a prompt/response pair in both cache tiers.
        Returns dict with 'exact_id' and 'semantic_id'.
        """
        cost_usd = self._estimate_cost(input_tokens, output_tokens)
        embedding = await self._embed(prompt)
        embedding_str = "[" + ",".join(str(x) for x in embedding) + "]"
        doc_ids = [str(d) for d in (source_document_ids or [])]
        tag_list = tags or []

        async with self.pool.acquire() as conn:
            async with conn.transaction():
                exact_id = await conn.fetchval(
                    "SELECT ai_cache.store_exact($1, $2, $3, $4, $5, $6, $7, $8, $9)",
                    self.config.model,
                    prompt,
                    response_text,
                    response_metadata,
                    self.tenant_id,
                    input_tokens,
                    output_tokens,
                    cost_usd,
                    self.config.exact_ttl_seconds,
                )

                semantic_id = await conn.fetchval(
                    "SELECT ai_cache.store_semantic($1, $2, $3, $4::vector, $5, $6, $7, $8, $9, $10, $11, $12, $13)",
                    self.config.model,
                    self.config.embedding_model,
                    prompt,
                    embedding_str,
                    response_text,
                    response_metadata,
                    self.tenant_id,
                    input_tokens,
                    output_tokens,
                    cost_usd,
                    self.config.semantic_ttl_seconds,
                    doc_ids,
                    tag_list,
                )

        return {"exact_id": exact_id, "semantic_id": semantic_id}

    async def get_or_generate(
        self,
        prompt: str,
        system_prompt: str = "",
        source_document_ids: Optional[list[UUID]] = None,
        tags: Optional[list[str]] = None,
    ) -> tuple[str, CacheResult]:
        """
        Full cache-aside pattern: check cache, call LLM on miss, store result.
        Returns (response_text, cache_result).
        """
        # Check cache first
        cache_result = await self.get(prompt)
        if cache_result.hit:
            return cache_result.response_text, cache_result

        # Cache miss — call the LLM
        messages = []
        if system_prompt:
            messages.append({"role": "system", "content": system_prompt})
        messages.append({"role": "user", "content": prompt})

        start = time.monotonic()
        response = await self.openai.chat.completions.create(
            model=self.config.model,
            messages=messages,
            max_tokens=self.config.max_tokens,
            temperature=self.config.temperature,
        )
        llm_latency_ms = int((time.monotonic() - start) * 1000)

        response_text = response.choices[0].message.content
        input_tokens = response.usage.prompt_tokens
        output_tokens = response.usage.completion_tokens
        metadata = {
            "finish_reason": response.choices[0].finish_reason,
            "llm_latency_ms": llm_latency_ms,
            "system_fingerprint": getattr(response, "system_fingerprint", None),
        }

        # Store in cache
        ids = await self.set(
            prompt=prompt,
            response_text=response_text,
            response_metadata=metadata,
            input_tokens=input_tokens,
            output_tokens=output_tokens,
            source_document_ids=source_document_ids,
            tags=tags,
        )

        logger.info(
            "LLM call stored to cache: exact_id=%s semantic_id=%s tokens=%d+%d latency=%dms",
            ids["exact_id"], ids["semantic_id"],
            input_tokens, output_tokens, llm_latency_ms,
        )

        miss_result = CacheResult(
            hit=False,
            cache_type="miss",
            response_text=response_text,
            cache_id=ids["exact_id"],
            similarity=None,
            latency_ms=llm_latency_ms,
            cost_saved_usd=0.0,
        )
        return response_text, miss_result

    async def _log_access(
        self,
        conn: asyncpg.Connection,
        cache_type: str,
        cache_entry_id: UUID,
        similarity: Optional[float],
        latency_ms: int,
    ) -> None:
        await conn.execute(
            """
            INSERT INTO ai_cache.access_log
                (cache_type, cache_entry_id, tenant_id, model, similarity, latency_ms)
            VALUES ($1, $2, $3, $4, $5, $6)
            """,
            cache_type,
            cache_entry_id,
            self.tenant_id,
            self.config.model,
            similarity,
            latency_ms,
        )

34.4 Cache Invalidation Strategies

Cache invalidation in AI systems has a nuance that key-value caches don't face: the same semantic question can have multiple cached answers pointing to different source documents. When a document changes, you need to find every cache entry that was generated from it — and invalidate those specifically, without touching unrelated entries.

#### Strategy 1: Document-based invalidation via source_document_ids

When you store a cache entry, record which documents contributed to the response. A trigger on your documents table fires invalidation automatically.

-- Mark semantic cache entries stale when source documents change
CREATE OR REPLACE FUNCTION ai_cache.invalidate_by_document(
    p_document_id UUID,
    p_tenant_id   UUID DEFAULT NULL
)
RETURNS INTEGER
LANGUAGE plpgsql
AS $$
DECLARE
    v_count INTEGER;
BEGIN
    UPDATE ai_cache.semantic_results
    SET invalidated_at = now()
    WHERE
        p_document_id = ANY(source_document_ids)
        AND invalidated_at IS NULL
        AND (p_tenant_id IS NULL OR tenant_id = p_tenant_id);

    GET DIAGNOSTICS v_count = ROW_COUNT;

    -- Also invalidate exact cache entries tagged with this document
    UPDATE ai_cache.exact_results
    SET invalidated_at = now()
    WHERE
        response_metadata->>'source_document_id' = p_document_id::TEXT
        AND invalidated_at IS NULL
        AND (p_tenant_id IS NULL OR tenant_id = p_tenant_id);

    GET DIAGNOSTICS v_count = v_count + ROW_COUNT;

    -- Notify application servers via pg_notify
    PERFORM pg_notify(
        'ai_cache_invalidation',
        json_build_object(
            'reason', 'document_change',
            'document_id', p_document_id,
            'tenant_id', p_tenant_id,
            'invalidated_count', v_count,
            'at', now()
        )::TEXT
    );

    RETURN v_count;
END;
$$;

-- Trigger function: auto-invalidate cache when document content changes
CREATE OR REPLACE FUNCTION ai_cache.on_document_update()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    -- Only invalidate if content actually changed
    IF OLD.content IS DISTINCT FROM NEW.content
       OR OLD.updated_at IS DISTINCT FROM NEW.updated_at THEN
        PERFORM ai_cache.invalidate_by_document(NEW.id, NEW.tenant_id);
    END IF;
    RETURN NEW;
END;
$$;

-- Attach trigger to your documents table
CREATE TRIGGER trg_document_cache_invalidation
    AFTER UPDATE ON public.documents
    FOR EACH ROW
    EXECUTE FUNCTION ai_cache.on_document_update();

CREATE TRIGGER trg_document_delete_cache_invalidation
    AFTER DELETE ON public.documents
    FOR EACH ROW
    EXECUTE FUNCTION ai_cache.on_document_update();

#### Strategy 2: Tag-based invalidation

Tags give you a flexible way to invalidate thematic groups of cache entries — for example, all entries about "pricing" when your pricing page changes, or all entries in a "product_launch" campaign after the launch date.

CREATE OR REPLACE FUNCTION ai_cache.invalidate_by_tag(
    p_tag       TEXT,
    p_tenant_id UUID DEFAULT NULL
)
RETURNS INTEGER
LANGUAGE plpgsql
AS $$
DECLARE
    v_count INTEGER;
BEGIN
    UPDATE ai_cache.semantic_results
    SET invalidated_at = now()
    WHERE
        p_tag = ANY(tags)
        AND invalidated_at IS NULL
        AND (p_tenant_id IS NULL OR tenant_id = p_tenant_id);

    GET DIAGNOSTICS v_count = ROW_COUNT;

    PERFORM pg_notify(
        'ai_cache_invalidation',
        json_build_object(
            'reason', 'tag_invalidation',
            'tag', p_tag,
            'tenant_id', p_tenant_id,
            'invalidated_count', v_count,
            'at', now()
        )::TEXT
    );

    RETURN v_count;
END;
$$;

#### Strategy 3: TTL-based expiry and background cleanup

TTLs handle the case where you don't have explicit invalidation signals — you just want answers to expire after some period. The schema already stores expires_at; the indexes exclude expired rows. What you also need is a background job that physically removes expired and invalidated rows so the table doesn't grow unbounded.

-- Background cleanup job — run via pg_cron or your scheduler
CREATE OR REPLACE FUNCTION ai_cache.cleanup_expired(
    p_older_than_days INTEGER DEFAULT 30
)
RETURNS TABLE (
    exact_deleted   INTEGER,
    semantic_deleted INTEGER
)
LANGUAGE plpgsql
AS $$
DECLARE
    v_exact_deleted    INTEGER;
    v_semantic_deleted INTEGER;
    v_cutoff           TIMESTAMPTZ;
BEGIN
    v_cutoff := now() - (p_older_than_days || ' days')::interval;

    -- Delete invalidated or expired exact entries older than cutoff
    DELETE FROM ai_cache.exact_results
    WHERE
        (invalidated_at IS NOT NULL AND invalidated_at < v_cutoff)
        OR (expires_at IS NOT NULL AND expires_at < v_cutoff);
    GET DIAGNOSTICS v_exact_deleted = ROW_COUNT;

    -- Delete invalidated or expired semantic entries older than cutoff
    DELETE FROM ai_cache.semantic_results
    WHERE
        (invalidated_at IS NOT NULL AND invalidated_at < v_cutoff)
        OR (expires_at IS NOT NULL AND expires_at < v_cutoff);
    GET DIAGNOSTICS v_semantic_deleted = ROW_COUNT;

    RETURN QUERY SELECT v_exact_deleted, v_semantic_deleted;
END;
$$;

#### Strategy 4: Real-time invalidation via pg_notify and Python

When the database fires a pg_notify, your application servers need to listen and respond — typically by clearing any in-process memory cache that might hold a now-stale entry.

# cache_invalidation_listener.py — Listen for PostgreSQL cache invalidation events
import asyncio
import json
import logging
from typing import Callable, Awaitable

import asyncpg

logger = logging.getLogger(__name__)

InvalidationHandler = Callable[[dict], Awaitable[None]]


class CacheInvalidationListener:
    """
    Listens on ai_cache_invalidation channel and dispatches
    invalidation events to registered handlers.
    """

    def __init__(self, dsn: str):
        self.dsn = dsn
        self._handlers: list[InvalidationHandler] = []
        self._conn: asyncpg.Connection | None = None
        self._running = False

    def register_handler(self, handler: InvalidationHandler) -> None:
        self._handlers.append(handler)

    async def start(self) -> None:
        self._conn = await asyncpg.connect(self.dsn)
        self._running = True
        await self._conn.add_listener(
            "ai_cache_invalidation", self._on_notification
        )
        logger.info("Cache invalidation listener started")

    async def stop(self) -> None:
        self._running = False
        if self._conn:
            await self._conn.remove_listener(
                "ai_cache_invalidation", self._on_notification
            )
            await self._conn.close()

    async def _on_notification(
        self,
        connection: asyncpg.Connection,
        pid: int,
        channel: str,
        payload: str,
    ) -> None:
        try:
            event = json.loads(payload)
            logger.info(
                "Cache invalidation event: reason=%s count=%s",
                event.get("reason"), event.get("invalidated_count")
            )
            for handler in self._handlers:
                await handler(event)
        except Exception:
            logger.exception("Error processing cache invalidation event")


# Example in-process cache that responds to invalidation events
class InProcessSemanticCache:
    """
    Small in-memory LRU layer in front of PostgreSQL.
    Cleared on invalidation events from pg_notify.
    """

    def __init__(self, max_size: int = 500):
        from collections import OrderedDict
        self._cache: OrderedDict[str, str] = OrderedDict()
        self._max_size = max_size

    def get(self, key: str) -> str | None:
        if key in self._cache:
            self._cache.move_to_end(key)
            return self._cache[key]
        return None

    def set(self, key: str, value: str) -> None:
        self._cache[key] = value
        self._cache.move_to_end(key)
        if len(self._cache) > self._max_size:
            self._cache.popitem(last=False)

    async def handle_invalidation(self, event: dict) -> None:
        """Clear entire in-process cache on any invalidation event."""
        # For production, you could be more surgical — clear only
        # entries matching the event's tenant_id or tags.
        size_before = len(self._cache)
        self._cache.clear()
        logger.info(
            "In-process cache cleared: %d entries removed (reason=%s)",
            size_before, event.get("reason")
        )

34.5 Cache Analytics and Cost Attribution

A cache that doesn't report its value gets defunded. Build dashboards that show cache hit rates, latency reduction, and dollar savings directly from PostgreSQL.

-- View: cache performance summary per tenant per day
CREATE OR REPLACE VIEW ai_cache.daily_performance AS
SELECT
    date_trunc('day', accessed_at)      AS day,
    tenant_id,
    model,
    COUNT(*)                            AS total_requests,
    COUNT(*) FILTER (WHERE cache_type = 'exact')    AS exact_hits,
    COUNT(*) FILTER (WHERE cache_type = 'semantic') AS semantic_hits,
    COUNT(*) FILTER (WHERE cache_type = 'miss')     AS misses,
    ROUND(
        100.0 * COUNT(*) FILTER (WHERE cache_type IN ('exact','semantic'))
        / NULLIF(COUNT(*), 0), 2
    )                                   AS hit_rate_pct,
    ROUND(AVG(latency_ms) FILTER (WHERE cache_type = 'exact'), 1)
                                        AS avg_exact_latency_ms,
    ROUND(AVG(latency_ms) FILTER (WHERE cache_type = 'semantic'), 1)
                                        AS avg_semantic_latency_ms,
    ROUND(AVG(latency_ms) FILTER (WHERE cache_type = 'miss'), 1)
                                        AS avg_miss_latency_ms,
    ROUND(SUM(cost_saved_usd)::NUMERIC, 4)
                                        AS total_cost_saved_usd
FROM ai_cache.access_log
GROUP BY 1, 2, 3
ORDER BY 1 DESC, 2, 3;

-- View: top cached prompts by hit count
CREATE OR REPLACE VIEW ai_cache.top_cached_prompts AS
SELECT
    sr.tenant_id,
    sr.model,
    LEFT(sr.prompt_text, 120)           AS prompt_preview,
    sr.hit_count,
    sr.cost_usd                         AS original_cost_usd,
    ROUND((sr.hit_count * sr.cost_usd)::NUMERIC, 4)
                                        AS estimated_savings_usd,
    sr.created_at,
    sr.last_hit_at,
    sr.tags
FROM ai_cache.semantic_results sr
WHERE sr.invalidated_at IS NULL
ORDER BY sr.hit_count DESC
LIMIT 100;

-- Function: return ROI summary for a time window
CREATE OR REPLACE FUNCTION ai_cache.roi_summary(
    p_start     TIMESTAMPTZ DEFAULT now() - INTERVAL '30 days',
    p_end       TIMESTAMPTZ DEFAULT now(),
    p_tenant_id UUID DEFAULT NULL
)
RETURNS TABLE (
    total_requests      BIGINT,
    cache_hits          BIGINT,
    hit_rate_pct        NUMERIC,
    avg_hit_latency_ms  NUMERIC,
    avg_miss_latency_ms NUMERIC,
    latency_reduction_pct NUMERIC,
    total_cost_saved_usd  NUMERIC
)
LANGUAGE sql STABLE
AS $$
    SELECT
        COUNT(*)                                        AS total_requests,
        COUNT(*) FILTER (WHERE cache_type != 'miss')   AS cache_hits,
        ROUND(
            100.0 * COUNT(*) FILTER (WHERE cache_type != 'miss')
            / NULLIF(COUNT(*), 0), 2
        )                                              AS hit_rate_pct,
        ROUND(AVG(latency_ms) FILTER (WHERE cache_type != 'miss'), 1)
                                                       AS avg_hit_latency_ms,
        ROUND(AVG(latency_ms) FILTER (WHERE cache_type = 'miss'), 1)
                                                       AS avg_miss_latency_ms,
        ROUND(
            100.0 * (
                1 - AVG(latency_ms) FILTER (WHERE cache_type != 'miss')
                    / NULLIF(AVG(latency_ms) FILTER (WHERE cache_type = 'miss'), 0)
            ), 2
        )                                              AS latency_reduction_pct,
        ROUND(COALESCE(SUM(cost_saved_usd), 0)::NUMERIC, 4)
                                                       AS total_cost_saved_usd
    FROM ai_cache.access_log
    WHERE
        accessed_at BETWEEN p_start AND p_end
        AND (p_tenant_id IS NULL OR tenant_id = p_tenant_id);
$$;

34.6 SQL Server Equivalent — Azure SQL / SQL Server Caching Patterns

SQL Server and Azure SQL don't have a native vector similarity operator, so the semantic cache tier requires an external component. The exact-match tier translates directly.

-- SQL Server: Exact-match AI response cache
CREATE TABLE ai_cache_exact (
    id                  UNIQUEIDENTIFIER PRIMARY KEY DEFAULT NEWSEQUENTIALID(),
    cache_key           NVARCHAR(64)   NOT NULL,   -- SHA-256 hex
    tenant_id           UNIQUEIDENTIFIER NULL,
    model               NVARCHAR(100)  NOT NULL,
    normalized_prompt   NVARCHAR(MAX)  NOT NULL,
    response_text       NVARCHAR(MAX)  NOT NULL,
    response_metadata   NVARCHAR(MAX)  NOT NULL DEFAULT '{}',  -- JSON string
    token_input         INT            NULL,
    token_output        INT            NULL,
    cost_usd            DECIMAL(10,6)  NULL,
    hit_count           INT            NOT NULL DEFAULT 0,
    created_at          DATETIMEOFFSET NOT NULL DEFAULT SYSDATETIMEOFFSET(),
    expires_at          DATETIMEOFFSET NULL,
    last_hit_at         DATETIMEOFFSET NULL,
    invalidated_at      DATETIMEOFFSET NULL,
    CONSTRAINT uq_cache_key UNIQUE (cache_key)
);

CREATE INDEX idx_cache_key_active
    ON ai_cache_exact (cache_key)
    WHERE invalidated_at IS NULL;

-- SQL Server: look up and bump hit counter
CREATE OR ALTER PROCEDURE ai_cache_lookup_exact
    @model      NVARCHAR(100),
    @prompt     NVARCHAR(MAX),
    @tenant_id  UNIQUEIDENTIFIER = NULL
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @normalized NVARCHAR(MAX);
    DECLARE @cache_key  NVARCHAR(64);

    -- Normalize: lowercase + trim (SQL Server LOWER + LTRIM/RTRIM)
    SET @normalized = LOWER(LTRIM(RTRIM(@prompt)));
    -- Collapse whitespace via a CLR function or application-side normalization
    -- For simplicity here: basic trim only

    -- Compute SHA-256 cache key
    SET @cache_key = LOWER(CONVERT(
        NVARCHAR(64),
        HASHBYTES('SHA2_256',
            ISNULL(CAST(@tenant_id AS NVARCHAR(36)), '') + '|' +
            @model + '|' + @normalized
        ),
        2
    ));

    UPDATE ai_cache_exact
    SET
        hit_count   = hit_count + 1,
        last_hit_at = SYSDATETIMEOFFSET()
    OUTPUT
        inserted.id,
        inserted.response_text,
        inserted.response_metadata,
        inserted.hit_count
    WHERE
        cache_key      = @cache_key
        AND invalidated_at IS NULL
        AND (expires_at IS NULL OR expires_at > SYSDATETIMEOFFSET());
END;
GO

-- SQL Server: invalidate cache entries by a JSON metadata field
CREATE OR ALTER PROCEDURE ai_cache_invalidate_by_document
    @document_id UNIQUEIDENTIFIER,
    @tenant_id   UNIQUEIDENTIFIER = NULL
AS
BEGIN
    SET NOCOUNT ON;

    UPDATE ai_cache_exact
    SET invalidated_at = SYSDATETIMEOFFSET()
    WHERE
        JSON_VALUE(response_metadata, '$.source_document_id') =
            CAST(@document_id AS NVARCHAR(36))
        AND invalidated_at IS NULL
        AND (@tenant_id IS NULL OR tenant_id = @tenant_id);

    SELECT @@ROWCOUNT AS rows_invalidated;
END;
GO

For semantic caching on SQL Server, the practical path is to use Azure Cognitive Search or Azure AI Search (which supports vector indexes) as the semantic layer, and store only canonical responses in SQL Server. The flow becomes:

1. Embed the incoming prompt in your application layer.

2. Query Azure AI Search for nearest-neighbor results above your similarity threshold.

3. If a hit is found, retrieve the full response from SQL Server using the result's cache_id.

4. On miss, call the LLM, store the response in SQL Server, and index the embedding in Azure AI Search.

This keeps SQL Server as the transactional store of record while delegating the vector search to the purpose-built service.

34.7 Production Operational Patterns

#### Warming the cache on deployment

Cold starts after deployments hurt. Maintain a list of high-frequency prompts — derived from your ai_cache.top_cached_prompts view — and pre-warm the cache as part of your deployment pipeline.

# cache_warmer.py — Pre-warm cache with known high-frequency prompts
import asyncio
import asyncpg
from openai import AsyncOpenAI


async def warm_cache(
    pool: asyncpg.Pool,
    openai_client: AsyncOpenAI,
    tenant_id,
    top_n: int = 50,
) -> None:
    """Re-generate responses for top-N prompts that have expired or been invalidated."""

    async with pool.acquire() as conn:
        rows = await conn.fetch(
            """
            SELECT prompt_text, model, embedding_model
            FROM ai_cache.semantic_results
            WHERE
                tenant_id = $1
                AND (
                    invalidated_at IS NOT NULL
                    OR (expires_at IS NOT NULL AND expires_at < now() + INTERVAL '1 hour')
                )
            ORDER BY hit_count DESC
            LIMIT $2
            """,
            tenant_id,
            top_n,
        )

    if not rows:
        return

    cache_client = PostgreSQLAICache(
        pg_pool=pool,
        openai_client=openai_client,
        config=LLMConfig(model=rows[0]["model"]),
        tenant_id=tenant_id,
    )

    tasks = [
        cache_client.get_or_generate(row["prompt_text"])
        for row in rows
    ]
    results = await asyncio.gather(*tasks, return_exceptions=True)

    warmed = sum(1 for r in results if not isinstance(r, Exception))
    print(f"Cache warmed: {warmed}/{len(rows)} entries refreshed")

#### Monitoring cache health with a single query

-- Snapshot view for monitoring dashboards / alerting
SELECT
    COUNT(*)                                        AS total_entries,
    COUNT(*) FILTER (WHERE invalidated_at IS NOT NULL)
                                                    AS invalidated,
    COUNT(*) FILTER (WHERE expires_at < now() AND invalidated_at IS NULL)
                                                    AS expired_pending_cleanup,

                                                    AS active,

FROM ai_cache.semantic_results;

#### Avoiding cache poisoning

Semantic caches are vulnerable to a subtle failure: if an LLM produces an incorrect response and that response is cached, every future semantically similar query gets the same wrong answer, amplifying the error.

Mitigations:

  • → **Store confidence scores.** Include LLM `logprobs` or confidence metadata, and set a higher similarity threshold for low-confidence entries.
  • → **Human-in-the-loop invalidation.** Expose a feedback mechanism (thumbs-down) that calls `ai_cache.invalidate_by_document` with the entry ID.
  • → **Short initial TTL + graduated extension.** Newly stored entries get a 24-hour TTL. A background job extends TTL to 7 days only for entries that have accumulated hits without negative feedback.
    • -- Extend TTL for high-hit, unflagged entries (run daily)
UPDATE ai_cache.semantic_results
SET expires_at = now() + INTERVAL '7 days'
WHERE
    hit_count >= 5
    AND invalidated_at IS NULL
    AND response_metadata->>'user_flagged' IS NULL
    AND (expires_at IS NULL OR expires_at < now() + INTERVAL '2 days');

    Key Takeaways

  • → **Two-tier caching** — exact match first, semantic similarity second — gives you the best of both worlds: zero-latency hits on repeated identical prompts, and cost savings on paraphrased queries that would otherwise each trigger a full LLM call.
  • → **pgvector's HNSW index** makes semantic cache lookups fast enough to add only single-digit milliseconds of overhead before the LLM fallback path, making the semantic tier safe to enable by default.
  • → **Document-aware invalidation** using `source_document_ids` arrays and PostgreSQL triggers ensures that when your underlying knowledge base changes, stale cached answers are automatically marked invalid — preventing cache poisoning at scale.
  • → **pg_notify** closes the loop between the database-level invalidation event and your application servers' in-process caches, giving you real-time consistency without polling.
  • → **Analytics live in the same schema**: hit rates, latency reductions, and cost savings can be queried directly from `ai_cache.access_log` and surfaced to stakeholders, making the cache's return on investment continuously visible and defensible.
